## 课题0-1：职业认知、等级体系与职业守则

**核心考点**
- 职业定义四关键词：数据库管理 / 算法参数设置 / 人机交互设计 / 性能测试跟踪
- 两个工种：数据标注员、人工智能算法测试员
- 五个等级与能力重心：五级(初级工)完成 → 四级(中级工)审核优化 → 三级(高级工)设计诊断 → 二级(技师)培训指导 → 一级(高级技师)架构决策
- 职业守则三条：诚实公正、严谨求是；遵章守法、恪尽职守；勤勉好学、追求卓越
- 核心职业价值认知：标注＝教模型，标错＝教错

**关键规则**
- 职业守则三条须逐字准确记忆，不能只记大意

**易错点**
- 遗漏或记混职业定义四关键词中的某一个
- 混淆五级"完成"与四级"审核"的能力重心区别
- 记混三条职业守则的具体表述

## 课题0-2：法律法规与数据安全基础

**核心考点**
- 国标明列四部法规：《劳动法》《劳动合同法》《网络安全法》《知识产权法》（低频触发，管用工关系/版权）
- 高频延伸两部法规：《数据安全法》《个人信息保护法》（管你每天的具体操作，高频触发）
- 日常违规行为：工作截图发个人社交账号、个人电脑远程处理公司任务、含隐私信息截图发工作群讨论，均属**违规**
- 违规后果三层次：对用户（骚扰/诈骗/身份冒用）、对公司（监管处罚/索赔/项目叫停）、对本人（个人担责，非"批评教育"了结）
- 标注员本人就是数据安全链条上的一环，接触原始数据的人越多，泄露风险越高

**关键规则（判别口诀）**
> 这条信息离开我手上之后，去的是受公司管控、能追责的地方，还是管不着、也追不到的地方？
> 去受控渠道（如正式工单系统）通常没问题；去工作群、个人社交账号、私人设备，都属于管不着的地方，一律先脱敏或先问。
> 判别关键变量是**信息内容**，不是"有没有发出去"这个动作本身（如仅含工作量数字、不含隐私/原始数据的截图发朋友圈，不违规）。

**易错点**
- 低估"截图""私拷"等看似无害行为的风险
- 误以为国标四部已覆盖全部日常场景，忽略延伸两部才是高频触发的
- 把"出发点是工作需要/没有恶意"直接等同于"行为合规"（也不能反向过度泛化，把所有"发出去"都当违规）

**配套题库**：单选9–14、判断3

## 课题0-3：计算机、办公软件与Python环境

**核心考点**
- Excel核心函数：`IF`条件判断 / `COUNTIF`按条件计数 / `SUMIF`按条件求和 / `VLOOKUP`按条件查找匹配值，配合数据透视表完成日常整理归类汇总
- Python环境搭建核心流程：安装Python → 安装依赖包 → 打开Jupyter Notebook → 运行代码
- 常见报错类型与解决：
  | 报错 | 原因 | 解决 |
  |---|---|---|
  | `ModuleNotFoundError` | 包未安装 | `pip install` 对应包名 |
  | `FileNotFoundError` | 文件路径或工作目录不对 | 核对相对/绝对路径 |
  | `UnicodeDecodeError` | 编码格式不匹配 | 尝试 `encoding="gbk"` 或 `"utf-8"` |

**关键规则**
- 读报错技巧：先看**最后一行**（错误类型+简要原因），不要被一长串红字吓到

**易错点**
- 混淆`COUNTIF`（按条件计数）和`SUMIF`（按条件求和）的用途
- 看到报错直接放弃，不读报错信息定位问题

## 课题0-4：人工智能与机器学习入门

**核心考点**
- 包含关系：**人工智能 ⊃ 机器学习 ⊃ 深度学习**
- 三大学习范式：监督学习（有标注/标准答案，如图片分类）、无监督学习（无标签，模型自己发现结构，如用户聚类）、强化学习（试错+反馈信号，如游戏AI）
- 核心类比：标注就是在"教"模型，标注错一次，模型就学错一次
- 常见AI任务类型与所需标注形式对应：图像分类→整图打类别标签；目标检测→画框标物体位置；文本分类→整段文本打类别标签；语音识别→音频转文字

**关键规则**
- 无监督学习虽不需要人工标注"标准答案"，训练师仍需判断模型自动发现的分组结果是否有实际业务意义，不能完全不介入

**易错点**
- 记反三者包含方向
- 混淆监督学习与强化学习（是否有"预先固定的标准答案"是判断依据）
- 把标注当成"机械操作"而非"教模型"

**配套题库**：单选21–28、判断4

## 课题1-1：设备工具原始业务数据采集

**核心考点**
- 采集前必须确认三件事：**数据用途、授权范围、采集口径**（字段定义/时间范围/抽样规则）
- 采集质量当场自检清单：分辨率是否符合要求、是否清晰（无模糊/过曝）、命名是否规范、有无重复采集
- 常见数据来源渠道：用户行为日志、业务系统导出、传感器/设备采集、第三方采购、公开数据集
- 核心习惯：采集完当场自检，发现问题当场重采——现场往往不可逆，上传后才发现问题常常无法重采

**关键规则**
- 实测案例：42张图像中640×480规格37张、320×240规格4张、1280×960规格1张——**5张分辨率不一致**，此外还有模糊/过曝/重复/命名不规范等问题

**易错点**
- 采集完直接提交，不做当场自检
- 遗漏采集前三件事中的某一项

## 课题1-2：数据库内数据采集（SQL查询与导出）

**核心考点**
- 基本概念：数据库、表、字段、主键（唯一标识每条记录）、记录
- 基础SQL能力：`SELECT`/`WHERE`/`ORDER BY`/`LIMIT`/`GROUP BY`/`COUNT`/基础`JOIN`
- 导出前核心习惯：**先用`COUNT`核对数量是否符合预期，再用`JOIN`核查关联字段完整性**
- 孤儿记录（脏数据）排查标准写法：`LEFT JOIN` + `WHERE 右表字段 IS NULL`

**关键公式/规则**
```sql
SELECT 字段 FROM 表名 WHERE 条件 ORDER BY 字段 LIMIT 数量;
SELECT 字段, COUNT(*) FROM 表名 GROUP BY 字段;
-- 查孤儿记录：
SELECT a.id FROM a LEFT JOIN b ON a.key = b.key WHERE b.key IS NULL;
```

**易错点**
- 写完查询直接导出，不核对数量（"少导一半数据还没发现"）
- 不知道用`LEFT JOIN`+`IS NULL`组合查找孤儿记录
- 把业务需求翻译成SQL时遗漏字段名/筛选值/时间范围等要素

**配套题库**：单选37–44、判断6；实操 五-1（续）

## 课题1-3：业务数据整理归类

**核心考点**
- 核心能力：识别同一含义的不同写法（如"手机"/"手機"/"手机 "应归为一类）
- 常见格式问题五类：日期格式不统一、全半角混用、首尾空格、单位不一致、大小写/同音异形混乱
- 统一方法：`str.strip()`去空格、`str.replace()`/`.replace({...})`统一写法、`pd.to_datetime()`统一日期格式
- 用`value_counts()`等统计方法系统性发现隐藏格式问题，仅凭肉眼检查容易漏掉

**关键公式/规则**
```python
d["字段"] = d["字段"].str.strip().replace({"手機": "手机"})
d["日期字段"] = pd.to_datetime(d["日期字段"], errors="coerce")
```

**易错点**
- 只看表面"没有明显错误"，忽视细微写法差异（首尾空格肉眼难辨）
- 不统一日期格式直接做日期计算，导致排序/比较出错

**配套题库**：单选45–52、判断7

## 课题1-4：业务数据汇总（Excel + pandas）

**核心考点**
- 核心顺序：**先归类统一（课题1-3）→ 再汇总（本课题），顺序不能颠倒**
- 汇总结果合理性自查四项：数字是否看起来合理、总数是否对得上、占比之和是否为100%、有无异常极值
- Excel数据透视表与pandas的对应关系：`groupby().size()`↔分组计数；`groupby()[列].sum()`↔分组求和

**关键公式/规则**
```python
d.groupby("商品类别").size()          # 对应数据透视表拖拽字段分组计数
d.groupby("商品类别")["数值列"].sum() # 对应透视表值字段设为求和
```
实测案例：归一化前"手机"被拆成三行（94+20+21），归一化后合并为135——不归类直接汇总会严重低估真实占比

**易错点**
- 跳过归类整理直接做汇总统计
- 得到汇总结果就提交，不做合理性自查

**配套题库**：单选53–60、判断8；实操 五-2

## 课题2-1：文本 / 视觉 / 语音数据清洗

**核心考点**
- 清洗五大目标：去重复、去缺失、去异常、去噪声、统一数据格式
- 文本清洗要点：去重、去空、去乱码、去HTML标签与表情符号、统一编码、过滤超长/超短样本、敏感信息替换
- 视觉清洗要点：剔除损坏/重复/模糊/过曝图像，统一分辨率与格式，核对图像与标注文件对应关系
- 语音清洗要点：剔除静音/截断/底噪过大音频，统一采样率与格式，核对音频与文本对应关系
- **铁律：清洗后另存为新文件，绝不覆盖原始数据文件**（清洗是不可逆操作）

**关键规则**
```python
df.to_csv("xxx_cleaned.csv", index=False, encoding="utf-8-sig")  # ✓ 另存为新文件
# df.to_csv("xxx_raw.csv", ...)                                   # ✗ 绝不能覆盖原文件
```

**易错点**
- 直接覆盖原文件，导致清洗规则出错后无法回溯
- 记混五类清洗问题的名称
- "清洗过度"（误删该保留的样本）或"清洗不彻底"（遗漏某类问题）

**配套题库**：单选61–76、多选1、判断9–10；实操 五-3

## 课题2-2：文本数据标注实操

**核心考点**
- 常见文本标注任务类型：文本分类（整段打一个类别标签）、命名实体识别NER（框出人名/地名/机构名，难点在实体边界）、序列标注/意图槽位
- 实体边界切分规则必须依标注规范，不能凭感觉决定（如"北京大学第三医院"整体标还是拆开标）
- **最重要原则：遇到规范未覆盖的边界样本，记录上报，不自行发挥**
- 要正确区分单标签/多标签标注的处理方式，不能混淆

**关键规则**
- 边界样本处理：标记为"待裁定"，记录原文，课后统一提交讨论上报，不自行决定标准继续标注
- 不能自行发挥的原因：个人判断可能与规范制定意图不一致；自定标准批量应用后一旦错误需整批返工；标注员各自理解不同会让模型学到互相矛盾的信号

**易错点**
- 自行判断一个标准后批量应用，不上报
- 不参照规范，凭感觉切分实体边界
- 混淆单标签与多标签标注的处理方式

**配套题库**：单选77–88、判断11；实操 五-4

## 课题2-3：视觉数据标注实操

**核心考点**
- 常见视觉标注任务类型：图像分类（整图打标签）、目标检测Bounding Box（画矩形框）、语义/实例分割（逐像素打标签，精度要求远高于画框）
- 框选质量三项标准：贴合物体边缘（不大不小）、不遗漏（密集小目标也要框）、不重复
- 特殊情形处理：
  | 情形 | 正确做法 |
  |---|---|
  | 部分遮挡 | 按可见部分框选，不猜测补全被遮挡部分 |
  | 密集小目标 | 逐个框选，不因小而遗漏 |
  | 模糊目标 | 标记"存疑"，不强行归类 |
- 核心素养：宁可慢一点标准确，也不要为赶量粗框——框偏一点，模型学到的位置就偏一点

**关键规则**
- 无公式类，核心是上表的三类特殊情形处理原则

**易错点**
- 漏标密集小目标、框选边缘不贴合
- 对遮挡物体猜测补全边界，而非按可见部分框选
- 对模糊目标强行归类，而非标记存疑

**配套题库**：单选89–96、判断12

## 课题2-4：语音数据标注实操

**核心考点**
- 常见语音标注任务类型：语音转写（ASR标注）、说话人分割/识别、语音情感与语调标注
- **转写规则必须全项目统一执行**（语气词是否转写、数字读法、标点使用等），不能标注员各自决定
- 特殊情形处理：
  | 情形 | 处理规则 |
  |---|---|
  | 听不清的片段 | 标记"[听不清]"，不得猜测填写 |
  | 多人重叠说话 | 标记"[重叠]"并说明可辨识内容 |
  | 数字读法 | 统一阿拉伯数字或中文数字，不混用 |

**关键规则**
- 诚实标记"听不清"优于猜测填写：猜测错误会被模型当成正确规律学习，危害比明确标记缺失信息更大

**易错点**
- 认为语气词转写与否无关紧要，可以随意处理
- 猜测填写而非如实标记听不清/存疑
- 数字读法等规则不统一，标注员各自为政

**配套题库**：单选97–104、判断13

## 课题2-5：标注后数据分类与统计

**核心考点**
- 交付前自检四项：数量完整、格式合规、标签取值合法、文件对应关系正确
- 核心能力：用统计工具（如`value_counts()`）对标签分布、标注员完成量做统计，并**主动审视数字是否正常**从中发现异常
- 两类典型异常：规范外标签取值（如三分类规范外出现"中性偏正""3"）需核查来源；某标注员完成量远低于其他人需上报核实，不能直接当正常情况处理

**关键规则**
```python
d["标签字段"].value_counts(dropna=False)
d["标注员"].value_counts()
```
- 核心心法：统计不是算完数字就结束，要带着"这个数字正常吗"的疑问去审视结果

**易错点**
- 算出统计数字就结束，不审视数字是否正常
- 发现规范外取值但不核查来源
- 对完成量异常偏低的个体直接归因"效率低"，不上报核实

**配套题库**：单选105–112、多选2、判断14；实操 五-5

## 课题3-1：智能系统基础操作

**核心考点**
- 系统开启流程：登录 → 权限确认 → 环境与服务状态检查
- 基础使用操作：数据导入导出、任务创建与领取、提交与保存、结果查看
- **铁律：操作前先确认当前是测试环境还是生产环境**——生产环境数据真实在用，误删误改后果往往不可逆
- 遇异常（登录失败/上传失败/任务无法提交）按流程上报，不自行反复尝试可能造成数据损坏的操作

**关键规则**
- 测试环境搞坏了可以重置；生产环境搞坏了可能影响真实用户或业务数据，后果完全不同

**易错点**
- 不确认环境标识直接操作
- 遗漏权限确认或服务状态检查环节
- 遇异常自行反复尝试（如强行多次提交），而非上报

**配套题库**：单选113–126、判断15–16；实操 五-6

## 课题3-2：智能系统维护与运行记录

**核心考点**
- 运行记录作用：问题可追溯、异常可复现、绩效可核查
- 运行记录三要素：功能使用情况、运行是否正常、异常现象描述
- **核心原则：写现象，不写结论**

**关键规则/对照**
| 写法 | 判断 |
|---|---|
| "系统坏了" | ✗ 结论，无法排查 |
| "点击提交后页面提示500错误，重试3次均失败" | ✓ 现象，可复现、可排查 |
| "数据不对" | ✗ 结论 |
| "导出文件行数为980，预期应为1000，缺少20行" | ✓ 现象，具体数字立刻能定位 |

**易错点**
- 用"系统坏了""不正常"等笼统结论描述问题
- 记录缺少具体时间、复现步骤
- 遗漏运行记录三要素中的某一项

**配套题库**：单选127–140、判断17–18；实操 五-6（续）
