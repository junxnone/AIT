## 一、为什么"先归类、再汇总"不能跳步——一个真实的反转案例

先交代一下背景：这批 508 条销售记录里，"商品类别"这个字段并不干净——同一个"手机"品类，在原始数据里被写成了好几种不同的样子，有的多打了一个空格，有的用了错别字"手機"。课题1-3里学的"归类整理"，做的就是把这些写法不统一的记录合并成同一类。

现在我们来看，如果**不做归类、直接对原始数据做分组汇总**，会发生什么：

```python
import pandas as pd
d = pd.read_csv("../数据集/sales_raw.csv")

print("归一化前（按商品类别计数）：")
print(d["商品类别"].value_counts().to_dict())

print("归一化前（按原始写法汇总销售数量）：")
print(d.groupby("商品类别")["销售数量"].sum().to_dict())
```

**实测结果**（已验证）：

```
归一化前（计数）：耳机104 笔记本电脑96 手机94 平板89 智能手表84 手機21 手机(尾空格)20
归一化前（销售数量求和，三种写法分开统计）：手机927 手机(尾空格)189 手機235
```

你看到了吗？"手机"这一个品类，在原始数据里被拆成了三行分别统计：标准写法"手机"94单/927件，多了空格的"手机 "20单/189件，用了错字的"手機"21单/235件。如果你只看第一行（最接近"手机"标准写法的那一行），就会得到和开篇那份报告一样的数字——94单、927件，确实是五个品类里垫底的那个。

现在我们按课题1-3的方法，先做归类整理，再汇总：

```python
d["商品类别"] = d["商品类别"].str.strip().replace({"手機": "手机"})

print("归一化后（按商品类别计数）：")
print(d["商品类别"].value_counts().to_dict())

print("归一化后（按商品类别汇总销售数量）：")
print(d.groupby("商品类别")["销售数量"].sum().to_dict())
```

**实测结果**（已验证）：

```
归一化后（计数）：手机135 耳机104 笔记本电脑96 平板89 智能手表84
归一化后（销售数量求和）：手机1351 耳机955 笔记本电脑921 平板787 智能手表780
```

归一化之后，"手机"是 135 单、1351 件——**五个品类里卖得最多的那一个**，而不是垫底。927 件和 1351 件相比，真实销量被低估了 (1351−927)/1351 ≈ **31%**，接近三成。

### 为什么会这样？——机制要理解透

这不是程序出了bug，而是程序本来就该这样工作。`groupby` 分组的时候，靠的是**字符串逐字符比对**：只有两个字符串完全相同，才会被分到同一组。对程序来说，"手机"、"手機"、"手机 "（多一个空格）是三个**完全不同**的字符串——它不理解"手機"是错别字、"手机 "只是多打了个空格，它不会帮你"脑补"语义，只会严格按字面比较。所以这三种写法，必然被分进三个不同的组，分别统计。

这就是为什么"先归类、再汇总"这个顺序不能颠倒：**汇总操作本身没有能力识别"写法不同、含义相同"这件事**，这件事必须在汇总之前，由人或者清洗代码先处理掉。你跳过这一步，代码照样能跑、不会报错、照样给你一个"结果"——但这个结果是失真的，而且这种失真不会自己报错提醒你，你必须主动去发现。

> 现在回到开篇那个判断：这份"手机品类垫底、建议砍半采购"的报告可信吗？**不可信**。它漏算了另外两种写法的 41 条记录，手机的真实销量被低估了约三成。如果真照这份报告去砍采购预算，砍掉的恰恰是卖得最好的那个品类——**一个技术上的归类疏漏，变成了一个方向完全相反的业务决策**。这就是为什么课题1-3的归类整理不是可做可不做的形式主义步骤，它直接决定了后面汇总结论的对错。

## 二、汇总结果的合理性自查——怎么在交付前自己先发现问题

学到这里你可能会想："那我以后汇总之前都先做归类不就行了吗？"——这当然是对的，但现实中你没法保证每一个字段、每一次都100%归类彻底，总会有漏网之鱼。所以除了"先归类再汇总"这个操作顺序之外，还需要养成第二个习惯：**拿到一个汇总结果，不能算完就直接提交，要先自己检查一遍**。

具体检查什么？四件事：
- 这个数字看起来合理吗？
- 总数是否对得上（各分类加起来等于总体）？
- 占比之和是否为100%？
- 有没有异常极值？

这四条不是走流程、凑数凑出来的清单，它们各自对应一类真实会发生的错误。下面用同一批数据的另一个字段，让你亲眼看到这些检查是怎么揪出问题的。

### 一个真实的例子：销售地区占比只有92.7%

这批508条数据里的"销售地区"字段，我们还没对它做过归类整理。先直接看它的原始取值：

```python
print(d["销售地区"].value_counts())
```

实际取值里，除了"华南""华东""东北""西南""华北"这5种"干净"写法之外，还混着"  东北 ""  华东 ""  华北 ""  华南 ""  西南 "这5种带首尾空格的写法。

**关键提问（请你自己先算一下）**：如果汇总时只统计看起来"正常"的那5种干净写法，会漏掉多少数据？占比会是多少？

答案：只统计5种干净写法，一共是471条，而总行数是508条——**占比只有 471/508 ≈ 92.7%，加不满100%**。

这正是"各地区销售额占比加起来只有92%"这类现象的真实来源：丢失的那 7.3%（也就是36条记录）不是数据凭空消失了，而是因为它们带着首尾空格、没有被归入任何一个"干净"类别，统计时被整体漏掉了。

> **这里要特别纠正一个常见的错误反应**：如果你看到"占比加不到100%"，第一反应很容易是"是不是代码算错了""是不是系统有问题"。但正确的排查顺序应该反过来——先去原始数据里核对一遍取值分布，看看是不是有没被归类进任何一组的"漏网"写法。绝大多数这类问题，根源都在数据本身写法不统一，而不是统计代码或工具出了错。

**判别口诀**：汇总结果的占比加不满100%、或者总数对不上总行数，第一反应不该是怀疑系统算错，而应该先怀疑——**是不是存在没被归类进任何一组的"漏网"写法？**

把这个口诀和前一节的手机案例放在一起看，你会发现它们说的是同一件事的两个侧面：手机案例是"同一个类别被拆成了好几份、各自统计"，地区案例是"一部分记录完全没被统计进任何一份"。两者的根源都一样——**归类没做彻底**，表现形式不同而已。所以这两条检查习惯要连在一起记：

**核心顺序**：先归类统一（课题1-3的工作），再汇总（本课题的工作），顺序不能颠倒。如果跳过归类直接汇总，看似"做完了"，实则得到的是一份连总数都对不上的失真结果——而这份失真结果，如果不做合理性自查，是检查不出来的，它会原样传递给下游做决策的人。

## 三、动手做：用Excel和pandas完成同一次汇总

理解了"为什么"之后，现在来看"怎么做"。汇总说白了就是把一堆明细记录按某个维度（比如商品类别、销售地区）分组，然后在每组里面做统计。最常见的四种统计口径是：

- **计数**——这个类别有多少条记录；
- **求和**——这个类别总共卖了多少件/多少钱；
- **均值**——平均客单价是多少；
- **占比**——这个类别占整体的百分之多少。

这四种口径，Excel里对应的工具是**数据透视表**，pandas里对应三个工具：**groupby**（先按字段分组）、**agg**（分组后一次性算出一个或多个统计量）、**pivot_table**（分组+行列交叉，一步到位）。工具不同，解决的是同一类问题，理解了其中一种工具的思路，迁移到另一种工具通常只是操作方式不同。

### 对照表

| 统计口径 | Excel | pandas |
|---|---|---|
| 分组计数 | 数据透视表值字段设为"计数项" | `df.groupby("字段").size()` |
| 分组求和 | 数据透视表值字段设为"求和项" | `df.groupby("字段")["数值列"].sum()` |
| 多指标同时算 | 值区域拖入多个字段 | `df.groupby("字段").agg(订单数=("订单编号","count"), 总销量=("销售数量","sum"))` |
| 行列交叉汇总 | 字段同时拖到"行"与"列" | `df.pivot_table(index="商品类别", columns="销售地区", values="销售数量", aggfunc="sum")` |

### Excel操作怎么做

打开数据透视表功能：把"商品类别"拖到"行"区域；把"订单编号"拖到"值"区域并设为"计数项"，就能统计订单数；把"销售数量"也拖到"值"区域并设为"求和项"，就能统计总销量。想要交叉汇总（比如看各地区各品类分别卖了多少），再把"销售地区"拖到"列"区域即可，Excel会自动生成商品类别×地区的交叉表。

这里有一个Excel新手最常见的操作失误，请特别留意：**值字段默认情况下可能被设为"计数项"而不是"求和项"**，如果你想统计的是销量总数却忘了手动切换成"求和项"，算出来的数字会完全不对。

### pandas核心代码

```python
# groupby + agg：一次性算出订单数与总销量
summary = d.groupby("商品类别").agg(
    订单数=("订单编号", "count"),
    总销量=("销售数量", "sum")
)
print(summary)

# pivot_table：商品类别 × 销售地区 交叉汇总
cross = d.pivot_table(index="商品类别", columns="销售地区", values="销售数量", aggfunc="sum")
print(cross)

# 占比
share = summary["总销量"] / summary["总销量"].sum()
print(share.round(3))
```

**实测结果**（已验证，建立在归类整理之后的干净数据上）：

```
        订单数   总销量
手机     135    1351
耳机     104     955
笔记本电脑 96     921
平板      89     787
智能手表   84     780
```

## 四、给自己的最终自查清单

做完一次汇总之后，不要立刻提交，按下面几条自己过一遍（这就是前面讲的"合理性自查"具体落地成的操作清单）：

- [ ] 汇总之前，是否已经对分组字段做过归类处理（去空格、统一错别字/不同写法）？
- [ ] Excel的"值字段"是否正确设为了"求和项"而不是默认的"计数项"（如果统计的是求和类指标）？
- [ ] 各分类的数量/销量加起来，是否等于总行数/总销量？
- [ ] 占比加起来是否接近100%？如果不是，有没有先去查原始数据里是否存在没被归类的"漏网"写法，而不是先怀疑工具出错？
- [ ] 有没有异常极值（某一类数字高得或低得不合常理）？

这份清单看起来琐碎，但它正是本课题最核心的职业习惯——**汇总结果出来之后，先自查再相信**。这也是为什么本课题是职业功能1（数据采集和处理）的收官课：课题1-1、1-2把数据采集进来，1-3把数据整理归类干净，到本课题1-4，你要对前面三课的全部成果做最后一道质量把关——如果这道关没把好，前面三课做得再仔细，最后交付出去的结论照样可能是错的。

## 自测练习（随堂练习，答案已直接展开）

**练习 1**：某汇总报告显示各地区销售额占比加起来只有92%，可能是什么原因？

**答案**：可能存在地区字段的写法不统一（如同一地区的不同写法被当成不同类别，部分未被识别归入汇总），或存在地区字段缺失/异常值未被纳入统计。应回头检查归类整理是否彻底，而不是直接采信这个有问题的汇总结果。

**练习 2**：为什么说"先归类统一，再汇总"这个顺序不能颠倒？

**答案**：因为汇总是建立在归类基础上的统计操作，如果归类没做彻底（同一含义的不同写法没有合并），汇总统计会把本该是一类的数据拆分统计，导致汇总结果严重失真。颠倒顺序（先汇总再归类）在逻辑上也说不通，因为汇总后的数字已经无法再回溯到原始的具体写法。

**练习 3**：汇总结果的合理性自查应该检查哪些内容？

**答案**：总数是否对得上（各分类之和等于总体）、占比之和是否为100%、有没有异常极值。这些检查能帮助发现归类不彻底、字段缺失等潜在问题，而不是拿到汇总数字就直接采信提交。

**练习 4**：Excel数据透视表和pandas的groupby在功能上是什么关系？

**答案**：两者在功能上可以实现同样的分组汇总效果——数据透视表通过拖拽字段完成分组统计，groupby通过代码完成同样的操作。掌握一种工具的思路后，迁移到另一种工具通常只是操作方式的不同，底层的分组聚合逻辑是一致的。

**练习 5**：如果业务方直接采信了一份有问题的汇总报告（比如把归类不彻底导致的低估数字当真），可能造成什么后果？

**答案**：可能造成错误的业务决策，比如误判某个商品品类销量不佳而减少该品类的采购或推广投入，而实际上这个品类的真实销量被错误地拆分低估了。这说明汇总数据的准确性直接关系到后续业务决策的正确性，不是单纯的技术细节问题。

## 小结

| 要点 | 一句话 |
|---|---|
| 核心教训 | 归类不彻底，汇总结果就会严重失真——手机品类曾被低估约31% |
| 判别口诀 | 占比加不满100%/总数对不上，先怀疑有"漏网"写法未归类，而不是怀疑系统出错 |
| 自查习惯 | 拿到汇总结果先核对总数、占比、异常极值，再决定是否相信它 |
| 工具迁移 | Excel数据透视表与pandas的groupby/agg/pivot_table解决的是同一类问题 |

**配套题库**：单选53-60、判断8；实操 五-2。

**模块收官，承上启下**：职业功能1（数据采集和处理）到这一课就学完了。课题1-1、1-2解决的是"怎么把数据采集进来"；课题1-3、1-4解决的是"怎么把采集来的数据整理干净、算明白"。这四课连起来，就是数据从"原始、杂乱"到"干净、可用于决策"的完整处理链条——少了任何一环，最后的汇总结论都可能是错的，就像本课反复出现的手机品类被低估三成这个例子。

下一个模块是职业功能2——**数据标注**，讨论的是另一个完全不同的问题：数据已经干净了、能汇总出可信结论了，接下来怎么给它打上"标签"，让它能喂给算法训练？这和职业功能1"整理已有信息"的性质不一样——**标注是给数据加新的信息，而整理归类和汇总是把已有的信息弄干净、算明白**。带着这个区别，去读下一课题2-1。
