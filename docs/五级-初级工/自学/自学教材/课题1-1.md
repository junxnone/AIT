## 写在前面

这一课题是整个"数据采集和处理"职业功能的开篇课。你在这里养成的工作习惯——采集前先想清楚、采集中守规格、采集后自己检查、检查完如实记录——会一直延续到后面十几个课题。很多零基础的人会把"采集"简单理解成"拿起手机拍一下、传上去就完事"，把采集等同于"按快门"这一个动作。这篇教材要纠正的就是这个误区：采集其实是"想清楚→按规格做→当场检查→如实记录"这一整套流程，少了任何一环都算没做完。

本教材不要求你一定要有电脑和 Python 环境才能学——没有环境，跳过代码运行步骤，照样能看懂机制和结论；有环境的话，建议把代码跑一遍，亲眼验证一下结果。

## 学习目标

读完这篇教材，你应该做到：

**知识目标**
1. 能说出常见的数据来源渠道：用户行为日志、业务系统导出、传感器/设备采集、第三方采购、公开数据集。

3. 能说出采集规格（分辨率/采样率/格式/命名规则）与归档记录的基本要素。

2. 能识别采集质量问题并当场重采，而不是提交之后才发现问题。
3. 能按规范完成采集文件的命名、归档与采集记录登记。

## 一、先给自己出一道判断题

设想这样一个场景：上周某位学员用手机采集了 42 张商品图片，准备用于后续的图像标注任务。他自己检查过——数量够了，也挨个点开看了一眼，感觉"挺清楚的，应该没问题"，于是把文件打包提交了。

结果质检环节把这批数据打了回来，要求重拍其中几张、重新命名归档。

**在继续往下读之前，先花三十秒自己判断一下**：这批图片问题可能出在哪？大概有几张不合格？把你的猜测写下来：问题类型 _______________　大概 _______ 张。

记住这个数字。读到第四节，你会看到这 42 张图片真实的检测结果——多半和你的猜测有不小的出入。这个出入本身就是本课题要讲的核心道理：**"看起来没问题"和"真的没问题"之间，差得比你想象的要多。**

## 二、采集不是"按快门"：动手之前先想清楚三件事

不管你用哪种渠道、哪种设备去采集数据，动手之前都要先确认三件事：**数据用途、授权范围、采集口径**。这三件事一旦漏掉，往往不是小问题，而是会让整批数据返工甚至报废。

### 为什么用途要问在最前面

用途决定规格。同样是拍商品图，用于电商详情页展示，和用于训练图像识别模型，对清晰度、背景干净程度的要求完全不一样。不先问清楚用途就开拍，拍回来才发现规格不对——这些照片往往要么全部重拍、要么干脆报废。事后返工的成本，远高于提前花一分钟确认用途。

### 为什么授权范围要问在最前面

采集本身可能涉及他人信息，比如采集门店场景时拍到了顾客。如果没有明确授权范围就采集，轻则这批数据不能用（必须删除重采），重则直接构成违规。这和课题0-2讲过的"标注员是数据安全链条上的一环"是同一个道理——**采集环节同样要先确认"能不能采"，不能等采完了再回头想这个问题。**

### 为什么采集口径要问在最前面

口径包括字段定义、时间范围、抽样规则。比如任务是"采集100张商品图"——这个"100张"是每个品类都要覆盖，还是随便拍满100张就行？是只拍正面，还是要多角度？口径不明确，采回来的样本结构很可能完全不满足后续标注、训练的实际需要。等发现问题再补拍，往往已经错过了最佳的拍摄条件（比如促销活动已经结束、商品已经下架）。

> **一句话记住**：想清楚"干什么用"，确认"能不能采"，定清楚"怎么算合格"——这三件事要做在采集动作**之前**，而不是采集之后。

### 常见数据来源渠道

不同渠道的采集方式和合规要求不一样，采集前都需要先明确具体来源及其授权情况：

| 渠道 | 举例 |
|---|---|
| 用户行为日志 | APP点击、浏览、停留时长记录 |
| 业务系统导出 | 订单系统导出的交易记录 |
| 传感器/设备采集 | 本课题讲的拍照、录音、门店摄像头 |
| 第三方采购 | 向数据供应商购买的标注数据集 |
| 公开数据集 | 政府/学术机构公开发布的数据 |

本课题重点练习的是"传感器/设备采集"这一类——用手机、相机这些工具，亲手把原始数据采回来。

## 三、采集规格、命名与归档记录规范

想清楚三件事之后，动手采集时还有具体的规格要求要满足：**分辨率/采样率、文件格式、命名规则**。这些通常写在采集任务书里，必须照办，不是"自己觉得差不多就行"。采集完成后，还要按规范归档，并同步填写**采集记录登记表**。

### 为什么命名规则看起来是小事，却经常是考核要点

因为后面清洗、标注环节的同事，大概率不会一张一张点开图片去看，而是写一段脚本，按文件名的规律去批量处理——比如用文件名前缀识别类别、用编号对应标注记录。

如果采集时随手命名，比如用手机相册自动生成的"IMG_3.jpg"，或者用中文加空格命名成"商品图片16.jpg"、"new photo 29.jpg"——下游的批量处理脚本按规律匹配文件名时，这些文件要么被漏掉、要么直接让脚本报错。

> **机制**：命名不规范，本质上是把本该由你在采集阶段当场解决的小问题，转嫁给了下游环节——而且下游环节往往更难发现根因（他们只看见"脚本报错"或"少了几个文件"，并不知道问题出在采集时命名不统一）。

### 采集记录登记表要写什么

登记表至少要包含：**采集人、采集时间、数据来源/渠道、采集数量、规格是否达标、异常情况说明**。

> **为什么异常情况说明必须写具体现象，不能只写"已完成"或"一切正常"**：如果采集过程中确实发生过重拍、因模糊/过曝剔除某张照片，登记表里就要如实写明。半年后如果有人要追溯这批数据是怎么采的——登记表是唯一的依据。一旦登记表和实际操作脱节（实际重拍过但写"一切正常"），这份记录就失去了"可追溯"这个存在的意义，等于白填。

**自我提问**：如果半年后有人问你，这批数据是什么时候、用什么设备采的、采集过程中出过什么状况，你现在填的登记表能回答清楚吗？如果答案是"不能"，说明登记表还没填到位。

## 四、动手验证：用代码揪出看不见的问题

现在回到第一节开头的判断题。我们用代码来查一下这 42 张图片到底有什么问题。如果你有 Python 3.11 + Pillow 环境，且本地有 `数据集/images/` 目录（42 张已采集商品图像），可以亲自运行下面的代码：

```python
from PIL import Image
from pathlib import Path
import re

files = sorted(Path("../数据集/images").glob("*.jpg"))
sizes = {}
irregular_names = []
for p in files:
    img = Image.open(p)
    sizes.setdefault(img.size, []).append(p.name)
    if not re.match(r"^[a-z]+_\d{3}", p.name):
        irregular_names.append(p.name)

print("分辨率分布:", {k: len(v) for k, v in sizes.items()})
print("命名不规范文件:", irregular_names)
print("总文件数:", len(files))
```

**实测结果**（已验证，你跑出来的结果应完全一致）：

```
分辨率分布: {(640, 480): 37, (320, 240): 4, (1280, 960): 1}
命名不规范文件: ['IMG_3.jpg', '商品图片16.jpg', 'new photo 29.jpg']
总文件数: 42
```

代码查出了 **5 张分辨率不一致**（4张320×240、1张1280×960）、**3张命名不规范**。但这份清单还没完——**这 42 张图里，实际还有 4 张严重模糊、3 张过曝、2 组完全重复的图片**。这些问题代码刚才查出来了吗？

**没有。** 代码只查了分辨率和文件名，模糊和过曝一个都没查出来。

### 为什么代码查不出模糊和过曝

这不是代码写得不够好，而是这两类问题的性质根本不同：

- **分辨率、文件名、文件内容是否完全重复**——这些都是"能被精确计算"的东西：尺寸是两个数字，文件名是一串字符，重复可以逐字节比对。代码能稳定、可靠地查出来。
- **模糊、过曝**——"看起来模糊""看起来发白"是主观视觉判断，没有一行简单代码能给出和人眼完全一致的结论（真要用算法做，需要专门的图像处理技术，属于进阶内容，超出本课题范围）。

> **机制**：代码能可靠查出客观可计算的问题，但主观视觉质量问题，现阶段最可靠的办法仍然是**人当场看一眼**。这就是为什么"采集质量当场自检"要反复强调——它不是"跑完代码就能替代"的步骤，而是必须有人眼参与的独立检查环节，代码和人眼各管一类问题，谁也替代不了谁。

### 回到开头的判断，揭晓答案

现在完整答案是：这 42 张图片里，有 **5 张分辨率不一致、4 张模糊、3 张过曝、3 张命名不规范，外加 2 组完全重复**。对照一下你在第一节写下的猜测——准吗？多数人往往只会注意到"分辨率不一样"这种一眼能看出的问题，而忽略了命名、重复这类需要专门检查才能发现的问题。这正说明了：光靠"挨个点开看一眼感觉还行"，和用系统化的清单逐项核对，查出来的结果可以差很多。

### 采集质量当场自检清单

- [ ] 分辨率是否符合要求（统一规格）
- [ ] 是否清晰（无模糊、无过曝）
- [ ] 命名是否规范
- [ ] 有无重复采集

### 三类图像问题怎么快速区分

| | 分辨率不一致 | 模糊 | 过曝 |
|---|---|---|---|
| 现象 | 同批图像尺寸不同 | 细节看不清 | 画面接近全白 |
| 常见成因 | 设备/模式切换未统一 | 低分辨率放大，或对焦失败 | 光线过强或曝光设置不当 |
| 能否代码检测 | 能 | 较难，建议人工目测 | 较难，建议人工目测 |
| 修复方式 | 统一规格重拍 | 当场重拍 | 调整光线/角度后重拍 |

> **判别口诀**：先问"尺寸对不对"（代码能查）→ 再问"看得清不清、亮不亮"（人眼当场查）。

### 为什么"当场自检"比"事后处理"省那么多成本

想象一下：如果这 4 张模糊、3 张过曝的图片是你拍的，你当场拍完立刻回看一眼，发现模糊了，**当场重拍**——成本几乎为零，光线、拍摄角度、商品摆放都还在，重拍一次就行。

但如果你拍完没检查，直接打包上传，几天后质检环节才告诉你"这几张不合格"——这时候你可能已经离开了拍摄现场，光线变了、设备换了，甚至这批商品已经下架、促销活动已经结束，**根本没法重新拍出一模一样的内容**。

> **核心习惯**：采集质量问题最大的代价不是"要重做"，而是很多时候"根本没法重做"。采集完当场自检，发现问题当场重采，比提交后在清洗/标注环节才发现问题的返工成本低得多——这正是开头案例里那位学员踩的坑：他"看了一眼"，但看的是"内容对不对"，而不是对照系统的自检清单逐项检查。

## 五、轮到你动手：现场采集与自检练习

读到这里，光看不练是不够的。找一个安静的环境，用你的手机或相机，按照下面的要求练习一次真实采集：

**任务**：采集 10 张你身边物品的照片，统一分辨率设置，并按照"类别_三位编号.jpg"的格式命名（例如 `cup_001.jpg`、`cup_002.jpg`）。

拍完之后，**立刻**对照第四节的"采集质量当场自检清单"检查一遍，而不是拍完就直接收工：

- 分辨率是否统一？
- 有没有模糊、过曝的照片？当场回看，不要只扫一眼构图对不对。
- 文件命名是否符合规则？不要图省事直接用手机相册给的默认文件名。
- 有没有重复拍到同一个物品、同一个角度？

如果你想检验自己对"当场自检"这件事是否真的养成了习惯，可以试一个小测试：**故意**拍一张明显过曝或模糊的照片，看看自己能不能立刻识别出来并重拍，而不是要靠别人提醒才发现。能做到这一点，说明你已经把"当场自检"内化成了动作，而不是停留在"知道要检查"这个认知层面。

## 六、把采集过程记录下来：登记表怎么填

采集完成后，按第三节讲的字段，给刚才这 10 张照片填一份采集记录登记表：

```
采集人：
采集时间：
数据来源/渠道：（传感器/设备采集）
采集数量：
规格是否达标：（分辨率/命名是否符合要求）
异常情况说明：（如有重拍、模糊、过曝等问题，写明具体现象，不要只写"有问题"）
```

填写时特别注意"异常情况说明"这一栏——如果你刚才确实发现并重拍过某张照片，就要如实写出具体现象，例如"第3张因手抖模糊，已当场重拍"，而不是图省事写"一切正常"。很多人即使采集中确实重拍过，也懒得在登记表里如实记录，这会导致记录与实际操作脱节，让登记表失去"可追溯"的意义——这也是实操考核的重要得分点之一。

## 七、自我诊断：这些采集记录错在哪

下面是三份别人提交的"问题采集记录"。请你先自己判断每一份错在哪里，再看后面揭晓的答案——这是检验你是否真正理解前面几节内容的好方法，而不只是"记住了结论"。

| 典型案例 | 你的判断（先自己想一想） |
|---|---|
| 登记表"异常情况说明"一栏写的是"已完成"，但实际提交的10张图里有1张明显模糊 | ？ |
| 命名为"1.jpg、2.jpg、3.jpg"，看起来"挺规范"（都是数字） | ？ |
| 10张图片中有2张分辨率不同于其余8张，登记表"规格是否达标"一栏直接打勾"达标" | ？ |

**答案揭晓**：

1. 异常说明没有如实反映实际情况，记录与操作脱节，失去了可追溯的意义——这正是第六节反复强调的问题。
2. 看起来是数字编号，但缺少类别前缀，下游按类别批量处理的脚本仍然无法识别这批文件属于哪一类——这正是第三节讲的"命名规则看起来是小事"的具体体现。
3. 没有真正核对规格就填写登记表，登记表沦为走形式——这比"漏填"更危险，因为它给人一种"已经检查过"的假象。

如果这三条你都能在看答案之前自己判断出来，说明前面几节的机制你是真的理解了，而不只是记住了结论本身。

## 八、举一反三：音频、日志场景怎么自检

今天练的是图像采集。但你以后的工作里还会遇到音频采集（比如录客服通话）、日志采集（比如导出系统运行日志）这些场景。这些场景的"当场自检"要查什么？

| 采集类型 | 对应的质量问题类型 | 识别方式 |
|---|---|---|
| 图像 | 模糊、过曝、分辨率不一致 | 人工目测 + 代码查规格 |
| 音频 | 底噪过大、截断（没录完就停了） | 当场回放试听 |
| 日志 | 字段缺失（如时间戳为空） | 当场抽样核对字段是否齐全 |

这三类问题表现形式完全不同，但背后是同一个原则：

> **迁移规则**：不管采集什么类型的数据，"当场自检、当场重采"这个工作习惯是通用的——**变的只是检查清单的具体内容，不变的是"不等上传之后才发现问题"这条原则。**

试着问自己一个问题：如果你负责录制客服通话音频，你会把哪几项加进自己的采集自检清单？把答案写下来，和上表对照一下。

## 九、本课小结

| 要点 | 一句话 |
|---|---|
| 采集前提 | 确认用途、授权、口径三件事，做在动手采集之前 |
| 采集中 | 按规格要求做（分辨率/采样率/格式/命名），命名不规范会把问题转嫁给下游 |
| 采集后 | 当场自检（分辨率/清晰度/命名/重复），发现问题当场重采 |
| 核心习惯 | 登记表异常说明写具体现象，不写"已完成"这类结论性套话 |
| 核心原则 | 代码能可靠查客观问题（分辨率/命名/重复），主观视觉问题（模糊/过曝）必须人眼当场查 |

**整课核心习惯一句话**：采集不是"按一下快门"这一个动作，而是"想清楚三件事→按规格采集→当场自检→如实登记"这一整套流程。

## 考点清单

| 考点 | 考试怎么考 | 易错点 |
|---|---|---|
| 采集前三件事 | 单选 | 遗漏其中一项，尤其容易漏掉"授权范围" |
| 数据来源渠道 | 单选 | 把"传感器/设备采集"和"业务系统导出"混淆 |
| 采集口径的具体内容 | 单选 | 误把"标注员联系方式"这类无关项当作采集口径的一部分 |
| 采集质量问题类型 | 单选/实操 | 分不清分辨率不一致、模糊、过曝三者的现象与成因 |
| **当场质检习惯** | 实操 | **采集完直接提交，不做自检** |
| 当场自检的成本优势 | 单选/判断 | 低估"事后处理"的真实代价，以为大不了重拍一次 |
| 采集设备/规格选择依据 | 单选 | 误以为"价格低/外观好看"是选择依据，而非"满足给定规格要求" |
| 命名与归档记录 | 实操 | 命名不规范、登记表异常说明写"已完成"而非具体现象 |

对应实操试题 **五-1（商品图像原始数据采集与归档）** 的评分要点：分辨率一致性检测正确（5分）、命名规范检测正确（5分）、重复图像检测正确（5分）、处理措施针对性合理（哪些需重采、哪些可规则化处理，10分）。

## 自测练习

读完全部正文后，不看前面的内容，尝试独立回答下面 5 道题，再对照答案检查。

**练习 1**：采集现场发现一张照片因光线过强导致画面几乎全白，该怎么处理？

**答案**：这属于过曝问题，应当场重新拍摄（调整光线或拍摄角度），而不是提交这张质量不合格的照片期待后续环节处理——过曝丢失的图像细节是无法通过后期处理完全恢复的。

**练习 2**：为什么说"采集质量问题最大的代价不是要重做，而是很多时候根本没法重做"？

**答案**：因为采集现场往往是一次性的——光线条件、拍摄场景、设备状态等因素一旦改变，很难完全还原当时的采集条件。如果等到上传之后、离开现场很久才发现采集质量问题，往往已经无法重新采集一模一样的内容，只能将这批数据作废，造成比"当场重拍"大得多的损失。

**练习 3**：采集前必须确认的三件事是什么？

**答案**：数据用途（采集来做什么）、授权范围（是否有合法采集授权）、采集口径（字段定义、时间范围、抽样规则是否明确）。这三件事没确认清楚就开始采集，后续处理和使用都可能出问题。

**练习 4**：采集质量当场自检应该检查哪些项目？

**答案**：分辨率是否符合要求、是否清晰（无模糊、无过曝）、命名是否规范、有无重复采集。这四项是采集完成后应立即核查的基本清单，发现问题当场处理比事后处理成本低得多。

**练习 5**：常见的数据来源渠道有哪些？

**答案**：用户行为日志、业务系统导出、传感器/设备采集、第三方采购、公开数据集等。不同来源渠道对应不同的采集方式和合规要求，采集前需要明确具体来源及其授权情况。
