## 一、计算机基础操作——容易被忽略，却决定后面顺不顺

在学Excel和Python之前，先过几个最基础、但天天要用、而且会直接影响后面学习是否顺利的操作。

### 1. 文件与目录管理

新建文件夹、重命名、移动、批量选择——这些操作本身不难，难的是养成**"分类存放"**的习惯：比如按日期建子文件夹、按任务建子文件夹，而不是把所有文件都堆在桌面或下载目录里。

为什么这个习惯值得特别强调？因为它会**直接影响你后面用Python读取文件时顺不顺利**。Python读取文件要写路径，如果你的文件到处乱放、文件夹层级混乱，你自己都不知道某个文件具体在哪一层目录下，写路径的时候就容易出错——这正是后面"读报错"一节会讲到的高频报错 `FileNotFoundError` 的根源之一。换句话说，今天养成的文件管理习惯，是在为几十分钟后排查报错做铺垫。

### 2. 压缩解压

`.zip`/`.rar` 格式的压缩与解压是基本操作。这里有一个小习惯值得提前养成：**解压后先看一眼里面的文件结构，再决定下一步怎么处理**，不要解压完就直接开始操作而不确认文件在哪一层。很多实操考核会把数据包以压缩包形式下发，解压路径找错，后面所有操作都会跟着出错。

### 3. 编码格式识别与转换

打开一个 `.csv` 文件，发现里面全是乱码（比如中文变成一堆问号或奇怪符号）。这时候第一反应该是什么——"文件坏了"，还是别的原因？

**正确答案是：大概率不是文件坏了，而是编码不匹配。**

机制是这样的：文件保存时会按照某一种字符编码规则（比如GBK）把文字转换成一串二进制数据存起来；你打开文件时，软件要按某种编码规则把这串二进制数据"翻译"回文字。如果软件翻译时用的编码规则（比如默认尝试UTF-8）跟文件当初保存时用的编码规则（GBK）对不上，就相当于**拿错了一本字典去翻译一段文字**，翻出来自然是乱码。

遇到这种情况，可以用记事本或Excel的"打开方式"手动指定编码重新打开，常见的两种编码是 `GBK`（很多国内老系统、旧版Excel导出的文件常用）和 `UTF-8`（更通用，尤其是跨平台场景）。

> **这里先埋一个伏笔**：这个"编码对不上导致乱码"的机制，和后面Python报错里的 `UnicodeDecodeError` 是同一件事的两种表现形式——一个是在Excel/记事本里看到乱码，一个是在Python里直接报错中断。理解了这里，后面那个报错你会秒懂。

## 二、Excel核心函数与数据透视表——为什么不能只靠"眼看手数"

### 先回答一个问题："数"出来的效率有多差

设想给你一张260行的门店销售表，让你数一下"已完成"状态的订单有多少条，你打算怎么数？

多数人的第一反应是肉眼一行行扫描数数，或者用Ctrl+F搜索再数。**行数一多，这种做法大概率会数错**——眼睛容易重复数或漏数，而且表只要一改动（比如又新增了几条订单），就得从头再数一遍，之前数的全部作废。

这正是函数存在的意义：**把重复性的条件判断、计数、查找这类工作交给电脑去做，电脑不会累、不会漏，表格改了也能一键刷新结果。**

### 四个核心函数，各自回答什么问题

| 函数 | 作用 | 回答的问题 |
|---|---|---|
| `IF` | 条件判断 | "满足条件该归到哪一类？" |
| `COUNTIF` | 按条件计数 | "符合条件的有几个？" |
| `SUMIF` | 按条件求和 | "符合条件的加起来是多少？" |
| `VLOOKUP` | 按条件查找匹配值 | "这个编号对应的是什么？" |

配合数据透视表，可以完成大部分日常数据整理归类与汇总任务，这也是五级初级工阶段最核心的办公软件技能。

> **判别口诀**：COUNTIF和SUMIF最容易被记混。记住——**问"有几个"用 COUNTIF，问"加起来是多少"用 SUMIF，问"对应的值是什么"用 VLOOKUP。** 别死记函数名，记它们各自回答的是哪一种问题，自然就不会用错。

### VLOOKUP为什么是这四个里最容易出错的一个

因为它的查找区域必须**锁定**。你写好一条VLOOKUP公式后，通常要往下拖拽填充到很多行，如果忘了给查找区域加 `$` 符号（绝对引用），这个查找区域会跟着每一行悄悄往下偏移——第一行查的是A2:B100，拖到第二行可能变成A3:B101，查出来的值全是错的，甚至直接报 `#N/A`。

这是Excel实操中最高频的一类报错来源，几乎每个新手都会踩一次。记住这个坑：**下拉填充VLOOKUP之前，先检查查找区域是不是已经按 `F4` 键锁定成了绝对引用。** `F4` 是Excel里在"相对引用"和"绝对引用"之间快速切换的快捷键，选中公式里的区域部分按一下就能加上 `$`。

另外两个常见小坑一并提醒：
- `COUNTIF` 的条件如果是文本（比如要统计"已完成"这个状态有多少条），一定要加英文引号，写成 `COUNTIF(区域,"已完成")`，漏了引号会出错或结果不对；
- 用数据透视表汇总时，如果只拖了一个维度（比如只拖了"门店"），结果只能回答"每个门店汇总是多少"这一个问题，如果你真正想问的是"门店×月份"的交叉结果，必须把两个维度都拖进去，否则相当于白做。

### 数据透视表解决的是什么问题

如果你要同时按"门店"和"月份"两个维度交叉汇总销售额，用SUMIF得为每一个"门店×月份"的组合单独写一条公式——比如20个门店×12个月，理论上要写240条公式，表一改字段（比如又加了个"产品类别"维度）就要重写一遍。

数据透视表不需要写公式——**把字段拖到行、列、值三个区域，它自动帮你交叉汇总；改变字段摆放的位置，就能立刻重新汇总出另一种视角的结果。** 这就是它比手写一堆SUMIF组合更高效的根本原因：它把"换个角度看数据"这件事，从"重写公式"变成了"拖一下鼠标"。

### 动手练一练（建议现在就打开Excel/WPS操作一遍）

找一份含"门店、月份、订单状态、销售额、负责人"等字段的销售流水表（没有现成的可以自己简单造几十行），尝试：

1. 用 `COUNTIF` 统计每个门店的订单数；
2. 用 `SUMIF` 统计每个门店的销售额合计；
3. 用 `VLOOKUP` 为每条订单匹配门店负责人姓名（记得锁定查找区域）；
4. 用数据透视表按"门店×月份"交叉汇总销售额。

做完这四步，再对照上面的"常见小坑"自查一遍，尤其是VLOOKUP有没有出现 `#N/A`。能独立完成这四步，说明这一节的内容已经过关。

## 三、Python环境搭建——环境变量和命令行到底是什么

这是整节课最容易让零基础学员发怵的部分，但也是最重要的部分——后续60学时所有实操课题都建立在这个环境之上。请放慢速度，一步一步来，每完成一步就自己验证一下再往下走，不要一口气装到底再回头查错。

### 两个让人发怵的词，先用类比理解

**命令行**，就是不用鼠标点图标，直接打字告诉电脑"做什么"的一个窗口——比如不点Jupyter的图标，而是在命令行里打字输入 `jupyter notebook` 回车，效果完全一样，只是换了一种"发指令"的方式。你可以把它理解成：平时你是"用手指点菜单"，命令行是"直接说出你要的菜名"，菜还是那道菜，只是沟通方式变了。

**环境变量**里有一项叫 `PATH`，可以把它想象成电脑的一张**"查找清单"**：你在命令行输入 `python`，电脑不会凭空知道"python"是什么，它会按照PATH这张清单上登记的若干个文件夹路径，一个一个去找，看有没有一个叫 `python.exe` 的文件。**如果你安装Python时没有勾选"Add Python to PATH"，这张清单里就没有登记Python的安装路径，电脑压根不知道去哪个文件夹里找 `python.exe`，于是输入 `python` 要么报错，要么跳到意想不到的地方。**

### 一个真实的坑：输入python却跳到了应用商店

Windows系统本身会预置一个"占位别名"——如果你根本没装真正的Python，在命令行输入 `python` 回车，系统会直接把你带到Microsoft应用商店，界面看起来好像"点一下就能装"。

**这不是真的装上了Python，是系统的一个假动作，是个"空壳"。** 如果你遇到这种情况，说明Python要么没装、要么装的时候没把路径登记进环境变量。解决办法：到"设置→应用→高级应用设置→应用执行别名"里，把 `python.exe` 对应的那个开关关闭，然后重新按正规步骤安装一次Python，安装时**重点检查"Add Python to PATH"这个选项有没有勾上**。

> **判别口诀**：输入 `python` 后如果**跳到应用商店**，说明根本没装（或者装的路径没登记进环境变量）；如果**弹出一堆看不懂的红字报错**，说明装是装了，但执行时另有问题（比如某个包没装、文件路径不对）。这是两种完全不同的现象，对应完全不同的排查方向，不要搞混——前者要重新走安装流程，后者要去读报错信息（见下一节）。

### 安装步骤（请跟着实际操作一遍）

1. 打开安装包，**务必勾选"Add Python to PATH"**——这是整个安装过程里唯一一个"一步错、后面全错"的关键选项；
2. 完成安装后，打开命令行输入 `python --version`，能看到版本号就说明这一步通过；
3. 安装 Jupyter 相关依赖（具体安装命令见 `公共资源/环境搭建指南.md`）；
4. 命令行输入 `jupyter notebook`，能自动打开浏览器界面就说明Jupyter装通了。

### 装完发现命令提示"不是内部或外部命令"怎么办

这是第二常见的卡点：安装看起来完成了，但 `jupyter notebook` 命令提示"不是内部或外部命令"。大概率原因和前面一样——**安装时漏勾了"Add Python to PATH"选项，环境变量清单里没登记这条路径**。解决办法是按前面的步骤重新走一遍安装，这次重点盯住那个勾选框。

### 为什么要用"专门的环境"，不直接装进系统默认环境

这是个容易被忽略但很重要的概念。不同项目依赖的包版本可能互相冲突——比如本课程要求 `pandas` 锁定在 2.x 版本，而你以后参与的别的项目可能需要 3.x 版本。如果所有项目都装进同一个系统默认环境，版本一冲突，新装的包就可能把旧项目依赖的版本覆盖坏，导致旧代码突然跑不通，而你根本不知道是哪次安装把它弄坏的。

**所以要用 conda / venv 这类工具建一个"隔离的工具箱"，每个项目用自己的工具箱，互不影响。** 本资料统一使用名为 `aitrainer` 的独立环境，已验证版本为 Python 3.11、pandas 2.x、scikit-learn 1.x。**请按照环境搭建指南装，不要自己手贱升级版本**，尤其不要把pandas升到3.x——因为3.x的默认行为和2.x有差异，同一段代码在两个版本上可能跑出不同的结果，这会让你在对照本资料的代码和答案时产生莫名其妙的出入。

安装完成后，核心使用流程是：**安装Python → 安装依赖包 → 打开Jupyter Notebook → 运行代码**。

### 验证是否装对了（装完务必运行这一行）

```bash
python -c "import sys, pandas, numpy, sklearn, matplotlib, PIL, openpyxl; print('python', sys.version.split()[0])"
```

把这行代码在命令行里原样粘贴运行。能看到类似 `python 3.11.x` 的输出且没有任何报错，就说明环境是通的，六个常用包（pandas、numpy、sklearn、matplotlib、PIL、openpyxl）都装好了。如果报错，说明某个包没装成功，先看报错最后一行写的是哪个包的名字（下一节会详细讲怎么读）。

> **核心句小结**：环境变量PATH = 电脑找命令时翻看的一张清单；命令行 = 打字代替点鼠标。

## 四、常见报错怎么看——报错不是惩罚，是地图

装完环境、写代码的过程中，报错是家常便饭，不是出事故。这一节要训练的，是"遇到报错先读、再查"的习惯，而不是"遇到报错就慌、就求助、就想重装"。

### 三类最常见的报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError` | 包未安装 | `pip install` 对应包名 |
| `FileNotFoundError` | 文件路径或工作目录不对 | 核对相对/绝对路径 |
| `UnicodeDecodeError` | 编码格式不匹配 | 尝试指定 `encoding="gbk"` 或 `"utf-8"` |

把表背下来没有用，重要的是理解**为什么会出现这些报错**：

**`ModuleNotFoundError`**：Python执行 `import` 语句时，会去**当前激活环境**的包安装目录里找这个名字的模块，找不到就报错。这里有个最容易被忽视的坑——最常见的原因往往**不是真的没装这个包**，而是**装到了别的环境里**。比如你有好几个Python环境，装包的时候命令行提示符前没有显示 `(aitrainer)` 这个环境名，说明你当时激活（切换）到的是别的环境，包装进了别处，而你运行代码时用的却是 `aitrainer` 环境，自然找不到。**排查第一步永远是先确认当前激活的是哪个环境**，而不是急着重复 `pip install`。

**`FileNotFoundError`**：Python读取文件用的是**相对当前工作目录**的路径，而"当前工作目录"不一定是你以为的那个文件夹——这才是报错的真正原因，并不一定是文件真的不存在。排查时先确认代码实际运行时的工作目录在哪（比如Jupyter Notebook的工作目录通常是启动它时所在的文件夹），再核对文件路径写得对不对。回想前面"文件与目录管理"一节提到的——文件分类存放的习惯好不好，直接决定了你这里排查起来是轻松还是痛苦。

**`UnicodeDecodeError`**：文件在保存时用了某一种编码方式（比如GBK），而你读取时让Python按另一种编码方式（比如UTF-8）去解析——机制上相当于"拿错误的字典去翻译一段文字"，自然读不通，于是报错或者显示乱码。这正是前面"编码格式识别与转换"一节埋下的伏笔：Excel里看到的是乱码（软件悄悄地、错误地"翻译"给你看），Python里看到的是直接报错并中断（Python更"诚实"，翻译不通就不往下走了）。本质是同一件事。

### 一个变式练习：PermissionError

再给你一个新的报错类型，不直接告诉你原因，自己想一想：如果代码提示 `PermissionError`，说文件写不进去，可能是什么原因？

真实常见的原因是：**该文件正在Excel（或别的软件）中被打开着，占用了写入权限**。Python想往这个文件里写数据，但操作系统不允许两个程序同时抢占同一个文件的写入权限，于是报错拒绝。遇到这种情况，先去检查这个文件是不是还开着一个Excel窗口没关，关掉再重新运行代码即可。

这个练习的意义在于：**报错类型不会只有书上写的这三种**，但排查的思路是相通的——先定位报错类型（最后一行的 `XxxError` 是什么），再结合常识推理这类错误通常由什么原因引起。

### 正反对比：读不读最后一行，差的不只是几分钟

同一个 `FileNotFoundError`，两种应对方式的差距：同学A一看见报错就直接举手求助，等了5分钟才有人来看；同学B自己翻到最后一行，发现是路径写错了一个字母，10秒自己改好继续做题。

**同样的报错，有没有掌握"先看最后一行"这个方法，差的是分钟级别的效率——在有时间限制的实操考核里，这个差距会被放大成好几道题的分差。** 这不是夸张，是真实的考场逻辑：排查一个报错多花5分钟，可能就是少做完一道实操题。

> **读报错的核心方法**：Python报错信息通常最后一行是最关键的（错误类型+简要原因），不要被前面一长串红色文字吓到，**先看最后一行**，再结合报错里提到的文件名、模块名、行号等具体信息去定位问题。

## 随堂练习（自测）

建议先自己想清楚答案再往下看，检验学习效果。

**练习 1**：运行代码时出现 `FileNotFoundError: [Errno 2] No such file or directory: 'data.csv'`，该怎么排查？

**答案**：检查当前工作目录是否与data.csv文件所在目录一致，或改用绝对路径指定文件位置；也可能是文件名拼写错误或扩展名不符。

**练习 2**：运行代码提示 `ModuleNotFoundError: No module named 'pandas'`，该怎么解决？

**答案**：说明pandas这个包还没有安装，在命令行执行 `pip install pandas` 安装后再运行。注意要确认当前激活/使用的是正确的Python环境，否则可能装到了别的环境里，运行代码时还是提示找不到模块。

**练习 3**：打开一个中文CSV文件时出现乱码或 `UnicodeDecodeError`，该怎么处理？

**答案**：多数情况是编码格式不匹配，可以尝试在读取时指定编码参数，比如 `encoding="gbk"` 或 `encoding="utf-8"`，如果一种不行就换另一种尝试。也可以在保存文件时统一使用"UTF-8 with BOM"（即utf-8-sig）编码，避免Excel等软件打开时乱码。

**练习 4**：Excel的VLOOKUP函数和COUNTIF函数分别用来做什么？

**答案**：VLOOKUP用来按条件在另一张表或区域中查找匹配的值（如根据商品编号查找对应的商品名称）；COUNTIF用来统计满足特定条件的单元格数量（如统计某一列中某个值出现了多少次）。两者都是数据整理归类汇总时的常用函数。

**练习 5**：遇到报错信息一大段看不懂的红色文字，正确的心态和做法是什么？

**答案**：不要被一长串文字吓到，先看报错信息的最后一行——这通常包含了最关键的错误类型和简要原因（如ModuleNotFoundError、FileNotFoundError等）。根据最后一行的信息类型，再结合报错提到的文件名、模块名等具体信息去排查，而不是一看到报错就直接放弃。
