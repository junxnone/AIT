## 学习目标

学完本课题，你应该能做到：

1. 能说明标注交付前须完成的自检项——**数量完整、格式合规、标签取值合法、文件对应关系正确**，并能说出每一项如果不做会造成什么具体后果，而不是只会背四个名词。

## 一、交付前自检四项——不是走形式，每一项都有真实代价

标完不等于能用。交付前至少要做四项自检，少一项都可能让问题悄悄漏进最终的训练数据里：

| 自检项 | 含义 | 如果不做，会怎样 |
|---|---|---|
| 数量完整 | 实际标注条数是否等于应标注的任务总量 | 比如本应标400条，实际只交了397条，少掉的3条样本永远不会进入训练集，模型在这类样本对应的场景上"没学过"，上线后遇到类似情况就可能判断失误 |
| 格式合规 | 字段名、文件编码、文件格式是否符合约定 | 字段名写错一个字（如把"情感标签"写成"情绪标签"），下游程序按约定字段名读取数据时会直接报错或读出空值，整批数据可能被判为无效 |
| 标签取值合法 | 标注值是否都落在规范定义的范围内 | 出现规范外取值（本课题后面你会亲手发现两种），模型训练时会把这些取值当成合法类别一起学进去，污染模型的输出空间 |
| 文件对应关系正确 | 标注记录与原始数据样本是否一一对应、没有错位 | 如果标注ID对应错了评价ID，标注内容就会"驴唇不对马嘴"——标的是这条评价的情感，却被错误地关联到另一条评价上，这种错误在人工抽查时也很难一眼看出来 |

> 📌 **判别句**：**"标完"只说明动作做了；"自检"才能确认结果能不能用。** 这四项里任何一项没做，哪怕数据表面上看起来完整，也不能算真正完成交付准备。

**先别往下看，自己想一下这个追问**：如果只做了前三项，漏了"文件对应关系正确"这一项，可能会造成什么后果？

答案：标注内容和原始评价内容可能错位对应——标的明明是这条评价的情感，却被挂到了另一条评价上。这种错误光看标注表格本身看不出来（标签取值可能完全合法、数量也完整），必须核对ID对应关系才能发现，所以极容易被漏掉。

## 二、先分类、再统计——国标两句话里藏着的顺序逻辑

国标对本课题的技能要求写的是两句话：**能利用分类工具进行分类，能利用统计工具进行统计。** 注意顺序——分类在前，统计在后，这不是随便排的。

**为什么必须先分类？** 因为统计是在某个"集合"上做计数。如果不先分类，你面对的永远是混在一起的400条记录，很难看出规律。**分类就是先把数据按某个维度切成几个互不重叠的小堆，统计才是在每一小堆或整体上数数、算占比。** 打个比方：**分类是"切"，统计是"数"——维度切错了，数字再准也看不出问题。**

### 常见的三个分类维度

| 分类维度 | 本课题中的例子 |
|---|---|
| 按标签 | 把400条记录按情感标签切成"正面""负面""中性"……几个子集 |
| 按批次 | 按任务下发时间切分，确认这批数据是否来自同一次下发，有没有混入其他批次的历史数据 |
| 按质量状态 | 把记录切成"合规""规范外""空值"三类，分别决定下一步动作 |

**举个反例感受一下"不先分类直接统计"的后果**：假设这批数据是分两次下发的，第一批200条、第二批200条。如果混在一起直接统计某标注员的完成量，你只能看到"A标注员一共标了90条"，却看不出是两批都正常、还是第一批标了80条而第二批只标了10条——后一种情况意味着第二批可能存在任务分配或效率问题，但混在一起统计会把这个信号完全盖住。**这就是为什么分类要先于统计——分类分得对，统计出来的数字才有意义。**

### 动手把数据按质量状态分类

```python
import pandas as pd
d = pd.read_csv("../数据集/labeled_results.csv")

valid = {"正面", "负面", "中性"}
d["质量状态"] = d["情感标签"].apply(
    lambda x: "空值" if pd.isna(x) else ("合规" if x in valid else "规范外")
)
print(d["质量状态"].value_counts())
```

把这批数据按"情感标签是否在规范范围内"分成三类，结果可以直接由下一节的统计数字相加得出：合规 348+28+12=**388条**、规范外 5+4=**9条**、空值**3条**。三者相加 388+9+3=**400**，正好等于总记录数——**这说明分类覆盖了全部记录，没有遗漏，这也是"数量完整"这项自检在分类环节的一次具体验证。**

分类之后，**每一类都要有明确的下一步动作**，而不是堆在那里不管：

| 质量状态 | 条数 | 下一步动作 |
|---|---|---|
| 合规 | 388 | 直接计入最终的标签分布统计，可交付 |
| 规范外 | 9 | 导出清单，交标注组长核查来源（工具漏洞还是标注员理解偏差） |
| 空值 | 3 | 核实是漏标，还是原始评价本身就是空文本，分别处理 |

> 🔑 **判别口诀**：分类不是为了分而分，**每切出一类，就要能回答"这一类接下来该怎么处理"**——答不上来，说明这个分类维度选错了，或者分类本身还没做完整。

再顺手按批次分类检查一下：

```python
print(d["任务下发时间"].nunique())
```

结果是 **1**——说明这400条记录的任务下发时间全部相同，确认这批数据来自单一批次，没有混入历史数据。这种"按批次分类再核验"的动作平时很容易被忽略，但一旦真的混入了旧批次数据，后果和"规范外取值"一样，会让统计结果失真。

## 三、一个会教你"从数字里看出问题"的案例

现在回到开篇那个判断题。打开代码环境，对这400条真实标注结果做统计，看看"能直接交付"这个直觉判断站不站得住脚：

```python
import pandas as pd
d = pd.read_csv("../数据集/labeled_results.csv")
print("情感标签分布:", d["情感标签"].value_counts(dropna=False).to_dict())
print("标注员完成量:", d["标注员"].value_counts().to_dict())
```

**实测**：共400条记录。

**情感标签分布**：正面348、负面28、中性12、**"中性偏正"5条**、**"3"4条**、空值3条。

**标注员完成量**：A02完成120、A01完成99、A03完成90、A04完成84、**A05仅完成7条**。

**先别往下看，自己想一下：盯着这两组数字，你能发现什么问题？**

给自己一点提示：合规的标签本该只有"正面、负面、中性"三种，这组分布里有没有超出这三种的取值？再看标注员完成量，有没有哪个数字和其他人明显不在一个量级上？

把两条线索分别挑出来看：

1. **"中性偏正""3"是规范外的标签取值**——规范里应该只有"正面/负面/中性"三选项，这两种取值说明标注工具可能存在输入校验漏洞，或标注员对规范理解有偏差，**需要核查这些记录的来源**。
2. **A05完成量仅7条，远低于其他人的84-120**——这不是正常的个体差异，很可能是任务分配出了问题（比如系统分配给A05的任务量本身就异常少）、设备故障、或A05出勤异常，**需要上报核实**，而不是简单地把这7条数据当正常情况处理。

### 为什么自检环节没发现，统计环节才暴露出来

这是个值得想一想的问题。"标签取值合法"明明是自检四项之一，为什么这两处规范外取值没有在自检时被挡下来？

**机制**：自检通常是抽查几条记录，而"中性偏正""3"这两种取值加起来只占总数的 (5+4)/400 ≈ **2.25%**。随手抽查20条，抽到这9条里任何一条的概率都很低，很容易被漏过去。**只有做全量的分类统计、把完整的取值分布摆出来看，这类小比例的异常才会稳定地显现。** 这就是为什么"分类统计"要作为交付前单独的一道工序，而不能指望自检环节顺带发现——**自检解决的是"有没有"，统计解决的是"分布正不正常"，两者缺一不可。**

### 回到开头的判断

现在回答第一节那个问题：**这批数据能直接交付吗？**

**不能。** 至少有9条规范外标签记录和A05的完成量异常需要先核实清楚，才能决定哪些数据能进入最终交付的数据集。"数量够了、文件也在"只是自检的一部分，**分类统计揭示的问题，自检的粗略检查根本看不到。**

> 📌 **核心能力**：统计不是算完数字就结束了。**要带着"这个数字正常吗"的疑问去看统计结果**，异常往往就藏在一个看起来不起眼的数字里。这是本课题、也是整个"数据标注"模块收官要沉淀下来的核心职业习惯：**算出数字只是第一步，审视这个数字是否正常才是训练师的价值所在。**

## 四、产出一份完整的标注后数据统计报表

统计发现了异常、分类理清了处置动作之后，这份工作不能只停在你自己脑子里"心中有数"，而要落地成一份别人也能看懂、能据此行动的报表。一份合格的标注后数据统计报表应覆盖五个部分，**不能只有数字**：

```
一、任务基本信息（任务名称、下发时间、应标注总量）
二、标签分布统计（各标签数量 + 占比）
三、标注员完成量统计
四、异常清单（规范外标签取值记录 / 完成量异常的标注员）
五、处理建议（对应每类异常，给出具体下一步动作）
```

自己动手写这份报表时，对照下面三条自查，这也是实操评分里真正会扣分的地方：

- **"二、标签分布统计"是否同时给出数量和占比**，不能只写数量（比如只写"正面348条"而没写占比，不符合"报表应包含数量与占比"这条考点要求）。
- **"四、异常清单"是否把具体记录列出来**（如规范外取值对应的标注ID、异常标注员的编号），而不是只写一句笼统的"有异常"。
- **"五、处理建议"是否逐条对应异常清单**，不能空着或只写"需要关注"这种空话——要写成"导出规范外记录交组长核查""上报A05所在小组核实出勤"这样具体可执行的动作。

另外别忘了把"一、任务基本信息"写完整：前面核验过这400条数据的 `任务下发时间` 只有一个值，说明来自单一批次，这也应该写进报表里，作为数据来源核验的一部分。

## 五、变式检验：统计结果"看起来很均匀"就一定没问题吗

前面的例子里，异常是靠"规范外取值""完成量偏低"这种明显的反差暴露出来的。但真实场景不会总是这么配合——下面这个变式题专门检验你是不是真的理解了"发现异常"的本质，而不是只记住了这一组具体数字。

**先别往下看，自己判断一下**：假设换一批数据，标签分布变成正面、负面、中性各占三分之一左右，每个标注员完成量也都在95-105条之间，看起来非常均匀——这批数据是不是就一定没问题了？

如果你的第一反应是"是的，分布均匀、完成量接近，说明大家都认真标了"——这正是一个常见的误判，往下看就知道漏洞在哪。

**追问**：如果有标注员图省事，不认真看评价内容，就按"正面、负面、中性"的固定顺序循环打标签呢？统计出来的分布和完成量会是什么样？——答案是：**照样会呈现"均匀、接近"的样子**，因为循环打标签本身就会制造出看起来很规整的分布。

**结论**：均匀的统计结果**不能单靠数字本身**证明标注是认真做的，还需要抽样人工复核几条具体内容，看标签和评价内容是否真的匹配。这和前面"标完≠能用"是同一个道理——**统计结果好看，只是通过了一道检查，不代表所有问题都没有了。**

> 🔑 **判别口诀**：异常不一定表现为"数字难看"，**数字"好看得过分、规整得不自然"同样值得警惕**——统计是发现问题的第一道关卡，不是唯一的一道。

## 自测练习（可直接核对答案）

**练习 1**：统计标注完成情况时发现某个标签的占比达到90%，其他正常项目里该标签占比通常在30%左右。这说明什么？

**答案**：可能存在异常，需要进一步核查：是否该批数据本身这个标签确实占主导（有合理业务原因），还是标注员为求省事把大部分样本都标成了这个"默认"或"保险"选项（即标注质量问题）。不能简单接受这个统计结果，应抽样复核验证。

**练习 2**：标注交付前的四项自检分别是什么？

**答案**：数量完整（标注数量是否齐全，有没有漏标）、格式合规（文件格式、字段命名是否符合要求）、标签取值合法（标签是否都在规范定义的范围内，没有多余的奇怪取值）、文件对应关系正确（标注文件和原始数据文件是否一一对应，没有错位）。

**练习 3**：发现某标注员完成量远低于其他人，正确的态度是什么？

**答案**：不能直接忽略这个数字，也不能简单认为"这个人效率低"，而应该核实具体原因——可能是任务分配系统出了问题、设备故障，或者该标注员存在出勤异常，这些都需要上报核实，而不是想当然地接受这个异常数字。

**练习 4**："标注依据取值出现规范外的内容（如本该是三类标签却出现了第四种取值）"，这说明什么，该怎么处理？

**答案**：说明标注工具可能存在输入校验漏洞，或者标注员对标注规范的理解存在偏差。应该核查这些规范外取值的具体记录来源，必要时修正为正确的标签取值，并视情况加强标注工具的输入限制或补充标注员培训。

**练习 5**：为什么说"统计不是算完数字就结束了"？

**答案**：因为统计数字本身只是客观计算结果，真正的价值在于审视这些数字是否符合预期、是否隐藏着异常信号。如果只是机械地算出数字就提交，很可能让规范外标签取值、任务分配异常等真实存在的问题被忽略过去，错失发现和纠正问题的机会。
