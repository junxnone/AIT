## 读完本课题你应该能做到什么

### 知识目标
1. 能说出数据清洗的**五大目标**：去重、去缺失、去异常、去噪声、统一数据格式。
2. 能说明**清洗为什么必须排在标注之前**——清洗是在给标注员"收拾桌子"，越早清洗，后面标注、质检环节返工成本越低。
3. 能说明**清洗必须按既定规范执行、并保留原始数据**——清洗是不可逆操作，不能直接覆盖原文件。

### 技能目标
1. **文本清洗**：会做去重、去空、去乱码、去HTML标签与表情符号、统一编码、过滤超长/超短样本、敏感信息替换。
2. 能用pandas完成结构化与文本数据的自动化清洗，并输出清洗后文件与清洗记录。
3. **视觉清洗**：能识别损坏/重复/模糊/过曝图像，统一分辨率与格式，核对图像与标注文件的对应关系。
4. **语音清洗**：能说明静音/截断/底噪过大音频的识别依据，统一采样率与格式，核对音频与文本的对应关系。
5. 能正确执行"另存为新文件"的操作，不覆盖原始数据。

### 职业素养
1. 建立"**清洗有边界**"的意识——删得多了会丢失真实信息（清洗过度），删得少了噪声会污染训练数据（清洗不彻底），两者都是失职。
2. 建立"**不同数据模态的清洗逻辑不能照搬**"的意识——结构化文本能靠代码精确判断的结论，换到图像、语音这类非结构化数据上未必成立，必须结合人工核验。

## 一、先搞清楚"为什么"：清洗目标与它在流程中的位置

数据标注这个职业功能下的第一步工作，**不是标注，是清洗**。这里有一个值得你先想清楚的问题：为什么清洗必须排在标注之前，而不是先标注、标完了再清洗？

设想两种情况：

- 如果一条**重复记录**没有提前清洗掉，标注员会把它当成两条不同样本各标一遍，工时直接浪费一倍。
- 如果一条评价里混着 `<br>` 这种**HTML标签**没清理，标注员盯着这种夹杂标签的文本判断情感时，注意力会被干扰，甚至可能把标签当成文本内容去理解。

**清洗，就是提前把桌子收拾干净，让标注员专心做判断，而不是让他们一边标注一边替你擦桌子。** 这也是为什么清洗工作排在"数据标注"这个职业功能最前面的原因。

清洗要解决的问题可以归纳成五大目标，分别对应数据的五种"不干净"状态：

| 目标 | 要解决的问题 | 不处理的后果 |
|---|---|---|
| 去重 | 同一条记录被重复采集/上传 | 该样本在训练中被过度加权，模型对它过拟合 |
| 去缺失 | 关键字段为空 | 无法支撑后续标注或统计 |
| 去异常 | 字段取值超出合理范围 | 污染统计结果，误导模型学习 |
| 去噪声 | 格式残留、乱码、表情符号等非语义内容 | 干扰标注判断，浪费标注工时 |
| 统一格式 | 编码、全半角、命名规则不一致 | 后续程序处理时被误判为不同类别 |

这五类问题该怎么判断、怎么处理，答案不是"你觉得"，而是**标注规范里写好的既定规则**。这是本课题最基本的纪律：**清洗规则必须按规范执行，不能凭感觉发挥**。这个纪律也是以后更高阶能力"清洗规范制定"的前提——得先有人按统一标准认真执行，才谈得上评估执行得好不好。

> **动手练习**：在继续往下读之前，花1分钟想一个自己熟悉的场景（比如手机相册、聊天记录），对应举出一个"重复/缺失/异常/噪声/格式不统一"的例子。这能帮你确认自己是真的理解了这五个概念，而不是只记住了名词。

## 二、文本清洗实操：长度从来不是判断标准

现在打开 Jupyter，我们用代码把625条评价全部检测一遍，验证开篇那条评价到底有没有问题。

```python
import pandas as pd

df = pd.read_csv("../数据集/reviews_raw.csv")
n_raw = len(df)
s = df["评价内容"].astype(str)

print("总记录数:", n_raw)
print("重复行:", df.duplicated().sum())
print("空/空白评价:", s.str.strip().eq("").sum())
print("含HTML标签:", s.str.contains("<").sum())
print("非法评分:", (~df["评分"].between(1, 5)).sum())
print("极短样本(1-2字符):", ((s.str.strip().str.len() >= 1) & (s.str.strip().str.len() <= 2)).sum())
print("超长样本(>=100字符):", s.str.len().ge(100).sum())
print("含手机号:", s.str.contains(r"1[3-9]\d{9}").sum())
```

**实测输出**（已验证，你跑出来的结果应该与此完全一致）：

```
总记录数: 625
重复行: 25
空/空白评价: 10
含HTML标签: 30
非法评分: 12
极短样本(1-2字符): 14
超长样本(>=100字符): 11
含手机号: 5
```

> **统计口径提醒**：以上每一项都是在原始625条数据上**各自独立统计**的，不是依次过滤后统计的——同一条记录完全可能同时命中多个问题（比如一条评价既重复又含HTML标签）。所以这7个数字加起来并不等于"625减去清洗后剩余条数"。这一点在撰写清洗记录时特别重要：不能把各项数字直接相加当成"总共清洗掉多少条"，否则账会对不上。

现在回到开篇那道判断题。"物流太慢了，等了半个月，联系我 13830093622"——表面上语义完整、没有乱码，但它命中了"含手机号"这一项（本批数据共5条）。**这就是为什么只看"字数够不够、语义通不通"是不够的：必须按完整的清洗规则逐项过一遍，哪怕看起来再正常的文本也不能跳过检测。**

### 长度陷阱一：超长样本不等于认真长评

运行下面这行代码，看看那11条超长样本（≥100字符）里具体写了什么：

```python
print(df.loc[s.str.len() >= 100, "评价内容"].iloc[0][:40], "...")
```

```
好评好评好评好评好评好评好评好评好评好评好评好评好评好评好评好评 ...（共600字，重复堆砌"好评"二字）
```

11条超长样本，**全部**是这种重复堆砌"好评"二字刷出来的600字文本，不是详细认真的长评论。

这里你可能会下意识地想："字数这么多，说明用户写得很用心，别删。" 先别急着下结论，问自己一个问题：**读完这600字，你比读"好评"两个字多知道了什么？** 如果你是标注员，要给这条评价打情感标签，这600字能不能比"好评"两个字提供更多可供判断的信息？答案是不能——这段文本的真实信息量和一个"好评"没有区别。

### 长度陷阱二：极短样本不等于"好歹有内容"

刚才统计的"空/空白评价"是10条，这是完全没写内容的。但还有**14条**，strip之后只剩1到2个字符，比如单独一个"嗯"、一个句号、一个"好"字。

这14条和那10条空白评价看起来很像，但请注意：**它们不是同一类问题**。10条是真的什么都没写；这14条是写了，但内容量几乎为零，不足以支撑标注员做出有依据的判断。

把这两组数据并排放在一起，才能看清本课题最容易踩的坑：

| | 超长样本（11条） | 极短样本（14条） |
|---|---|---|
| 字数 | 600字，看起来"内容很多" | 1-2字，看起来"内容太少" |
| 真实信息量 | **几乎为零**（纯重复堆砌） | **几乎为零**（无实质描述） |
| 新手常见误判 | "这么长肯定是认真写的，别删" | "好歹写了点东西，不算有问题" |

**机制说明**：清洗不是"按字数卡阈值"的游戏。字数只是一个容易拿到的代理指标，真正要判断的是**这条文本有没有真实、独立的语义信息**。600字的刷屏文本，字数虽然达标，但本质和空白文本一样——没有任何可供模型学习的情感表达细节；1-2个字的"嗯""好"，虽然有内容，但信息量同样不足以支撑标注判断。

这正是"清洗过度"和"清洗不彻底"这对难点在这批数据里具体的样子：只按长度简单设一道阈值线，长的一律放过会漏掉刷屏文本（清洗不彻底），短的一律放过会留下无效样本（也是清洗不彻底）；反过来如果看见长文本就不分青红皂白删掉，又会把认真写的详细评论一起误伤（清洗过度）。**清洗规则必须按内容性质设计，而不是按表面长度设计。**

### 含手机号的样本：既不能整条删，也不能放任不管

回到开篇那条评价。手机号这种问题，能不能直接把整条记录删掉？

- 如果**整条删除**：这条评价里的评分、情感倾向这些有效信息也被一起丢掉了——属于清洗过度。
- 如果**原样保留**：用户的真实手机号被暴露给标注员甚至后续所有接触这批数据的人——是数据安全事故。

正确做法是**局部处理**——把手机号替换成占位符，其余内容原样保留：

```python
df["评价内容"] = s.str.replace(r"1[3-9]\d{9}", "[手机号]", regex=True)
```

处理后，"物流太慢了，等了半个月，联系我 13830093622" 变成 "物流太慢了，等了半个月，联系我 [手机号]"——**负面情绪、抱怨物流这些真正要标注的信息完整保留，敏感信息被安全移除。**

> **判别口诀**：遇到"问题文本该怎么处理"，先问——**这条记录除了这个问题之外，还有没有其他有效信息？** 有 → 局部处理（替换/剥离问题部分），不要整条删；没有（如刷屏文本、空白、极短无意义内容）→ 整条剔除。

### 完整清洗脚本

把以上所有判断落实成代码，就是下面这段完整的文本清洗脚本。请自己敲一遍并运行：

```python
df = df.drop_duplicates()
df["评价内容"] = df["评价内容"].astype(str).str.replace(r"<[^>]+>", "", regex=True)
df["评价内容"] = df["评价内容"].str.replace(r"1[3-9]\d{9}", "[手机号]", regex=True)
df = df[df["评价内容"].str.strip().str.len() > 2]          # 剔除空白与极短样本
df = df[df["评价内容"].str.len() < 100]                     # 剔除刷屏式超长样本
df = df[df["评分"].between(1, 5)]

df.to_csv("reviews_cleaned.csv", index=False, encoding="utf-8-sig")
print(f"清洗前 {n_raw} 行 → 清洗后 {len(df)} 行")
```

运行后核对清洗前后的行数变化，确认 `reviews_cleaned.csv` 已经正确生成。

## 三、视觉清洗实操：图像的"重复"不能照搬文本的判断逻辑

文本清洗我们刚刚证明了一件事——重复，用 `duplicated()` 一行代码就能精确抓出来，因为字符串要么完全一样要么不一样，没有中间状态。

图像呢？**能不能也套用同一个思路，算个哈希值，哈希一样就是重复？**

先不要急着回答，我们数据集 `images/` 文件夹里有两组文件名很可疑的文件：

- `phone_000.jpg` 和 `phone_000_copy.jpg`
- `laptop_001.jpg` 和 `laptop_001_副本.jpg`

文件名里的"copy""副本"几乎是在明示"这是重复文件"。**先在心里预测一下：这两组文件的MD5哈希，你猜是相同还是不同？** 预测完再往下看验证代码。

```python
import os, hashlib
from PIL import Image
from collections import Counter

img_dir = "../数据集/images"
files = sorted(os.listdir(img_dir))
print("图片总数:", len(files))

sizes = Counter()
for f in files:
    with Image.open(os.path.join(img_dir, f)) as im:
        sizes[im.size] += 1
print("分辨率分布:", dict(sizes))

suspects = [f for f in files if "copy" in f.lower() or "副本" in f]
print("文件名疑似重复:", suspects)

for f in suspects:
    base = f.replace("_copy", "").replace("_副本", "")
    h1 = hashlib.md5(open(os.path.join(img_dir, f), "rb").read()).hexdigest()
    h2 = hashlib.md5(open(os.path.join(img_dir, base), "rb").read()).hexdigest()
    print(f, "vs", base, "→ MD5相同:", h1 == h2)
```

**实测结果**（已验证）：

```
图片总数: 42
分辨率分布: {(640, 480): 37, (1280, 960): 1, (320, 240): 4}
文件名疑似重复: ['laptop_001_副本.jpg', 'phone_000_copy.jpg']
laptop_001_副本.jpg vs laptop_001.jpg → MD5相同: False
phone_000_copy.jpg vs phone_000.jpg → MD5相同: False
```

**两组文件的MD5都不相同。** 这个结果和大多数人的预测相反——文件名都写明了copy/副本，为什么字节内容会不一样？

原因在于：图像文件的 MD5 是对**整个文件的二进制内容**做哈希，哪怕只是重新用图片软件保存一次、压缩质量调整了1%，哪怕人眼完全看不出区别，底层的字节流就已经不同，MD5 自然也会不同。

如果看到这个结果就直接下结论"哈希不同，说明确实不是重复，可以放心当成两张不同的图"，这一步还为时过早——打开 `phone_000.jpg` 和 `phone_000_copy.jpg` 实际看一下内容（用图片查看器对比），看完之后，这两张还能说"不是重复"吗？从文件名和实际画面看，它们大概率是同一张商品图的两个版本（比如重新保存、压缩、轻微裁切过）。

**这就是图像清洗和文本清洗最根本的区别**：文本的"一样"是字符完全相等，算法能精确判断；图像的"一样"是**看起来一样**，哪怕只是重新保存一次、压缩质量调整一点点，底层字节就会变，哈希自然就不同了。**哈希比对算出来的结果只是一个线索，不是结论。** 遇到文件名高度可疑但哈希不同的情况，必须人工打开图片确认，不能让代码替你做最终判断。

> **判别口诀**：结构化的数据能靠代码"算"出结论（如文本精确匹配）；非结构化数据的清洗，代码算出来的只是**线索**，最终判断往往还要人工"看"一眼才能确认。

### 分辨率不一致：另一个需要统一处理的问题

再看上面代码输出的分辨率统计结果——42张图里，**37张**是标准的640×480，但有**4张**（`laptop_005.jpg`、`laptop_033.jpg`、`watch_011.jpg`、`watch_019.jpg`）只有320×240（标准尺寸的四分之一面积），还有**1张**（`headphone_026.jpg`）是1280×960（标准尺寸的4倍面积）。

这些不统一的分辨率会带来什么问题？如果不统一直接混合使用，后续标注工具里框选同样大小的物体会呈现完全不同的像素尺度，模型训练时也会面对输入尺寸不一致的问题，因此必须在清洗阶段统一缩放到统一规格。

### 视觉清洗完整检查清单

| 检查项 | 做法 |
|---|---|
| 损坏文件 | 用 `Image.open().verify()` 逐张校验能否正常打开（本批次42张实测全部可正常打开，但生产环境中仍必须执行此步骤，不能因为"这批没问题"就跳过） |
| 重复图像 | 哈希/文件名线索 + 人工目验，不能只信哈希结果 |
| 模糊/过曝图像 | 人工抽查或用清晰度算法辅助筛查，剔除无法辨认主体的图片 |
| 分辨率/格式统一 | 统一缩放到规范尺寸，统一保存格式 |
| 图像与标注文件对应关系 | 核对文件名与标注记录是否一一对应，避免错位 |

**自我实操建议**：对42张图片逐一查看分辨率检测结果，列出需要统一处理的文件清单；对2组疑似重复图像打开人工核验，写出核验结论（是否确系同一实物的重复图像，应保留哪一张）。这一步务必自己动手做一遍，光看不做很难真正建立"图像清洗要靠人工目验"这个手感。

## 四、语音清洗要点：无专属数据集，重点建立判断依据

语音和图像一样，都是非结构化数据，清洗时不能靠一行pandas代码扫完。

本课题随发的实操数据集**不包含音频样本**——这是如实说明：音频文件体积大，需要真实录音素材，程序没法合成出有教学意义的音频。这一节重点帮你建立"该检查什么、为什么"的判断依据，实际操练请结合后续课题或授课机构提供的真实音频素材进行。

语音清洗要处理的典型问题：

| 问题 | 为什么必须清洗掉 |
|---|---|
| 静音片段 | 整段没有说话内容，对语音识别/情感模型训练无信息增量，反而会让模型学到"大段静音也是正常样本"这种错误规律 |
| 截断音频 | 录音开始或结束被切断，可能丢失关键语义，若用于转写标注，标注员会面对不完整的信息做判断 |
| 底噪过大 | 背景噪声掩盖了人声，轻则影响转写准确率，重则导致整段无法辨识，必须剔除或做降噪处理后复核 |
| 采样率/格式不统一 | 和图像分辨率不统一是同一类问题——混合不同采样率的音频直接输入模型，会造成特征尺度不一致 |
| 音频与文本对应关系错位 | 语音文件和对应的转写文本因命名或排序问题对应错了，标注员会对着A的录音看着B的文本做判断，产出的是完全错误的数据 |

**自测判断题**（不需要数据集，动脑想一下）：一段10秒的客服录音，中间有2秒是电话另一端的忙音提示音，不是人声。这2秒应该怎么处理？整条录音要不要作废？

先想一下你的答案，再看下面的参考思路。

<details><summary>参考思路</summary>

不是整段音频作废。先判断这2秒是否影响整体语义的可理解性——如果前后8秒的人声内容仍然完整、可辨识，通常的做法是对这2秒做标记说明（如"非人声片段"），而不是因为中间混入了噪声就把整条10秒录音都剔除掉。否则前后8秒完整、能听清楚的人声内容就这么浪费掉了，并不值得。

这和前面文本清洗"含手机号不能整条删除"是同一个道理：**先看问题影响的范围，局部问题局部处理，不要因小失大整条剔除。**

</details>

把这一节和前两节放在一起看，你会发现一个可以跨模态通用的判断依据：**不管是文本、图像还是语音，遇到问题时先问"这个问题影响的范围有多大、除了这个问题还有没有其他有效信息"，再决定是局部处理还是整条剔除。**

## 六、一条铁律：保留原始数据

本课题最后要强调一条不容妥协的规则：

```python
df.to_csv("reviews_cleaned.csv", index=False, encoding="utf-8-sig")   # 正确：另存为新文件
# df.to_csv("reviews_raw.csv", ...)                                    # 错误：绝不能覆盖原文件
```

**清洗是不可逆操作。** 如果直接在原文件上修改保存，一旦清洗规则本身有问题（比如误删了本该保留的样本，或者把"好评"刷屏文本和真实长评论的判断标准搞反了），就再也无法恢复原始数据来重新处理。

**无论是文本、图像还是语音，无论做什么清洗操作，都要先把原始文件保留好，清洗结果另存为新文件。** 这条规则没有例外，请把它当成肌肉记忆。

## 七、本课题核心框架回顾

把本课题的知识点串起来看，贯穿始终的其实是同一个认知陷阱：**表面指标正常 ≠ 真的没问题。**

- 看起来语义完整的评价，藏着手机号；
- 看起来字数很多的评价，其实是刷屏文本；
- 看起来哈希不同的图片，其实是同一张图的重复版本。

清洗工作的核心能力，就是不满足于"看起来没问题"，而是按规范把每一类问题都检测一遍。下一课题讲文本标注实操时，你会发现同样的道理——规范没写到的边界样本，看起来"标哪个都说得过去"，但照样不能凭感觉，要上报。

核心框架总结：

```
                清洗五大目标：去重 / 去缺失 / 去异常 / 去噪声 / 统一格式

流程位置：原始数据 → 【清　洗】 → 标注 → 质检        （先清洗，后标注）

文本清洗实测(625条)：
重复25   空/空白10   极短(≤2字)14   超长(≥100字)11
含HTML 30   非法评分12   含手机号5
→ 11条"好评"刷屏600字 ≠ 认真长评！长度≠真实语义信息

文本去重 vs 图像"去重"：
判断方式    文本=精确匹配(字符完全相等)      图像=文件名线索 + 人工目验
实测对照    df.duplicated()→25条           phone_000/_copy、laptop_001/_副本 → MD5均不同!

铁律：清洗后另存为新文件，绝不覆盖原始数据文件
```

两条贯穿全课题的判别口诀：

1. **问题处理方式判别**：这条记录除了这个问题之外，还有没有其他有效信息？有 → 局部处理；没有 → 整条剔除。
2. **模态判断方式判别**：结构化数据能"算"出结论，非结构化数据的代码结果只是线索，最终还要人工"看"一眼才能确认。

## 自测练习（随堂练习，建议合上前文独立完成后再核对答案）

**练习 1**：为什么清洗后的数据要另存为新文件，而不是直接覆盖原始文件？

**答案**：清洗是不可逆操作。如果直接覆盖原文件，一旦发现清洗规则有误（比如误删了有效数据），将无法恢复到清洗前的状态重新处理。另存为新文件可以保留完整的原始数据作为"后悔药"，也便于后续审计清洗过程是否合理。

**练习 2**：数据清洗的五类目标分别是什么？

**答案**：去除重复、去除缺失、去除异常、去除噪声、统一数据格式。这五类问题是数据清洗要解决的核心内容，不同数据类型（文本/视觉/语音）体现的具体形式不同，但都归属于这五大类。

**练习 3**：文本清洗中，含HTML标签和含emoji表情的文本应该怎么处理？

**答案**：HTML标签通常用正则表达式批量剥离，因为它们是采集过程中的残留格式标记，不属于用户语义内容；emoji等特殊符号一般也会统一清除，以保证文本内容的一致性，便于后续标注和分析处理。

**练习 4**：评分字段的正常取值是1-5，发现有记录是0或6，应该怎么处理？

**答案**：这属于非法取值（超出字段定义域），应当作异常数据剔除。因为0和6都不在规定的评分范围内，很可能是录入错误或系统异常导致，保留这些记录会给后续的统计分析带来错误信息。

**练习 5**：对于完全重复的记录，清洗时应该怎么处理？为什么？

**答案**：应该去重，只保留一份。因为重复记录会导致模型在训练时对该样本的表述过度学习（过拟合于特定表述），而且重复数据还会虚增数据量，影响后续基于数据量的统计和分析结果的准确性。
