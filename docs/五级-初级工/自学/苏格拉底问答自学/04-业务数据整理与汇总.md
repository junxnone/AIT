## 第一节：看起来"挺干净"的数据，藏着多少坑

### 先做个判断

这是一份508条记录的销售流水：字段齐全，排版工整，数字看起来也都"正常"。

> **如果现在直接按"商品类别"字段做分组汇总，算出各品类的销量占比——这个结果能信吗？**

先别往下看，花三十秒写下你的判断。读完这一节你会发现，光靠肉眼看，这类问题几乎一个都发现不了。

### 用代码"揪"出问题

```python
import pandas as pd
d = pd.read_csv("../数据集/sales_raw.csv")
print("商品类别取值:", d["商品类别"].value_counts().to_dict())
print("销售地区取值样例:", d["销售地区"].unique().tolist())
```

实测结果：商品类别出现"手机"94条、"手機"21条、"手机 "（含尾部空格）20条——**同一个类别，三种不同写法**；销售地区存在首尾带空格的取值（如" 华东 "）；下单日期混用四种格式（`2026-03-05`、`2026/3/5`、`03-05-2026`、`20260305`）。

老师抛出关键追问：**如果不统一这些写法，直接做分组汇总，会发生什么？**

同一类商品的数据会被拆成三份统计，严重低估真实销量。这正是归类整理工作的核心价值所在——看起来"多打几个字""多留个空格"的小问题，会直接影响后续所有统计分析的准确性。

### 为什么计算机会把"手机"和"手機"当成两个不同的东西

这是最容易被忽视、但必须想清楚的一点。老师问你：人看"手机"和"手機"，会不会觉得是同一个东西？

会，因为人会自动用"意思"去理解，两个字长得像、意思一样，大脑直接判定"这是同一个东西"。但计算机不理解"意思"，它只做一件事：**逐个字符比对编码是否完全相同**。"机"和"機"是两个不同的字符（繁简字形不同，对应不同编码），哪怕含义相同，对程序来说就是两个不同的字符串，分组统计时会被分到不同类别。首尾空格同理——"华东"和" 华东 "在显示出来的样子上几乎分辨不出差异，但多出来的空格字符会让整个字符串"不相等"。

一句话记住：**格式问题的共同特点是——对人眼来说"差不多"，对程序来说"完全不同"。**

### 怎么统一，以及一个容易矫枉过正的坑

```python
d["商品类别"] = d["商品类别"].str.strip()
d["商品类别"] = d["商品类别"].replace({"手機": "手机"})
d["下单日期"] = pd.to_datetime(d["下单日期"], errors="coerce")
```

统一之后，"手机"合并为 **135** 条（94+21+20），真实销量才显现出来。

老师这时候会故意挖一个坑：学会"合并同义写法"之后，数据集里还有"平板"和"笔记本电脑"两类，**要不要也合并**？

不要。判别方法：问自己一句——**这两条记录描述的是不是同一个真实世界的事物？** 是 → 合并（"手机"和"手機"说的是同一种商品，只是写法不同）；不是 → 保留为不同类别（"平板"和"笔记本电脑"是两种真实存在的不同商品，根本不存在"同义词"问题，不能因为"都是电子产品"就合并）。合并类别和区分类别，用的是同一把尺子：**看描述的是不是同一个事物，而不是看写法长得像不像。**

### 同样的陷阱换了个样子，又在数字字段里出现了一次

老师提醒你：别以为格式问题只出现在文字字段里。再看"销售金额"这一列：

```python
print(d["销售金额"].sample(10, random_state=2).tolist())
print("能直接转换为数字的条数:", pd.to_numeric(d["销售金额"], errors="coerce").notna().sum(), "/", len(d))
```

实测：抽样会看到"27986""27986元""143,984"（千分位逗号）、全角数字等多种写法混杂；**能直接转换为数字的只有436/508条**，剩下72条因为带了"元"字、千分位逗号或全角数字，被当成普通文本，无法参与任何求和、求均值运算。

老师追问：**这和前面"手机/手機"的问题是不是同一类？**

是。商品类别的问题是"同一含义，多种文字写法"；销售金额的问题是"同一数值，多种文本包装"。根因完全一样：写法不统一，程序没法识别成同一类东西。对人眼来说"27986"和"27986元"显然是同一个数；但程序看到字符串里混进了汉字"元"，就不再当数字处理，而是当成普通文本——这意味着**如果直接对这一列求和，带单位的记录会被悄悄跳过，求和结果偏小，而且不会报错提醒你**，这比直接报错更危险。

清洗代码：

```python
def clean_amount(s):
    if pd.isna(s):
        return None
    s = str(s)
    s = s.translate(str.maketrans("０１２３４５６７８９", "0123456789"))
    s = s.replace(",", "").replace("元", "").strip()
    try:
        return float(s)
    except ValueError:
        return None

d["销售金额"] = d["销售金额"].apply(clean_amount)
```

实测：清洗后能转换为数字的条数提升到 **495/508**，多找回59条本来就是正常数值、只是写法不规范的数据。剩下的13条仍是空值，这13条是**真正缺失的数据**，不属于格式问题，需要用其他方式处理。

**区分清楚**：整理归类只负责统一写法、把能救回来的格式问题修正好；它不负责补全真正没有的数据。把"格式不规范"和"数据真缺失"混为一谈，是很容易踩的另一个坑。

## 第二节：归类做完了，才轮到汇总——顺序不能颠倒

### 先用一个实验验证"归类先于汇总"这句话

老师带你跑一个对比实验：

```python
print("归一化前：")
print(d.groupby("商品类别").size())

d["商品类别"] = d["商品类别"].str.strip().replace({"手機": "手机"})
print("归一化后：")
print(d.groupby("商品类别").size())
```

归一化前：手机94、手机(含尾空格)20、手機21——同一类商品被拆成三行；归一化后：手机135。

老师追问一个站在业务视角的问题：**如果你是业务方，看到汇总报告说"手机"只有94单，会不会误判这个品类不受欢迎？**

会——而实际上手机类目真实销量是135单，是归类没做干净让数字看起来"分散而不起眼"。如果业务方据此减少了手机品类的采购或推广投入，这就是一个由数据处理顺序错误直接导致的业务误判。

**核心顺序：先归类统一（上一节的内容），再汇总（本节），顺序不能颠倒。** 如果跳过归类直接汇总，看似"做完了"，实则得到的是失真的结果。

### 拿到汇总结果，不能直接相信，要反问自己四句话

- 这个数字看起来合理吗？
- 总数是否对得上（各分类之和等于总体）？
- 占比之和是否为100%？
- 有没有异常极值？

老师出一道诊断题：某汇总报告显示各地区销售额占比加起来只有92%，可能是什么原因？

可能是地区字段的写法不统一（同一地区的不同写法被当成不同类别，部分未被识别归入汇总），或存在地区字段缺失/异常值未被纳入统计。应该回头检查归类整理是否彻底，而不是直接采信这个有问题的汇总结果——这正好呼应了本篇第一节讲的内容：**汇总阶段发现的异常，往往要回头到归类阶段去找根因**。

### Excel 和 pandas，做的是同一件事

| 操作 | Excel | pandas |
|---|---|---|
| 分组计数 | 数据透视表拖拽字段 | `df.groupby("字段").size()` |
| 分组求和 | 数据透视表值字段设为求和 | `df.groupby("字段")["数值列"].sum()` |

两者在功能上实现同样的分组汇总效果，掌握一种工具的思路后，迁移到另一种工具通常只是操作方式的不同，底层的分组聚合逻辑是一致的。
