| 项目 | 内容 |

---

## 一、教学目标

### 知识目标
1. 能说明常见数据来源渠道：用户行为日志、业务系统导出、传感器/设备采集、第三方采购、公开数据集。
2. **能说明采集前必须确认的三件事**：数据用途、授权范围、采集口径。
3. 能说明采集规格（分辨率/采样率/格式/命名规则）与归档记录的基本要素。

### 技能目标
1. **能使用采集设备/工具完成原始业务数据采集**，满足给定规格要求。
2. 能识别采集质量问题并当场重采。
3. 能按规范完成采集文件的命名、归档与采集记录登记。

---

## 二、教学重点与难点

**重点**：采集质量问题的现场识别（模糊、过曝、分辨率不一致）。

**难点**：零基础学员容易采集完就提交，不做质量自检，等到后续环节才发现问题，造成返工成本。

---

## 三、学情分析与前置知识

**前置知识**：课题0-4（AI与机器学习入门，理解标注质量为何重要）、课题0-2（数据安全意识——采集前先确认授权范围，是合规意识在采集环节的延续）。

**学情判断**：学员多有日常使用手机拍照的经验，但从未从"采集质量标准"这个角度审视过自己拍摄的内容，更没有"采集前先想清楚三件事"的职业习惯。容易把采集简单理解为"拍完传上去就行"，把"采集"等同于"按快门"这一个动作，而意识不到采集前的确认、采集中的规格控制、采集后的自检与归档登记同样是采集工作的组成部分。本课题是整个数据采集和处理职业功能的开篇课题，建立的工作习惯会延续到后面十几个课题。

---

## 四、教学方法与手段

1. **先体验后总结法**（核心）：先让学员看现有数据集里真实存在的质量问题，再讲采集规范，让规范的必要性"可感知"而非"被灌输"。
2. **现场实操法**：真实使用采集设备完成一次采集任务，而非纸面讨论。
3. **任务驱动法**：以"产出一份合规的采集记录登记表"作为本课题的可交付成果，对接实操题五-1。
4. **案例诊断法**：展示典型不合格采集案例，组织学员分组诊断问题所在。

### 环节一：导入（0–10′）

**教师活动** —— 投影展示（不给结论）：

> "这是上周某位学员采集的42张商品图片，他自己检查过，觉得分辨率都差不多、数量也够，就直接打包提交了。如果你是他，你觉得这批图片能直接通过质检吗？先别急着回答，认真看一眼投影里的几张样图。"

（投影展示其中几张明显有问题的图片，但不点名问题所在）

**提问话术**：

> "请大家举手表决——认为这批图片不需要任何修改就能直接提交的，请举手。"

（预期：部分学员会举手，尤其是没有特意去看细节的学员）

> "好，先记住你的判断。这节课结束前，我们会用代码把这批图片的问题全部挖出来，到时候你会发现，'看起来没问题'和'真的没问题'之间差得有多远。"

**设计意图**：不直接否定，让"拍完就是采集完"的直觉判断先被公开表达出来，后面用真实检测数据推翻，冲击力更强。

---

### 环节二：数据来源渠道与采集前三件事（10–30′）

**讲授脚本**：

> "采集数据不是拿起设备就拍、就录、就导出这么简单。我们先搞清楚两件事：数据从哪来，以及动手之前要想清楚什么。"

**数据来源渠道讲解**（逐项举例）：

| 渠道 | 举例 |
|---|---|
| 用户行为日志 | APP点击、浏览、停留时长记录 |
| 业务系统导出 | 订单系统导出的交易记录 |
| 传感器/设备采集 | 本课题的拍照、录音、门店摄像头 |
| 第三方采购 | 向数据供应商购买的标注数据集 |
| 公开数据集 | 政府/学术机构公开发布的数据 |

> "今天这节课聚焦的是'传感器/设备采集'这一类——用手机、相机、录音笔这些工具，亲手把原始数据采回来。"

**采集前三件事讲解**：

> "不管用哪种渠道、哪种设备，动手之前都要先确认三件事：**数据用途、授权范围、采集口径**。"

**逐项"为什么"展开**：

> "**为什么先问用途？** 因为用途决定规格。同样是拍商品图，用于电商详情页展示和用于训练图像识别模型，对清晰度、背景干净程度的要求完全不一样。不问清楚用途就开拍，拍回来发现规格不对，等于白干。
>
> **为什么先问授权范围？** 这是课题0-2讲过的合规意识在采集环节的落地——采集本身可能涉及他人信息（比如拍摄包含顾客的门店场景），没有明确授权范围就采集，轻则返工，重则直接违规。
>
> **为什么先问采集口径？** 口径包括字段定义、时间范围、抽样规则。比如'采集100张商品图'，是每个品类都要有，还是随便拍满100张就行？口径不明确，采回来的样本结构可能完全不满足后续标注、训练的需要。"

**板书核心句**：

> **采集前三件事，缺一不可：想清楚"干什么用"，确认"能不能采"，定清楚"怎么算合格"。**

**学员活动**：记录三件事，各自口头举一个自己熟悉场景（如开学拍班级照、拍快递面单）里"如果不先想清楚这三件事，会出什么问题"的例子，提问2-3人。

---

### 环节三：采集规格、命名与归档记录规范（30–55′）

> 📌 **教学提示**：这一环节对应国标技能要求"能按规范完成采集文件的命名、归档与采集记录登记"，是容易被忽视但实操题会直接考核的内容，务必讲清楚"为什么"而不是只念一遍清单。

**讲授脚本**：

> "想清楚三件事之后，动手采集时还有具体的规格要求要满足——分辨率、采样率（音频）、文件格式、命名规则。这些写在采集任务书里，必须照办，不是你自己觉得'差不多就行'。"

**为什么命名规则很重要——机制展开**：

> "命名规则看起来是小事，但你想一想：后面清洗、标注环节的同事，大概率不会一张一张去点开图片看，而是写一段脚本，按文件名的规律去批量处理——比如用文件名前缀识别类别、用编号对应标注记录。
>
> 如果你命名的时候自己随便起名字，比如用手机相册自动生成的'IMG_3.jpg'，或者干脆用中文加空格命名成'商品图片16.jpg'、'new photo 29.jpg'——下游的批量处理脚本按规律匹配文件名的时候，这些文件要么被漏掉、要么让脚本直接报错。**命名不规范，本质上是把本该由你当场解决的小问题，转嫁给了下游环节，而且下游往往更难发现。**"

**归档与采集记录登记讲解**：

> "采集完的文件要按规范归档——放进约定好的目录结构，而不是堆在一个文件夹里。同时要同步填写**采集记录登记表**，至少包含：采集人、采集时间、数据来源/渠道、采集数量、规格是否达标、异常情况说明。"

**板书核心句**：

> **采集规格要素**：分辨率/采样率、文件格式、命名规则
> **采集记录登记表字段**：采集人 / 采集时间 / 数据来源 / 采集数量 / 异常说明

**学员活动**：对照投影的登记表模板，记录字段要求；讨论"如果采集记录不写异常说明，只写'已完成'，后面排查问题会遇到什么困难"。

### 环节四：实操一——识别现有图像数据集的质量问题（难点突破，55–80′）

**教师指令**：

> "现在打开 `images/` 文件夹，我们用代码把这42张图片的问题全部挖出来。"

**核心实操代码（已实测验证）**：

```python
from PIL import Image
from pathlib import Path
import re

files = sorted(Path("../数据集/images").glob("*.jpg"))
sizes = {}
irregular_names = []
for p in files:
    img = Image.open(p)
    sizes.setdefault(img.size, []).append(p.name)
    if not re.match(r"^[a-z]+_\d{3}", p.name):
        irregular_names.append(p.name)

print("分辨率分布:", {k: len(v) for k, v in sizes.items()})
print("命名不规范文件:", irregular_names)
print("总文件数:", len(files))
```

**实测结果（已验证，学员结果应完全一致）**：

```
分辨率分布: {(640, 480): 37, (320, 240): 4, (1280, 960): 1}
命名不规范文件: ['IMG_3.jpg', '商品图片16.jpg', 'new photo 29.jpg']
总文件数: 42
```

> "代码查出了**5张分辨率不一致**（4张320×240、1张1280×960）、**3张命名不规范**。但这份清单还没完——这42张图里，还有**4张严重模糊、3张过曝、2组完全重复**的图片，代码刚才有没有把它们找出来？"

**关键提问（难点突破核心）**：

> "大家回忆一下，刚才的代码能可靠查出什么问题？模糊和过曝这两类，代码查出来了吗？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "代码只查了分辨率和命名，没查模糊和过曝" | 追问："那模糊、过曝这两类问题，现在要靠什么发现？"——引导到"人眼当场看一遍" |
| "可以写代码识别模糊/过曝" | 肯定并补充："确实有更复杂的图像处理方法可以辅助判断，但那是进阶内容。现阶段你**手头能立刻用上的方法**就是采集完当场用眼睛看一遍——这比等以后学了复杂算法再回头查，成本低得多" |
| 答不上来 | 引导："代码能稳定查的，是'能被精确计算'的东西——像素尺寸、文件名字符串。模糊和过曝呢？'看起来模糊'这件事，能用一行代码精确定义吗？" |

**教师总结话术**：

> "这就是为什么我反复强调'当场自检'，而不是'跑完代码就算完事'。**代码能可靠查出客观可计算的问题（分辨率、命名、重复文件），但模糊、过曝这类主观视觉质量问题，现阶段最可靠的办法仍然是人当场看一眼。**
>
> 回到开头那42张图：如果这是你采集的，交上去之后才被发现这4张模糊、3张过曝，会怎么样？"

（停顿，等待反应，呼应环节一的判断）

> "**采集质量问题最大的代价不是'要重做'，而是'很多时候根本没法重做'**——现场已经过去了，光线变了、设备换了、甚至商品都下架了。这就是为什么'当场自检'这么重要——采集完立刻看一眼，模糊的、过曝的，当场重拍，成本几乎为零；等上传之后才被发现，往往已经来不及了。"

**学员活动**：填写问题汇总表

| 问题类型 | 数量 | 能否用代码可靠检测 |
|---|---|---|
| 分辨率不一致 | 5张 | 能 |
| 模糊 | 4张 | 较难，建议人工目测 |
| 过曝 | 3张 | 较难，建议人工目测 |
| 命名不规范 | 3张 | 能 |
| 完全重复 | 2组 | 能（可用文件内容哈希或肉眼比对） |

### 环节六：实操二——现场采集并当场自检（90–130′）

**任务布置**：

> "现在轮到你们自己动手。用手机或相机，按照投影上的规格要求（统一分辨率、统一命名格式"类别_三位编号.jpg"），采集10张你身边物品的照片。拍完**立刻**对照自检清单检查一遍，再提交。"

**采集质量当场自检清单**（投影+讲义已有）：

- [ ] 分辨率是否符合要求（统一规格）
- [ ] 是否清晰（无模糊、无过曝）
- [ ] 命名是否规范
- [ ] 有无重复采集

**教师巡回指导要点**：

- 发现学员拍完不检查直接提交的，现场追问："你刚才拍的时候有没有回看一眼？"——当场演示一次自检动作，而不是事后批评。
- 发现命名偷懒（如直接用手机相册默认文件名）的，提醒环节三讲过的"命名不规范会转嫁给下游"的机制。
- 对完成快的学员追加任务："再故意拍一张过曝或模糊的照片，看看你自己能不能当场识别出来并重拍。"

### 环节七：实操三——填写采集记录登记表（130–150′）

**任务书**（投影）：

> "你今天在课堂上使用手机采集了10张物品图片，用于本课题的采集规范练习任务。请按规范填写一份采集记录登记表。"

**登记表必备字段**：

```
采集人：
采集时间：
数据来源/渠道：（传感器/设备采集）
采集数量：
规格是否达标：（分辨率/命名是否符合要求）
异常情况说明：（如有重拍、模糊、过曝等问题，写明具体现象，不要只写"有问题"）
```

**巡回指导要点**：检查学员是否把"异常情况说明"写成具体现象（如"第3张因手抖模糊，已当场重拍"），而不是笼统写"一切正常"或"没有问题"——很多学员即使采集中确实重拍过，也懒得在登记表里如实记录，这会导致记录与实际操作脱节，失去登记表"可追溯"的意义。

**对完成快的学员追问**：

> "如果半年后有人问你，这批数据是什么时候、用什么设备采的，你的登记表能回答清楚吗？"

### 环节八：分组互评——典型采集问题诊断（150–175′）

**教师活动**：投影展示教师预先准备的2-3份"典型不合格"采集案例，组织学员分组诊断问题所在。

**典型案例与应诊断出的问题**：

| 典型案例 | 应诊断出的问题 |
|---|---|
| 登记表"异常情况说明"一栏写的是"已完成"，但实际提交的10张图里有1张明显模糊 | 异常说明没有如实反映实际情况，记录与操作脱节，失去可追溯意义 |
| 命名为"1.jpg、2.jpg、3.jpg"，看起来"挺规范"（都是数字） | 缺少类别前缀，下游按类别批量处理的脚本无法识别这批文件属于哪一类 |
| 10张图片中有2张分辨率不同于其余8张，登记表"规格是否达标"一栏直接打勾"达标" | 没有真正核对规格就填写登记表，登记表沦为走形式 |

**学员活动**：分组讨论，每组派代表指出至少1处问题并给出修改建议。

**教师点评要点**：重点点评"为什么这算问题"，而不只是对答案——呼应环节三讲过的机制。

---

### 环节九：变式迁移——非图像场景的质量问题识别（175–195′）

**讲授脚本**：

> "今天我们练的是图像采集。但你们以后的工作里还会遇到音频采集（比如录客服通话）、日志采集（比如导出系统运行日志）。这些场景的'当场自检'要查什么？"

**引导讨论**（不涉及新的量化数据，只做类比迁移）：

| 采集类型 | 对应的质量问题类型 | 识别方式 |
|---|---|---|
| 图像 | 模糊、过曝、分辨率不一致 | 人工目测+代码查规格 |
| 音频 | 底噪过大、截断（没录完就停了） | 当场回放试听 |
| 日志 | 字段缺失（如时间戳为空） | 当场抽样核对字段是否齐全 |

**关键提问**：

> "这三类问题，表现形式完全不同，但有没有共同点？"

**板书核心句**：

> **不管采集什么类型的数据，"当场自检、当场重采"这个工作习惯是通用的——变的只是检查清单的具体内容，不变的是"不等上传之后才发现问题"这个原则。**

**学员活动**：分组讨论"如果你负责录制客服通话音频，你会把哪几项加进自己的采集自检清单"，派代表口头分享。

### 环节十：阶段性小测（195–215′）

**教师活动**：发放题库对应小测题（单选29–36、判断5，共9题），当堂巡视，统一讲评。

**题目覆盖方向**：
1. 采集前三件事的具体内容与遗漏项判断。
2. 采集质量问题类型的识别（分辨率/模糊/命名/重复）。
3. 当场自检相对于事后处理的成本优势。
4. 采集口径应明确的具体内容。
5. 采集设备选择的正确依据（规格 vs 价格/外观）。

**学员活动**：独立完成，交卷后对照答案自评，记录自己的错题。

### 环节十一：小结与作业（215–240′）

**知识回顾**（请学员口述，教师补全）：

1. 采集前必须确认哪三件事？为什么这三件事要放在最前面？
2. 这42张图片里，哪些问题能用代码可靠查出，哪些必须靠人眼当场看？
3. 采集记录登记表为什么不能随便写"一切正常"？

**回扣主线**：

> "这节课的核心习惯是：**采集不是'按一下快门'这一个动作，而是'想清楚三件事→按规格采集→当场自检→如实登记'这一整套流程**。今天用图像数据练的这套方法，下一课题你们会用它去查数据库导出的数据对不对。"

**作业**：见下方"作业与课后任务"表。

## 七、板书设计

**主板书区**

```
采集前三件事：数据用途？ 授权范围？ 采集口径（字段/时间/抽样规则）？

数据来源渠道：用户行为日志 / 业务系统导出 / 传感器设备采集 / 第三方采购 / 公开数据集

┌─────────────── 实测：42张图像质量自检 ───────────────┐
│ 分辨率不一致 5张    模糊 4张    过曝 3张              │
│ 命名不规范 3张      完全重复 2组                      │
│ → 代码能可靠查：分辨率 / 命名 / 重复                  │
│ → 必须人眼当场查：模糊 / 过曝                         │
└────────────────────────────────────────────────────┘

采集质量当场自检清单：
  □ 分辨率是否符合要求   □ 是否清晰（无模糊/过曝）
  □ 命名是否规范         □ 有无重复采集
  □ 采集记录是否同步登记（异常情况写具体现象，不写结论）
```

**副板书区（三类图像问题辨析）**

```
                分辨率不一致        模糊                过曝
现象            同批图像尺寸不同     细节看不清           画面接近全白
能否代码检测    能                  较难，建议人工目测    较难，建议人工目测
修复方式        统一规格重拍        当场重拍             调整光线/角度后重拍

判别口诀：先问"尺寸对不对"（代码能查）→ 再问"看得清不清、亮不亮"（人眼当场查）
```
