---

## 一、教学目标

### 技能目标
1. **能根据数据处理要求完成业务数据的整理与归类**。
2. **能处理常见格式问题**：日期格式不统一、全半角混用、首尾空格、单位不一致、大小写混乱。

---

## 二、教学重点与难点

**重点**：识别同一含义的不同写法（如"手机"/"手機"/"手机 "应归为一类），同时能反向判断"写法不同但确实是不同事物"的情形不应被误合并。

### 难点

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| 零基础学员容易只做表面"看起来没问题"的检查，忽视类别写法混乱、首尾空格等隐藏的格式问题 | 浏览数据后认为"字段都有值、数字看起来也正常"，就判断数据可以直接使用，只在被要求"检查格式问题"时才想起去看写法细节，且往往只能想到"商品类别"一处，想不到销售金额、销售地区等字段同样存在格式问题 | 让学员先凭肉眼判断"这批数据能不能直接用"，再用代码逐字段跑出`value_counts()`/`unique()`的真实统计结果，用"肉眼看不出、代码一跑一大把"的反差制造认知冲突；并在难点突破后追加销售金额字段的"二次新发现"，检验学员能否把"隐藏格式问题"的警觉从商品类别迁移到其他字段 |

---

## 三、学情分析与前置知识

学员已学完课题1-2的SQL基础，对"数据里有问题"已有一定敏感度，但本课题关注的格式问题（首尾空格、同义不同写法、单位混用）往往"肉眼看不太出来"，需要通过实际代码统计才能发现，容易被零基础学员低估其重要性。此外，部分学员在建立"同义词要合并"的意识后，容易矫枉过正，把真正不同的类别也当成"写法不同"强行合并，教学中需要同时建立这两个方向的判断力。

---

## 四、教学方法与手段

1. **真实数据揭示法**：直接用代码跑出隐藏的格式问题，让学员直观看到"看起来没问题的数据，实际问题不少"。
2. **工具迁移训练法**：同一任务用Python和Excel各做一遍，巩固两种工具的操作并建立迁移能力。
3. **变式练习法**：在商品类别的难点突破之后，换一个字段（销售金额）让学员独立重复"发现问题→统一处理→验证结果"的完整流程，检验方法是否真正迁移。

### 环节一：导入（0–10′）

**教师活动** —— 投影展示（不给结论）：

> "这是我们要用的销售记录表，字段齐全，表格排版工工整整，乍一看没什么毛病。如果现在要你直接按'商品类别'做汇总统计，算出各品类的销量占比，你觉得算出来的结果能信吗？"

**提问话术**：

> "三十秒内判断：这批数据能不能直接拿去汇总？举手表决——认为能直接用的请举手。"

（预期：相当一部分学员会倾向于"看起来没问题，可以用"）

**教师应对**：

> "好，先记住你的判断。这节课结束前我们会回来验证这个判断，到时候你会发现，光凭眼睛看，这类问题几乎发现不了。"

**设计意图**：不直接否定，让"想当然没问题"的判断先被公开表达出来，后面用真实统计结果推翻，冲击力更强。

---

### 环节二：新授——五类常见格式问题（10–60′）

**讲授脚本**：

> "判断一份业务数据能不能直接用，不能只看'字段齐不齐全'，还要看字段里**具体的写法**统不统一。零基础的同学最容易忽视这一层，因为这类问题**用眼睛扫一遍几乎看不出来**。我们一个个来看。"

**逐项讲解**（板书 + 举例）：

| 问题类型 | 定义 | 业务后果 |
|---|---|---|
| 日期格式不统一 | 同一个字段里，日期用了不同的书写格式（如`2026-03-05`、`2026/3/5`、`03-05-2026`、`20260305`） | 程序无法把它们当成同一种"日期类型"统一排序、比较和计算，按日期筛选时会漏掉写法不同的记录 |
| 全半角混用 | 同样的字符用了全角和半角两种编码（如数字"1"和"１"） | 对程序而言这是两个完全不同的字符，字符串比较和数值转换都会失败 |
| 首尾空格 | 字段值前后多出看不见的空格（如"华东"和" 华东 "） | 肉眼完全看不出差异，但程序判断两者是不同的字符串，分组统计时会被当成不同类别 |
| 单位不一致 | 同一个数值字段，有的记录带单位后缀或千分位符号，有的没有（如"27986"和"27986元"、"143,984"） | 带文字或符号的数值无法直接参与数学运算，会被当成文本处理，汇总求和时报错或被跳过 |
| 大小写/同音异形混乱 | 同一含义的词使用了不同的字形写法（如"手机"/"手機"） | 程序按字符逐个比对，这是两个不同的字符串，会被分别统计，同一类商品的数据被人为拆散 |

**教师提问**（埋下难点突破的引子）：

> "这五类问题里，大家觉得哪一类最容易被漏掉？"

（引导学员意识到：**越是"看起来像文字小瑕疵"的问题，越容易被当成无关紧要而忽视**——首尾空格和同音异形尤其如此）

**板书核心句**：

> **格式问题的共同特点：对人眼来说"差不多"，对程序来说"完全不同"。**

**学员活动**：记录五类问题定义，针对每一类口头举一个自己熟悉场景（如考勤系统、购物软件）里可能出现的具体例子。

### 环节四：难点突破——手机94/手機21/手机(空格)20 认知冲突与统一写法（100–130′）

**教师提问（难点突破核心）**：

> "'手机'94条，'手機'21条，'手机 '（带空格）20条。如果不统一这些写法，后面按商品类别做汇总统计会发生什么？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "没什么影响，反正都是手机" | 追问："程序怎么知道'手機'和'手机'是同一个意思？在计算机眼里，这是两个完全不同的字符串，会被当成两个不同的类别分别统计。" |
| "会被拆成三份统计" | 肯定并追问："拆成三份之后，报表上显示的'手机'销量会是多少？是94，还是三份加起来的135？差距有多大？" |
| 答不上来 | 引导："把'手机'94条和'手機'21条放在报表上看，哪个数字更接近真相？如果你是业务负责人，只看到94条，会怎么判断这个品类？" |

**教师总结**：

> "会把同一类商品的数据拆成三份统计，严重低估真实销量——这正是归类整理的核心价值所在。**看起来'差不多'的写法，对程序来说是完全不同的东西**，这是本课题最容易被忽视、但后果很严重的一个点。"

**统一写法代码**（投影 + 学员跟做）：

```python
d["商品类别"] = d["商品类别"].str.strip()                    # 去除首尾空格
d["商品类别"] = d["商品类别"].replace({"手機": "手机"})       # 统一同义写法
print(d["商品类别"].value_counts())
```

**验证输出（已实测）**：

```
手机        135
耳机        104
笔记本电脑   96
平板         89
智能手表     84
```

**反向判断追问**（防止矫枉过正）：

> "既然'手机'和'手機'要合并，那'平板'和'笔记本电脑'要不要也合并？都是电子产品啊。"

（预期学员反应：多数会答"不要"，但说不清理由）

**判别口诀（板书）**：

> **先问：这两条记录描述的是不是同一个真实世界的事物？**
> 是 → 合并（"手机"和"手機"说的是同一种商品）；
> 不是 → 保留为不同类别（"平板"和"笔记本电脑"是两种真实不同的商品，写法清清楚楚，不存在"同义词"的问题）。

**学员活动**：填写对比表

| | 手机 | 手機 | 手机（空格） | 合并后 |
|---|---|---|---|---|
| 条数 | 94 | 21 | 20 | 135 |

### 环节六：实操二——统一销售地区空格与下单日期格式（140–170′）

**教师指令**：

> "刚才处理的是商品类别。现在用同样的思路处理另外两个字段：销售地区和下单日期。"

```python
# 销售地区：去除首尾空格
d["销售地区"] = d["销售地区"].str.strip()

# 下单日期：统一转换为标准日期类型
```

**巡回指导要点**：检查学员是否记得用`errors="coerce"`参数；若有学员忘记写，提示——"不加这个参数，遇到识别不了的格式代码会直接报错中断，不是写出空值"。

### 环节七：实操三——销售金额单位不一致清洗（变式练习，170–205′）

**教师指令（不给代码，先给探查任务）**：

> "前面两轮都是我带着做。这一次换一个字段——销售金额，你们自己先探查一下，这个字段有没有格式问题，属于哪一类，再想办法统一。"

**学员独立探查（提示性代码，引导方向不给答案）**：

```python
print(d["销售金额"].sample(10, random_state=2).tolist())
print("能直接转换为数字的条数:", pd.to_numeric(d["销售金额"], errors="coerce").notna().sum(), "/", len(d))
```

**实测结果（已验证）**：

> 样例中会看到"27986"、"27986元"、"143,984"、全角数字等多种写法混杂；**能直接转换为数字的只有 436/508 条**，其余 72 条因为带了"元"字、千分位逗号或全角数字，被当成普通文本，无法参与任何求和、求均值等数学运算。

**关键提问**：

> "72条无法直接转换，这属于五类问题里的哪一类？为什么商品类别那种'手机/手機'的问题和这里的'27986/27986元'的问题，本质上是同一件事？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "属于单位不一致，因为有的带'元'有的不带" | 肯定："对。本质和商品类别的问题完全一样——对人眼来说'27986'和'27986元'说的是同一个数，但对程序来说，带了'元'字之后这就不再是一个数字，而是一串文字。" |
| "这个和商品类别没关系，是两种问题" | 纠正："换个角度看：商品类别是'同一含义，多种文字写法'；销售金额是'同一数值，多种文本包装'。两者的根本原因都是——**写法不统一，程序没法把它们识别成同一类东西**。处理思路也是一样的：先找出所有不规范写法，再统一替换成标准形式。" |

**统一清洗代码（教师给出，学员跟做）**：

```python
def clean_amount(s):
    if pd.isna(s):
        return None
    s = str(s)
    s = s.translate(str.maketrans("０１２３４５６７８９", "0123456789"))  # 全角转半角
    s = s.replace(",", "").replace("元", "").strip()                      # 去千分位、去单位
    try:
        return float(s)
    except ValueError:
        return None

d["销售金额"] = d["销售金额"].apply(clean_amount)
print("清洗后能转换为数字的条数:", d["销售金额"].notna().sum(), "/", len(d))
```

**验证输出（已实测）**：

```
清洗后能转换为数字的条数: 495 / 508
```

**教师总结**：

> "清洗前436条能直接用，清洗后495条——多找回了59条本来就是正常数值、只是写法不规范的数据。剩下13条仍然是空值，这13条是**真正缺失的数据**，不是格式问题，这个会在后面课题里再处理。**本课题只负责把'能救回来'的格式问题统一好，不负责补全真正没有的数据。**"

### 环节九：分组互评与常见错误纠错（220–230′）

**教师活动**：投影展示2-3份教师预先准备的"只处理了商品类别、漏掉销售金额或销售地区"的典型不完整结果，组织学员分组诊断遗漏了哪个字段。

**预期诊断点**：

| 典型遗漏 | 应诊断出的问题 |
|---|---|
| 只统一了商品类别，销售地区仍带空格 | 分组统计销售地区时，"华东"和" 华东 "会被当成两个不同地区 |
| 销售金额没有清洗，直接对该列求和 | 带"元"字和逗号的记录会被当成文本跳过，求和结果偏小且不报错，最隐蔽、最容易被忽略 |

**学员活动**：分组讨论，每组派代表指出至少1处遗漏并说明会造成什么后果。

## 七、板书设计

**主板书区**

```
常见格式问题（五类）：
  日期格式混用（4种）     全半角混用        首尾空格
  单位不一致             大小写/同音异形混乱（手机/手機）

共同特点：对人眼"差不多"，对程序"完全不同"

┌──────────────── 实测反差 ────────────────┐
│ 商品类别"手机"：94 + 21(手機) + 20(空格) │
│          → 统一后合并为 135              │
│ 销售金额：清洗前 436/508 可转数字         │
│          → 清洗后 495/508 可转数字        │
└────────────────────────────────────────────┘

统一方法：str.strip() 去空格 / str.replace() 或 replace() 统一写法
         / pd.to_datetime() 统一日期 / 全角转半角 + 去单位符号 统一数值
```

**副板书区（易混淆点辨析）**

```
                写法不同但同义        写法不同且确实不同
本课题例子      手机 / 手機 / 手机    平板 / 笔记本电脑
该怎么做        合并为一类            保留为不同类别

判别口诀：这两条记录描述的是不是同一个真实世界的事物？
          是 → 合并    不是 → 保留
```
