# 教案 · 课题 2-5：标注后数据分类与统计

| 项目 | 内容 |
|---|---|
| 所属等级 | 五级 / 初级工 |
| 对应国标 | 职业功能2 数据标注 · 2.2 标注后数据分类与统计 |
| 学时 | **4 学时**（理论 1 + 实操 3） |
| 教学场地 | 计算机机房 |
| 数据文件 | `数据集/labeled_results.csv` |

---

## 一、教学目标

### 知识目标

1. 能说明标注交付前须完成的自检项：**数量完整、格式合规、标签取值合法、文件对应关系正确**，并能说出每一项如果不做会造成什么具体后果。
2. 能说明"**分类**"与"**统计**"的关系——先按标签/批次/质量状态把数据切成互不重叠的子集（分类），再在子集或整体上做计数与占比计算（统计），顺序不能颠倒。
3. 能说明一份合格的标注后数据统计报表应覆盖哪些维度（标签分布、完成量、异常清单、处理建议）。

### 技能目标

1. **能利用分类工具对标注后数据进行分类**（按标签、批次、质量状态）。
2. **能利用统计工具对标注后数据进行统计**（数量、占比、标注员完成量分布）。
3. **能从统计结果中发现异常**（规范外标签取值、完成量异常偏低的个体），并提出可执行的处理建议。

### 素养目标

1. 建立"**算出数字只是第一步，审视这个数字是否正常才是训练师的价值所在**"的职业意识——这是本课题、也是整个"数据标注"职业功能模块收官要沉淀下来的核心习惯。

---

## 二、教学重点与难点

### 重点

1. 从统计结果中主动发现异常（规范外标签取值、某标注员完成量异常偏低）。
2. 分类与统计的正确顺序，以及统计报表应覆盖的维度。

### 难点

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| 零基础学员容易止步于"算出统计数字"，不去审视统计结果本身是否正常，错过发现问题的机会 | 学员能准确运行代码、算出标签分布和完成量，但面对打印出来的结果只会说"算完了""数字都出来了"，被追问"你发现了什么问题"时沉默或只能泛泛地说"数据看起来还可以" | 不直接告诉学员异常在哪，用"看到这两组数字，你能发现什么问题"逐步追问，倒逼学员自己从"合规三类之外还有没有别的取值""完成量数字之间是不是有被忽略的落差"这两条线索里主动找出异常，而不是教师直接揭晓答案 |

---

## 三、学情分析与前置知识

学员已完成文本/视觉/语音三类标注实操（课题2-2～2-4），本课题是职业功能2"数据标注"模块的收尾课题，承接前面的标注成果进行交付前质检。

**学情判断**：学员已经很熟练"跑代码、算数字"这个动作本身（`value_counts()`、`isna().sum()` 这类调用上手很快），但容易把统计当成"算完数字就交差"的机械任务，缺乏主动审视数字是否合理的意识——这正是本课题要重点培养、也是"数据标注"模块最后要沉淀的能力："会算"只是起点，"会判断算出来的东西对不对"才是训练师区别于普通操作工的地方。此外，学员此前接触的"分类"大多停留在标注任务本身（给一条数据打标签），还没有练习过"把已标注好的数据按某个维度重新切分归类"这个动作，这是本课题新增的技能点，需要单独花时间建立。

---

## 四、教学方法与手段

1. **数据驱动发现法**（核心）：不直接告诉学员"有问题"，让学员自己从统计结果里找出异常。
2. **任务驱动法**：以"产出一份可交付的标注后数据统计报表"作为本课题的终产物。
3. **变式迁移法**：通过"假如标签分布看起来很均匀、完成量也很接近，是不是就一定没问题"这类变式提问，检验学员是否真正理解"发现异常"的本质，而不是只记住了这一组具体数字。

### 环节一：导入（0–10′）

**教师活动** —— 投影展示（不给结论）：

> "某标注项目400条商品评价已经全部标完情感标签，项目负责人看了一眼——数量够了、文件也都在，准备直接把这批数据交给算法团队训练模型。"

**提问话术**：

> "请大家用三十秒判断：这批数据能直接交付吗？认为能直接交付的举手。"

（预期：相当一部分学员会举手，理由是"都标完了，数量也够"）

> "好，先记住你的判断。这节课结束前我们会回来验证它。"

**设计意图**：先让"标完=能用"这个直觉判断被公开表达出来，后面用真实统计结果推翻，冲击力更强——这个手法和前面课题的"一份看起来没问题的数据"导入是同一个套路，目的都是先暴露直觉误区。

---

### 环节二：交付前自检四项（10–30′）

**讲授脚本**：

> "标完了不等于能用。交付前至少要做四项自检，少一项都可能让问题漏进最终的训练数据里。"

**逐项讲解（板书+反例）**：

| 自检项 | 含义 | 如果不做，会怎样 |
|---|---|---|
| 数量完整 | 实际标注条数是否等于应标注的任务总量 | 比如本应标400条，实际只交了397条，少掉的3条样本永远不会进入训练集，模型在这类样本对应的场景上"没学过"，上线后遇到类似情况就可能判断失误 |
| 格式合规 | 字段名、文件编码、文件格式是否符合约定 | 字段名写错一个字（如把"情感标签"写成"情绪标签"），下游程序按约定字段名读取数据时直接报错或读出空值，整批数据可能被判为无效 |
| 标签取值合法 | 标注值是否都落在规范定义的范围内 | 出现规范外取值（本课题后面会亲手发现两种），模型训练时会把这些取值当成合法类别学进去，污染模型的输出空间 |
| 文件对应关系正确 | 标注记录与原始数据样本是否一一对应、没有错位 | 如果标注ID对应错了评价ID，标注内容就会"驴唇不对马嘴"——标的是这条评价的情感，却被错误地关联到另一条评价上，这种错误在人工抽查时也很难一眼看出 |

**学员活动**：记录四项自检内容，口头回答——"如果只做了前三项，漏了'文件对应关系'这一项，可能会造成什么后果？"（提问2-3人，引导说出"标签和原始内容对不上"这一后果）

**板书核心句**：

> **标完只说明"动作做了"，自检才能确认"结果能用"。**

---

### 环节三：先分类、再统计（30–50′）

**讲授脚本**：

> "国标对这个课题的技能要求写的是两句话：**能利用分类工具进行分类，能利用统计工具进行统计**。注意顺序——分类在前，统计在后。为什么？"

（停顿，引导思考）

> "因为统计是在某个'集合'上做计数，如果不先分类，你面对的永远是混在一起的400条记录，很难看出规律。**分类就是先把数据按某个维度切成几个互不重叠的小堆，统计才是在每一小堆或整体上数数、算占比。**"

**分类的三个常见维度（板书）**：

| 分类维度 | 本课题中的例子 |
|---|---|
| 按标签 | 把400条记录按情感标签切成"正面""负面""中性"……几个子集 |
| 按批次 | 按任务下发时间切分，确认这批数据是否来自同一次下发，有没有混入其他批次的历史数据 |
| 按质量状态 | 把记录切成"合规""规范外""空值"三类，分别决定下一步动作 |

**教师提问**：

> "如果今天这批数据是分两次下发给标注员的，第一批200条和第二批200条如果混在一起直接统计完成量，会出现什么问题？"

**预期学员反应与应对**：

| 学员反应 | 教师应对 |
|---|---|
| "看不出是哪一批标注员标得慢" | 肯定："对，两批混在一起统计，没法判断是某人效率问题还是某一批任务本身难度更大、更费时间。这就是为什么分类要先于统计——分类分得对，统计出来的数字才有意义。" |
| 答不上来 | 引导："假设A标注员在第一批里标了80条、第二批只标了10条，如果不按批次分开看，你只会看到'A一共90条'，看不出问题出在第二批。" |

**板书核心句**：

> **分类是"切"，统计是"数"。切错了维度，数字再准也看不出问题。**

### 环节四：实操一——统计并发现异常（难点突破，50–90′）

**教师指令**：

> "打开 Jupyter，我们来对这400条真实标注结果做统计，看看导入环节那个'能直接交付'的判断到底站不站得住脚。"

**投影代码**（学员照抄运行）：

```python
import pandas as pd
d = pd.read_csv("../数据集/labeled_results.csv")
print("情感标签分布:", d["情感标签"].value_counts(dropna=False).to_dict())
print("标注员完成量:", d["标注员"].value_counts().to_dict())
```

**实测**（已验证，学员结果应与此完全一致）：共400条记录。情感标签分布：正面348、负面28、中性12、**"中性偏正"5条（规范外取值）**、**"3"4条（规范外取值）**、空值3条。标注员完成量：A02完成120、A01完成99、A03完成90、A04完成84、**A05仅完成7条（异常偏低）**。

**教师提问（难点突破核心）**：

> "看到这两组统计数字，你能发现什么问题？"

**预期学员反应与应对**：

| 学员反应 | 教师应对 |
|---|---|
| "没发现什么问题，数字都算出来了" | 追问："情感标签只应该有正面、负面、中性三种，你看到的取值里有没有超出这三种的？" —— 引导发现"中性偏正""3"这两种规范外取值 |
| 发现了规范外取值但没看标注员分布 | 追问："再看标注员完成量这组数字，有没有哪个人的数字看起来不太对劲？" —— 引导发现A05完成量异常偏低 |
| "为什么自检的时候没发现这些问题？" | **这是个好问题，当堂正面回应**："自检四项里的'标签取值合法'确实包含这一层，但自检往往是抽查几条记录，规范外取值只占总数的1.25%+1%，抽查20条很可能一条都抽不到。**必须做全量统计、看完整分布，异常才会稳定地暴露出来。**这就是为什么'分类统计'要作为交付前单独的一道工序，不能指望自检环节顺带发现。" |

**教师总结**：

> "**统计不是算完数字就结束了**。要带着'这个数字正常吗'的疑问去看统计结果：规范外标签取值（'中性偏正''3'）说明标注工具或标注员对规范理解有偏差，需要核查；A05完成量仅7条，远低于其他人的84-120，可能是任务分配异常、设备故障或标注员出勤异常，需要上报核实，不能当作正常情况直接放过。"

**回扣导入**：

> "现在回到开头的判断——这批数据能直接交付吗？**不能。** 至少有9条规范外标签记录和A05的完成量异常需要先核实清楚，才能决定哪些数据能进入最终交付的数据集。"

---

### 环节五：实操二——按质量状态分类归档（100–130′）

**教师指令**：

> "刚才我们统计出了问题，现在把'分类工具'的技能补上——用代码把这400条记录按质量状态真正切分开，而不是只在脑子里记住'大概有问题'。"

**投影代码**：

```python
import pandas as pd
d = pd.read_csv("../数据集/labeled_results.csv")

valid = {"正面", "负面", "中性"}
d["质量状态"] = d["情感标签"].apply(
    lambda x: "空值" if pd.isna(x) else ("合规" if x in valid else "规范外")
)
print(d["质量状态"].value_counts())
print(d[d["质量状态"] == "规范外"][["标注ID", "评价ID", "标注员", "情感标签"]])
```

**推算结果**（由环节四的统计数字直接相加可得，用于核对分类有没有遗漏）：合规 348+28+12=**388条**、规范外 5+4=**9条**、空值 **3条**，三者相加 388+9+3=**400**，与总记录数完全吻合——**这说明分类覆盖了全部记录，没有遗漏，也是"数量完整"这项自检在统计环节的具体落地。**

**教师追加提问（批次维度）**：

> "再按批次分类检查一下，这400条数据是不是都来自同一次任务下发？"

```python
print(d["任务下发时间"].nunique())
```

（预期输出：**1** —— 全部400条记录的任务下发时间完全相同，说明本批数据来自单一批次，没有混入其他批次的历史数据）

**学员活动**：运行代码，讨论并填写"质量状态 → 下一步动作"对照表：

| 质量状态 | 条数 | 下一步动作 |
|---|---|---|
| 合规 | 388 | 直接计入最终的标签分布统计，可交付 |
| 规范外 | 9 | 导出清单，交标注组长核查来源（工具漏洞还是标注员理解偏差） |
| 空值 | 3 | 核实是漏标，还是原始评价本身就是空文本，分别处理 |

**教师点拨**：

> "注意，**分类之后不是堆在那里不管，每一类都要有明确的下一步动作**。合规的直接用，规范外的要核查，空值的要核实原因——分类的价值就在于让你能对不同的数据采取不同的处理方式，而不是眉毛胡子一把抓。"

### 环节六：实操三——产出完整统计报表（130–170′）

**任务布置**：

> "请你为这批 `labeled_results.csv` 数据产出一份完整的标注后数据统计报表，覆盖五个部分，不能只有数字。"

**报表必备要素（教师给模板）**：

```
一、任务基本信息（任务名称、下发时间、应标注总量）
二、标签分布统计（各标签数量 + 占比）
三、标注员完成量统计
四、异常清单（规范外标签取值记录 / 完成量异常的标注员）
五、处理建议（对应每类异常，给出具体下一步动作）
```

**巡回指导要点**：

- 检查"二、标签分布统计"是否同时给出**数量和占比**，不能只写数量（如"正面348条"没写占比，不符合题库考点"报表应包含数量与占比"）。
- 检查"四、异常清单"是否把具体记录列出来（如规范外取值的标注ID），而不是只写一句"有异常"。
- 检查"五、处理建议"是否逐条对应异常清单，**不能空着或只写"需要关注"这种空话**。

**对完成快的学员的追问话术**：

> "你的报表里有没有写清楚这400条数据是否来自同一批次？刚才我们查过 `任务下发时间` 只有一个值——这也应该写进'一、任务基本信息'里，作为数据来源核验的一部分。"

### 环节七：变式练习与分组互评（170–200′）

**变式提问（迁移巩固，检验是否真正理解"异常发现"）**：

> "假设换一批数据，标签分布变成正面、负面、中性各占三分之一左右，每个标注员完成量也都在95-105条之间，看起来非常均匀——这批数据是不是就一定没问题了？"

**预期学员反应与应对**：

| 学员反应 | 教师应对 |
|---|---|
| "是的，分布均匀、完成量接近，说明大家都认真标了" | 追问："如果有标注员图省事，不认真看内容，就按'正面、负面、中性'的固定顺序循环打标签呢？统计出来的分布和完成量会是什么样？" —— 引导意识到也会呈现"均匀、接近"的样子 |
| 想到了"循环打标签"的可能性 | 肯定："对，**均匀的统计结果不能单靠数字本身证明标注是认真做的**，还需要抽样人工复核几条具体内容，看标签和评价内容是否真的匹配。这和前面'标完≠能用'是同一个道理——统计结果好看，只是通过了一道检查，不代表所有问题都没有了。" |

**分组互评**：学员两两交换各自环节六写的统计报表，依据下表找至少1处问题：

| 常见问题 | 应指出的修改意见 |
|---|---|
| 标签分布只写数量，没写占比 | 补上占比，便于横向比较不同批次的分布是否正常 |
| 异常清单只写"有问题"，没列具体记录 | 补上具体的标注ID/标注员编号，便于后续核查 |
| 处理建议空着或写"需要关注" | 改为具体动作，如"导出规范外记录交组长核查""上报A05所在小组核实出勤" |

## 七、板书设计

**主板书区**

```
                   标注后数据分类与统计

交付前自检四项：数量完整 / 格式合规 / 标签取值合法 / 文件对应关系正确

分类 → 统计 → 发现异常
(先把数据切成子集)  (在子集上数数、算占比)  (审视数字是否正常)

┌──────────────── 实测统计（共400条） ────────────────┐
│ 标签分布：正面348  负面28  中性12                    │
│           规范外9条(中性偏正5+"3"4)  空值3            │
│ 标注员完成量：A02=120 A01=99 A03=90 A04=84  A05=7 ←异常│
└────────────────────────────────────────────────────┘
```

**副板书区（分类维度与质量状态判别）**

```
分类三维度：  标签  /  批次  /  质量状态

质量状态三类 →  下一步动作
  合规(388)  →  直接计入统计，可交付
  规范外(9)  →  导出清单，交组长核查来源
  空值(3)    →  核实是漏标还是本来无内容

判别口诀：算出数字只是第一步，审视"这个数字正常吗"才是关键
```
