## 一、教学目标

### 技能目标
1. 能完成文件与目录管理、压缩解压、编码格式识别与转换。
2. **能熟练使用Excel/WPS**：排序、筛选、查找替换、分列、去重、条件格式、常用函数、数据透视表。
3. **能完成Python环境安装与Jupyter Notebook基本使用**。
4. 能运行给定的Python脚本、读懂报错信息的第一行并定位问题。

## 二、教学重点与难点

### 重点
1. Excel核心函数（`IF`/`COUNTIF`/`SUMIF`/`VLOOKUP`）与数据透视表。
2. Python环境安装与Jupyter Notebook的基本使用。
3. 报错信息的阅读方法（先看最后一行再定位）。

### 难点

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| 难点一：Python环境安装（对"环境变量""命令行"等概念陌生） | 零基础学员看到黑色命令行窗口就紧张，安装弹窗里的选项（尤其"Add Python to PATH"）不知道该不该勾，容易瞎点导致装完却用不了，进而受挫放弃 | 不讲抽象定义，先用"电脑去哪里找python这个命令"的类比讲清楚环境变量的作用；分步演示+逐人确认机制，每完成一步就现场确认全员到位，掉队立即单独跟进，不让任何人掉队太远 |
| 难点二：面对报错信息产生畏惧，不会读、不敢读 | 看到一大片红色文字的报错堆栈，第一反应是"坏了"，倾向于直接重装软件/系统，或等人来处理，而不去读内容 | 故意设置3类常见报错让学员亲手触发，强调"先看最后一行"，当堂演示报错信息本身就是解题地图，而不是惩罚提示 |

## 三、学情分析与前置知识

**前置知识**：课题0-1（职业认知）、课题0-2（法律法规与数据安全基础）。

**学情判断**：

- 本课题面向零基础学员，对"环境变量""命令行""安装路径"这类概念完全陌生，是整个60学时课程中最容易让学员产生挫败感、中途放弃的一个环节。教学时必须放慢节奏，逐人确认每一步操作成功后再推进，不能按统一进度"赶课"。
- 多数学员有基础的Excel使用经验（如简单的排序筛选），但很少用过`COUNTIF`/`VLOOKUP`这类函数和数据透视表，容易停留在"用眼睛数、手动复制粘贴"的低效做法上，需要用效率对比制造"该学函数了"的动机。
- 学员普遍对"报错"存在天然的畏惧心理，第一次遇到满屏红字时容易直接放弃或求助，而不尝试自己读。这是后续60学时所有实操课题都会反复遇到的心理障碍，本课题是**第一次系统训练"读报错"这件事**，训练效果会直接影响后续课题的学习自主性。

---

## 四、教学方法与手段

1. **分步演示+逐人确认法**：Python环境安装环节，每完成一步都要确认全员跟上，避免掉队。
2. **故意设错演练法**：人为制造常见报错场景，训练学员"遇到报错不慌、照着信息排查"的习惯，而非在真实考试环境下第一次遇到报错而手足无措。
3. **效率对比法**：用"手动数/复制粘贴"与"函数/透视表"完成同一任务的耗时和出错率做对比，建立使用函数的内在动机。

### 环节一：导入——一张"吓人"的报错截图（0–10′）

**教师活动**——投影展示（不加任何注释）：

```
Traceback (most recent call last):
  File "analyze.py", line 3, in <module>
    import pandas as pd
  File "...\site-packages\pandas\__init__.py", line 22, in <module>
    ...（中间还有十几行）...
ModuleNotFoundError: No module named 'pandas'
```

**提问话术**：

> "这是一位同学运行代码时电脑弹出来的真实画面，满屏红字。给大家30秒——看到这种画面，你的第一反应是什么？
> A. 赶紧叫人来处理，自己先不碰
> B. 重装一遍软件甚至系统，说不定就好了
> C. 深呼吸，看看最后一行到底在说什么
>
> 把你的选择写下来。"

**预期学员反应**：多数零基础学员会选A或B。

**教师追问**：

> "先记住你的选择。今天这节课上完，我会让你们自己回头看这张截图——你会发现，它比你想象的好解决得多。"

**设计意图**：不直接否定"报错很可怕"这个直觉，让它先被公开表达出来，为环节八的回扣积蓄冲击力。

### 环节二：新授——计算机基础操作（10–35′）

**讲授脚本**：

> "在正式学Excel和Python之前，先过几个最基础、但天天会用到的操作：文件和目录怎么管理、压缩包怎么解压、文件乱码了怎么办。"

**逐项讲解+演示**：

1. **文件与目录管理**：新建文件夹、重命名、移动、批量选择——强调"分类存放"的习惯（如按日期/按任务建子文件夹），这个习惯会直接影响后面Python读取文件路径是否顺利。
2. **压缩解压**：演示 `.zip`/`.rar` 的压缩与解压，强调"解压后先看一眼里面的文件结构，再决定下一步怎么处理"。
3. **编码格式识别与转换**：现场打开一个乱码的 `.csv` 文件，提问"这是文件坏了，还是别的原因？"——引出**编码不匹配**的概念：文件保存时用的字符编码（如GBK）和你打开时软件默认尝试的编码（如UTF-8）对不上，软件按错误的规则去"翻译"文件内容，就会出现乱码。演示用记事本/Excel的"打开方式"手动指定编码重新打开。

**学员活动**：跟做三项操作，并在自己电脑上找一个乱码文件（教师提前投放）尝试修复。

**设计意图**：这三项是最基础但最容易被忽略的能力，直接为后面"文件路径写不对""编码不对导致报错"两个高频坑做铺垫。

### 环节三：新授+演示——Excel核心函数与数据透视表（35–85′）

**讲授脚本（效率对比，制造动机）**：

> "先问一个问题：如果给你一张260行的门店销售表，让你数一下'已完成'状态的订单有多少条，你打算怎么数？"

（预期学员反应：手动数、肉眼扫描、Ctrl+F搜索再数）

> "手动数，大概率会数错——行数一多，眼睛容易重复数或漏数，而且表一改动，你就得从头再数一遍。这正是函数存在的意义：**把重复性的条件判断、计数、查找这类工作交给电脑，电脑不会累、不会漏。**"

**逐项讲解**（板书+演示）：

| 函数 | 作用 | 回答的问题 |
|---|---|---|
| `IF` | 条件判断 | "满足条件该归到哪一类？" |
| `COUNTIF` | 按条件计数 | "符合条件的有几个？" |
| `SUMIF` | 按条件求和 | "符合条件的加起来是多少？" |
| `VLOOKUP` | 按条件查找匹配值 | "这个编号对应的是什么？" |

**易混淆点提问**：

> "COUNTIF和SUMIF，很多人会记混。怎么快速区分？"

**判别口诀**（板书）：

> **问"有几个"用 COUNTIF，问"加起来是多少"用 SUMIF，问"对应的值是什么"用 VLOOKUP。** 别死记函数名，记它们各自回答的是哪种问题。

**VLOOKUP高频报错讲解**：

> "VLOOKUP是这四个函数里最容易出错的一个。原因是**查找区域必须锁定**——如果你下拉填充公式时忘了给查找区域加 `$` 符号（绝对引用），区域会跟着每一行往下偏移，查出来的值就全错了，甚至直接报 `#N/A`。这是Excel实操里最高频的一个坑，等下实操练习时我会重点检查这一项。"

**数据透视表讲解**：

> "如果我现在要同时按'门店'和'月份'两个维度交叉汇总销售额，用SUMIF要为每个门店×月份的组合写一条公式，表一改字段就要重写。数据透视表不用写公式——**把字段拖到行、列、值三个区域，它自动帮你交叉汇总，改变字段位置就能重新汇总，这是它比手写公式组合更高效的根本原因。**"

**学员活动**：跟随演示操作，在自己电脑上对练习素材做一次COUNTIF计数和一次数据透视表汇总。

### 环节四：实操一——Excel综合练习（85–115′）

**任务书**：

> 给定一份门店销售流水练习素材，请你产出一张汇总表：
> 1. 用 `COUNTIF` 统计每个门店的订单数；
> 2. 用 `SUMIF` 统计每个门店的销售额合计；
> 3. 用 `VLOOKUP` 为每条订单匹配门店负责人姓名；
> 4. 用数据透视表按"门店×月份"交叉汇总销售额。

**巡回指导要点**：

| 常见问题 | 教师应对 |
|---|---|
| VLOOKUP下拉后出现 `#N/A` 或查到错误值 | 检查查找区域是否加 `$` 锁定（绝对引用），现场演示 `F4` 键快速切换相对/绝对引用 |
| COUNTIF条件写成了文本但没加引号 | 提醒"按条件筛选的值如果是文字，要用英文引号括起来" |
| 数据透视表只拖了一个维度 | 追问"门店和月份两个维度都要体现，你现在的透视表只回答了哪一个问题？" |

**学员活动**：独立完成汇总表，遇到问题举手，教师现场排查。

### 环节六：实操二——Python环境安装+Jupyter使用（难点一突破，125–185′）

**讲授脚本（先建立类比理解，再动手）**：

> "装Python之前，先搞懂两个让人发怵的词：**环境变量**、**命令行**。
>
> 命令行，就是不用鼠标点图标，直接打字告诉电脑'做什么'的一个窗口——比如你不点Jupyter的图标，而是打字输入 `jupyter notebook` 回车，效果是一样的，只是换了一种'发指令'的方式。
>
> 环境变量里有一项叫PATH，你可以把它想象成电脑的一张'查找清单'：你在命令行输入 `python`，电脑会按这张清单上登记的路径，一个一个去找有没有一个叫 `python.exe` 的文件。**如果安装时没有勾选'Add Python to PATH'，这张清单里就没有登记这条路径，电脑压根不知道去哪找，输入 `python` 自然就找不到或者跳到别的地方。**"

**教师提醒**：

> "这一步最容易卡住，别慌。如果中途报错或弹窗看不懂，举手，我过来看，**不要自己瞎试着点各种选项**，很多问题是越点越乱，装错了比没装更难排查。"

**安装步骤演示**（投影，逐步进行）：
1. 打开安装包，**务必勾选"Add Python to PATH"**；
2. 完成安装后，打开命令行输入 `python --version` 验证；
3. 安装 Jupyter 相关依赖；
4. 命令行输入 `jupyter notebook` 打开浏览器界面。

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| 输入 `python` 后直接跳转到 Microsoft 应用商店 | "这是Windows系统自带的'占位别名'，不是真的装上了Python，是系统的假动作。说明你的Python要么没装、要么装的时候没把这条路径登记进环境变量。到'设置→应用→高级应用设置→应用执行别名'里把 `python.exe` 关闭，再重新安装一次，安装时注意勾选PATH选项。" |
| 安装完成但 `jupyter notebook` 命令提示"不是内部或外部命令" | "大概率是安装时漏勾了PATH选项，环境变量清单里没登记。按刚才演示的路径重新走一遍安装，这次重点看那个勾选框。" |
| 安装成功，但不确定装的版本对不对 | 投影验证命令："运行这一行代码，能看到pandas、numpy等各个包的版本号，没有报错就说明环境是通的。" |

**验证命令**（投影）：

```bash
python -c "import sys, pandas, numpy, sklearn, matplotlib, PIL, openpyxl; print('python', sys.version.split()[0])"
```

**巡回确认机制**：每完成一个关键步骤（Python安装完成、能打开Jupyter、验证命令无报错），教师在教室前方喊"完成的举手"，确认全员到位再进入下一步，掉队的学员单独跟进，不拖累整体进度，也不让任何人掉队太远。

**板书核心句**：

> **环境变量PATH = 电脑找命令时翻看的一张清单；命令行 = 打字代替点鼠标。**

### 环节七：实操三——运行脚本+读报错定位（难点二突破，185–225′）

**教师活动**：

> "现在我给大家一段代码，故意让它报错，大家自己看报错信息试着解决，解决不了的举手。"

| 报错 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError` | 包未安装（或装到了别的环境里） | `pip install` 对应包名；并确认当前激活的是正确环境 |
| `FileNotFoundError` | 文件路径或当前工作目录不对 | 核对相对/绝对路径，确认"当前工作目录"实际在哪 |
| `UnicodeDecodeError` | 保存编码与读取时指定的编码不匹配 | 尝试指定 `encoding="gbk"` 或 `"utf-8"` |

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| 看到一大段红字就举手求助，没读内容 | 先不直接给答案，引导："别看中间那一堆，往下翻到**最后一行**，它写了什么？"——训练先自己读的习惯 |
| 读到最后一行但不理解英文含义 | 逐词拆解："`ModuleNotFoundError: No module named 'pandas'`——意思是'没找到名字叫pandas的模块'，翻译过来就是这个包没装或者没装对地方" |
| 解决一个报错后很有成就感，主动问还有没有 | 顺势布置变式练习（见下） |

**变式练习（迁移巩固）**：

> "再给大家一个新的报错，这次不告诉你是哪一类——`PermissionError`，提示文件写不进去。自己想想可能是什么原因？"

（真实常见原因：该文件正在Excel中被打开着，占用了写入权限）

**教师总结话术**：

> "**报错不可怕，可怕的是看到报错就直接放弃，不读内容。** Python报错信息通常最后一行是最关键的（错误类型+简要原因），养成先看最后一行的习惯，以后考试现场遇到报错，这个习惯能救你。"

## 七、板书设计

**主板书区**

```
文件与目录管理 → 压缩解压 → 编码识别转换(乱码=编码对不上)
        ↓
Excel核心函数：IF / COUNTIF / SUMIF / VLOOKUP → 数据透视表(拖字段交叉汇总)
        ↓
Python环境：环境变量(查找清单) → 命令行(打字代替点鼠标) → 安装 → Jupyter

┌────────────── 报错排查三步法 ──────────────┐
│ ① 先看最后一行（错误类型 + 简要原因）       │
│ ② 定位报错涉及的文件名/模块名/行号          │
│ ③ 对照常见报错表排查，不盲目重装            │
└──────────────────────────────────────────┘
```

**副板书区（易混淆辨析）**

```
COUNTIF          SUMIF           VLOOKUP
问"有几个"       问"加起来多少"   问"对应的是什么"

三类常见报错：
ModuleNotFoundError  → 包未装对环境  → pip install / 切换环境
FileNotFoundError    → 工作目录不对  → 核对相对/绝对路径
UnicodeDecodeError   → 编码不匹配    → 指定 encoding="gbk"/"utf-8"
```
