## 一、教学目标

### （一）知识目标

1. 能说明数据清洗的**五大目标**：去重、去缺失、去异常、去噪声、统一数据格式。
2. 能说明**清洗必须排在标注之前**的原因——清洗是在给标注员"收拾桌子"，越早清洗，后面标注、质检环节返工成本越低。
3. **能说明清洗必须按既定规范执行、并保留原始数据**——清洗是不可逆操作，不能直接覆盖原文件。

### （二）技能目标

1. **文本清洗**：去重、去空、去乱码、去HTML标签与表情符号、统一编码、过滤超长/超短样本、敏感信息替换。
2. 能用pandas完成结构化与文本数据的自动化清洗，并输出清洗后文件与清洗记录。
3. **视觉清洗**：能识别损坏/重复/模糊/过曝图像，统一分辨率与格式，核对图像与标注文件的对应关系。
4. **语音清洗**：能说明静音/截断/底噪过大音频的识别依据，统一采样率与格式，核对音频与文本的对应关系。
5. **能说明清洗必须保留原始数据**，并能正确执行"另存为新文件"的操作。

### （三）素养目标

1. 建立"**清洗有边界**"的职业意识——删得多了会丢失真实信息（清洗过度），删得少了噪声会污染训练数据（清洗不彻底），两者都是失职。
2. 建立"**不同数据模态的清洗逻辑不能照搬**"的意识——结构化文本能靠代码精确判断的结论，换到图像、语音这类非结构化数据上未必成立，必须结合人工核验。

## 二、教学重点与难点

### 重点

1. 清洗规则必须按既定规范执行，不能凭感觉发挥。
2. 清洗操作不可逆，必须另存为新文件保留原始数据。
3. 文本 / 视觉 / 语音三种模态的清洗逻辑各有侧重，不能用同一套标准照搬套用。

### 难点

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| **难点一**：零基础学员容易"清洗过度"（删掉本该保留的样本）或"清洗不彻底"（遗漏某类问题），需要用真实数据反复练习建立手感 | 看到评价内容字数很多（如超过100字），直接认定"写得认真"而不做检查；看到评价内容很短（如一两个字），觉得"好歹有内容"而放任不处理，忽视这两种情况下真实语义信息都可能严重不足 | 用`reviews_raw.csv`里真实的11条"好评"刷屏600字样本和14条1-2字符极短样本做正反对比练习，让学员亲手验证"长/短不是判断标准，有没有真实语义信息才是" |
| **难点二**：图像、语音等非结构化数据的"重复""异常"判断不能照搬文本清洗"精确匹配"的思路，必须结合人工核验 | 看到文件名含"copy""副本"字样就直接当成完全重复的文件处理；或反过来迷信代码算出的哈希结果，哈希不同就断定"不是重复"，忽视文件名这个强线索 | 用`images/`文件夹里两组真实的"疑似重复"文件（`phone_000.jpg`/`phone_000_copy.jpg`，`laptop_001.jpg`/`laptop_001_副本.jpg`）做实测，发现MD5均不相同，引导学员理解"图像去重不能单靠哈希全匹配，代码结果只是线索，最终要人工目验确认" |

## 三、学情分析与前置知识

**前置知识**：模块一全部课题（数据采集、整理归类、汇总），具备pandas基础操作能力。

**学情判断**：

- 本课题进入模块二"数据标注"，是五级考核权重最大的模块（约35%），需要特别投入教学精力。
- 学员对结构化数据的清洗代码（`isna()`、`duplicated()`这类调用）上手很快，但容易把"代码能算出结果"等同于"问题已经判断清楚"——本课题最大的认知陷阱就在这里：文本清洗里"长度够不够"不能替代"有没有真实语义"的判断，图像清洗里"哈希是否相同"也不能替代"是否确系同一实物"的判断。
- 学员此前接触的"重复"概念基本来自结构化字段（如订单号重复），第一次遇到图像这种非结构化数据的"重复"判断时，容易想当然地套用"完全一致才算重复"的思维，这正是难点二要突破的认知惯性。

---

## 四、教学方法与手段

1. **认知冲突法**（核心）：用真实数据的反直觉结果（刷屏长文本 vs 真实详评、文件名可疑但哈希不同的图片）制造认知冲击，强化"看起来没问题≠真的没问题"的意识。
2. **模态对比法**：把文本清洗与视觉清洗的判断逻辑并置对比，归纳"结构化数据能算、非结构化数据要看"的共同规律。
3. **演示+独立实操法**：教师先演示完整清洗流程，再让学员独立完成巩固，并迁移到新字段（商品ID）和新模态（图像检测清单）上检验是否真正建立手感。
4. **铁律强调法**：对"保留原始数据"这一不容妥协的规则反复强调，直至形成肌肉记忆。

### 环节一：导入（0–10′）

**教师活动** —— 投影展示（不给结论）：

> 某电商平台的一条用户评价：
> **"物流太慢了，等了半个月，联系我 13830093622"**

**提问话术**：

> "这条评价字数适中、情感倾向很明确（抱怨物流慢），也没有乱码和HTML标签——如果现在要把这批625条评价原样交给标注员做情感分类标注，这一条能直接通过吗？举手表决，认为能直接用的请举手。"

（预期：多数学员认为可以，因为"内容完整、看得懂"）

> "好，先记住你的判断。接下来我们用代码把这625条评价全部检测一遍，看看'看起来没问题'和'真的没问题'差多少。"

**设计意图**：不直接点破问题所在，让"内容完整=没问题"的直觉判断先被公开表达，为后面"含手机号"检测结果的反转积蓄冲击力。

---

### 环节二：新授——清洗目标与流程位置（10–35′）

**讲授脚本**：

> "数据标注这个职业功能下的第一步工作，不是标注，是清洗。为什么清洗必须排在标注之前，而不是先标注、标完了再清洗？"

（引导学员思考，给出30秒）

> "想象一下：如果一条重复记录没有提前清洗掉，标注员会把它当成两条不同样本各标一遍，工时直接浪费一倍；如果一条评价里混着`<br>`这种HTML标签没清理，标注员盯着这种夹杂标签的文本，判断情感时注意力会被干扰，甚至可能把标签当成文本内容去理解。**清洗，就是提前把桌子收拾干净，让标注员专心做判断，而不是让他们一边标注一边替你擦桌子。**"

**板书核心句**：清洗的五大目标——去重 / 去缺失 / 去异常 / 去噪声 / 统一格式

**逐项讲解**（投影 + 举例）：

| 目标 | 要解决的问题 | 不处理的后果 |
|---|---|---|
| 去重 | 同一条记录被重复采集/上传 | 该样本在训练中被过度加权 |
| 去缺失 | 关键字段为空 | 无法支撑后续标注或统计 |
| 去异常 | 字段取值超出合理范围 | 污染统计结果，误导模型学习 |
| 去噪声 | 格式残留、乱码、表情符号等非语义内容 | 干扰标注判断，浪费标注工时 |
| 统一格式 | 编码、全半角、命名规则不一致 | 后续程序处理时被误判为不同类别 |

**强调（对应重点一）**：

> "这五类问题该怎么判断、怎么处理，答案不是'你觉得'，而是标注规范里写好的既定规则。**清洗规则必须按规范执行，不能凭感觉发挥**——这是本课题最基本的纪律，也是以后'清洗规范制定'这项更高阶能力的前提：得先有人按统一标准认真执行，才谈得上评估执行得好不好。"

**学员活动**：记录五大目标，口头举一个自己熟悉场景（如手机相册、聊天记录）里可能存在的"重复/缺失/异常/噪声/格式不统一"的例子，教师随机抽问2-3人。

### 环节三：实操一——文本全流程清洗（难点一突破，35–100′）

**教师指令**：

> "打开Jupyter。回到开头那条手机号评价——我们现在用代码，把这625条评价全部检测一遍。"

**投影代码**（学员照抄运行）：

```python
import pandas as pd

df = pd.read_csv("../数据集/reviews_raw.csv")
n_raw = len(df)
s = df["评价内容"].astype(str)

print("总记录数:", n_raw)
print("重复行:", df.duplicated().sum())
print("空/空白评价:", s.str.strip().eq("").sum())
print("含HTML标签:", s.str.contains("<").sum())
print("非法评分:", (~df["评分"].between(1, 5)).sum())
print("极短样本(1-2字符):", ((s.str.strip().str.len() >= 1) & (s.str.strip().str.len() <= 2)).sum())
print("超长样本(>=100字符):", s.str.len().ge(100).sum())
print("含手机号:", s.str.contains(r"1[3-9]\d{9}").sum())
```

**预期输出**（已实测验证，学员结果应完全一致）：

```
总记录数: 625
重复行: 25
空/空白评价: 10
含HTML标签: 30
非法评分: 12
极短样本(1-2字符): 14
超长样本(>=100字符): 11
含手机号: 5
```

> 📌 **教学提示**：以上每一项都是在原始625条数据上**各自独立统计**的，不是依次过滤后统计的——同一条记录可能同时命中多个问题。所以这7个数字加起来不等于"清洗前减清洗后的行数差"，撰写清洗记录时要讲清楚统计口径，不能把各项数字直接相加当成"总共清洗掉多少条"。

**学员活动**：运行代码，核对输出是否与投影一致；在清洗记录表里逐项抄录7个数字。

**关键提问一**（难点突破核心，长度陷阱——超长样本）：

> "大家运行一下 `df.loc[s.str.len()>=100, "评价内容"].head(3)`，看看超长样本里具体写了什么。"

（学员运行后看到：600字"好评好评好评……"重复堆砌文本）

> "这条600字的评价，字数远超其他评论——按'字数多说明写得认真'的直觉，要不要留着？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "留着，字数这么多说明用户写得很用心" | 追问："你看这600字里有多少种不同的信息？读完这600字，你比读'好评'两个字多知道了什么？" —— 引导意识到重复堆砌没有增加任何真实语义 |
| "删掉，这明显是刷的" | 肯定："对，这11条全部是同一种模式——重复堆砌'好评'二字凑字数。这种文本对模型训练没有价值，反而可能让模型学到'写得越啰嗦权重越高'这种错误规律。" |
| 答不上来 | 引导："假设你是标注员，要给这条评价打情感标签，光看这600字，你能提炼出比'好评'两个字更多的信息吗？" |

**关键提问二**（难点突破核心，长度陷阱——极短样本）：

> "刚才的空/空白评价是10条，这是完全没写内容的。但还有14条，strip之后只有1到2个字符，比如单独一个'嗯'、一个句号。这14条算不算'有内容'？要不要清洗掉？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "算有内容，好歹写了字，不用处理" | 追问："这个'嗯'字，标注员能从里面判断出用户是满意还是不满意吗？" —— 引导意识到"有字符"不等于"有判断依据" |
| "应该清洗掉，和空白是一类问题" | 肯定并区分："方向对，但注意这14条和空白评价**不是同一类**——空白是真的什么都没写，这14条是写了，但信息量不足以支撑标注判断。处理上可以归入同一类'过短样本'统一按阈值过滤，但清洗记录里要分开记数，不能混为一谈。" |

**教师总结话术**：

> "这两个提问合在一起，就是今天最容易踩的坑——**有人看到'长'就不敢删，有人看到'短'就懒得管**。记住：**判断标准不是字数，是这条文本有没有真实、独立的语义信息。** 这就是'清洗过度'和'清洗不彻底'这对难点在今天的数据里具体的样子——只按长度设一道阈值线，长的一律放过会漏掉刷屏文本（清洗不彻底），短的一律放过会留下无效样本（也是清洗不彻底）；反过来如果看见长文本就不分青红皂白删掉，又会把认真写的详细评论一起误伤（清洗过度）。"

**手机号处理演示**（回扣导入环节）：

> "回到开头那条评价。手机号这种问题，能不能直接把整条记录删掉？"

（引导学员意识到：整条删除会连带丢失评分、情感倾向这些有效信息，属于清洗过度；但原样保留又是信息安全问题）

> "正确做法是**局部处理**——把手机号替换成占位符，其余内容原样保留。"

```python
df["评价内容"] = s.str.replace(r"1[3-9]\d{9}", "[手机号]", regex=True)
```

**板书核心句**：判别口诀——这条记录除了这个问题还有没有其他有效信息？有 → 局部处理；没有 → 整条剔除。

**完整清洗脚本**（学员独立运行）：

```python
df = df.drop_duplicates()
df["评价内容"] = df["评价内容"].astype(str).str.replace(r"<[^>]+>", "", regex=True)
df["评价内容"] = df["评价内容"].str.replace(r"1[3-9]\d{9}", "[手机号]", regex=True)
df = df[df["评价内容"].str.strip().str.len() > 2]          # 剔除空白与极短样本
df = df[df["评价内容"].str.len() < 100]                     # 剔除刷屏式超长样本
df = df[df["评分"].between(1, 5)]

df.to_csv("reviews_cleaned.csv", index=False, encoding="utf-8-sig")
print(f"清洗前 {n_raw} 行 → 清洗后 {len(df)} 行")
```

**学员活动**：独立运行完整清洗脚本，核对清洗前后行数变化，保存产出的 `reviews_cleaned.csv`。

### 环节七：实操三——图像批量检测与人工复核（难点二突破，175–235′）

**教师指令**：

> "打开Jupyter，运行下面的代码，验证你刚才的预测。"

**投影代码**（学员照抄运行）：

```python
import os, hashlib
from PIL import Image
from collections import Counter

img_dir = "../数据集/images"
files = sorted(os.listdir(img_dir))
print("图片总数:", len(files))

sizes = Counter()
for f in files:
    with Image.open(os.path.join(img_dir, f)) as im:
        sizes[im.size] += 1
print("分辨率分布:", dict(sizes))

suspects = [f for f in files if "copy" in f.lower() or "副本" in f]
print("文件名疑似重复:", suspects)

for f in suspects:
    base = f.replace("_copy", "").replace("_副本", "")
    h1 = hashlib.md5(open(os.path.join(img_dir, f), "rb").read()).hexdigest()
    h2 = hashlib.md5(open(os.path.join(img_dir, base), "rb").read()).hexdigest()
    print(f, "vs", base, "→ MD5相同:", h1 == h2)
```

**实测结果**（已验证）：

```
图片总数: 42
分辨率分布: {(640, 480): 37, (1280, 960): 1, (320, 240): 4}
文件名疑似重复: ['laptop_001_副本.jpg', 'phone_000_copy.jpg']
laptop_001_副本.jpg vs laptop_001.jpg → MD5相同: False
phone_000_copy.jpg vs phone_000.jpg → MD5相同: False
```

**关键提问**（难点突破核心）：

> "两组文件的MD5，结果是'相同'还是'不同'？和你刚才的预测一样吗？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "预测相同，结果不同，没想到" | 追问："文件名都写明了copy/副本，为什么字节内容会不一样？" —— 引导学员想到"重新保存/压缩会改变底层字节，但人眼看不出来" |
| "哈希不同，说明确实不是重复，可以放心当成两张不同的图" | 纠正："先别这么快下结论——打开这两张图实际看一下内容。"（组织学员用图片查看器打开`phone_000.jpg`和`phone_000_copy.jpg`对比）"看完之后，这两张还能说'不是重复'吗？" |

**教师总结话术**：

> "这就是图像清洗和文本清洗最根本的区别：**文本的'一样'是字符完全相等，算法能精确判断；图像的'一样'是看起来一样，哪怕只是重新保存一次、压缩质量调整一点点，底层字节就会变，哈希自然就不同了。** 哈希比对算出来的结果只是一个**线索**，不是**结论**。遇到文件名高度可疑但哈希不同的情况，必须人工打开图片确认，不能让代码替你做最终判断。"

**分辨率检测环节**：

> "再看一下分辨率统计结果——42张图里，37张是标准的640×480，但有4张只有320×240，1张是1280×960。这些不统一的分辨率会带来什么问题？"

（引导学员答出：后续标注和模型训练时输入尺寸不一致，需要统一缩放处理）

**视觉清洗检查清单**（投影 + 讲义已有）：

| 检查项 | 做法 |
|---|---|
| 损坏文件 | 用 `Image.open().verify()` 逐张校验能否正常打开（本批次42张实测全部可正常打开，但生产环境中仍必须执行此步骤） |
| 重复图像 | 哈希/文件名线索 + 人工目验，不能只信哈希结果 |
| 模糊/过曝图像 | 人工抽查，剔除无法辨认主体的图片 |
| 分辨率/格式统一 | 统一缩放到规范尺寸，统一保存格式 |
| 图像与标注文件对应关系 | 核对文件名与标注记录是否一一对应，避免错位 |

**学员活动**：对42张图片逐一查看分辨率检测结果，列出需要统一处理的文件清单；对2组疑似重复图像打开人工核验，写出核验结论（是否确系同一实物的重复图像，应保留哪一张）。

### 环节九：新授——语音清洗要点（245–270′）

**讲授脚本**：

> "语音和图像一样，都是非结构化数据，清洗时不能靠一行pandas代码扫完。本课题的数据集不包含音频样本——这是如实告诉大家：音频文件体积大，需要真实录音素材，程序没法合成出有教学意义的音频。这节我们重点建立'该检查什么、为什么'的判断依据，实际操练请结合后续课题提供的真实音频素材。"

**逐项讲解**（投影 + 举例）：

| 问题 | 为什么必须清洗掉 |
|---|---|
| 静音片段 | 整段没有说话内容，对模型训练无信息增量，反而会让模型学到"大段静音也是正常样本"的错误规律 |
| 截断音频 | 录音开始或结束被切断，可能丢失关键语义，标注员会面对不完整信息做判断 |
| 底噪过大 | 背景噪声掩盖人声，轻则影响转写准确率，重则导致整段无法辨识 |
| 采样率/格式不统一 | 和图像分辨率不统一是同一类问题——混合不同采样率的音频直接输入模型，会造成特征尺度不一致 |
| 音频与文本对应关系错位 | 语音文件和转写文本因命名/排序问题对应错了，标注员会对着A的录音看着B的文本做判断 |

**教师提问**（判断练习，无需数据集即可思考）：

> "一段10秒的客服录音，中间有2秒是电话另一端的忙音提示音，不是人声。这2秒应该怎么处理？整条录音作废吗？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "整条删掉，因为混进了噪声" | 追问："前后8秒的人声内容完整、能听清楚，这8秒的信息就这么浪费掉，值得吗？" —— 引导意识到局部问题不该整条剔除 |
| "标记这2秒为非人声片段，其余保留" | 肯定："对。这和前面文本清洗里手机号的处理是同一个道理——先看问题影响的范围，局部问题局部处理，不要因小失大整条剔除。" |

**学员活动**：记录语音清洗检查清单，总结"局部处理 vs 整条剔除"的判断依据可以跨模态通用。
