## 一、教学目标

### 知识目标
1. 能说清汇总的常见统计口径（计数、求和、均值、占比），并说出 Excel 数据透视表与 pandas `groupby`/`agg`/`pivot_table` 之间的对应关系。
2. **能说明"先归类、再汇总"这个顺序背后的机制**——为什么跳过归类直接汇总会导致结果失真，而不只是记住这句结论。

### 技能目标
1. **能根据数据处理要求完成业务数据汇总**。
2. 能用 Excel 数据透视表与 pandas 的 `groupby`/`agg`/`pivot_table` 完成同样的汇总任务。
3. **能对汇总结果做合理性自查**（总数是否对得上、占比是否为100%、有无异常极值）。

### 素养目标
1. 建立"**汇总结果出来之后，先自查再相信**"的职业习惯——这是本课题作为职业功能1收官课，对前三课题"采集-处理-整理"成果的最后一道质量关卡。

---

## 二、教学重点与难点

**重点**：归类不彻底会直接导致汇总结果失真——与课题1-3形成直接呼应。

**难点**：零基础学员容易跳过"先归类统一、再汇总"这一步，直接对未处理的原始数据做分组统计，得到错误结论而不自知。

---

## 三、学情分析与前置知识

学员刚学完课题1-3的归类整理，本课题与其形成直接呼应，是检验学员是否真正理解"归类先于汇总"这个顺序的关键一课。容易出现"上节课学过了，这节课直接汇总"的跳步心理，需要用同一份数据的对比结果再次强化这个顺序意识。本课题还是职业功能1（数据采集和处理）的收官课题，学情上还需要关注学员是否能把1-1(采集)→1-2(SQL采集)→1-3(整理归类)→1-4(汇总)这四课串成一条完整的数据处理链条，而不是把每一课当成孤立的技能点。

---

## 四、教学方法与手段

1. **前后对比法**：同一份数据，归一化前后两次汇总，直观展现差异。
2. **工具迁移法**：Excel和pandas各做一遍，强化操作迁移能力。
3. **自查习惯养成法**：用一个真实存在于本批数据中的"占比加不满100%"案例，让学员亲手发现问题，而不是空讲"要自查"。

### 环节二：新授——常见汇总口径与工具对应（15–35′）

**讲授脚本**：

> "汇总，说白了就是把一堆明细记录按某个维度（比如商品类别、销售地区）分组，然后在每组里面做统计。最常见的四种统计口径是：**计数**（这个类别有多少条记录）、**求和**（这个类别总共卖了多少件/多少钱）、**均值**（平均客单价）、**占比**（这个类别占整体的百分之多少）。
>
> 做这件事，Excel里对应的工具是**数据透视表**；pandas里对应三个工具：**groupby**（先按字段分组）、**agg**（分组后一次性算出一个或多个统计量）、**pivot_table**（分组 + 行列交叉，一步到位）。工具不同，解决的是同一个问题。"

**板书对照表**：

| 统计口径 | Excel | pandas |
|---|---|---|
| 计数 | 数据透视表值字段设为"计数项" | `df.groupby("字段").size()` |
| 求和 | 数据透视表值字段设为"求和项" | `df.groupby("字段")["数值列"].sum()` |
| 多指标同时算 | 值区域拖入多个字段 | `df.groupby("字段").agg(...)` |
| 行列交叉汇总 | 字段同时拖到"行"与"列" | `df.pivot_table(index=, columns=, values=, aggfunc=)` |

**学员活动**：记录对照表；口头举一个自己熟悉场景里的"汇总"例子（如按月份汇总考勤迟到次数）。

### 环节三：实操一——对比归一化前后的汇总结果（难点突破，35–85′）

**教师指令**：

> "打开 Jupyter，我们来验证一下导入环节那份'手机品类垫底'的报告，到底对不对。"

**投影代码**（学员照抄运行）：

```python
import pandas as pd
d = pd.read_csv("../数据集/sales_raw.csv")

print("归一化前（按商品类别计数）：")
print(d["商品类别"].value_counts().to_dict())

print("归一化前（按原始写法汇总销售数量）：")
print(d.groupby("商品类别")["销售数量"].sum().to_dict())

d["商品类别"] = d["商品类别"].str.strip().replace({"手機": "手机"})

print("归一化后（按商品类别计数）：")
print(d["商品类别"].value_counts().to_dict())

print("归一化后（按商品类别汇总销售数量）：")
print(d.groupby("商品类别")["销售数量"].sum().to_dict())
```

**实测**（已验证）：

```
归一化前（计数）：耳机104 笔记本电脑96 手机94 平板89 智能手表84 手機21 手机(尾空格)20
归一化前（销售数量求和，三种写法分开统计）：手机927 手机(尾空格)189 手機235
归一化后（计数）：手机135 耳机104 笔记本电脑96 平板89 智能手表84
归一化后（销售数量求和）：手机1351 耳机955 笔记本电脑921 平板787 智能手表780
```

**关键提问（难点突破核心）**：

> "运营报告里说'手机只卖了94单、927件，垫底'。但归一化之后呢？——135单、1351件，是五个品类里**卖得最多**的。927件和1351件，手机的真实销量被低估了多少？"

（引导学员算出 (1351−927)/1351 ≈ **31%**，接近三成）

**预期学员反应与应对**：

| 学员反应 | 教师应对 |
|---|---|
| "会，可能就砍掉这个品类的采购了" | 肯定："对，这就是真实的业务后果——一个归类没做干净的技术失误，变成了一个错误的业务决策。而且这个低估不是小数目，接近三成。" |
| "不会啊，业务方应该知道数据有问题" | 纠正："业务方看到的只是一份'汇总报告'，他们不知道背后数据处理是否规范，他们只能相信这个数字。错误的责任在做汇总的人，不在业务方。" |
| 算错百分比或说不清楚怎么算低估比例 | 引导："低估的量是1351−927=424件，拿这个'少算的量'除以'真实总量'1351，而不是除以'错误统计的量'927——这样算出来的才是'相对真实值被低估了多少'。" |

**教师总结**：

> "这就是为什么课题1-3强调的'先归类再汇总'不是形式主义——同样的508条原始数据，不归类统计，手机是垫底品类，差点被砍掉采购预算；归类之后，手机反而是销量最高的品类。**汇总前的归类整理，直接决定了一个业务决策的方向是对的还是错的**。这也是为什么要求'对汇总结果做合理性自查'——拿到一个汇总结果，要反问自己：这个数字看起来合理吗？有没有可能是归类没做干净导致的失真？"

**回扣导入**：

> "现在回答开头的判断——这份'手机垫底、建议砍半采购'的报告可信吗？不可信，它漏算了另外两种写法的41条记录，真实销量被低估了约三成。"

### 环节五：实操二——Excel透视表 + pandas groupby/agg/pivot_table 双实现（95–175′）

**任务书**（投影 + 讲义附）：

> 用课题1-3整理归类好的508条数据，分别用Excel和pandas完成下面三项汇总任务：
> 1. 按商品类别统计订单数、总销量；
> 2. 按商品类别 × 销售地区做交叉汇总，统计各地区各品类的销售数量；
> 3. 计算各商品类别的销量占比。

**Excel操作讲解**：

> "插入数据透视表：把'商品类别'拖到'行'区域；把'订单编号'拖到'值'区域并设为'计数项'，统计订单数；把'销售数量'也拖到'值'区域并设为'求和项'，统计总销量。想要交叉汇总，再把'销售地区'拖到'列'区域即可，Excel会自动生成商品类别×地区的交叉表。"

**pandas核心代码**（投影，学员照抄）：

```python
# groupby + agg：一次性算出订单数与总销量
summary = d.groupby("商品类别").agg(
    订单数=("订单编号", "count"),
    总销量=("销售数量", "sum")
)
print(summary)

# pivot_table：商品类别 × 销售地区 交叉汇总
cross = d.pivot_table(index="商品类别", columns="销售地区", values="销售数量", aggfunc="sum")
print(cross)

# 占比
share = summary["总销量"] / summary["总销量"].sum()
print(share.round(3))
```

**实测**（已验证）：

```
        订单数   总销量
手机     135    1351
耳机     104     955
笔记本电脑 96     921
平板      89     787
智能手表   84     780
```

**学员活动**：独立在Excel和pandas里各做一遍，核对两边算出的"手机总销量"是否都是1351——核对不一致说明哪一边的操作有误。

**巡回指导要点**：
- 检查pandas代码是否先执行了归类处理（`strip`/`replace`）再汇总——这是对难点的二次检验；
- 检查Excel透视表"值字段"是否正确设为"求和项"而非默认的"计数项"——这是Excel新手最常见的操作失误。

### 环节六：变式练习——地区字段汇总误差复现（难点二次巩固，175–205′）

**教师指令**：

> "换一个字段练手：销售地区。这个字段我们还没做过归类整理，大家先直接做分组汇总，看看会发生什么。"

**投影代码**：

```python
print("销售地区原始取值:", d["销售地区"].value_counts().to_dict())
clean = d[d["销售地区"].isin(["华南","华东","东北","西南","华北"])]
print("只统计这5种'干净'写法的记录数:", len(clean), " / 总行数:", len(d))
print("占比:", round(len(clean)/len(d), 3))
```

**实测**（已验证）：

```
销售地区原始取值：{'华南':97,'华东':96,'东北':95,'西南':93,'华北':90,
                 '  东北 ':10,'  华东 ':10,'  华北 ':7,'  华南 ':5,'  西南 ':5}
只统计5种"干净"写法：471条 / 总行数508条，占比92.7%
```

**关键提问**：

> "如果这时候你直接拿这471条做地区销售占比汇总，五个地区的占比加起来会是多少？是100%吗？"

**预期学员反应与应对**：

| 学员反应 | 教师应对 |
|---|---|
| "是不是代码算错了/系统有问题" | 追问："会不会是数据本身的问题，而不是代码的问题？把这5种'干净'写法和原始取值表再对一遍——漏了哪些？" |
| "是因为有带空格的重复写法没被归进去" | 肯定："对，这和讲义随堂练习1里'各地区销售额占比加起来只有92%'是同一个真实原因——不是系统出错，是字段写法没有统一归类，36条带空格的记录没被任何一个'干净'类别统计进去。" |

**教师总结**：

> "这件事提醒我们一个通用的自查习惯：**拿到一份分组汇总结果，先把各组占比加起来看看是不是接近100%（或总数是否对得上总行数）。如果不是，第一反应不该是怀疑系统出错，而应该先怀疑——是不是有没被归类进任何一组的'漏网'写法？**"

**学员活动**：运行 `d["销售地区"].str.strip()` 重新归类，验证占比恢复到100%，与刚才对商品类别做的操作形成呼应对照。

```
│ → 若只看未归类的"手机"一行，销量被低估约31%！        │
└──────────────────────────────────────────────────────┘

┌──────────────── 实测反差：销售地区 ────────────────┐
│ 带空格写法未归类前：只统计5种"干净"写法 = 471条       │
│ 总行数 = 508条 → 占比只有 92.7%                     │
│ → 消失的 7.3%，正是写法没统一导致的"漏统计"          │
└──────────────────────────────────────────────────────┘
```
