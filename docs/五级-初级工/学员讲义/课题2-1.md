## 一、清洗目标：为什么清洗必须排在标注之前

> 清洗的目标：去除重复、缺失、异常、噪声数据，统一数据格式。

先回答一个更基础的问题：**为什么清洗一定要放在标注之前，而不是先标注、标完了再清洗？**

想象一下：如果一条重复记录没有被提前清洗掉，标注员会把它当成两条不同的样本分别标注一遍——标注工时就这样白白浪费了一倍；如果一条评价里混着`<br>`这种HTML标签没清理，标注员看着这种夹杂标签的文本，判断情感时注意力会被干扰，甚至可能把标签本身当成文本内容去理解。**清洗，相当于提前把桌子收拾干净，让标注员专心做判断，而不是让他们一边标注一边替你擦桌子。** 这也是为什么清洗工作排在"数据标注"这个职业功能的最前面。

五大清洗目标，分别对应着数据的五种"不干净"状态：

| 目标 | 要解决的问题 | 不处理的后果 |
|---|---|---|
| 去重 | 同一条记录被重复采集/上传 | 该样本在训练中被过度加权，模型对它过拟合 |
| 去缺失 | 关键字段为空 | 无法支撑后续标注或统计 |
| 去异常 | 字段取值超出合理范围 | 污染统计结果，误导模型学习 |
| 去噪声 | 格式残留、乱码、表情符号等非语义内容 | 干扰标注判断，浪费标注工时 |
| 统一格式 | 编码、全半角、命名规则不一致 | 后续程序处理时被误判为不同类别 |

## 二、文本清洗实操：长度不是判断标准

运行下面这段代码，把625条评价全部检测一遍：

```python
import pandas as pd

df = pd.read_csv("../数据集/reviews_raw.csv")
n_raw = len(df)
s = df["评价内容"].astype(str)

print("总记录数:", n_raw)
print("重复行:", df.duplicated().sum())
print("空/空白评价:", s.str.strip().eq("").sum())
print("含HTML标签:", s.str.contains("<").sum())
print("非法评分:", (~df["评分"].between(1, 5)).sum())
print("极短样本(1-2字符):", ((s.str.strip().str.len() >= 1) & (s.str.strip().str.len() <= 2)).sum())
print("超长样本(>=100字符):", s.str.len().ge(100).sum())
print("含手机号:", s.str.contains(r"1[3-9]\d{9}").sum())
```

**实测**（已验证，你的结果应与此完全一致）：

```
总记录数: 625
重复行: 25
空/空白评价: 10
含HTML标签: 30
非法评分: 12
极短样本(1-2字符): 14
超长样本(>=100字符): 11
含手机号: 5
```

> 📌 以上每一项都是在原始625条数据上**各自独立统计**的，不是依次过滤后统计的——同一条记录完全可能同时命中多个问题（比如一条评价既重复又含HTML）。所以这7个数字加起来并不等于"625减去清洗后剩余条数"，这一点在撰写清洗记录时要注意，不要把各项数字直接相加当成"总共清洗掉多少条"。

现在回到开篇那道判断题——"物流太慢了，等了半个月，联系我 13830093622"。表面上语义完整、没有乱码，但它命中了"含手机号"这一项（本批数据里共有5条）。**这就是为什么只看"字数够不够、语义通不通"是不够的，必须按完整的清洗规则逐项过一遍，哪怕看起来再正常的文本也不能跳过检测。**

### 长度不是判断标准：两组反直觉的真实样本

**先看超长样本（≥100字符，共11条）**。打开看看它们的内容：

```python
print(df.loc[s.str.len() >= 100, "评价内容"].iloc[0][:40], "...")
```

```
好评好评好评好评好评好评好评好评好评好评好评好评好评好评好评好评 ...（共600字，重复堆砌"好评"二字）
```

11条超长样本，**全部**是这种"好评"二字重复刷出来的600字文本，不是详细认真的长评论。

**再看极短样本（strip后1-2字符，共14条）**，内容例如：`。`、`嗯`、`好`。这14条和前面统计的"空/空白评价10条"是**两类不同的问题**——10条是连一个字都没有的真空，这14条是**写了内容，但内容量几乎为零**。

两组数据放在一起，才能看清本课题最容易踩的坑：

| | 超长样本（11条） | 极短样本（14条） |
|---|---|---|
| 字数 | 600字，看起来"内容很多" | 1-2字，看起来"内容太少" |
| 真实信息量 | **几乎为零**（纯重复堆砌） | **几乎为零**（无实质描述） |
| 新手常见误判 | "这么长肯定是认真写的，别删" | "好歹写了点东西，不算有问题" |

> ⚠️ **机制说明**：清洗不是"按字数卡阈值"的游戏。字数只是一个容易拿到的代理指标，真正要判断的是**这条文本有没有真实、独立的语义信息**。600字的"好评"刷屏文本，字数虽然达标，但本质和空白文本一样——没有任何可供模型学习的情感表达细节；1-2个字的"嗯""好"，虽然有内容，但信息量同样不足以支撑标注员做出有依据的情感判断。**这正是"清洗过度"和"清洗不彻底"这对难点在本课题里的具体体现**：只按长度简单设一道阈值线，长的一律放过、短的一律放过，看起来"没有清洗错"，实际上该清掉的噪声留了下来（清洗不彻底）；反过来如果看见长文本就一律当异常删掉，又会错杀真正认真写的详细评论（清洗过度）。**清洗规则必须按内容性质设计，而不是按表面长度设计。**

### 含手机号的样本：为什么不能直接删，也不能放任不管

5条含手机号的评价，**既不应该直接整条删除，也不能原样放进标注队列**。

- 如果**整条删除**：这条评价里的评分、情感倾向这些有效信息也被一起丢掉了，是清洗过度。
- 如果**原样保留**：用户的真实手机号被暴露给标注员甚至后续所有接触这批数据的人，是数据安全事故。

正确做法是**替换为占位符，保留其余语义**：

```python
df["评价内容"] = s.str.replace(r"1[3-9]\d{9}", "[手机号]", regex=True)
```

处理后，"物流太慢了，等了半个月，联系我 13830093622" 变成 "物流太慢了，等了半个月，联系我 [手机号]"——**负面情绪、抱怨物流这些真正要标注的信息完整保留，敏感信息被安全移除。**

> 🔑 **判别口诀**：遇到"问题文本该怎么处理"，先问——**这条记录除了这个问题之外，还有没有其他有效信息？** 有 → 局部处理（替换/剥离问题部分），不要整条删；没有（如刷屏文本、空白、极短无意义内容）→ 整条剔除。

### 完整清洗脚本

```python
df = df.drop_duplicates()
df["评价内容"] = df["评价内容"].astype(str).str.replace(r"<[^>]+>", "", regex=True)
df["评价内容"] = df["评价内容"].str.replace(r"1[3-9]\d{9}", "[手机号]", regex=True)
df = df[df["评价内容"].str.strip().str.len() > 2]          # 剔除空白与极短样本
df = df[df["评价内容"].str.len() < 100]                     # 剔除刷屏式超长样本
df = df[df["评分"].between(1, 5)]

df.to_csv("reviews_cleaned.csv", index=False, encoding="utf-8-sig")
print(f"清洗前 {n_raw} 行 → 清洗后 {len(df)} 行")
```

## 三、视觉清洗实操：图像的"重复"不能照搬文本的判断逻辑

开篇先问一个问题：**文本去重用 `df.duplicated()` 一行代码就能精确识别。图像的重复判断，能不能也套用同一个思路——算出每张图片的哈希值，哈希相同就是重复？**

**先别急着回答，看一组真实数据。**

数据集 `images/` 文件夹里有42张商品图片。其中有两组文件名看起来高度可疑：

- `phone_000.jpg` 和 `phone_000_copy.jpg`
- `laptop_001.jpg` 和 `laptop_001_副本.jpg`

文件名里的"copy""副本"几乎是在明示"这是重复文件"。用代码验证一下：

```python
import os, hashlib
from PIL import Image
from collections import Counter

img_dir = "../数据集/images"
files = sorted(os.listdir(img_dir))
print("图片总数:", len(files))

sizes = Counter()
for f in files:
    with Image.open(os.path.join(img_dir, f)) as im:
        sizes[im.size] += 1
print("分辨率分布:", dict(sizes))

suspects = [f for f in files if "copy" in f.lower() or "副本" in f]
print("文件名疑似重复:", suspects)

for f in suspects:
    base = f.replace("_copy", "").replace("_副本", "")
    h1 = hashlib.md5(open(os.path.join(img_dir, f), "rb").read()).hexdigest()
    h2 = hashlib.md5(open(os.path.join(img_dir, base), "rb").read()).hexdigest()
    print(f, "vs", base, "→ MD5相同:", h1 == h2)
```

**实测结果**（已验证）：

```
图片总数: 42
分辨率分布: {(640, 480): 37, (1280, 960): 1, (320, 240): 4}
文件名疑似重复: ['laptop_001_副本.jpg', 'phone_000_copy.jpg']
laptop_001_副本.jpg vs laptop_001.jpg → MD5相同: False
phone_000_copy.jpg vs phone_000.jpg → MD5相同: False
```

**两组文件的 MD5 都不相同。** 如果按"哈希相同才算重复"的思路写去重代码，这两组文件会被判定为"不重复"，照样会被当成两张不同的图片分别标注——但从文件名看，它们大概率是同一张商品图的两个版本（比如重新保存、压缩、轻微裁切过）。

> 📌 **为什么会这样**：文本的"重复"判断的是**字符串是否完全相等**——只要内容一字不差，`duplicated()` 就能百分之百抓出来。但图像文件的 MD5 是对**整个文件的二进制内容**做哈希，哪怕只是重新用图片软件保存一次、压缩质量调整了1%，哪怕人眼完全看不出区别，底层的字节流就已经不同，MD5 自然也会不同。**图像的"一样"是"看起来一样"，不是"字节级完全一样"**，这是图像/语音这类非结构化数据和结构化文本最根本的区别。
>
> 正确的处理思路：**文件名里的"copy""副本"这类线索不能忽略，哈希比对不一致不代表就不是重复——遇到这种情况，要点开两张图片人工目验确认**，确认是同一实物的重复拍摄/重复保存后，再决定保留哪一张、删除哪一张（通常保留文件名更规范、清晰度更高的一张）。

> 🔑 **判别口诀**：结构化的数据能靠代码"算"出结论（如文本精确匹配）；非结构化数据的清洗，代码算出来的只是**线索**，最终判断往往还要人工"看"一眼才能确认。

除了疑似重复，这批图片还有一个需要统一处理的问题——**分辨率不一致**：42张图片里37张是标准的640×480，但有4张（`laptop_005.jpg`、`laptop_033.jpg`、`watch_011.jpg`、`watch_019.jpg`）只有320×240（标准尺寸的四分之一面积），还有1张（`headphone_026.jpg`）是1280×960（标准尺寸的4倍面积）。如果不统一分辨率直接混合使用，后续标注工具里框选同样大小的物体会呈现完全不同的像素尺度，也会给后续模型训练带来输入尺寸不一致的问题，必须在清洗阶段统一缩放到统一规格。

视觉清洗完整的检查清单：

| 检查项 | 做法 |
|---|---|
| 损坏文件 | 用 `Image.open().verify()` 逐张校验能否正常打开（本批次42张实测全部可正常打开，但生产环境中仍必须执行此步骤，不能因为"这批没问题"就跳过） |
| 重复图像 | 哈希/文件名线索 + 人工目验，不能只信哈希结果 |
| 模糊/过曝图像 | 人工抽查或用清晰度算法辅助筛查，剔除无法辨认主体的图片 |
| 分辨率/格式统一 | 统一缩放到规范尺寸，统一保存格式 |
| 图像与标注文件对应关系 | 核对文件名与标注记录是否一一对应，避免错位 |

## 四、语音清洗要点：无专属数据集，重点建立判断依据

> ⚠️ 本课题随发的实操数据集不含音频样本（音频文件体积大，需要真实录音素材，不适合程序合成），语音清洗的实操练习请结合授课机构提供的音频样本或公开语音数据集进行。这里重点讲清楚**该检查什么、为什么要检查**。

语音清洗要处理的典型问题：

| 问题 | 为什么必须清洗掉 |
|---|---|
| 静音片段 | 整段没有说话内容，对语音识别/情感模型训练无信息增量，反而会让模型学到"大段静音也是正常样本"这种错误规律 |
| 截断音频 | 录音开始或结束被切断，可能丢失关键语义，若用于转写标注，标注员会面对不完整的信息做判断 |
| 底噪过大 | 背景噪声掩盖了人声，轻则影响转写准确率，重则导致整段无法辨识，必须剔除或做降噪处理后复核 |
| 采样率/格式不统一 | 和图像分辨率不统一是同一类问题——混合不同采样率的音频直接输入模型，会造成特征尺度不一致 |
| 音频与文本对应关系错位 | 如果语音文件和对应的转写文本因为命名或排序问题对应错了，标注员会对着A的录音看着B的文本做判断，产出的是完全错误的数据 |

**练习判断**（无需数据集即可思考）：如果一段10秒的客服录音，中间有2秒是电话另一端的忙音提示音（不是人声），这2秒应该怎么处理？

**参考思路**：不是整段音频作废，而是先判断这2秒是否影响整体语义的可理解性——如果前后8秒的人声内容仍然完整、可辨识，通常是对这2秒做标记说明（如"非人声片段"），而不是因为中间混入了噪声就把整条10秒录音都剔除掉。这和前面文本清洗"含手机号不能整条删除"是同一个道理：**先看问题影响的范围，局部问题局部处理，不要因小失大整条剔除。**

## 五、一条铁律：保留原始数据

```python
df.to_csv("reviews_cleaned.csv", index=False, encoding="utf-8-sig")   # ✓ 另存为新文件
# df.to_csv("reviews_raw.csv", ...)                                    # ✗ 绝不能覆盖原文件
```

> ⚠️ **清洗是不可逆操作**。如果直接在原文件上修改保存，一旦清洗规则本身有问题（比如误删了本该保留的样本，或者把"好评"刷屏文本和真实长评论的判断标准搞反了），就再也无法恢复原始数据来重新处理。**无论是文本、图像还是语音，无论做什么清洗操作，都要先把原始文件保留好，清洗结果另存为新文件。**

## 随堂练习

**练习 1**：为什么清洗后的数据要另存为新文件，而不是直接覆盖原始文件？

<details><summary>答案</summary>清洗是不可逆操作。如果直接覆盖原文件，一旦发现清洗规则有误（比如误删了有效数据），将无法恢复到清洗前的状态重新处理。另存为新文件可以保留完整的原始数据作为"后悔药"，也便于后续审计清洗过程是否合理。</details>

**练习 2**：数据清洗的五类目标分别是什么？

<details><summary>答案</summary>去除重复、去除缺失、去除异常、去除噪声、统一数据格式。这五类问题是数据清洗要解决的核心内容，不同数据类型（文本/视觉/语音）体现的具体形式不同，但都归属于这五大类。</details>

**练习 3**：文本清洗中，含HTML标签和含emoji表情的文本应该怎么处理？

<details><summary>答案</summary>HTML标签通常用正则表达式批量剥离，因为它们是采集过程中的残留格式标记，不属于用户语义内容；emoji等特殊符号一般也会统一清除，以保证文本内容的一致性，便于后续标注和分析处理。</details>

**练习 4**：评分字段的正常取值是1-5，发现有记录是0或6，应该怎么处理？

<details><summary>答案</summary>这属于非法取值（超出字段定义域），应当作异常数据剔除。因为0和6都不在规定的评分范围内，很可能是录入错误或系统异常导致，保留这些记录会给后续的统计分析带来错误信息。</details>

**练习 5**：对于完全重复的记录，清洗时应该怎么处理？为什么？

<details><summary>答案</summary>应该去重，只保留一份。因为重复记录会导致模型在训练时对该样本的表述过度学习（过拟合于特定表述），而且重复数据还会虚增数据量，影响后续基于数据量的统计和分析结果的准确性。</details>
