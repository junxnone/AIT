## 一、采集前必须确认的三件事

1. **数据用途**——采集来做什么？
2. **授权范围**——是否有合法采集授权？
3. **采集口径**——字段定义、时间范围、抽样规则是否明确？

> ⚠️ 采集前不确认清楚，后面全白干——这是课题0-2合规意识在采集环节的具体落地。

**为什么这三件事必须排在动手之前，而不是采集完再补？**

**先说用途。** 用途决定规格。同样是拍商品图，用于电商详情页展示，和用于训练图像识别模型，对清晰度、背景干净程度的要求完全不一样。不先问清楚用途就开拍，拍回来才发现规格不对，这些照片往往要么全部重拍、要么干脆报废——事后再返工的成本，远高于提前花一分钟确认。

**再说授权范围。** 采集本身可能涉及他人信息，比如采集门店场景时拍到了顾客。如果没有明确授权范围就采集，轻则这批数据不能用（必须删除重采），重则直接构成违规——这和课题0-2讲的"标注员是数据安全链条上的一环"是同一个道理：**采集环节同样要先确认"能不能采"，不能等采完了再想这个问题。**

**最后说采集口径。** 口径包括字段定义、时间范围、抽样规则。比如任务是"采集100张商品图"，这个"100张"是每个品类都要覆盖，还是随便拍满100张就行？是只拍正面还是要多角度？口径不明确，采回来的样本结构很可能完全不满足后续标注、训练的实际需要——到那时再补拍，往往已经错过了最佳的拍摄条件（比如促销活动已经结束、商品已经下架）。

> 🔑 **一句话记住**：**想清楚"干什么用"，确认"能不能采"，定清楚"怎么算合格"——这三件事做在采集动作之前，而不是采集之后。**

### 常见数据来源渠道

不同渠道的采集方式和合规要求不一样，采集前需要明确具体来源及其授权情况：

| 渠道 | 举例 |
|---|---|
| 用户行为日志 | APP点击、浏览、停留时长记录 |
| 业务系统导出 | 订单系统导出的交易记录 |
| 传感器/设备采集 | 本课题讲的拍照、录音、门店摄像头 |
| 第三方采购 | 向数据供应商购买的标注数据集 |
| 公开数据集 | 政府/学术机构公开发布的数据 |

本课题重点练习的是"传感器/设备采集"这一类——用手机、相机这些工具，亲手把原始数据采回来。

## 二、采集规格、命名与归档记录

想清楚三件事之后，动手采集时还有具体的规格要求要满足：**分辨率/采样率、文件格式、命名规则**，这些通常写在采集任务书里，必须照办。采集完成后，还要按规范归档，并同步填写**采集记录登记表**。

**为什么命名规则看起来是小事，却经常被单独列为考核要点？**

因为后面清洗、标注环节的同事，大概率不会一张一张点开图片去看，而是写一段脚本，按文件名的规律去批量处理——比如用文件名前缀识别类别、用编号对应标注记录。

如果采集时随手命名，比如用手机相册自动生成的"IMG_3.jpg"，或者用中文加空格命名成"商品图片16.jpg"、"new photo 29.jpg"——下游的批量处理脚本按规律匹配文件名时，这些文件要么被漏掉、要么直接让脚本报错。

> 📌 **机制**：命名不规范，本质上是把本该由你在采集阶段当场解决的小问题，转嫁给了下游环节——而且下游环节往往更难发现（他们只看见"脚本报错"或"少了几个文件"，并不知道根因是采集时命名不统一）。

**采集记录登记表**至少要包含：采集人、采集时间、数据来源/渠道、采集数量、规格是否达标、**异常情况说明**。

> 💡 异常情况说明要写具体现象，不能只写"已完成"或"一切正常"。如果采集过程中确实发生过重拍、因模糊/过曝剔除某张照片，登记表里就要如实写明——这样半年后有人要追溯这批数据是怎么采的，才能查得到。登记表一旦和实际操作脱节，就失去了"可追溯"这个存在意义。

## 三、采集质量问题自检

现在回到开头的判断题。我们用代码来查一下这42张图片到底有什么问题。

```python
from PIL import Image
from pathlib import Path
import re

files = sorted(Path("../数据集/images").glob("*.jpg"))
sizes = {}
irregular_names = []
for p in files:
    img = Image.open(p)
    sizes.setdefault(img.size, []).append(p.name)
    if not re.match(r"^[a-z]+_\d{3}", p.name):
        irregular_names.append(p.name)

print("分辨率分布:", {k: len(v) for k, v in sizes.items()})
print("命名不规范文件:", irregular_names)
print("总文件数:", len(files))
```

**实测**（已验证，你的结果应完全一致）：

```
分辨率分布: {(640, 480): 37, (320, 240): 4, (1280, 960): 1}
命名不规范文件: ['IMG_3.jpg', '商品图片16.jpg', 'new photo 29.jpg']
总文件数: 42
```

代码查出了**5张分辨率不一致**（4张320×240、1张1280×960）、**3张命名不规范**。但这份清单还没完——**这42张图里实际还有4张严重模糊、3张过曝、2组完全重复的图片**，这些代码刚才有没有查出来？

**没有。** 代码只查了分辨率和文件名，模糊和过曝一个都没查出来。

### 为什么代码查不出模糊和过曝？

这不是代码写得不够好，而是这两类问题的性质不同：

- **分辨率、文件名、文件内容是否完全重复**——这些都是"能被精确计算"的东西：尺寸是两个数字，文件名是一串字符，重复可以逐字节比对。代码能稳定、可靠地查出来。
- **模糊、过曝**——"看起来模糊""看起来发白"是主观视觉判断，没有一行简单代码能给出和人眼完全一致的结论（真要做，需要专门的图像处理算法，属于进阶内容）。

> 📌 **机制**：**代码能可靠查出客观可计算的问题，但主观视觉质量问题，现阶段最可靠的办法仍然是人当场看一眼。** 这就是为什么"采集质量当场自检"反复被强调——它不是"跑完代码就能替代"的步骤，而是必须有人眼参与的独立检查环节。

### 回到开头的判断

现在揭晓完整答案：这42张图片里，有**5张分辨率不一致、4张模糊、3张过曝、3张命名不规范，外加2组完全重复**的图片。你一开始的猜测准吗？多数人往往只会注意到"分辨率不一样"这种一眼能看出的问题，而忽略了命名、重复这类需要专门检查才能发现的问题。

**采集质量当场自检清单**：

- [ ] 分辨率是否符合要求（统一规格）
- [ ] 是否清晰（无模糊、无过曝）
- [ ] 命名是否规范
- [ ] 有无重复采集

### 三类图像问题怎么快速区分

| | 分辨率不一致 | 模糊 | 过曝 |
|---|---|---|---|
| 现象 | 同批图像尺寸不同 | 细节看不清 | 画面接近全白 |
| 常见成因 | 设备/模式切换未统一 | 低分辨率放大，或对焦失败 | 光线过强或曝光设置不当 |
| 能否代码检测 | 能 | 较难，建议人工目测 | 较难，建议人工目测 |
| 修复方式 | 统一规格重拍 | 当场重拍 | 调整光线/角度后重拍 |

> 🔑 **判别口诀**：先问"尺寸对不对"（代码能查）→ 再问"看得清不清、亮不亮"（人眼当场查）。

### 为什么"当场自检"比"事后处理"省那么多成本？

想象一下：如果这4张模糊、3张过曝的图片是你拍的，你当场拍完立刻回看一眼，发现模糊了，**当场重拍**——成本几乎为零，光线、拍摄角度、商品摆放都还在，重拍一次就行。

但如果你拍完没检查，直接打包上传，几天后质检环节才告诉你"这几张不合格"——这时候你可能已经离开了拍摄现场，光线变了、设备换了，甚至这批商品已经下架、促销活动已经结束，**根本没法重新拍出一模一样的内容**。

> 📌 **核心习惯**：**采集质量问题最大的代价不是"要重做"，而是很多时候"根本没法重做"**。采集完当场自检，发现问题当场重采，比提交后在清洗/标注环节才发现问题的返工成本低得多——这正是开头那个真实案例里，那位学员踩的坑：他"看了一眼"，但看的是"内容对不对"，而不是对照系统的自检清单逐项检查。

## 四、非图像场景的迁移：音频与日志采集

不是所有采集任务都是拍照片。以后你可能还会遇到录制客服通话音频、导出系统运行日志这类采集任务。这些场景的"当场自检"查什么？

| 采集类型 | 对应的质量问题类型 | 识别方式 |
|---|---|---|
| 图像 | 模糊、过曝、分辨率不一致 | 人工目测 + 代码查规格 |
| 音频 | 底噪过大、截断（没录完就停了） | 当场回放试听 |
| 日志 | 字段缺失（如时间戳为空） | 当场抽样核对字段是否齐全 |

表现形式完全不同，但背后是同一个原则：

> 🔑 **迁移规则**：不管采集什么类型的数据，"当场自检、当场重采"这个工作习惯是通用的——**变的只是检查清单的具体内容，不变的是"不等上传之后才发现问题"这条原则。**

## 考点清单

| 考点 | 考试怎么考 | 易错点 |
|---|---|---|
| 采集前三件事 | 单选 | 遗漏其中一项，尤其容易漏掉"授权范围" |
| 数据来源渠道 | 单选 | 把"传感器/设备采集"和"业务系统导出"混淆 |
| 采集口径的具体内容 | 单选 | 误把"标注员联系方式"这类无关项当作采集口径的一部分 |
| 采集质量问题类型 | 单选/实操 | 分不清分辨率不一致、模糊、过曝三者的现象与成因 |
| **当场质检习惯** | 实操 | **采集完直接提交，不做自检** |
| 当场自检的成本优势 | 单选/判断 | 低估"事后处理"的真实代价，以为大不了重拍一次 |
| 采集设备/规格选择依据 | 单选 | 误以为"价格低/外观好看"是选择依据，而非"满足给定规格要求" |
| 命名与归档记录 | 实操 | 命名不规范、登记表异常说明写"已完成"而非具体现象 |

## 随堂练习

**练习 1**：采集现场发现一张照片因光线过强导致画面几乎全白，该怎么处理？

<details><summary>答案</summary>这属于过曝问题，应当场重新拍摄（调整光线或拍摄角度），而不是提交这张质量不合格的照片期待后续环节处理——过曝丢失的图像细节是无法通过后期处理完全恢复的。</details>

**练习 2**：为什么说"采集质量问题最大的代价不是要重做，而是很多时候根本没法重做"？

<details><summary>答案</summary>因为采集现场往往是一次性的——光线条件、拍摄场景、设备状态等因素一旦改变，很难完全还原当时的采集条件。如果等到上传之后、离开现场很久才发现采集质量问题，往往已经无法重新采集一模一样的内容，只能将这批数据作废，造成比"当场重拍"大得多的损失。</details>

**练习 3**：采集前必须确认的三件事是什么？

<details><summary>答案</summary>数据用途（采集来做什么）、授权范围（是否有合法采集授权）、采集口径（字段定义、时间范围、抽样规则是否明确）。这三件事没确认清楚就开始采集，后续处理和使用都可能出问题。</details>

**练习 4**：采集质量当场自检应该检查哪些项目？

<details><summary>答案</summary>分辨率是否符合要求、是否清晰（无模糊、无过曝）、命名是否规范、有无重复采集。这四项是采集完成后应立即核查的基本清单，发现问题当场处理比事后处理成本低得多。</details>

**练习 5**：常见的数据来源渠道有哪些？

<details><summary>答案</summary>用户行为日志、业务系统导出、传感器/设备采集、第三方采购、公开数据集等。不同来源渠道对应不同的采集方式和合规要求，采集前需要明确具体来源及其授权情况。</details>
