## 一、一个会让你理解"归类先于汇总"的案例

```python
import pandas as pd
d = pd.read_csv("../数据集/sales_raw.csv")

print("归一化前：")
print(d.groupby("商品类别").size())

d["商品类别"] = d["商品类别"].str.strip().replace({"手機": "手机"})
print("归一化后：")
print(d.groupby("商品类别").size())
```

**实测**：
- 归一化前：手机94、手机(含尾空格)20、手機21——**同一类商品被拆成三行**
- 归一化后：手机135

不止订单数被拆散，**销量（件数）也被同样拆散**：归一化前三种写法的销售数量分别求和是927、189、235；归一化后合并统计，真实总销量是 **1351 件**。

### 为什么会这样？——机制要讲清楚

`groupby`分组时，靠的是字符串**逐字符比对**是否完全相同，它不理解"手机"和"手機"是同一个意思，也分不清"手机"和"手机 "（多一个空格）有什么区别——对程序来说，这是三个完全不同的字符串，自然被分到三个不同的组里分别统计。**程序不会帮你"脑补"语义，它只会严格按字面比较。** 这就是为什么"归类先于汇总"不能跳过：汇总操作本身没有能力识别"写法不同、含义相同"这件事，这件事必须在汇总之前由人（或清洗代码）先处理掉。

> ⚠️ 回到开头那个判断：**运营报告说"手机94单、927件，垫底"——归一化之后，手机是135单、1351件，是五个品类里卖得最多的那一个。** 927件和1351件相比，低估了 (1351−927)/1351 ≈ **31%**，接近三成。如果真按这份报告建议砍掉手机的采购预算，砍掉的恰恰是卖得最好的品类——**一个技术上的归类疏漏，变成了一个方向完全相反的业务决策**。

## 二、汇总结果的合理性自查

拿到一个汇总结果，不能算完就直接提交，要反问自己几个问题：
- 这个数字看起来合理吗？
- 总数是否对得上（各分类之和等于总体）？
- 占比之和是否为100%？
- 有没有异常极值？

### 为什么这几条检查能揪出问题？——一个真实的例子

这几条检查不是走流程，它们各自对应一类真实会发生的错误。以这批508条数据的**销售地区**字段为例，我们还没对它做过归类整理：

```python
print(d["销售地区"].value_counts())
```

实际取值里，"华南""华东""东北""西南""华北"这5种"干净"写法之外，还混着"  东北 ""  华东 ""  华北 ""  华南 ""  西南 "这5种带首尾空格的写法。如果汇总时只统计看起来"正常"的这5种，一共是471条，而总行数是508条——**占比只有471/508 ≈ 92.7%，加不满100%**。

这正是随堂练习1里"各地区销售额占比加起来只有92%"这个现象的**真实来源**：丢失的那7.3%不是数据凭空消失了，而是因为36条带空格的记录没有被归入任何一个"干净"类别，统计时被整体漏掉了。

> 🔑 **判别口诀**：汇总结果的占比加不满100%、或总数对不上总行数，第一反应不该是"是不是系统算错了"，而应该先怀疑——**是不是存在没被归类进任何一组的"漏网"写法？**

**核心顺序：先归类统一（课题1-3），再汇总（本课题），顺序不能颠倒。** 如果跳过归类直接汇总，看似"做完了"，实则得到的是一份连总数都对不上的失真结果——而这份失真结果，如果不做合理性自查，是检查不出来的。

## 三、用Excel和pandas做同一件事

| 统计口径 | Excel | pandas |
|---|---|---|
| 分组计数 | 数据透视表值字段设为"计数项" | `df.groupby("字段").size()` |
| 分组求和 | 数据透视表值字段设为"求和项" | `df.groupby("字段")["数值列"].sum()` |
| 多指标同时算 | 值区域拖入多个字段 | `df.groupby("字段").agg(订单数=("订单编号","count"), 总销量=("销售数量","sum"))` |
| 行列交叉汇总 | 字段同时拖到"行"与"列" | `df.pivot_table(index="商品类别", columns="销售地区", values="销售数量", aggfunc="sum")` |

四行操作，解决的是同一类问题：按某个字段分组，再在组内做统计。**工具不同，底层的分组聚合逻辑是一致的**——用`groupby`+`agg`算出的"手机总销量1351件"，和用Excel数据透视表拖拽字段算出的结果，应该是完全相同的数字。如果两边对不上，大概率是哪一边的"值字段"统计方式选错了（比如把"求和项"误设成了"计数项"），而不是工具本身有问题。

## 随堂练习

**练习 1**：某汇总报告显示各地区销售额占比加起来只有92%，可能是什么原因？

<details><summary>答案</summary>可能存在地区字段的写法不统一（如同一地区的不同写法被当成不同类别，部分未被识别归入汇总），或存在地区字段缺失/异常值未被纳入统计。应回头检查归类整理是否彻底，而不是直接采信这个有问题的汇总结果。</details>

**练习 2**：为什么说"先归类统一，再汇总"这个顺序不能颠倒？

<details><summary>答案</summary>因为汇总是建立在归类基础上的统计操作，如果归类没做彻底（同一含义的不同写法没有合并），汇总统计会把本该是一类的数据拆分统计，导致汇总结果严重失真。颠倒顺序（先汇总再归类）在逻辑上也说不通，因为汇总后的数字已经无法再回溯到原始的具体写法。</details>

**练习 3**：汇总结果的合理性自查应该检查哪些内容？

<details><summary>答案</summary>总数是否对得上（各分类之和等于总体）、占比之和是否为100%、有没有异常极值。这些检查能帮助发现归类不彻底、字段缺失等潜在问题，而不是拿到汇总数字就直接采信提交。</details>

**练习 4**：Excel数据透视表和pandas的groupby在功能上是什么关系？

<details><summary>答案</summary>两者在功能上可以实现同样的分组汇总效果——数据透视表通过拖拽字段完成分组统计，groupby通过代码完成同样的操作。掌握一种工具的思路后，迁移到另一种工具通常只是操作方式的不同，底层的分组聚合逻辑是一致的。</details>

**练习 5**：如果业务方直接采信了一份有问题的汇总报告（比如把归类不彻底导致的低估数字当真），可能造成什么后果？

<details><summary>答案</summary>可能造成错误的业务决策，比如误判某个商品品类销量不佳而减少该品类的采购或推广投入，而实际上这个品类的真实销量被错误地拆分低估了。这说明汇总数据的准确性直接关系到后续业务决策的正确性，不是单纯的技术细节问题。</details>
