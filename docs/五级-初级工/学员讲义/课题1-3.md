## 一、一批真实存在的格式问题

```python
import pandas as pd
d = pd.read_csv("../数据集/sales_raw.csv")
print("商品类别取值:", d["商品类别"].value_counts().to_dict())
print("销售地区取值样例:", d["销售地区"].unique().tolist())
print("下单日期样例:", d["下单日期"].sample(8, random_state=1).tolist())
```

**实测**：商品类别出现"手机"94条、"手機"21条、"手机 "（含尾部空格）20条——**同一个类别，三种不同写法**；销售地区存在首尾带空格的取值（如" 华东 "）；下单日期混用四种格式（如`2026-03-05`、`2026/3/5`、`03-05-2026`、`20260305`）。

> ⚠️ **如果不统一这些写法，后面按商品类别做汇总统计会把同一类商品的数据拆成三份统计，严重低估真实销量**——这正是归类整理工作的核心价值所在：看起来"多打几个字""多留个空格"的小问题，会直接影响后续所有统计分析的准确性。

### 为什么计算机会把"手机"和"手機"当成两个不同的东西？

这是本节最容易被忽视、但必须想清楚的一点。人看"手机"和"手機"，会自动用"意思"去理解——两个字长得像、意思一样，大脑直接判定"这是同一个东西"。但计算机不理解"意思"，它只做一件事：**逐个字符比对编码是否完全相同**。"机"和"機"是两个不同的字符（繁简字形不同，对应不同的编码），哪怕含义相同，对程序来说就是两个不同的字符串，分组统计时会被分到两个不同的类别里。首尾空格同理——"华东"和" 华东 "在显示出来的样子上几乎分辨不出差异，但多出来的空格字符会让整个字符串"不相等"，程序照样把它们当成两个不同的地区分别统计。

**一句话记住**：**格式问题的共同特点是——对人眼来说"差不多"，对程序来说"完全不同"。**

## 二、统一方法

```python
# 去除首尾空格
d["商品类别"] = d["商品类别"].str.strip()
# 统一同义写法
d["商品类别"] = d["商品类别"].replace({"手機": "手机"})
# 统一日期格式（pandas能自动识别多数常见格式）
d["下单日期"] = pd.to_datetime(d["下单日期"], errors="coerce")
print(d["商品类别"].value_counts())
```

统一之后，"手机"合并为 **135** 条（94 + 21 + 20），真实销量才显现出来。

### 该合并的，和不该合并的——怎么区分？

学会"合并同义写法"之后，很容易矫枉过正，把本来就不一样的东西也强行合并。比如数据集里还有"平板"和"笔记本电脑"两类，要不要也合并？

**不要。** 判别方法很简单，问自己一句：

> 🔑 **判别口诀：这两条记录描述的是不是同一个真实世界的事物？**
> 是 → 合并（"手机"和"手機"说的是同一种商品，只是写法不同）；
> 不是 → 保留为不同类别（"平板"和"笔记本电脑"是两种真实存在的不同商品，写法本身没有任何问题）。

"手机/手機/手机 "三种写法指向的是同一个真实商品品类，只是书写形式不同，所以要合并；"平板"和"笔记本电脑"是两个不同的真实商品，根本不存在"同义词"的问题，不能因为"都是电子产品"就合并——合并类别和区分类别，用的是同一把尺子：**看描述的是不是同一个事物，而不是看写法长得像不像**。

## 三、同样的陷阱还藏在数字字段里

前面处理的"手机/手機"是文字字段的格式问题。再看一个数值字段——**销售金额**，会发现同一种陷阱换了个样子又出现了一次。

```python
print(d["销售金额"].sample(10, random_state=2).tolist())
print("能直接转换为数字的条数:", pd.to_numeric(d["销售金额"], errors="coerce").notna().sum(), "/", len(d))
```

**实测**：抽样会看到"27986"、"27986元"、"143,984"（千分位逗号）、全角数字等多种写法混杂；**能直接转换为数字的只有 436/508 条**，剩下 72 条因为带了"元"字、千分位逗号或全角数字，被当成普通文本，无法参与任何求和、求均值等数学运算。

### 为什么这也是"同一类问题"？

商品类别的问题是"同一含义，多种文字写法"（手机/手機）；销售金额的问题是"同一数值，多种文本包装"（27986/27986元）。表面看一个是文字字段一个是数字字段，但根因完全一样：**写法不统一，程序没法把它们识别成同一类东西**。对人眼来说"27986"和"27986元"显然是同一个数；但程序看到字符串里混进了汉字"元"，就不再把它当数字处理，而是当成一串普通文本——这意味着如果直接对这一列求和，带单位的记录会被悄悄跳过，**求和结果偏小，而且不会报错提醒你**，比报错更危险。

**统一清洗**：

```python
def clean_amount(s):
    if pd.isna(s):
        return None
    s = str(s)
    s = s.translate(str.maketrans("０１２３４５６７８９", "0123456789"))  # 全角转半角
    s = s.replace(",", "").replace("元", "").strip()                      # 去千分位、去单位
    try:
        return float(s)
    except ValueError:
        return None

d["销售金额"] = d["销售金额"].apply(clean_amount)
print("清洗后能转换为数字的条数:", d["销售金额"].notna().sum(), "/", len(d))
```

**实测**：清洗后能转换为数字的条数提升到 **495/508**——多找回了59条本来就是正常数值、只是写法不规范的数据。剩下的13条仍然是空值，这13条是**真正缺失的数据**，不属于格式问题，需要用其他方式处理（后续课题会讲）。

> 📌 **区分清楚**：本课题的"整理归类"只负责统一写法、把能救回来的格式问题修正好；它不负责补全真正没有的数据。把"格式不规范"和"数据真缺失"混为一谈，是零基础学员很容易踩的另一个坑。

## 随堂练习

**练习 1**：某字段存在"北京""北京市""BEIJING"三种写法表示同一地区，该怎么处理？

<details><summary>答案</summary>应先统一映射为同一个标准写法（如统一为"北京"），再进行后续的分组统计分析，否则同一地区的数据会被拆分成三个不同类别，导致统计结果失真。</details>

**练习 2**：`str.strip()` 的作用是什么？为什么首尾空格问题容易被忽视？

<details><summary>答案</summary>`str.strip()`用于去除字符串首尾的空格。首尾空格容易被忽视是因为肉眼从表格或打印输出里很难直接看出某个字符串末尾多了一个空格，但对程序来说"手机"和"手机 "是两个不同的字符串，会导致分组统计时被当成不同类别。</details>

**练习 3**：下单日期字段同时存在`2026-03-05`、`2026/3/5`、`20260305`三种格式，该怎么统一处理？

<details><summary>答案</summary>使用`pd.to_datetime()`函数，pandas能够自动识别多种常见的日期格式字符串并统一转换为标准的日期类型，转换后的日期可以直接进行排序、比较和日期计算，不会因为原始格式不同而出错。</details>

**练习 4**：为什么"同一含义不同写法"的问题，仅凭肉眼检查很容易被漏掉？

<details><summary>答案</summary>因为肉眼浏览数据时，"手机"和"手機"字形接近、含义相同，容易被当作"同一类"直接略过；而首尾空格这类问题在普通查看方式下几乎不可见。这类问题通常需要通过代码统计各取值的出现次数（如`value_counts()`）才能被系统性地发现。</details>

**练习 5**：整理归类工作完成后，应该怎么验证处理结果是否正确？

<details><summary>答案</summary>可以重新运行`value_counts()`等统计方法，检查同一含义的数据是否已经合并为统一的取值，取值种类数是否符合预期（比如原本8种门店编码写法应归并为4种）；也可以抽样检查几条处理前后的数据，确认转换逻辑没有引入新的错误。</details>
