---

## 一、教学目标

### （一）知识目标

1. 能说明常见数据质量问题类型（重复、缺失、异常、噪声、格式不一致）。
2. 能说明清洗规则阈值必须有业务依据，不能套用通用脚本。
3. 能区分三种处理方式——**删除 / 替换 / 标记**——各自适用的场景差异。

### （二）技能目标

1. **能针对给定原始数据制定数据清洗标准，并用 pandas 实现清洗、输出清洗后数据文件**。
2. 能为清洗规范撰写可交付文档（适用范围、逐条规则、处理方式、例外情形、产出字段说明）。
3. 能对他人制定的清洗规则做出判断依据层面的复核，指出其是否会误删有价值数据。

### （三）素养目标

1. 养成"每条清洗规则都要能回答'为什么这样处理'"的习惯，而非照搬模板脚本。

---

## 二、教学重点与难点

### 重点

1. 清洗规则的业务依据判断——尤其是"异常值"的边界判断（金额特别大未必是异常，可能是大客户批量采购）。
2. 三种处理方式（删除 / 替换 / 标记）的选择依据。
3. 清洗规范文档的完整要素。

### 难点

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| 从"执行清洗手册"到"自己设计清洗手册"的角色转变 | **把清洗简化为"调用几个标准函数"**（`dropna()` 去空、`drop_duplicates()` 去重），忽视每条规则背后需要的业务判断——比如超长文本删除的字数阈值从哪来、HTML 标签要不要保留部分语义信息、含个人信息的样本该删还是该替换。学员在四级/五级阶段习惯了"照着清洗手册执行"，三级要求"自己定手册"，这个角色转变在本课题首次落到具体的编码实操上，容易产生不适应 | 不直接讲道理，先让学员**亲手验证"两行标准代码"到底能处理多少问题**：`dropna().drop_duplicates()` 在真实数据上只能排除完全重复的 40 条，对空文本、超短/超长文本、非法评分合计 117 条完全无效，HTML/emoji/个人信息这类"需要替换而非删除"的问题更是从未触碰。用这个实测反差制造认知冲突，再引出"每条规则都要自己定判定依据"这句结论 |

## 三、学情分析与前置知识

学员已学完课题1-1、1-2的流程设计与业务分析训练，具备"针对真实问题设计方案"的意识，但这是第一次要求**把设计方案真正写成可运行的代码**。需要注意部分学员Python基础薄弱，清洗代码本身的编写可能成为瓶颈，教学时应把"设计思路"和"代码实现"分开检查，不要让编码能力掩盖了对清洗规范设计能力的评估。

---

## 四、教学方法与手段

1. **认知冲突法**（核心）：先让学员预判"两行标准代码能不能清洗干净"，再用实测结果推翻直觉。
2. **案例讨论法**：用两种清洗规则的优劣对比，建立"规则要有依据"的判断标准。
3. **任务驱动法**：以制定一份真实可交付的清洗规范文档+配套代码作为课堂产出。

### 环节一：导入（0–15′）

**教师话术**：

> "打开 data.csv，随便抽 20 条看看，大家告诉我看到了哪些问题。"

（学员陆续发现重复、空值、HTML标签、emoji、超长刷屏评论、含手机号邮箱的评价、非法评分等问题）

> "好，这些问题确实都要清洗掉。现在我给大家看一份'标准答案'——某学员拿到这份数据后，写了这两行代码："

**投影代码**：

```python
df = df.dropna().drop_duplicates()
```

> "他说：'清洗完成，1040条数据，缺失值和重复值都处理完了，可以直接训练了。'
>
> **花三十秒判断：他说得对吗？这份数据现在能用了吗？** 把你的判断写下来。"

**预期学员反应**：多数学员会倾向于"看起来确实处理了缺失和重复，应该差不多了"，少数学员会质疑"HTML标签和手机号好像没处理"。

**教师应对**：

> "先记住你的判断，不管你刚才写的是'能'还是'不能'。待会儿实操一我们会跑代码亲眼验证——你会发现这两行代码能处理的问题，连四分之一都不到。"

**设计意图**：不急于否定，让错误判断先被公开表达出来，后面的实测反差才有冲击力；同时呼应难点"把清洗简化为调用标准函数"。

---

### 环节二：清洗规则设计方法论（15–40′）

**讲授脚本**：

> "我们先建立一套系统的方法论。数据质量问题通常分五类：重复、缺失、异常、噪声、格式不一致。"

**逐类讲解**（板书 + 举例）：

| 类型 | 典型表现 | 本课题数据集中的例子 |
|---|---|---|
| 重复 | 完全重复行、主键重复 | 完全重复的评价记录 |
| 缺失 | 空值、空字符串 | 空文本评价 |
| 异常 | 超出合理范围的数值、非法取值 | `rating` 不在 1–5 区间 |
| 噪声 | HTML标签、emoji、个人信息、超长/超短文本 | 采集残留标签、手机号、刷屏评价 |
| 格式不一致 | 编码混乱、大小写/全半角混用 | （本数据集暂未出现，提示学员其他业务场景常见） |

> "发现问题只是第一步。更关键的是**怎么处理**——每类问题不是只有'删除'一种选择。处理方式其实只有三种：**删除、替换、标记。**"

**讲解三种处理方式的判定依据**：

> "**删除**：这条信息本身没有可保留的价值，比如完全重复的行、空文本、非法评分——留着它对模型训练没有任何帮助，反而是噪声。
>
> **替换**：信息需要处理，但处理对象之外的内容仍然有价值。最典型的是手机号、邮箱——这类个人信息必须脱敏，但整条评价剩下的情感语义还是有用的，所以**用占位符替换，不整条删除**。
>
> **标记**：规则暂时无法确定该怎么处理，先标记出来流转给人工复核，而不是自己瞎猜一个处理方式。"

**板书核心句**：

> **这条信息删掉后，会不会损失本可以保留的语义？会 → 优先替换；不会 → 可以删除；不确定 → 标记流转人工。**

**学员活动**：记录五类问题与三种处理方式，口头举一个自己熟悉场景（如外卖评价、客服工单）里可能遇到的例子，并判断该用哪种处理方式。

---

### 环节三：案例讨论——阈值的业务依据（40–65′，难点突破核心）

**讨论题**：

> "某学员的清洗规则写'删除所有超过100字的评价'，另一学员写'删除超过200字且内容高度重复的评价'。哪个更合理？"

**预期学员意见分歧**：部分学员会觉得"第一种更简单直接，效率高"。

**教师追问**：
> "假设一条评价是用户认认真真写了150字的详细使用体验，第一种规则会怎么处理它？"

（学员意识到会被误删）

**教师点破**：
> "对，这就是问题所在。第一种规则武断——长评价不一定是垃圾数据，可能是用户认真写的详细体验。第二种规则加了'高度重复'这个判定条件，更贴近真实业务场景（刷屏灌水）。**清洗规则不是'多删等于多干净'，是'删对地方'。**
>
> 以后每条规则写出来后，自己要能回答一个问题：**这条规则会不会把有价值的真实数据误删？** 回答不上来，这条规则就不合格。"

**延伸提问（巩固判定依据的普适性）**：

> "再问一个：`rating` 字段出现 0 和 6，这个阈值（1–5）的依据是什么，是不是也要自己拍脑袋定？"

（引导学员答出：不是拍脑袋，是字段本身的业务定义域——评分系统设计时就规定了 1–5 分，0 和 6 只能是录入或埋点错误，这是有据可查的业务规则，不是训练师主观设定的）

**板书核心句**：

> **阈值不是经验数字，是业务规则的量化表达。有的依据来自数据本身的异常模式（如长度+重复度），有的依据来自字段的既定业务定义域（如评分 1–5）。**

**学员活动**：讨论发言，填写"这条规则会不会误删有价值数据"的自检问句到笔记。

### 环节五：实操一——量化检视：两行代码 vs 实际问题规模（75–100′，难点落地）

**教师指令**：

> "现在回到导入环节的判断题。打开 Jupyter，我们来真刀真枪验证一下——那两行代码到底处理了多少问题，又漏掉了多少。"

**投影代码**（学员照抄运行）：

```python
import pandas as pd

df = pd.read_csv("../数据集/data.csv")
n_raw = len(df)

print("完全重复行:", df.duplicated().sum())
print("review_id重复:", df.duplicated(subset=["review_id"]).sum())
print("空文本(空字符串):", (df["review_text"].astype(str).str.len() == 0).sum())
print("真正的NaN缺失:", df["review_text"].isna().sum())
print("超短文本(<3字):", (df["review_text"].astype(str).str.len() < 3).sum())
print("超长文本(>200字):", (df["review_text"].astype(str).str.len() > 200).sum())
print("非法rating:", (~df["rating"].between(1, 5)).sum())
```

**实际运行输出（已在实操题 2.1.1 参考答案中验证通过，学员结果应一致）**：

```
完全重复行: 40
review_id重复: 0
空文本(空字符串): 31
真正的NaN缺失: 0
超短文本(<3字): 57
超长文本(>200字): 19
非法rating: 10
```

**关键提问（推翻直觉的引爆点）**：

> "看第四行——'真正的 NaN 缺失' 是 0。但'空文本'是 31。这是不是说明 `dropna()` 这个函数……？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "`dropna()` 一条都删不掉，因为根本没有 NaN" | 肯定并点破："对。这 31 条问题样本，表现形式是空字符串 `''`，不是 pandas 认识的缺失值 NaN。`dropna()` 认不出空字符串，它只认 NaN。这就是为什么'调用标准函数'会漏掉问题——**函数认的是技术上的'缺失'，不是业务上的'无效'。**" |
| 答不上来 | 引导："`dropna()` 判断的标准是什么？是单元格里有没有存值。空字符串 `''` 是不是'有值'？只是这个值恰好是空的？" |

**教师总结话术**：

> "我们来算一笔账。`drop_duplicates()` 处理了 40 条完全重复；`dropna()` 一条都没处理，因为空文本不是 NaN。剩下空文本 31、超短 57、超长 19、非法评分 10，**合计 117 条问题，两行标准代码完全没碰**。
>
> 更不用说 HTML 标签、emoji、手机号邮箱这些——它们根本不减少行数，是要在文本内容里做替换，两行代码从来没有处理'替换'这个维度。
>
> 现在回答导入时的判断：**这批数据清洗完成了吗？** 答案是：两行代码连四分之一的问题都没解决。"

**学员活动**：填写对比表

| | 两行标准代码能处理 | 实际需要处理 |
|---|---|---|
| 完全重复 | 40 条 ✓ | 40 条 |
| 空文本 | 0 条（`dropna`认不出空字符串）✗ | 31 条 |
| 超短/超长/非法评分 | 0 条 ✗ | 86 条 |
| HTML/emoji/手机号邮箱（替换类） | 0 条 ✗ | 需逐类正则处理 |

**设计意图**：用实测数字把"难点"从抽象说教变成可验证的反差，学员亲手跑出结果后，比教师单方面强调更有说服力。

### 环节六：实操二——制定清洗标准并实现（100–190′，核心产出）

**任务书**：

> 针对 `data.csv` 制定完整清洗规则（覆盖重复、空值、HTML、emoji、超长超短、个人信息、非法评分等问题类型），撰写规则文档并用代码实现，输出 `data_cleaned.csv`。

**规范必备要素**（教师给模板）：

```
一、适用范围与清洗目标
二、逐条规则（处理对象 + 处理方式 + 判定依据）
三、例外情形
四、产出字段说明（清洗前后数据量对比）
```

**巡回指导重点**：

1. 检查每条规则是否写明判定依据，而不仅仅是处理方式——这是本课题最核心的评分点。
2. 检查代码是否真的输出了清洗前后的数量对比，以及**各类问题各自命中的记录数**（不能只给一个总数）。
3. 警惕"两行代码思维"复发——巡视中若发现学员只写了 `dropna().drop_duplicates()` 就认为完成，追问环节五刚验证过的那 117 条问题去哪了。

**中途检查点（约第 45 分钟）**：

> "写到一半停一下——检查一下你的规则文档，有没有哪一条只写了'删除超长文本'，却没写'为什么是200字而不是100字'？没写清楚的现在补上。"

## 七、板书设计

**主板书区**

```
                  清洗规则设计三问
  ① 判定依据是什么？（不能拍脑袋）
  ② 会不会误删有价值的数据？
  ③ 处理方式：删除 / 替换 / 标记？为什么选这种？

┌────────────── 实测：两行代码能处理多少？ ──────────────┐
│ dropna().drop_duplicates()                              │
│   完全重复 40 条 ✓ 处理了                                │
│   空文本31 / 超短57 / 超长19 / 非法评分10 = 117条 ✗ 没处理 │
│   （空文本是空字符串，不是NaN，dropna认不出来！）          │
│ → 两行代码连四分之一的问题都没解决                        │
└──────────────────────────────────────────────────────────┘

清洗规范文档结构：
  适用范围 → 逐条规则(对象+方式+依据) → 例外情形 → 产出字段说明
```

**副板书区（三种处理方式判别）**

```
            删除              替换(占位符)         标记(待人工复核)
典型场景    空文本/完全重复/   含个人信息/          处理方式不确定、
            非法评分           需保留语义的噪声      存在争议的边界情形

判别口诀：这条信息删掉后，会不会损失本可以保留的语义？
  会 → 优先替换，不会 → 可以删除，拿不准 → 标记流转人工
```
