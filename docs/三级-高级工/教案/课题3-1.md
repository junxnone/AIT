## 一、教学目标

### 知识目标
1. 能说明数据漂移、概念漂移、模型退化的定义与成因。
2. 能设计监控指标体系与告警阈值。

### 技能目标
1. **能对单一智能产品的使用数据做全面分析并输出分析报告**。
2. **能提出产品优化需求并设计智能解决方案**。
3. 能说明"先看汇总指标、再下钻具体样本"的通用诊断方法论。

### 素养目标
1. 延续主线：一个整体指标下滑，必须拆解成不同原因分别处理，不能用一个方案覆盖全部。

---

## 二、教学重点与难点

**重点**：区分数据漂移（用户/数据结构变化）与模型退化（模型本身能力下降）。

**难点**：学员典型错误预判——**看到整体指标下滑就直接归因于"模型变差了，需要重新训练"**，不做分群下钻验证。本课题数据集的下滑可精确拆解为两个独立成分，是本课题认知冲突的核心素材。

---

## 三、学情分析与前置知识

学员已学完模块二全部课题，对"指标下滑要分维度下钻归因"这一方法论已有课题1-2（漏斗分析）、课题2-2（标注差异诊断）两次训练。本课题把同样的方法论迁移到系统监控场景，学员应该能较快上手分群下钻的操作，重点在于能否主动想到"要分群看"而不是等教师提示。

另外需要注意：知识目标1里的"概念漂移"此前教学内容中从未展开讲授过（只在定义层面出现过名词），而试题库单选第123题直接考查"概念漂移与数据漂移的区别"——这是一个此前被遗漏的真实知识缺口，本轮补齐。

---

## 四、教学方法与手段

1. **认知冲突法**：先展示"下滑"这个表面现象，让学员先入为主地归因，再用分群数据推翻单一归因。
2. **迁移类比法**：明确提示本课题方法论和课题1-2、2-2是同一套，训练学员的方法论迁移能力；并用"医生接诊效果下降"的类比帮助区分模型退化与数据漂移。
3. **对比辨析法**：数据漂移 / 概念漂移 / 模型退化三者并置对比，给出统一判别口诀。

### 环节一：导入（0–10′）

**教师活动** —— 投影展示（不给结论）：

> "这是某智能音箱产品过去12周的识别成功率曲线——从91.4%一路降到82.6%，下滑了8.8个百分点。产品经理在会上直接拍板：'模型肯定是变差了，赶紧安排重新训练。'"

**提问话术**：

> "请大家用三十秒判断：这个决定对不对？如果你是负责这件事的训练师，会不会直接照办？举手表决——认为'直接重新训练就够了'的请举手。"

（预期：相当一部分学员举手或犹豫）

> "好，先记住你刚才的判断。这节课结束前我们会回来看，这个决定到底漏掉了什么。"

**设计意图**：不急于否定，让"一刀切归因"先被公开表达出来，后面的推翻才有冲击力。

---

### 环节二：新授——数据漂移与模型退化的定义区分（10–25′）

**讲授脚本**：

> "先把两个最容易混的概念说清楚。
>
> **模型退化**：模型本身的判别能力随时间下降了——可能是没有持续更新，也可能是训练数据和真实场景逐渐脱节。这是'模型变差了'。
>
> **数据漂移**：模型的能力完全没变，但它面对的数据'长得不一样了'——比如说话的用户群体结构变了。这不是'模型变差'，是'考题变了'。"

**类比讲解**（板书）：

> "想象两个医生：一个是'治疗能力本身下降了的医生'——这是模型退化，得给他重新培训；另一个是'接诊的病人类型变了，但医生水平完全没变'——这是数据漂移，得给他补充针对新病人类型的专门培训。两种情况表面上都叫'接诊效果下降'，解决办法完全不同。"

**学员活动**：记录两者定义，口头举一个自己熟悉场景里"模型退化"和"数据漂移"各自可能的例子（提问2-3人）。

**板书核心句**：

> 模型退化 = 模型自己变差了；数据漂移 = 数据本身变了，模型没变。

---

### 环节三：新授——概念漂移：容易被遗漏的第三个对象（25–40′）

**讲授脚本**：

> "刚才区分的是两种情况。但还有第三种情况经常被遗漏——**概念漂移（Concept Drift）**。
>
> 数据漂移问的是：**输入数据本身长什么样，变了没有**（比如用户群体结构）。概念漂移问的是：**同样的输入，正确答案变了没有**。"

**场景举例**：

> "比如智能音箱收到同一句指令'帮我放首歌'——这句话本身没有变化，识别文本完全一样。但过去大部分用户说这句话是想听流行歌曲，现在相当一部分用户说这句话其实是想放白噪音助眠。**输入完全相同，但'正确的回应'变了**——这就是概念漂移。它和识别准不准没关系，出问题的不是'听懂了没有'，而是'听懂之后该给什么回应'这件事，标准本身在悄悄变化。"

**判别提问**：

> "现在请大家判断：如果某个推荐系统的用户画像特征完全没变，但同一批用户的购买偏好随着季节更替变了——夏天想买短袖的人，现在想买外套。这属于数据漂移还是概念漂移？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "数据漂移，因为是用户变了" | 追问："用户的什么变了？是画像特征（输入）变了，还是画像没变、但他想要的东西（正确答案）变了？"——引导回到"输入 vs 输出对应关系"这把尺子 |
| "概念漂移，因为用户想要的东西变了" | 肯定："对。输入（用户画像）没变，但'同样输入对应的正确输出'变了，这正是概念漂移的定义。" |
| 答不上来 | 用板书口诀引导："数据漂移问的是'数据长什么样变了没有'；概念漂移问的是'同样的数据，正确答案变了没有'。先问输入变没变，再问对应关系变没变。" |

**判别口诀**（板书）：

> 数据长什么样变了 → 数据漂移；同样的数据，正确答案变了 → 概念漂移；模型自己能力降了 → 模型退化。

**教师总结**：

> "这三者可以同时发生，也可以只发生一个。考试喜欢考的是：给你一个场景描述，让你判断属于哪一种——不是让你背定义，是让你用这把尺子去套场景。"

### 环节四：实操一——分群下钻验证（难点突破，40–60′）

**教师指令**：

> "打开编辑器，我们来真正验证一下导入环节那张曲线图背后的构成。"

**投影代码**（学员照抄运行）：

```python
import pandas as pd

d = pd.read_csv("../数据集/speaker_logs.csv")
overall = d.groupby("周次")["识别成功"].mean()
print("第1周:", round(overall.iloc[0], 3), " 第12周:", round(overall.iloc[-1], 3))

seg = d.pivot_table(index="周次", columns="用户群体", values="识别成功", aggfunc="mean")
child_ratio = d.groupby("周次")["用户群体"].apply(lambda s: (s == "儿童").mean())
print(seg.round(3))
print("儿童占比:", child_ratio.iloc[0], "->", child_ratio.iloc[-1])

conf = d.groupby("周次")["置信度"].mean()
print("置信度均值:", round(conf.iloc[0], 3), "->", round(conf.iloc[-1], 3))
```

**实测**（已验证）：整体识别成功率第1周91.4%→第12周82.6%，下滑8.8个百分点。按群体下钻：**成人群体**从92.6%降到87.3%（**下滑5.3个百分点，真实模型退化**）；**儿童用户占比**从7.7%骤升到28.8%（第7周起），儿童群体成功率始终比成人低约16-20个百分点，**占比上升本身把整体均值拉低约3.5个百分点（数据漂移）**。模型平均置信度同步从71.7%降到67.6%——这是一个独立统计出来的量，与"识别是否成功"没有直接计算关系。

**教师提问**：

> "如果你只报'模型退化了，建议重新训练'，这个方案能解决百分之百的问题吗？"

**引导学员计算**：8.8pp = 5.3pp（模型真实退化）+ 3.5pp（用户结构变化）。**只做重训练无法解决漂移部分**——儿童语音本身就更难识别，重训练解决不了"结构变了"这件事，需要针对性补充儿童语音训练数据。

**追问（交叉验证意识）**：

> "成人群体那5.3个百分点，我们怎么确认这是模型真的变差了，而不是巧合？"
>
> （引导学员注意到置信度也在同步下滑）
>
> "置信度是模型对自己判断的'底气'，和识别成功率是两条独立算出来的曲线。如果只是数据漂移（模型没变，只是换了批更难的用户），模型该没把握的时候一向会表现出没把握，置信度不会系统性下滑。置信度同步下降，是'成人群体那部分确实是模型自己变差了'的一个独立佐证——**一个结论最好有不止一个独立信号支撑，不要只凭一张曲线图就下判断**，这是训练师的工作习惯。"

**学员活动**：填写对比表

| | 数值 |
|---|---|
| 整体识别成功率 | 91.4% → 82.6%（↓8.8pp） |
| 成人群体成功率 | 92.6% → 87.3%（↓5.3pp） |
| 儿童占比 | 7.7% → 28.8% |
| 置信度均值 | 71.7% → 67.6% |
| 8.8pp 如何拆分？ | ____ pp 模型退化 + ____ pp 数据漂移 |

**预期学员反应与应对**：

| 学员反应 | 教师应对 |
|---|---|
| "全部重新训练模型就行了" | 追问："重新训练能解决儿童占比上升这件事本身吗？"——引导意识到重训练只能提升模型能力，不能改变用户结构已经变化这个事实 |
| "数据漂移和模型退化我分不清要怎么分别处理" | 重复医生类比，追问本例里哪部分对应哪种医生 |

**教师总结**：

> "这和课题1-2的漏斗分析、课题2-2的标注差异诊断是完全同一套方法论——**一个指标下滑，先不要急着下结论，要分维度下钻，看看是不是藏着不止一个原因。** 这是你们在这门课里第三次用到这套方法论了，希望从今往后看到任何'整体指标变化'的场景，都能条件反射地想到要下钻。"

### 环节五：新授——监控指标体系设计（60–75′）

**讲授脚本**：

> "刚才我们已经能诊断'为什么下滑'了。但训练师不能等指标已经下滑了才行动，日常就要有一套监控体系，让问题尽早被发现。监控体系要覆盖四类指标，缺一类，就可能有一类问题被漏掉。"

**四类指标**（板书）：

| 类别 | 示例 |
|---|---|
| 业务指标 | 识别成功率、用户满意度、转人工率 |
| 模型指标 | 置信度分布、各类别准确率 |
| 数据质量指标 | 埋点异常率（如本数据集中2%日志响应时长为负值） |
| 时效指标 | 响应时长、处理延迟 |

**讲授脚本（强调数据质量指标）**：

> "数据质量指标这一类最容易被忽视，但恰恰是三级实操题里的一个独立考核点。本数据集里有2%的日志记录'响应时长'是负值——这是设备或采集链路的埋点bug，和模型的判别能力毫无关系。如果你把这2%异常也算进'模型表现变差'的证据里，就是把两类完全不同性质的问题混在一起了，会让后续的优化方向跑偏。"

**学员活动**：运行代码验证响应时长负值占比，讨论该归入哪一类指标。

```python
print("响应时长异常(-1)记录数:", (d["响应时长ms"] == -1).sum())
print("占比:", (d["响应时长ms"] == -1).mean())
```

**实测**：约2%的日志记录响应时长为-1，属于埋点/采集环节的数据质量问题。

**板书核心句**：

> 数据质量问题 ≠ 模型问题——先分清"地基"和"房子"，别把地基裂缝算成房子设计出了错。

### 环节七：实操二——输出分析报告与优化方案（85–140′）

**讲授脚本（报告结构）**：

> "拿到分析结果，不能只甩一堆数字。一份合格的分析报告要有固定结构：**结论先行 → 关键指标 → 分群下钻 → 问题定位 → 优化建议 → 验证方案**。
>
> 为什么结论先行？因为决策者没时间跟你一起推导过程，他需要先看到'掉了多少、严不严重'，再决定要不要往下看你的分析过程。把结论放在报告最后，等于让最忙的人去读最长的那部分。"

**任务书**（投影）：

> 请你独立完成一份完整的智能音箱识别成功率分析报告，对应真题3.1.1的全部4个小问：
> 1. 计算整体识别成功率的周度变化趋势，量化下滑幅度；
> 2. 按用户群体做分群分析，判断下滑的真实构成（不要止步于"模型退化"这一个结论）；
> 3. 输出完整的分析报告，包含归因结论和对应的优化方案；
> 4. 检查日志数据本身是否存在质量问题，说明如何处理。

**巡回指导要点**：检查学员是否——①给出精确的百分点数值而非笼统描述；②做了分群下钻而不是只给整体结论；③归因拆成两部分并各给数值；④优化方案对应两个原因分别给出；⑤单独指出响应时长异常是数据质量问题，不混入模型归因。

**对完成快的学员的追问**：

> "你的报告里，模型退化部分的优化方案和数据漂移部分的优化方案，如果只能先做一个，你会先做哪个？为什么？"（无标准答案，训练学员权衡投入产出，呼应"提出优化需求并设计智能解决方案"这一技能目标）

### 环节八：分组互评与典型错误诊断（140–160′）

**教师活动**：投影展示2-3份教师预先准备的"典型不合格报告"（如：只报"模型退化，建议重新训练"，没有分群下钻；下钻了但优化方案只写了一条；完全没提响应时长异常，或把它当成模型问题处理），组织学员分组诊断问题所在。

**预期诊断点**：

| 典型错误 | 应诊断出的问题 |
|---|---|
| 报告只写"模型退化了，建议重新训练" | 没有做分群下钻，漏掉数据漂移那部分，方案不完整 |
| 下钻了但只给一条优化方案 | 两个独立成因（模型退化、数据漂移）必须分别给方案，不能用一个方案覆盖 |
| 把响应时长异常算进"模型变差"的证据里 | 混淆了数据质量问题与模型问题，应单独指出并剔除 |

**学员活动**：分组讨论，每组派代表指出至少1处问题并给出修改建议（10 min 汇报）。

### 环节九：变式练习——换个指标，验证方法论可迁移（160–195′）

**教师指令**：

> "刚才分析的是'识别成功率'。现在换一个字段——`是否转人工`。请用同样的'先看总体趋势、再分群下钻'的方法分析一下，这次会得出什么结论？"

**投影代码**：

```python
transfer = d.groupby("周次")["是否转人工"].mean()
print("转人工率 第1周:", round(transfer.iloc[0], 4), " 第12周:", round(transfer.iloc[-1], 4))

transfer_seg = d.pivot_table(index="周次", columns="用户群体", values="是否转人工", aggfunc="mean")
print(transfer_seg.round(4))
```

**实测**（已验证）：总体转人工率从第1周1.5%上升到第12周2.6%；分群看，儿童群体转人工率全程明显高于成人群体（儿童群体在1.6%~7.3%之间波动，成人群体稳定在1.2%~2.2%之间）。

**关键提问（迁移巩固的核心）**：

> "转人工率上升了，这是不是又出现了一个'全新的问题'，需要重新做一遍归因？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "是，需要重新分析转人工率变差的原因" | 追问："儿童占比在这12周里发生了什么变化？你在环节四已经算过了。"——引导学员把两件事联系起来 |
| "不是，因为儿童占比上升本来就会同时推高转人工率" | 肯定："对。这不是一个新问题，是**同一个数据漂移（儿童占比上升）同时在多个指标上留下了痕迹**。训练师看到多个指标同时变化时，要先检查是不是已知的同一个根因在起作用，而不是把每个指标当成全新问题逐个重新归因一遍——那样效率很低，还容易把同一个根因拆成好几份互相矛盾的报告。" |

**学员活动**：独立完成转人工率的下钻分析，判断其变化是否可以归因到环节四已识别的同一个根因，写出1-2句结论。

**设计意图**：不引入新计算难度，而是训练"识别同一根因的多指标表现"这一更高阶的分析能力，直接对接实操题第4问"检查日志数据本身是否存在质量问题"所需要的全局视角，以及单选124"优化需求设计首先应基于全面数据分析明确具体成因"。

## 七、板书设计

**主板书区**

```
                 数据漂移 vs 模型退化 vs 概念漂移

模型退化 = 模型自己变差了（判别能力下降）
数据漂移 = 数据本身变了，模型没变（如用户群体结构变化）
概念漂移 = 同样的输入，正确答案变了（"听懂之后该给什么回应"的标准变了）

┌──────────────────── 实测反差 ────────────────────┐
│ 整体识别成功率：第1周91.4% → 第12周82.6%，↓8.8pp   │
│   ├─ 成人群体 92.6%→87.3%，↓5.3pp → 模型退化      │
│   └─ 儿童占比 7.7%→28.8% → 拉低均值↓3.5pp → 数据漂移│
│ 置信度均值：71.7%→67.6%（独立信号，印证模型退化）   │
└──────────────────────────────────────────────────┘

诊断流程：先看总体趋势 → 分群下钻 → 分别归因 → 分别给方案
```

**副板书区（三者辨析 + 判别口诀）**

```
              模型退化           数据漂移              概念漂移
变了什么？    模型能力本身       输入数据分布          输入-输出对应关系
本例证据      成人群体↓5.3pp     儿童占比↑21.1pp        （本例暂未出现，考试爱问）
对策          重新训练/优化模型  补充新结构训练数据      重新定义任务/更新标准

判别口诀：
  数据长什么样变了 → 数据漂移
  同样数据，正确答案变了 → 概念漂移
  模型自己能力降了 → 模型退化
```
