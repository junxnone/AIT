## 一、教学目标

### 知识目标
1. 能说明学习率、Batch Size、Epoch 的含义及设置不当的后果。
2. 能计算 Iteration 数 = 训练集样本总数 ÷ Batch Size。
3. 能说明大 Batch Size "效率高但泛化可能更差"的反直觉结论。

### 技能目标
1. **能依据训练现象反推超参数问题**（Loss不降→学习率过小；Loss震荡/发散→学习率过大；训练集表现好而验证集表现差→过拟合）。
2. 能说明过拟合与欠拟合的判别依据与应对手段。
3. **能用真实数据跑出训练曲线，并据此判断训练是否出现问题**，而不只是凭感觉下结论。

### 素养目标
1. 延续本课程主线——"单一指标持续变好不代表真实目标达成"，这次体现在"训练集Loss持续下降≠模型越来越好"。

---

## 二、教学重点与难点

### 重点

依据训练现象反推超参数问题的诊断路径（先定位"学不动"还是"学过头"，再定位具体参数）。

### 难点

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| 只记住"现象对应哪个原因"的表格，遇到现实中现象描述变化（不是标准措辞）就对不上号 | 把诊断表当成一张死记硬背的对照表，考题换个说法（如用"验证集指标不升反降"代替"过拟合"这个词）就识别不出来 | 不止给结论，**让学员亲手跑出两组真实训练曲线**（过拟合曲线、学习率过大导致发散的曲线），用真实、会变化的数字倒逼学员说出"先判断学不动还是学过头，再定位参数"这条诊断路径，而不是背对照表 |

### 环节一：导入（0–10′）

**教师提问**：

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| 条件反射答"不一定，要看验证集" | 肯定："很好，这是前两课题（Kappa、WER）训练出来的警觉性。今天我们具体讲——为什么会出现'训练集好看、实际不行'这种情况，以及怎么通过调整三个关键超参数去避免它。" |
| 回答"是好事，说明模型学得很好" | 追问："99%是在哪个数据集上算出来的？模型有没有在没见过的数据上测过？"——引导学员意识到"训练集"和"没见过的数据"是两回事 |
| 犹豫不表态 | 鼓励先写下自己当下的直觉判断，不要求马上给出完整理由，"记住你现在的判断，待会儿我们会用真实数据验证它对不对" |

**设计意图**：不急于给结论，让学员先公开表达判断，后面用环节六的真实实验数据回扣验证，冲击力更强。

### 环节二：新授——学习率（10–35′）

**讲授脚本**：
> "神经网络训练的本质是：每一轮算出当前预测的误差（Loss），然后朝着能减小误差的方向调整一步。学习率，决定的就是**这一步迈多大**。"

**板书表格**：

| 学习率 | 后果 | 为什么会这样（机制） |
|---|---|---|
| 太大 | Loss剧烈震荡，极端时数值发散甚至变成NaN | 每一步迈得太猛，**越过了误差最小的那个点**，下一步再往回迈又迈过头，来回"打摆子"，严重时误差越调越大，彻底失控 |
| 太小 | 收敛极慢，容易在局部小坑里打转 | 每一步迈得太碎，走到真正的最优点要花极多轮次，还容易陷进一个不太好的"小坑"出不来 |

**教师追问（检验机制理解）**：
> "为什么学习率太大会'震荡'而不是直接'卡住不动'？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| 答不上来 | 用台阶类比引导："好比你想走到房间正中间，正常脚步能精准停在中间；但如果你每步都迈三米，你会从中间这边跨到那边，再从那边跨回这边，来回跨，永远停不到中间——这就是'震荡'" |
| 答"步子太大容易走过头" | 肯定并补全："对，走过头之后模型会朝相反方向再调整，同样的大步子又会走过头，于是不断来回震荡，而不是停在最优点附近" |

**应对手段讲授**：
> "既然大学习率容易震荡、小学习率收敛太慢，实际工作中常用**学习率调度（Learning Rate Scheduling）**：训练初期用稍大学习率快速逼近，中后期逐步减小做精细调整。还有一个常见做法叫**Warmup**——刚开始学习率从很小值逐渐升到目标值，避免一上来步子太大，把刚初始化、还很不稳定的权重直接冲乱。"

**学员活动**：记录学习率过大/过小的现象与机制，口头举一个"步子太大来回跨"之外自己能想到的类比（如倒车入库时打方向盘过猛来回修正）。

### 环节三：新授——Batch Size（35–55′）

**讲授脚本**：
> "Batch Size，就是每次调整参数之前，先看多少条数据。这里有一个三级考试最爱考的反直觉结论——**不是Batch Size越大越好**。"

**板书权衡表**：

| | Batch Size 较大 | Batch Size 较小 |
|---|---|---|
| 梯度估计 | 更稳定，噪声小 | 噪声大，方向不够准 |
| 训练速度（单步） | 能更充分利用硬件并行，单步更快 | 单步计算量小但步数更多 |
| 内存占用 | 更大 | 更小 |
| 泛化能力 | **可能更差**——容易收敛到"尖锐"局部最优 | 小批次噪声反而有正则化效果，有时泛化更好 |

**教师提问（制造认知冲突）**：
> "直觉上大Batch Size看得数据更多，梯度更准，应该学得更好才对。为什么反而'泛化能力可能更差'？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "大Batch Size更快，但不代表更好" | 肯定，并追问机制："'更快'和'更好'之间到底差了什么？" |
| 说不出机制 | 用地形类比引导："想象误差函数是一片高低起伏的地形，有又窄又深的'尖锐坑'，也有又宽又浅的'平缓坑'。大Batch Size因为梯度估计很稳定、噪声小，容易一头扎进离初始点最近的那个坑，哪怕它是个尖锐坑；小Batch Size的梯度噪声反而像'不停轻轻晃动'，容易把模型从尖锐坑里晃出来，停在更平缓、更稳健的坑里。尖锐坑对训练数据拟合得很紧，但换一批新数据（验证集/测试集），稍微偏一点点就可能大幅掉出坑外——这就是'泛化能力更差'的来源。" |

**板书强调句**：
> **"Batch Size越大、训练越快越好"是错的**——大Batch Size单位时间处理更多数据，但不等于模型最终效果更好。这和"Kappa高不代表标注真的好""WER为0不代表任务设计没问题"是同一类思维模式：**表面的效率/一致性指标，不能替代对最终目标的直接检验。**

**学员活动**：记录权衡表，讨论"如果手头的训练任务对训练速度要求极高、对泛化能力要求一般（如内部实验原型），能不能优先选大Batch Size？"（引导学员意识到超参数选择要结合业务场景权衡，不是非黑即白）。

### 环节五：新授——Epoch与过拟合/欠拟合（70–90′）

**讲授脚本**：
> "Epoch，指模型完整遍历一次全部训练数据。还记得课题0-2提到的概念吗？**Iteration 数 = 训练集样本总数 ÷ Batch Size**，也就是一个Epoch里要做多少次参数更新。"

**举例**：
> "假设训练集10000条数据，Batch Size设100，一个Epoch就包含100次权重更新。"

**板书对照**：

| Epoch | 后果 | 机制 |
|---|---|---|
| 太少 | 欠拟合——训练集上表现本身就不好 | 模型还没来得及学到数据里的规律，训练就结束了 |
| 太多 | 过拟合——训练集越学越好，验证集/测试集表现反而变差 | 训练到后期，模型开始"死记硬背"训练数据里的具体细节（包括噪声），这些细节对训练集"有用"，但对没见过的新数据毫无意义甚至起反作用 |

**关键提问**：
> "那该怎么判断，训练到第几个Epoch该停下来？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "看训练集Loss不再下降就停" | 纠正："训练集Loss几乎总是能持续下降（甚至是靠死记硬背压下去的），单看它判断不出'什么时候开始过拟合'" |
| "同时看验证集表现" | 肯定并讲清判断点："对。**Early Stopping（早停）**的判断依据是：训练集Loss持续下降，但验证集Loss从某个点开始不降反升——这个拐点，就是该停止训练的信号。" |

**学员活动**：记录Early Stopping的判断依据，并思考"如果只监控训练集准确率，为什么永远发现不了过拟合已经发生"。

### 环节六：实操一——真实数据跑出过拟合曲线（90–130′，难点突破的实证基础）

**教师指令**：
> "刚才讲的'训练集越学越好、验证集反而变差'，不要只信我说的，我们在`credit_data.csv`上亲手跑一遍，用真实数字看看这个现象到底长什么样。"

**投影代码**（学员照抄运行）：

```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.neural_network import MLPClassifier
from sklearn.metrics import log_loss, accuracy_score

d = pd.read_csv("../数据集/credit_data.csv")
d["age"] = d["age"].mask((d.age < 18) | (d.age > 100), d.age.median())
d["monthly_income"] = d["monthly_income"].fillna(d["monthly_income"].median())

F = ["age", "monthly_income", "debt_ratio", "credit_history_months", "late_payment_times", "credit_lines"]
X, y = d[F], d["is_default"]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)
sc = StandardScaler().fit(Xtr)
Xtr_s, Xte_s = sc.transform(Xtr), sc.transform(Xte)

# max_iter=1 + warm_start=True：每调用一次fit，就相当于多训练1个Epoch
clf = MLPClassifier(hidden_layer_sizes=(32, 16), solver="adam", max_iter=1,
                     warm_start=True, random_state=42, learning_rate_init=0.01)

checkpoints = [5, 50, 200, 1000]
for epoch in range(1, 1001):
    clf.fit(Xtr_s, ytr)
    if epoch in checkpoints:
        train_loss = log_loss(ytr, clf.predict_proba(Xtr_s))
        val_loss = log_loss(yte, clf.predict_proba(Xte_s))
        train_acc = accuracy_score(ytr, clf.predict(Xtr_s))
        val_acc = accuracy_score(yte, clf.predict(Xte_s))
        print(f"epoch={epoch:4d}  训练Loss={train_loss:.3f}  验证Loss={val_loss:.3f}  "
              f"训练Acc={train_acc:.1%}  验证Acc={val_acc:.1%}")
```

**实测输出**（已验证，学员结果应基本一致，个别位数可能因环境有极小波动）：

```
epoch=   5  训练Loss=0.371  验证Loss=0.387  训练Acc=85.1%  验证Acc=84.3%
epoch=  50  训练Loss=0.333  验证Loss=0.467  训练Acc=87.1%  验证Acc=82.8%
epoch= 200  训练Loss=0.351  验证Loss=0.947  训练Acc=89.8%  验证Acc=79.3%
epoch=1000  训练Loss=0.372  验证Loss=2.188  训练Acc=93.2%  验证Acc=79.7%
```

**学员活动**：填写对比表

| | epoch=5 | epoch=50 | epoch=200 | epoch=1000 |
|---|---|---|---|---|
| 训练Acc | 85.1% | 87.1% | 89.8% | 93.2% |
| 验证Acc | 84.3% | 82.8% | 79.3% | 79.7% |
| 验证Loss | 0.387 | 0.467 | 0.947 | 2.188 |

**关键提问（呼应导入环节）**：
> "训练Acc从85.1%一路涨到93.2%，涨了8个百分点，看起来模型越训越好。但验证Acc呢？从84.3%跌到79.3%附近，验证Loss更是从0.387涨到2.188，涨了近6倍。这和导入环节那个'训练100个Epoch、准确率99%'的假设是不是同一个陷阱？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "数字不完全一样（这里没到99%），所以不算同一个问题" | 纠正方向："具体数字当然会因数据集、模型结构不同而不一样，但**现象的本质完全相同**：训练指标在涨、验证指标在跌，这就是过拟合，不需要刚好涨到99%才算" |
| 正确指出"这是过拟合，训练Loss虽然自己有点波动，但没有和验证Loss一起往上涨，说明模型在训练集上学到的东西，一部分是噪声，对新数据没用甚至有害" | 肯定并追问细节："训练Loss其实没有严格单调下降，在0.33～0.40之间来回波动，这是不是代码写错了？"——引导学员意识到小批量/随机优化本身带噪声是正常现象，**判断过拟合要看验证集的整体趋势，而不是要求训练Loss必须每一步都严格下降** |

**教师总结话术**：
> "这组真实数字给我们的提示是：**不要等到训练集准确率涨到某个吓人的数字（比如99%）才警觉，只要验证集指标开始掉头往坏的方向走，过拟合就已经发生了。** Early Stopping要盯的是验证集这条线的拐点，不是训练集这条线涨到多高。"

### 环节七：实操二——学习率过大导致发散（130–160′）

**教师指令**：
> "刚才环节二讲到学习率太大会震荡甚至发散，现在也用真实数据验证一次。我们固定其他设置不变，只改学习率，对比几组结果。"

**投影代码**：

```python
from sklearn.neural_network import MLPClassifier
from sklearn.metrics import accuracy_score

for lr in [0.01, 50.0]:
    clf = MLPClassifier(hidden_layer_sizes=(32, 16), solver="sgd", max_iter=60,
                         learning_rate_init=lr, random_state=42, momentum=0,
                         n_iter_no_change=1000, tol=0.0)
    clf.fit(Xtr_s, ytr)
    lc = clf.loss_curve_
    print(f"学习率={lr}")
    print(f"  前3轮Loss：{[round(x, 3) for x in lc[:3]]}")
    print(f"  末3轮Loss：{[round(x, 3) for x in lc[-3:]]}")
    print(f"  最终 训练Acc={accuracy_score(ytr, clf.predict(Xtr_s)):.1%}  "
          f"验证Acc={accuracy_score(yte, clf.predict(Xte_s)):.1%}\n")
```

**实测输出**（已验证）：

```
学习率=0.01
  前3轮Loss：[0.706, 0.669, 0.637]
  末3轮Loss：[0.404, 0.403, 0.402]
  最终 训练Acc=84.5%  验证Acc=84.5%

学习率=50.0
  前3轮Loss：[4006.63, 131592416.23, 131546367.87]
  末3轮Loss：[129128646.92, 129083457.43, 129038287.2]
  最终 训练Acc=84.5%  验证Acc=84.5%
```

**关键提问（制造认知冲突）**：
> "学习率0.01，Loss从0.706平稳降到0.402，这是正常收敛。学习率50呢？Loss从4006.63，下一轮直接跳到1.3亿，后面一直在上亿的量级里打转，再也没回到正常范围。这是不是课本里说的'震荡/NaN'？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "这不是NaN，所以不算学习率过大的典型案例" | 纠正："NaN只是数值发散的其中一种表现形式。这里Loss涨到1.3亿这种天文数字，同样代表训练已经彻底失控——本质都是'数值发散、训练失败'，表现形式会因具体框架、具体数据而略有不同，不要死记'必须变成NaN才算'" |
| 注意到两组最终Acc都是84.5%，追问"那学习率0.01是不是也没训好" | 肯定这个观察力："很敏锐。这里只跑了60轮、网络也很简单，lr=0.01确实还没收敛到最优，这组实验的重点不是比较'谁的最终效果更好'，而是比较'Loss曲线的健康程度'——一个在平稳下降，一个已经炸到天文数字，后者不管再训多久都没有意义，因为权重已经被巨大的更新步长破坏了" |

**教师总结话术（点出"没有放之四海而皆准的固定数字"）**：
> "有同学可能会问，学习率多大算'太大'？这里有个真实细节值得注意：这组数据在学习率1甚至10的时候都还能正常收敛，直到50才彻底发散。**这说明'多大算太大'没有一个统一数字，它取决于具体的数据、网络结构和特征缩放。** 判断的办法不是去背一个阈值，而是**实际训练时盯着Loss曲线看**——曲线在合理范围内波动下降是正常的，曲线脱离合理量级往上飞，就是学习率过大的信号，不管它有没有最终变成NaN。"

### 环节八：实操三——诊断训练现象（160–200′，难点突破核心）

**教师发放诊断卡片，布置任务**：

> "刚才两组实验，你们已经亲手见过'过拟合的验证Loss曲线'和'学习率过大的发散曲线'长什么样。现在换一批**现象描述换了说法**的卡片，看看能不能用同样的诊断路径找到答案。每组4张卡片，15分钟，判断原因并写出调整方向。"

| 现象 | 学员诊断 | 标准答案 |
|---|---|---|
| Loss几乎不下降，训练很多轮都没起色 | | 学习率太小/欠拟合→适当增大学习率或检查模型复杂度 |
| Loss剧烈震荡甚至数值变得极大 | | 学习率太大→减小学习率，必要时梯度裁剪 |
| 训练集Loss很低，验证集Loss很高且持续上升 | | 过拟合→Early Stopping、减少Epoch、增加正则化 |
| 训练很快但效果一般，调大Batch Size后效果反而更差 | | Batch Size增大需同步调整学习率，否则梯度估计变化导致收敛位置不同 |

**巡回指导时的追问设计**：若学员只写出"标准答案"而说不出判断路径，追问："你是怎么判断出'这是学不动还是学过头'的？能不能对应到刚才环节六、七亲手跑出的哪条曲线？"——逼迫学员把真实实验经验和抽象现象描述联系起来，而不是凭空套表格。

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| 把"Loss剧烈震荡甚至数值变得极大"误判为"过拟合" | 追问："过拟合的典型标志是什么？是训练集表现好、验证集表现差，还是训练过程本身就不稳定？"——引导回忆环节七的发散曲线，意识到这是"学过头"里的"学习率太大"，不是"过拟合" |
| 能快速答对但说不出机制 | 追问一句"为什么"，要求补全机制层面的解释，不能止步于"背答案" |

**教师总结（难点突破关键话术）**：
> "记住这张表的**诊断逻辑**比记住'现象对应哪个原因'更重要——因为实际考题给的现象描述会千变万化，用词可能和这张表完全不一样，但背后的判断路径是固定的：先定位是'学不动'（欠拟合/学习率小）还是'学过头'（过拟合/学习率大/epoch多），再决定调哪个参数。死记这张表，考题换个说法你就懵了；掌握判断路径，任何现象描述都能套进去——就像刚才两组真实曲线，表述方式和这张卡片完全不同，但背后是同一条诊断路径。"

**汇报与点评（最后5分钟）**：每组汇报1-2张卡片，教师重点点评判别依据而非结论对错。

## 七、板书设计

**主板书区**

```
诊断路径：
  Loss不降 ────────────→ 学不动 → 学习率太小 / 欠拟合
  Loss震荡或数值发散 ───→ 学过头 → 学习率太大
  训练集好验证集差 ─────→ 学过头 → 过拟合（Epoch过多）

┌──────────── 实测：过拟合曲线（credit_data.csv 真实训练）────────────┐
│          epoch=5    epoch=50   epoch=200   epoch=1000             │
│ 训练Acc   85.1% →    87.1% →    89.8% →     93.2%   （持续上涨）   │
│ 验证Acc   84.3% →    82.8% →    79.3% →     79.7%   （掉头向下）   │
│ 验证Loss  0.387 →    0.467 →    0.947 →     2.188   （涨近6倍）    │
└──────────────────────────────────────────────────────────────────┘

┌──────────── 实测：学习率过大→Loss发散（同一数据集）───────────────┐
│ 学习率0.01：Loss 0.706 → 0.402（平稳收敛）                        │
│ 学习率50　：Loss 4006.6 → 1.3亿（彻底发散，无法恢复）              │
└──────────────────────────────────────────────────────────────────┘

主线延伸：训练集指标持续变好 ≠ 模型越来越好
  必须同时监控验证集指标，独立于训练集指标之外做检验
```

**副板书区（三超参数速查 + 判别口诀）**

```
            学习率            Batch Size              Epoch
太大/太多   震荡 / 数值发散    收敛快但可能泛化更差     过拟合
太小/太少   收敛极慢          梯度噪声大（有时泛化更好） 欠拟合

判别口诀：先问"学不动"还是"学过头"，再定位具体是哪个参数
　　　　　学不动 → 欠拟合 / 学习率太小
　　　　　学过头 → 过拟合 / 学习率太大 / Epoch太多
```
