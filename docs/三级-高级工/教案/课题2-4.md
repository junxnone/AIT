## 二、教学重点与难点

**重点**：准确率失效的识别，以及依业务代价选择优化方向（提精确率还是召回率）。

**难点**：学员典型错误预判——**看到84.7%的准确率就认为模型可用**，不去拆解混淆矩阵检查少数类（违约类）的召回率。这是本课程"单一指标变好≠真实目标达成"主线的最强案例，务必让学员亲手算出这个反差，并说出"为什么类别不均衡会让基线准确率天然就很高"这一机制，而不只是停在"样本不平衡"这个现象层面。

## 三、学情分析与前置知识

学员已学完课题2-3（超参数诊断），对"单一指标变好不代表真实达成"这条主线已有三次铺垫，对"要看验证集/要看更深层指标"已形成一定警觉性。本课题是该主线在模型评测场景下最有冲击力的一次实证，需要学员亲手跑出84.7%准确率与84.5%基线的对比，而不是只听教师讲结论。部分学员对scikit-learn的基础API（train_test_split、LogisticRegression）不熟悉，需要在实操环节多加巡回指导。此外，学员在业务代价判断环节容易停留在"记住风控保召回率"这类结论，而说不出"为什么"，是本课题技能目标1要重点纠正的思维惯性。

## 四、教学方法与手段

1. **认知冲突法**（核心）：先让学员看到"高准确率"，再用基线对比戳穿假象。
2. **实操验证法**：所有结论都通过学员亲手运行代码得出，不是教师口头讲解。
3. **分组研讨法**：精确率/召回率的业务权衡判断，用分组讨论强化"先比较代价、再下结论"的思维习惯，而非死记场景与答案的对应表。
4. **错误案例辨析法**：现场展示典型错误判断语句，让学员诊断问题所在，巩固诊断顺序（先看AUC、再查阈值、最后才考虑换模型）。

### 环节一：导入——"模型准确率84.7%，能不能上线？"（0–10′）

> 某金融公司的算法团队训练了一个信用违约预测模型，用于审批阶段自动筛查高风险客户。模型上线前的测试报告显示：
> **测试集准确率 84.7%。**
> 团队负责人看到这个数字，认为"84.7%已经相当不错了"，准备批准模型上线。

**提问话术**：

> "好，记住你刚才的判断和理由。这节课我们会亲手跑出这个84.7%背后真正的情况——你会发现这个数字可能比你想象的更让人担心。"

**设计意图**：延续课题2-3已经建立的"警觉性"，但不直接提示陷阱所在，让学员的第一直觉判断先被公开表达，为环节五的认知冲突蓄力。

### 环节二：新授——混淆矩阵与P/R/F1（10–25′）

**讲授脚本**：

> "要判断刚才那份报告里的84.7%到底靠不靠谱，我们需要比准确率更细的工具——混淆矩阵。"

**板书四格**：

| | 预测为正（违约） | 预测为负（不违约） |
|---|---|---|
| 实际为正（真违约） | TP 真正例 | FN 假负例（漏判） |
| 实际为负（真不违约） | FP 假正例（误判） | TN 真负例 |

**逐项讲解话术**：

> "准确率是最粗的指标——(TP+TN)÷总数，只看'整体判对了多少'，**不区分判对的是正例还是负例**。这正是它会骗人的地方，我们稍后会看到。
>
> 精确率 = TP÷(TP+FP)，回答的是：**我模型说'是违约'的这些人里，真正违约的占多少？**——衡量的是'宁可错杀会不会错太多'。
>
> 召回率 = TP÷(TP+FN)，回答的是：**真正会违约的人里，我模型抓出来了多少？**——衡量的是'有没有漏网之鱼'。
>
> F1是精确率和召回率的调和平均，用于两者都要兼顾、又要用一个数字排序模型时。"

**提问检验**：

> "如果一个模型把100个真实违约客户里的95个都放过去了（预测成'不违约'），这95个属于混淆矩阵里的哪一格？"

（引导学员答出：FN，假负例/漏判）

**学员活动**：记录四格定义与三个公式，对照提问口头复述FN的含义。

### 环节三：新授——准确率陷阱（25–40′）

**讲授脚本**：

> "现在来看准确率为什么不能单独使用。假设一个数据集，99%的样本都是'不违约'，只有1%是'违约'。我训练一个全世界最懒的模型——**它什么都不学，收到任何样本一律判'不违约'**。这个模型的准确率是多少？"

（引导学员计算：99%）

> "99%的准确率，但这个模型**连一行判断逻辑都没有**，纯粹靠数据本身的分布白捡的。这就是类别不均衡数据集的共同陷阱——**负样本占比越高，什么都不做的基线准确率就越高，训练出来的模型想证明自己有价值，就必须明显超过这个基线，而不是贴着它。**"

**板书核心句**：

> **类别越不均衡，"什么都不做"的基线准确率天然就越高——准确率这个数字本身就混进了"蒙对"的成分。**

**学员活动**：心算"如果某数据集违约率只有15.5%，全判不违约的基线准确率是多少"，为环节五铺垫。

（引导学员口算得出 84.5%，但先不点破和84.7%的关系，留到环节五揭晓）

### 环节四：实操一——训练信用评分模型（40–70′）

**教师指令**：

> "打开Jupyter，我们现在就把开头那份'84.7%准确率'的报告，自己跑一遍、拆开看看。"

**投影代码**（学员照抄运行）：

```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix, classification_report, roc_auc_score

d = pd.read_csv("../数据集/credit_data.csv")
d["age"] = d["age"].mask((d.age < 18) | (d.age > 100), d.age.median())
d["monthly_income"] = d["monthly_income"].fillna(d["monthly_income"].median())

F = ["age","monthly_income","debt_ratio","credit_history_months","late_payment_times","credit_lines"]
X, y = d[F], d["is_default"]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)
sc = StandardScaler().fit(Xtr)
m = LogisticRegression(max_iter=1000).fit(sc.transform(Xtr), ytr)

p = m.predict(sc.transform(Xte))
pr = m.predict_proba(sc.transform(Xte))[:, 1]
print(confusion_matrix(yte, p))
print(classification_report(yte, p, target_names=["未违约","违约"], digits=3))
print("AUC", round(roc_auc_score(yte, pr), 3))
```

**巡回指导要点**：

- 检查 `stratify=y` 是否被遗漏——若遗漏，训练集/测试集的违约比例可能不一致，学员跑出的数字会和实测值有偏差，不易复现本课题的关键对比。
- 检查 `StandardScaler` 是否只在训练集 `fit`、测试集只 `transform`，避免数据泄漏（四级已学过的常见踩坑点，此处顺带复查）。
- 若发现学员未处理 `age` 异常值就直接建模，追问："课题2-1学过的数据清洗规范，这里要不要用上？"

**学员活动**：运行代码，记录混淆矩阵、分类报告、AUC的实际输出。

**实测输出核对**（教师口头核对，确保全员一致）：

```
[[499   8]
 [ 84   9]]
准确率 84.7%
违约类：精确率 0.529　召回率 0.097　F1 0.164
AUC = 0.768
```

### 环节六：新授+实操二——阈值与P/R权衡（110–130′）

**讲授脚本**：

> "既然问题在阈值，我们就调阈值试试。默认阈值0.5的意思是：模型预测违约概率只要超过50%，就判'违约'。现在我们把这个门槛降低——降到0.3，意味着只要预测概率超过30%就判'违约'，放宽了判定违约的标准。"

**投影代码**：

```python
p3 = (pr >= 0.3).astype(int)
print(confusion_matrix(yte, p3))
print(classification_report(yte, p3, target_names=["未违约","违约"], digits=3))
```

**学员活动**：运行代码，记录调整前后的对比，填表：

| | 阈值0.5 | 阈值0.3 |
|---|---|---|
| 召回率 | 0.097 | 0.366 |
| 精确率 | 0.529 | 0.500 |

**讲授脚本（解读结果）**：

> "召回率从0.097升到0.366，提升了3.8倍；精确率只从0.529降到0.500，降了2.9个百分点。**用很小的精确率代价，换来大幅召回率提升**——这就是为什么训练师要会调阈值，而不是拿到一个默认阈值的结果就直接下结论。"

**板书核心句**：

> **模型没有变，阈值一调，召回率和精确率此消彼长——这就是"阈值"和"模型能力"是两件事的直接证据。**

### 环节七：新授——ROC曲线与AUC（130–150′）

**讲授脚本**：

> "刚才我们手动试了一个阈值0.3，那如果把所有可能的阈值都试一遍呢？这就是ROC曲线在做的事：**横轴是假正例率，纵轴是召回率（真正例率），画出阈值从1滑到0时，这两个值怎么变化。**"

> "AUC就是这条曲线下方的面积。它的意义在于——**不依赖你选了哪个具体阈值**，只衡量模型把正负样本'排序排得对不对'：随机乱猜的模型AUC是0.5，完美区分正负样本的模型AUC是1。我们这个模型AUC是0.768，说明它确实学到了违约和不违约之间的差异，只是默认阈值没用好这份能力。"

**判别口诀（板书）**：

> **AUC接近0.5 → 模型本身没学到东西，调阈值也救不回来；AUC明显高于0.5但某个阈值下召回率很差 → 问题大概率在阈值，不在模型。**

**学员活动**：记录ROC/AUC定义，用口诀判断本课题的模型属于哪一种情况（AUC0.768明显高于0.5，属于"阈值问题"）。

### 环节八：讨论——精确率vs召回率，该保哪个？（150–170′）

**任务布置**：

> "分三组，每组分到一个业务场景：风控审批、垃圾邮件过滤、医疗筛查。讨论2分钟：这个场景该优先保精确率还是召回率？说出理由，理由里必须包含'漏判的代价'和'误判的代价'各自是什么，不能只说结论。"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| 风控组直接说"保召回率"，说不出为什么 | 追问："漏判一个真实违约客户，公司损失的是什么？误判一个正常客户，损失的又是什么？两者比一比。" |
| 垃圾邮件组说"精确率和召回率都要高" | 肯定方向后追问："如果只能优先保一个，选哪个？想象一封重要的客户合同邮件被误判进垃圾箱，后果是什么？" |
| 医疗筛查组套用风控组的理由，不单独分析 | 追问："医疗筛查和风控审批，'漏判'的后果是不是同一类代价？漏诊和漏放一个坏账客户，哪个更难挽回？" |

**汇报与归纳**（板书三行对比表）：

| 场景 | 该优先保什么 | 为什么 |
|---|---|---|
| 风控审批 | 召回率 | 漏判一个违约客户（坏账）代价远高于误判一个正常客户 |
| 垃圾邮件过滤 | 精确率 | 误判一封正常邮件为垃圾（用户丢失重要信息）代价高于漏掉一封垃圾邮件 |
| 医疗筛查 | 召回率 | 漏诊的代价远高于误诊后进一步检查的代价 |

**教师总结话术**：

> "注意，三个场景里，'该保召回率'出现了两次，但原因不能照抄——风控是因为'坏账'，医疗是因为'漏诊致命'，结论看起来一样，但业务代价的内容完全不同。**判别口诀：先问自己，漏掉一个的代价大，还是错抓一个的代价大？代价在'漏' → 保召回率；代价在'错抓' → 保精确率。**这是三级训练师该有的能力——不是记住三个场景的答案，而是会用这把尺子去量没见过的新场景。"

### 环节九：变式练习——换个场景，重新判断（170–195′）

**教师指令**：

> "现在给你们一个没讨论过的新场景：某电商平台的'高价值客户流失预警模型'，用来识别哪些VIP客户即将流失，以便客服提前挽留。这个模型该优先保精确率还是召回率？独立思考3分钟，写下判断和理由。"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| 直接照搬"风控=召回率"的结论 | 追问："这里的'漏判'代价是什么？'误判'代价又是什么？不要因为都叫'预警模型'就照抄风控的答案。" |
| 答"召回率，因为漏掉一个真正要流失的VIP，公司会损失这个客户" | 追问（深化）："那误判呢？把一个本来不会流失的VIP也标成'即将流失'，公司会多做什么动作？这个动作成本高吗？"——引导得出：误判成本通常只是"多打一个挽留电话"，代价远低于漏判，所以依然偏召回率，但理由要讲清楚，不是套公式 |
| 答"精确率，因为不能打扰正常客户" | 追问："打扰一个客户发一条优惠券，和流失一个高价值客户、被竞争对手挖走，这两个代价差距有多大？" |

**设计意图**：检验环节八是否真正建立了"先比较代价、再下结论"的判断习惯，而不是记住了三个标准答案。

### 环节十：分组互评/错误辨析——常见误判现场纠错（195–215′）

**教师活动**：投影展示3条教师预先准备的"典型错误判断语句"，组织学员分组诊断问题所在。

**典型错误语句（教师预备）**：

| 错误语句 | 应诊断出的问题 |
|---|---|
| "模型准确率84.7%，比基线84.5%高，所以模型有效" | 没有对比召回率等细分指标，只用准确率的微小领先就下结论，忽视了召回率仅0.097这一致命问题 |
| "这个模型召回率这么低，说明模型本身学得不好，要重新选算法" | 跳过了"先看AUC判断模型是否有判别力"这一步——AUC0.768说明模型是有效的，问题更可能出在阈值而非算法选型 |
| "AUC是0.768，所以这个模型的准确率也差不多是76.8%" | 把AUC和准确率混为一谈——AUC衡量的是排序能力，不是某个具体阈值下的判对比例，两者没有换算关系 |

**学员活动**：分组讨论，每组选1条诊断问题所在并说明依据，派代表汇报。

**教师点评要点**：重点点评学员是否抓住"先看AUC、再查阈值、最后才考虑换模型"这个诊断顺序，而不是直接给结论。

## 七、板书设计

**主板书区**

```
                     算法测试与错误分析

混淆矩阵:          预测为正    预测为负
        实际为正     TP          FN(漏判)
        实际为负     FP(误判)     TN

准确率=(TP+TN)/总数   精确率=TP/(TP+FP)   召回率=TP/(TP+FN)

┌──────────────── 实测反差 ────────────────┐
│ 模型准确率 84.7%  vs  全判不违约基线 84.5% │
│ → 仅高0.2个百分点，模型几乎白训练！        │
└────────────────────────────────────────────┘

召回率：0.097(阈值0.5) ──→ 0.366(阈值0.3)   提升3.8倍
精确率：0.529        ──→ 0.500              仅降2.9pp
AUC = 0.768 → 模型本身有判别力，问题在阈值，不在模型
```

**副板书区（业务代价决定优化方向）**

```
场景            保什么     为什么
──────────────────────────────────────────────
风控审批        召回率     漏判违约(坏账)代价 > 误判正常客户(多审一次)
垃圾邮件过滤    精确率     误判正常邮件(丢信息)代价 > 漏判垃圾邮件
医疗筛查        召回率     漏诊代价 > 误诊后复查代价

判别口诀：
  漏掉一个代价大，还是错抓一个代价大？
  代价在"漏" → 保召回率   代价在"错抓" → 保精确率
```

**角落常驻（整个课程主线，每课题都写）**

```
⚠ 单一指标变好 ≠ 真实目标达成
```
