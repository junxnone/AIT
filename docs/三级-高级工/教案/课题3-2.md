## 一、教学目标

### （一）知识目标
1. 能说明人机协同的基本模式（全自动、AI建议+人工确认、人工兜底转接、人工复核抽检）。
2. 能说明置信度阈值、转人工触发条件的设计原则——**阈值不是拍脑袋定的，要同时看准确率和成本**。

### （二）技能目标
1. **能通过数据分析找到单一场景下人工与智能交互的最优方式**。
2. **能设计单一场景下的人机交互最优流程**。

### （三）素养目标
1. 理解交互设计是**数据驱动的权衡决策**，不是凭经验拍脑袋定阈值。

---

## 二、教学重点与难点

### 重点

依据置信度分段的准确率差异设计分层交互流程。

### 难点

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| 设计交互流程时只考虑准确率，不考虑人工成本 | 认为"全部转人工"是最优方案，因为准确率最高；说不出"为什么不能这样做"的具体代价 | 用真实数字制造冲突：人工处理成本是AI的**20倍**（4元 vs 0.2元），转人工后平均处理时长也从65秒拉长到177秒（约2.7倍）。逼问学员"如果全部会话都转人工，这套AI系统存在的意义是什么"，把抽象的"要考虑成本"落实成具体的数字权衡 |

## 三、学情分析与前置知识

学员已学完课题3-1（系统监控），对"数据驱动分析"的操作模式已经熟悉，本课题是把分析结果用于"设计"而非"诊断"，是分析能力向设计能力的一次转化训练。常见认知偏差是把"交互设计"简单理解为界面好不好看，而不是流程逻辑的设计——需要在导入环节及时纠正。

---

## 四、教学方法与手段

1. **数据驱动设计法**：所有设计决策都要求有数据支撑，不接受"凭经验"的表述。
2. **成本效益对比法**：用具体的成本数字（4元 vs 0.2元）和时长数字（65秒 vs 177秒）打破"准确率优先"的单一思维。
3. **真实试题情境法**：实操任务直接采用实操试题代码3.2.1的真实场景设定（当前系统统一按置信度0.6转人工），让学员在课堂上就完成一次近似实考的任务。

### 环节一：导入（0–15′）

**讲授脚本**：

> "大家平时用智能客服，有没有遇到过这种情况：问了一个问题，AI开始答非所问，这时候你最希望发生什么？"

（引导学员答出"转人工"）

> "反过来，如果AI答得又快又准，你还希望每次都要先经过人工确认一遍吗？"

（引导学员答出"不需要"）

> "那问题来了——作为设计这套系统的训练师，你怎么知道'什么时候该转人工，什么时候不用'？总不能靠感觉。系统里有一个数字叫'置信度'，从0到1，表示AI对自己回答的自信程度。现在请大家写下一个具体数字：置信度要达到多少以上，你觉得就可以完全不需要人工介入了？"

（学员各自写下猜测，先不评判）

> "好，这个数字先放一边，别忘了它。这节课我们不靠猜，而是把真实数据跑出来验证——课的最后我们会回来看，你的猜测和真实数据差多远。"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| 直接给出一个具体数字（如"0.8以上"） | 不评判对错，记下来："好，这是你的猜测，待会儿用真实数据验证" |
| 说"看情况，不同场景不一样" | 肯定并追问："很好的直觉——那'情况'具体指什么？你觉得真实场景里，置信度和正确率是什么关系？" |
| 答不上来 | 引导："换个问题，你点外卖的时候，骑手定位显示'还有2分钟到'和'还有40分钟到'，你对这两条信息的信任程度一样吗？AI的置信度就是类似的'自信程度提示'" |

**设计意图**：先让学员公开写下一个主观猜测的阈值，制造悬念和记忆锚点，为后续数据反转做铺垫。

---

### 环节二：新授——人机协同模式（15–35′）

**讲授脚本**：

> "设计人机交互流程，第一步不是定阈值，是先认识清楚有哪些'模式'可以选。"

**逐项讲解**（板书 + 举例）：

| 模式 | 适用场景 | 本课题对应置信度区间 |
|---|---|---|
| 全自动 | AI判断高度可靠，人工介入反而增加成本和延迟 | 待数据验证（见实操一） |
| AI建议 + 人工确认 | AI有一定判断力但不够可靠，人工快速把关 | 待数据验证 |
| 人工兜底转接 | AI判断不可靠或超出能力范围，直接转人工 | 待数据验证 |
| 人工复核抽检 | 事后质量监控，不影响实时流程 | 全区间均可叠加 |

**教师提问**：

> "注意第四种'人工复核抽检'和前三种不一样——前三种是在回答用户的那一刻就决定走哪条路，第四种是事后的，它和前三种冲突吗？"

（引导学员答出：不冲突，可以叠加在任何模式之上，作为质量监控手段，不影响实时响应速度）

**学员活动**：记录四种模式定义，口头举一个自己接触过的场景（如订票系统、医疗问诊）里可以套用这四种模式的例子。

**设计意图**：先建立"选项清单"，让学员知道"有哪几种牌可以打"，再在后续环节用数据决定"该打哪张"。

---

### 环节三：新授——成本效益与阈值设计原则（35–55′）

**讲授脚本**：

> "光知道有几种模式还不够，核心问题是：阈值切在哪？切得太高，AI该自动处理的也转了人工，浪费钱；切得太低，该转人工的留给AI处理，用户体验差、还可能出错。"

**引入成本数据**：

> "先看一组硬数字：这批客服数据里，AI每处理一次会话平均成本**0.2元**，转人工处理一次平均成本**4元**——人工是AI的**20倍**。而且不只是钱，转人工的会话平均处理时长是**177秒**，AI独立处理只要**65秒**，接近3倍。人工坐席数量有限，处理时间越长，排队的人就越多，这也是一种隐性成本。"

**揭露现状阈值的真实漏洞**（铺垫实操二的真实试题场景）：

> "这套系统目前的实际策略是：统一按**置信度0.6**作为转人工的分界线——低于0.6转人工，0.6以上一律AI自动处理。乍一听挺合理，是不是？我们来看细一点的数据。"

**投影代码**（教师演示，不要求学员此刻动手，后面实操一会让学员自己跑）：

```python
import pandas as pd
d = pd.read_csv("../数据集/cx_interaction.csv")
for lo, hi in [(0.0, 0.6), (0.6, 0.7), (0.7, 0.8), (0.8, 0.9), (0.9, 1.01)]:
    m = (d["AI置信度"] >= lo) & (d["AI置信度"] < hi)
    print(f"[{lo},{hi}): 样本{m.sum()}, 正确率{d.loc[m,'AI回答正确'].mean():.1%}")
```

**实测结果（已验证）**：

```
[0.0,0.6): 样本899,  正确率52.7%
[0.6,0.7): 样本744,  正确率50.0%
[0.7,0.8): 样本949,  正确率82.8%
[0.8,0.9): 样本884,  正确率83.0%
[0.9,1.01): 样本524, 正确率96.2%
```

**关键提问**：

> "看第二行——置信度**0.6到0.7**这个区间，正确率只有**50.0%**，跟抛硬币没区别。按现状策略，这个区间已经高于0.6，完全由AI自动处理，**没有任何人工介入**。这合理吗？"

（预期学员反应：多数会意识到不合理）

**板书核心句**：

> **阈值不是经验数字，是业务规则的量化表达。现状阈值0.6只是"一刀切"，没有看清0.6-0.7这一段其实和<0.6一样不可靠。**

**教师小结**：

> "这就是本课题实操任务的真实出发点——你们待会儿要做的，正是去诊断这套系统现在的阈值设计有没有问题，然后给出一个更合理的分层方案。"

### 环节四：实操一——置信度分段分析（55–80′）

**教师指令**：

> "打开终端或Jupyter，我们来跑一下官方的三段式分析——看看按0.7和0.9两个分界点划分，三个区间各自的表现和成本如何。"

**投影代码**（学员照抄运行）：

```python
import pandas as pd

d = pd.read_csv("../数据集/cx_interaction.csv")
for lo, hi in [(0.0, 0.7), (0.7, 0.9), (0.9, 1.01)]:
    m = (d["AI置信度"] >= lo) & (d["AI置信度"] < hi)
    print(f"置信度[{lo},{hi}): 样本{m.sum()}, 正确率{d.loc[m,'AI回答正确'].mean():.1%}")

print("人工平均成本:", d[d["是否转人工"] == 1]["处理成本元"].mean())
print("AI平均成本:", d[d["是否转人工"] == 0]["处理成本元"].mean())
```

**实测结果（已验证，学员结果应完全一致）**：

```
置信度[0.0,0.7): 样本1643, 正确率51.5%
置信度[0.7,0.9): 样本1833, 正确率82.9%
置信度[0.9,1.01): 样本524, 正确率96.2%
人工平均成本: 4.0
AI平均成本: 0.2
```

**学员活动**：运行代码，填写数据依据表：

| 置信度区间 | 样本数 | 正确率 | 初步判断该用哪种模式 |
|---|---|---|---|
| [0.0, 0.7) | 1643 | 51.5% | |
| [0.7, 0.9) | 1833 | 82.9% | |
| [0.9, 1.01) | 524 | 96.2% | |

**设计意图**：学员亲手跑出和实际操作技能试题完全一致的核心数据，为后续设计任务打下不可动摇的事实基础。

### 环节六：难点突破——全部转人工行不行（90–110′）

**教师引导设计提问**：

> "现在数据都有了：≥0.9 正确率96.2%，<0.7只有51.5%。既然准确率最重要，为什么不干脆把所有会话都转人工，这样整体正确率岂不是更高？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "既然全转人工准确率最高，为什么不这样做" | 追问："人工成本是AI的20倍，如果全部会话都转人工，这套AI系统还有存在的意义吗？"——引导意识到引入AI客服的初衷就是降本增效，全转人工违背了这个初衷 |
| 设计阈值时只写"置信度高就自动，低就转人工"，不给具体数值 | 追问："高是多高？具体切在哪个数字？依据是什么？"——逼迫学员把判断落到具体的、有数据支撑的阈值上 |
| "那时长也要算吗？转人工不是更让用户满意吗" | 追问："转人工组满意度确实更高（3.79 vs 3.42），但处理时长从65秒变成177秒，接近3倍。如果所有会话都这样，坐席忙得过来吗？排队变长，满意度还会一直更高吗？" |

**学员活动**：填写对比表

| | 全自动（AI独立） | 转人工 |
|---|---|---|
| 平均处理成本 | 0.2元 | 4元（20倍） |
| 平均处理时长 | 约65秒 | 约177秒（约2.7倍） |
| 平均满意度 | 3.42 | 3.79 |

**教师总结话术**：

> "交互设计不是凭感觉'我觉得应该这样'，而是**拿数据说话**——置信度每个区间的真实正确率是多少，人工和AI的成本、时长差多少，这些数字摆出来，阈值该切在哪基本就清楚了。这是三级'设计者'能力的核心——设计不是拍脑袋，是用数据支撑的权衡决策。"

**回扣导入**：

> "现在回到开头你们写的那个猜测阈值。多数人猜的数字，要么偏高（觉得要很有把握才敢自动），要么偏低（低估了中间区间的风险）。真实答案不是靠猜，接下来的实操任务，你们要自己用数据把这个阈值定出来。"

### 环节七：实操二——设计分层交互流程（110–170′）

**任务书**（与操作技能试题代码3.2.1场景一致）：

> 某客户体验管理智能系统的AI客服当前统一按置信度**0.6**作为转人工阈值。公司希望你分析数据，判断该阈值是否合理，并设计更优的人机交互流程。
>
> 1. 分析不同置信度区间下AI回答的正确率，为交互流程设计提供数据依据。
> 2. 设计分层人机交互流程（**不能只以"追求最高准确率"为目标**，需同时考虑人工处理成本）。
> 3. 为你的流程设计补充异常/降级路径和效果度量指标。

**方案必备要素**（教师给模板，学员填充）：

```
一、置信度分段与正确率数据（至少三个区间）
二、成本数据引用（人工 vs AI成本差异，用于支撑第三部分的论证）
三、分层交互流程设计
    置信度≥0.9  → 处理方式？理由？
    置信度0.7–0.9 → 处理方式？理由？
    置信度<0.7  → 处理方式？理由？
    对"当前阈值0.6是否合理"给出明确结论
四、异常与降级路径（如人工坐席全忙时怎么办）
五、效果度量指标（至少3项，如满意度、处理成本、转人工率）
```

**教师点拨要点**：

> "三个地方最容易写得不合格：
>
> **第一，只谈准确率，不谈成本权衡。** 这是这道题配分最高的一个点——写'全部转人工准确率最高'不给成本分析，只能拿一半分甚至更低。
>
> **第二，异常路径只字不提。** 人工坐席不是永远有空的，坐席全忙时你的流程怎么办？这是实操评分表里独立配分的一项。
>
> **第三，效果指标只写一项。** 只写'转人工率'不够，至少要覆盖满意度、成本、转人工率这几个维度，单一指标不能说明设计是否真的达成了目标。"

**巡回指导**：重点检查学员是否明确回答了"当前阈值0.6是否合理"这一问（常见遗漏：只给出新方案，不对现状做评判）。

**对完成快的学员的追问**：

> "如果公司告诉你，人工坐席这个月成本预算要砍一半，你的分层方案要怎么调整？阈值会往哪个方向移动，为什么？"

### 环节八：分组互评与典型错误诊断（170–195′）

**教师活动**：投影展示教师预先准备的2-3份"典型不合格方案"，组织学员分组诊断。

**典型错误样例与应诊断出的问题**：

| 典型错误 | 应诊断出的问题 |
|---|---|
| 方案只写"置信度≥0.6自动，<0.6转人工"，照搬现状，没有分析0.6-0.7区间 | 没有真正分析数据就得出"现状合理"的结论，漏掉了0.6-0.7区间正确率只有50.0%这一关键发现 |
| 流程图画了三层，但没写人工坐席全忙时怎么办 | 缺少异常/降级路径，评分表中独立配分 |
| 效果指标只写了"转人工率要低" | 指标片面，没有同时看满意度和成本，可能为了压低转人工率而牺牲准确率 |

**学员活动**：分组讨论，每组派代表指出至少1处问题并给出修改建议。

### 环节九：变式练习——现状策略漏洞诊断（195–220′）

**教师指令**：

> "现在换个角度：不是让你从零设计，而是让你当'质检员'，去挑现状策略的毛病。现状是：置信度<0.6时，系统实际只转了其中72.2%到人工，另外27.8%还是AI自己处理；0.6以上则完全没有人工介入。这个现状，你能挑出几个毛病？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "现状看起来还行，转人工比例不算高，成本控制得不错" | 追问："成本控制得好，代价是什么？<0.6区间里，还有27.8%正确率只有52.7%的会话完全由AI独立处理，这意味着什么样的用户体验？" |
| 找到"0.6-0.7区间完全没有人工介入"这一点 | 肯定并追问："如果按你们的分层方案，这个区间应该怎么处理？现状和你们的方案差在哪？差的这部分，风险有多大（样本量744条）？" |
| 答不上来 | 引导："回忆环节三的那张细分表——0.6到0.7这一段的正确率是多少？和<0.6相比差多少？" |

**学员活动**：独立或分组列出现状策略的至少两处漏洞，并说明各自对应的真实数据依据。

**参考漏洞点**：
1. <0.6区间仅72.2%被转人工，剩余27.8%（约250条）仍由AI独立处理，而该区间整体正确率只有52.7%。
2. 0.6-0.7区间（744条，占比18.6%）正确率只有50.0%，与<0.6区间几乎无差别，却因为"数字上高于0.6"被完全划入自动处理，没有任何人工把关。
