## 二、一个现象，可能有不止一个原因

本课题用一个真实场景说明三级业务分析的核心能力：**不要找到第一个问题就停止分析**。

**数据**：某自动化营销项目的曝光→点击→加购→下单→支付五环节漏斗数据（`数据集/marketing_funnel.csv`），分渠道、分周次记录。

### 第一步：看总体转化率

```python
import pandas as pd
d = pd.read_csv("../数据集/marketing_funnel.csv")
agg = d.groupby("渠道")[["曝光量","点击量","加购量","下单量","支付量"]].sum()
agg["点击率"] = agg.点击量 / agg.曝光量
agg["加购率"] = agg.加购量 / agg.点击量
agg["下单率"] = agg.下单量 / agg.加购量
agg["支付率"] = agg.支付量 / agg.下单量
print(agg.round(3))
```

**实测结果**：

| 渠道 | 点击率 | 加购率 | 下单率 | 支付率 |
|---|---|---|---|---|
| A | 5.1% | 27.0% | 10.8% | 91.1% |
| B | 3.0% | 27.7% | 10.8% | 90.5% |
| C | 6.2% | **3.0%** | 10.6% | 87.0% |
| D | 4.3% | 26.7% | 10.8% | 90.1% |

**第一个发现（全局瓶颈）**：所有渠道的"加购→下单"转化率都只有约 **10.8%**，远低于"加购率"（~27%）和"支付率"（~90%）。**这是一个全局性瓶颈**——无论哪个渠道，用户到了购物车之后，大部分都没有继续下单。

### 第二步：别停在这里——分渠道下钻

**如果你只报"加购→下单转化率低，建议优化下单流程"就提交了，这个方案对渠道C完全不对症。**

看渠道C这一行：加购率只有 **3.0%**，而其他渠道都在 27% 左右。**这是一个局部异常**，和刚才的全局瓶颈是两个完全独立的问题——渠道C的问题根本不在"加购→下单"，而在更前面的"点击→加购"环节。

**为什么总体汇总表看不出渠道C的异常？**

这是本节最容易被忽略的一点：渠道C的加购率从27%掉到3%，差距这么大，为什么汇总表没有直接暴露出来？

**机制**：总体指标是四个渠道加总之后算出来的——只要渠道C不是流量绝对主导的那个渠道，它的极端值就会被A、B、D三个正常渠道的数据"平均"稀释掉，总体层面依然会落在看起来正常的区间。换句话说，**总体数字正常，不代表每一个子群体都正常**——这也是为什么漏斗分析强制要求"必须下钻"，而不是看一眼总体数字就收工。

把两种写法并排对比：

| | 只报全局瓶颈（常见错误写法） | 完整报告（两个发现都报） |
|---|---|---|
| 问题定位 | "加购→下单转化率低，建议优化下单流程" | 同上 + "渠道C加购率仅3.0%，远低于其他渠道的27%，问题出在点击→加购环节" |
| 对渠道C的效果 | 完全不对症——渠道C的真实问题依旧存在 | 渠道C被单独立项排查，问题可被真正解决 |
| 实操得分 | 只覆盖了一半的问题，只能拿到部分分 | 两个独立发现均覆盖，不漏判 |

> 🔑 **判别口诀**：下钻之后看，是不是**所有**子群体都有同样的问题？
> 是 → 全局瓶颈（需要全局方案）。不是，只有个别子群体异常 → 局部异常（需要针对该子群体单独诊断、单独出方案）。

### 第三个发现（时序异常，可选深入）

```python
b = d[d["渠道"]=="B"]
before = b[b["周次"]<5]
after = b[b["周次"]>=5]
print("第5周前曝光均值:", before["曝光量"].mean(), " CTR:", before["点击量"].sum()/before["曝光量"].sum())
print("第5周后曝光均值:", after["曝光量"].mean(), " CTR:", after["点击量"].sum()/after["曝光量"].sum())
```

**实测**：渠道B第5周前曝光均值约5.9万/周，CTR约4.85%；第5周后曝光均值翻倍到约12.8万/周，但CTR腰斩到约2.43%。**投放量增加了，但流量质量下降了**——这是第三个独立问题，体现在时间维度而非渠道维度。

**为什么渠道维度的下钻查不出这个问题？** 按渠道汇总时，渠道B整个统计周期内的数据会被合在一起算一个平均CTR——前5周高、后面低，两段数据相互抵消后，算出来的"渠道B整体CTR"看起来可能还在正常范围，**阶段性的变化趋势会被平均值掩盖**。只有专门按周次切片对比，才能看到"投放质量从第5周开始下降"这种渐变过程。

> 📌 **核心方法**：先看总体转化率定位"哪个环节整体最差"，再**分维度下钻**（渠道/时间/人群）——全局瓶颈和局部异常往往同时存在，而且需要完全不同的优化方案。

## 三、优化方案怎么写

一份合格的业务模块优化方案须包含：

1. **问题定位**（分清全局瓶颈 vs 局部异常，不要混为一谈）
2. **根因假设**（为什么会出现这个问题，可能有多个假设）
3. **优化方案**（针对每个独立问题分别给方案，不能用一个方案覆盖所有问题）
4. **可度量的成功指标**（如"下单率从10.8%提升到15%"，而非"提升转化率"这类无法验证的表述）
5. **推动实现的路径**（涉及的角色、数据支持、验证方式）

**第4点最容易被写成空话，但也是最容易丢分的地方。** 对比这两种写法：

| | 不合格写法 | 合格写法 |
|---|---|---|
| 目标表述 | "将下单率尽可能提升" | "将下单率从10.8%提升至15%以上，观察周期4周" |
| 问题 | "尽可能"没有具体数字和时间点 | 有明确的起点、目标值、观察周期 |
| 后果 | 4周后根本无法判断方案是否生效——涨到11%算不算达成？ | 4周后对照15%这个数字，一眼就能判断达成与否 |

**为什么"可度量"是硬性要求，而不只是写作规范？** 因为目标写不清楚，就没有验证的起点——训练师提出的方案到底有没有效果，没法被考核，后续是继续执行还是调整，也没有判断依据。一份"尽量提升"的方案，哪怕执行得再认真，交付时也拿不出任何能证明自己做对了的证据。

> 🔑 **判别口诀**：这个目标写出来后，能不能在未来某个时间点，拿一个具体数字去验证"达成了"还是"没达成"？
> 能 → 合格目标。只有"尽量""提升""优化"这类词、没有数字和周期 → 需要重写。

**第5点"推动实现的路径"**同样不能写空话。要具体说明：这个方案需要产品、技术、运营等哪些角色配合推动；需要监测哪些后续数据来验证效果；多久之后回看一次指标。缺了这部分，方案就只是一个"想法"，没有落地路径。

## 考点清单

| 考点 | 考试怎么考 | 易错点 |
|---|---|---|
| 全局瓶颈 vs 局部异常 | 实操核心考点 | **只报一个问题，漏掉同时存在的第二个独立问题** |
| 优化方案的可度量性 | 实操评分点 | 写"提升转化率"而非具体可验证的数字目标 |
| 下钻分析方法 | 简答/实操 | 只看总体汇总数字，不做维度拆解 |

## 随堂练习

**练习 1**：某数据分析发现整体转化率偏低，分渠道下钻后发现各渠道该环节转化率都差不多。这说明什么？下一步该怎么下钻？

<details><summary>答案</summary>说明问题不在渠道维度，是真正的全局性瓶颈（如页面设计、支付流程本身的问题）。下一步应换维度下钻，比如按设备类型、按用户新老、按时间段分析，而非继续在渠道维度打转。</details>

**练习 2**：为什么"漏斗分析必须做渠道/人群下钻，不能只看总体一个数字"？

<details><summary>答案</summary>因为总体数字是各渠道/人群加权平均的结果，会掩盖某个渠道或群体的局部异常。例如本课题案例中，总体漏斗显示"加购→下单"是全局瓶颈，但只有下钻到渠道维度才能发现渠道C存在"点击→加购"这个完全独立的局部问题——不下钻就会漏掉这个发现，提交的优化方案也只能覆盖一半问题。</details>

**练习 3**：某学员提交的优化方案写道"渠道C和其他渠道一起优化下单流程即可"。这个方案的问题是什么？

<details><summary>答案</summary>渠道C的真实问题在"点击→加购"环节（加购率仅3.0%），不在下单环节。用同一个"优化下单流程"的方案覆盖渠道C，完全不对症，无法解决渠道C的真实问题。应针对渠道C的加购环节单独设计方案（如排查流量质量、落地页体验），而非用全局方案一刀切。</details>

**练习 4**：渠道B第5周后曝光量翻倍但点击率腰斩，这个发现是从哪个维度下钻出来的？和渠道维度的下钻有何不同？

<details><summary>答案</summary>这是从**时间维度**下钻发现的，和渠道维度下钻是两个不同的分析角度。渠道维度回答"哪个渠道有问题"，时间维度回答"问题是什么时候开始出现的"。两种下钻方式互补，只做渠道维度下钻会错过这类随时间推移才显现的问题（如某渠道投放质量的阶段性下降）。</details>

**练习 5**：一份优化方案写"将下单率尽可能提升"，这个表述合格吗？应该如何修改？

<details><summary>答案</summary>不合格，因为"尽可能"不是可度量、可验证的目标。应修改为具体数字和观察周期，如"将下单率从10.8%提升至15%以上，观察周期4周"。可度量的目标才能在方案落地后判断是否真正达到了预期效果。</details>

## 小结

| 要点 | 一句话 |
|---|---|
| 核心原则 | 一个现象可能有不止一个独立原因 |
| 分析方法 | 先看总体 → 分维度下钻（渠道/时间/人群） |
| 方案要求 | 针对不同问题给不同方案，指标须可度量 |
