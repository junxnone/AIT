## 一、清洗不是"调用几个标准函数"

四级/五级做清洗，是拿到既定规则去执行。三级要**自己设计这套规则**，而设计规则的核心难点不是技术，是**判断力**。

常见数据质量问题类型：

| 类型 | 典型表现 |
|---|---|
| 重复 | 完全重复行、主键重复 |
| 缺失 | 空值、空字符串 |
| 异常 | 超出合理范围的数值、非法取值 |
| 噪声 | HTML标签、emoji、个人信息、超长/超短文本 |
| 格式不一致 | 编码混乱、大小写/全半角混用 |

发现问题只是第一步，更关键的是**怎么处理**。处理方式只有三种：**删除、替换、标记**，选哪一种不是凭感觉：

> **判别口诀**：这条信息删掉后，会不会损失本可以保留的语义？
> 会 → 优先**替换**（如个人信息脱敏，保留其余语义）；
> 不会 → 可以**删除**（如完全重复、空文本）；
> 拿不准 → **标记**流转人工复核，不要自己瞎猜。

**关键原则**：清洗规则的阈值要有业务依据，不能拍脑袋。

> 举例：某学员的清洗规则写"删除所有超过100字的评价"，另一学员写"删除超过200字**且内容高度重复**的评价"。哪个更合理？
>
> 第一种规则武断——长评价不一定是垃圾数据，可能是用户认真写的详细体验。第二种加了"高度重复"这个判定条件，更贴近真实业务场景（刷屏灌水）。**清洗规则不是"多删等于多干净"，是"删对地方"。**

每条规则写出来后，自己要能回答：**这条规则会不会把有价值的真实数据误删？**

阈值的依据不止一种来源：有的来自数据本身的异常模式（如"超长+高度重复"才判定为刷屏），有的来自字段既定的业务定义域（如评分字段的合法取值是 1–5，这不是训练师主观定的，是系统设计时就有的规则）。**区分"我设计的判定条件"和"系统本来就规定的取值范围"，能帮你快速判断一个阈值到底该不该质疑。**

## 二、回到开头：两行代码到底处理了多少问题？

揭晓答案前，先看真实样本：

```python
import pandas as pd
df = pd.read_csv("../数据集/data.csv")
print(df.shape)
print(df["review_text"].sample(15, random_state=1).to_string())
```

抽样会发现：完全重复、空文本、HTML标签、emoji、超长刷屏、超短文本、含手机号邮箱、非法评分（0或6）这些问题都真实存在。

现在用代码逐项检视，验证开头的判断：

```python
import pandas as pd
df = pd.read_csv("../数据集/data.csv")

print("完全重复行:", df.duplicated().sum())
print("review_id重复:", df.duplicated(subset=["review_id"]).sum())
print("空文本(空字符串):", (df["review_text"].astype(str).str.len() == 0).sum())
print("真正的NaN缺失:", df["review_text"].isna().sum())
print("超短文本(<3字):", (df["review_text"].astype(str).str.len() < 3).sum())
print("超长文本(>200字):", (df["review_text"].astype(str).str.len() > 200).sum())
print("非法rating:", (~df["rating"].between(1, 5)).sum())
```

**实际运行结果**（已在试题库实操题 2.1.1 参考答案中验证通过，你的结果应与此一致）：

```
完全重复行: 40
review_id重复: 0
空文本(空字符串): 31
真正的NaN缺失: 0
超短文本(<3字): 57
超长文本(>200字): 19
非法rating: 10
```

把两行代码能处理的和实际要处理的并排对比：

| | 两行标准代码 `dropna().drop_duplicates()` | 实际问题规模 |
|---|---|---|
| 完全重复 | 处理了 ✅ | 40 条 |
| 空文本 | **没处理** ❌ | 31 条 |
| 超短 / 超长 / 非法评分 | **没处理** ❌ | 合计 86 条 |
| HTML / emoji / 手机号邮箱 | **从未触碰**（这类是替换，不是删除） | 需要逐类正则处理 |

### 为什么 `dropna()` 对空文本完全无效？——这才是机制

看第二行一个反直觉的细节：**"真正的 NaN 缺失"是 0，但"空文本"有 31 条。**

`dropna()` 判断的标准是**单元格里有没有存值**，它只认 pandas 语义上的缺失值 `NaN`。而这 31 条问题样本，表现形式是**空字符串 `''`**——单元格里确实"有值"，只是这个值恰好是空的。`dropna()` 认不出这种情况，一条都不会删。

> 📌 **这就是"调用标准函数"这件事最容易出错的地方**：函数认的是**技术上的"缺失"**，不是**业务上的"无效"**。两者看起来很像，实际完全是两回事。

再加上超短文本57条、超长文本19条、非法评分10条——这三类问题和"重复""缺失"都不沾边，`drop_duplicates()` 和 `dropna()` 天生就管不到。合计 **117 条问题**（31+57+19+10），两行标准代码从头到尾没有处理过一条。

更不用说 HTML 标签、emoji、手机号邮箱——它们根本不涉及"删除整行"，而是要在文本内容**内部做替换**。两行代码从未触及"替换"这个维度。

### 回到开头的判断

**现在回答：这批数据清洗完成了吗？**

**没有。** `drop_duplicates()` 处理了 40 条完全重复，这是两行代码唯一真正起作用的地方。剩下至少 117 条行级问题、外加若干需要文本内替换的噪声，全部没有处理。"调用了标准函数"和"清洗完成"之间，差着一整套需要自己设计判定依据的规则。

## 三、完整清洗规则该怎么写

### 清洗规则示例（节选）

| 处理对象 | 处理方式 | 判定依据 |
|---|---|---|
| 完全重复记录 | 整行去重 | **为什么**：重复样本会让模型在训练时对这条特定表述反复加权，产生"虚假共识"的学习信号，造成过拟合 |
| HTML标签 | 正则剥离 `<...>` | **为什么**：标签是采集阶段残留的系统噪声，不是用户真实表达；不剥离，模型可能学到标签符号与情感的伪相关，而非文本本身的语义 |
| 个人信息（手机号/邮箱） | 替换为占位符，不整条删除 | **为什么**：整条删除会连带丢掉该样本中其他有效的情感语义；用占位符替换，既满足脱敏合规要求，又保留了样本的可用性——脱敏保护的是隐私，删除会额外损失数据价值，这是两件不同的事 |
| 超长文本（>200字） | 整条剔除 | **为什么**：经查为刷屏灌水样本而非真实评价；若保留，还会在文本长度相关特征上引入和情感本身无关的干扰 |
| 非法 rating（不在1-5） | 剔除 | **为什么**：字段的业务定义域是1-5，0或6只能是录入或埋点环节出的错，不是真实评分，留着会让模型学习一个不存在的标签取值 |

### 两种做法的正反对比

> ❌ **只写处理方式，不写判定依据**：
> "删除超长文本" —— 这句话本身没有错，但评分表里"判定依据"是**独立配分**的一项，光写处理方式拿不到这部分分数，而且下次换一批数据，你自己都答不上来"多长算超长"。
>
> ✅ **处理方式 + 判定依据**：
> "删除超过200字且内容高度重复的文本，判定依据：经抽样核实为刷屏类好评模板，并非真实详细体验" —— 这句话既说清楚做什么，也说清楚为什么能这么做，换一批数据你还是能复用这套判断逻辑。

### 清洗代码

```python
import re

df = pd.read_csv("../数据集/data.csv")
n_raw = len(df)

df = df.drop_duplicates()
df["review_text"] = df["review_text"].astype(str)
df["review_text"] = df["review_text"].str.replace(r"<[^>]+>", "", regex=True)
df["review_text"] = df["review_text"].str.replace(r"1[3-9]\d{9}", "[手机号]", regex=True)
df["review_text"] = df["review_text"].str.strip()

length = df["review_text"].str.len()
df = df[(length >= 3) & (length <= 200)]
df = df[df["rating"].between(1, 5)]

df.to_csv("data_cleaned.csv", index=False, encoding="utf-8-sig")
print(f"清洗前 {n_raw} 行 → 清洗后 {len(df)} 行")
```

> 💡 完整清洗规则与代码（含 emoji 处理、空文本处理等全部9条规则，实测清洗前1040行→清洗后883行，保留率84.9%）见试题库实操题 2.1.1 参考答案。本课题重点练习"设计思路"，课题2-2会在此基础上继续制定标注规范。

## 随堂练习

**练习 1**：清洗规则"删除所有包含数字的评价文本"是否合理？为什么？

<details><summary>答案</summary>不合理。包含数字的评价可能是真实有效信息（如"用了3天就坏了"），该规则会误删大量有价值数据。应该针对具体问题（如手机号、邮箱这类个人信息）做定向处理，而不是用"包含数字"这种过度宽泛的条件一刀切。</details>

**练习 2**：为什么"删除超过100字的评价"和"删除超过200字且内容高度重复的评价"这两条规则，后者更合理？

<details><summary>答案</summary>前者是武断的一刀切，会把用户认真写的详细使用体验也误删，因为评价长度本身不是判断垃圾内容的可靠依据。后者加了"高度重复"这个判定条件，贴近真实业务场景（刷屏灌水的典型特征是内容重复），不会误伤真实的长篇评价。</details>

**练习 3**：制定清洗规则时，自我检验的核心问题是什么？

<details><summary>答案</summary>这条规则会不会把有价值的真实数据误删？每条规则写出来后都要能回答这个问题，回答不上来说明规则本身需要重新设计判定依据，而不是急于执行。</details>

**练习 4**：清洗规范文档应包含哪些要素？只写清洗代码是否足够？

<details><summary>答案</summary>应包含适用范围、逐条规则（对象+处理方式+判定依据）、例外情形、产出字段说明。只写代码不够——实操评分表中，"判定依据"是独立于代码正确性之外的单独配分项，没有文字说明依据，即使代码跑通了也不能拿满分。</details>

**练习 5**：含手机号、邮箱的评价样本，应该整条删除还是用占位符替换？为什么？

<details><summary>答案</summary>应该用占位符替换（如替换为"[手机号]"），而不是整条删除。因为整条删除会损失该样本中其他有价值的情感语义信息，而用占位符替换既满足脱敏合规要求，又保留了样本的可用性，是更精细化的处理方式。</details>
