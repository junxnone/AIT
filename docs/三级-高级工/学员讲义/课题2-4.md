## 一、混淆矩阵与四个指标

判断一个模型能不能用，不能只看一个笼统的"对不对"，要先把"对"拆开看——拆成四种情况：

| | 预测为正 | 预测为负 |
|---|---|---|
| 实际为正 | TP（真正例） | FN（假负例，漏判） |
| 实际为负 | FP（假正例，误判） | TN（真负例） |

- **准确率（Accuracy）** = (TP+TN) / 总数——整体判对的比例，**但它不区分判对的是正例还是负例**，这正是它会骗人的地方。
- **精确率（Precision）** = TP / (TP+FP)——**预测为正的样本中，真正是正的比例**，回答的是"宁可错杀会不会错太多"。
- **召回率（Recall）** = TP / (TP+FN)——**真正是正的样本中，被模型找出来的比例**，回答的是"有没有漏网之鱼"。
- **F1** = 精确率和召回率的调和平均，用于两者都要兼顾、又要用一个数字给模型排序时。

记住一句话：**准确率看的是"整体对不对"，精确率和召回率看的是"对哪一类、漏了哪一类"**——这就是为什么只报一个准确率不够，下面的案例会让你直接看到这件事能骗到什么程度。

## 二、一个会让你重新理解"准确率"的真实案例

**场景**：训练一个信用评分模型，预测客户是否会违约（`数据集/credit_data.csv`，2000条记录）。

```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix, classification_report, roc_auc_score

d = pd.read_csv("../数据集/credit_data.csv")
print("违约率:", d["is_default"].mean())
print("缺失:", d.isnull().sum()[lambda s: s > 0].to_dict())

# 先处理缺失与异常
d["age"] = d["age"].mask((d.age < 18) | (d.age > 100), d.age.median())
d["monthly_income"] = d["monthly_income"].fillna(d["monthly_income"].median())

F = ["age","monthly_income","debt_ratio","credit_history_months","late_payment_times","credit_lines"]
X, y = d[F], d["is_default"]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)
sc = StandardScaler().fit(Xtr)
model = LogisticRegression(max_iter=1000).fit(sc.transform(Xtr), ytr)

pred = model.predict(sc.transform(Xte))
proba = model.predict_proba(sc.transform(Xte))[:, 1]

print(confusion_matrix(yte, pred))
print(classification_report(yte, pred, target_names=["未违约","违约"], digits=3))
print("AUC =", round(roc_auc_score(yte, proba), 3))
```

**实测结果**（你的运行结果应与此一致）：

```
违约率 15.5%　缺失: {'monthly_income': 160}　年龄异常: [0.0, 150.0, 199.0]

混淆矩阵：
[[499   8]
 [ 84   9]]

              precision    recall  f1-score
       未违约      0.856     0.984     0.916
        违约      0.529     0.097     0.164

accuracy = 0.847　AUC = 0.768
```

### 停下来算一笔账

> **如果什么都不做，把所有人都判断为"不违约"，准确率是多少？**

违约率 15.5%，意味着"全判不违约"的准确率是 **84.5%**。

而我们辛辛苦苦训练出来的模型，准确率是 **84.7%**——**只比什么都不做高了 0.2 个百分点。**

**为什么"什么都不做"也能拿到这么高的分数？** 机制很简单：这批数据里本来就只有15.5%的人会违约，意味着"全判不违约"这种零智能策略天然就能蒙对84.5%。**数据的类别越不均衡，这个"白捡"的基线就越高**——模型要证明自己真正学到了东西，必须明显超过这个基线，而不是贴着它。这就是为什么单独看一个84.7%，完全判断不出模型好不好：你得先问"基线是多少"，再看模型比基线高了多少。

再看违约类的召回率：**0.097**。意思是，100个真实会违约的客户里，模型只找出了约10个，剩下90个全部被放过，系统会把他们当成"安全客户"正常放款。**对风控场景而言，这个模型形同虚设。**

> ⚠️ **这就是本课程最有力的一次主线实证**：准确率84.7%看起来不错，但它几乎全靠"大多数人本来就不违约"撑起来的——这和课题2-2里"一致率87.8%但Kappa仅0.217"是同一个陷阱结构：**一个指标数字很好看，不代表它排除了"白捡"的成分**。类别不均衡时，准确率会严重失真，必须拆解混淆矩阵看每个类别的表现。

### 模型是无能，还是阈值选错了？

AUC = 0.768，说明模型**本身有判别力**（不是瞎猜，随机模型AUC应为0.5）。问题出在**决策阈值**——默认阈值是0.5，但这不一定是最适合业务目标的阈值。

```python
pred_03 = (proba >= 0.3).astype(int)
print(confusion_matrix(yte, pred_03))
print(classification_report(yte, pred_03, target_names=["未违约","违约"], digits=3))
```

**实测**：阈值降到0.3后，违约类**召回率从0.097升到0.366**（提升3.8倍），**精确率仅从0.529降到0.500**（只降2.9个百分点）。

**用很小的精确率代价，换来大幅召回率提升**——这正是风控场景该做的权衡：漏判一个真实违约客户的代价（坏账），远高于误判一个正常客户（多审核一次）。

**这也说明一件事：模型本身没有任何改变，只是换了判定门槛，召回率和精确率就此消彼长**——这就是"模型能力"和"阈值选择"是两件不同事情的直接证据。

> 🔑 **判别口诀**：拿到一个评测结果，先看AUC，再判断问题出在哪——**AUC接近0.5 → 模型本身没学到东西，调阈值也救不回来；AUC明显高于0.5、但某个阈值下召回率很差 → 问题大概率在阈值，不在模型。** 本例AUC为0.768，明显高于0.5，所以属于后一种情况：不需要换模型、换算法，调阈值就能大幅改善。

## 三、精确率 vs 召回率：该保哪个，看业务代价

每个场景的"漏判"和"误判"对应的实际后果不一样，所以没有一个放之四海而皆准的"最优阈值"，必须先想清楚两种错误各自的代价：

| 场景 | 该优先保什么 | 为什么 |
|---|---|---|
| 风控审批 | 召回率 | 漏判一个违约客户（坏账）代价远高于误判一个正常客户 |
| 垃圾邮件过滤 | 精确率 | 误判一封正常邮件为垃圾（用户丢失重要信息）代价高于漏掉一封垃圾邮件 |
| 医疗筛查 | 召回率 | 漏诊的代价远高于误诊后进一步检查的代价 |

注意表格里"该优先保召回率"出现了两次（风控、医疗），但**原因不能照抄**：风控怕的是"坏账"，医疗怕的是"漏诊致命"，结论相同，业务代价的具体内容完全不同。如果换一个没见过的新场景（比如"VIP客户流失预警"），照搬"风控=召回率"的结论会漏掉真正该比较的东西。

> 🔑 **判别口诀**：遇到任何一个新场景，先别急着套用已知结论，问自己一句——**漏掉一个的代价大，还是错抓一个的代价大？** 代价在"漏" → 保召回率；代价在"错抓" → 保精确率。这把尺子能用在任何没见过的新场景上，而死记"风控=召回率"这种对照表做不到。

> 🔑 **没有"万能最优阈值"，阈值必须依据业务代价调整**，这也是三级"设计者"能力的体现——四级执行既定阈值，三级要能判断阈值该不该调、往哪个方向调。

## 四、ROC曲线与AUC

前面我们只手动试了阈值0.5和0.3两个点。ROC曲线做的事情是：**把所有可能的阈值都滑一遍，画出召回率（真正例率）和假正例率如何此消彼长**。AUC（曲线下面积）衡量的是模型把正负样本"排序排得对不对"这件整体能力，**不依赖具体选了哪个阈值**——这正是为什么AUC能回答"模型本身有没有用"，而准确率在类别不均衡时做不到这一点：准确率的高低会被某一个具体阈值和数据分布一起带偏，AUC不会。

值得留一个问题继续想：这节课我们看到模型刚评测完，AUC、精确率、召回率都已经核实过了，是不是就意味着这个模型可以一劳永逸地用下去？**不一定**——模型上线后面对的真实数据会随时间推移慢慢变化，今天测出来达标的指标，不代表半年后依然达标。这个问题会在下一课题"智能系统监控与优化"里详细展开。

## 随堂练习

**练习 1**：某模型在违约率仅2%的数据集上，准确率达到98%。这是否说明模型效果好？你会追问什么？

<details><summary>答案</summary>不能直接判断。98%的准确率可能仅略高于"全判不违约"的98%基线（因为违约率只有2%）。必须追问：违约类的召回率和精确率分别是多少？混淆矩阵长什么样？如果召回率接近0，说明模型实际上没有学到任何有效的违约判别能力。</details>

**练习 2**：本课题信用评分模型准确率84.7%，全判不违约基线84.5%，为什么说"模型几乎白训练"？

<details><summary>答案</summary>因为花费时间精力训练出的模型，准确率只比什么都不做（全判不违约）高0.2个百分点，几乎没有体现出模型的价值。更关键的是，违约类的召回率仅0.097，意味着100个真实违约客户中模型只找出约10个，对风控场景而言这个模型实际上没有提供有效的判别能力。</details>

**练习 3**：AUC为0.768，但模型在阈值0.5下的召回率只有0.097，这说明问题出在哪里？

<details><summary>答案</summary>AUC不依赖具体阈值，衡量的是模型整体的判别能力，0.768明显高于随机水平（0.5），说明模型本身是有判别力的。问题更可能出在决策阈值的选择上——默认阈值0.5不适合这批类别不均衡的数据，调低阈值后召回率有显著提升，说明"模型无能"的判断是错的，真正的问题是阈值设置不当。</details>

**练习 4**：阈值从0.5降到0.3后，召回率从0.097升到0.366，精确率仅从0.529降到0.500。为什么说这个权衡在风控场景下是合理的？

<details><summary>答案</summary>风控场景中，漏判一个真实违约客户（造成坏账）的代价，远高于误判一个正常客户（只是多了一次审核环节）。召回率提升3.8倍，而精确率只下降了2.9个百分点，用很小的代价换来了大幅提升的风险识别能力，符合风控业务对漏判代价的权衡逻辑。</details>

**练习 5**：垃圾邮件过滤场景和信用风控场景，在精确率/召回率的权衡方向上有何不同？为什么？

<details><summary>答案</summary>信用风控场景优先保召回率——漏判一个违约客户的代价高，宁可误判也不能放过。垃圾邮件过滤场景优先保精确率——误判一封正常邮件为垃圾邮件（用户可能丢失重要信息）的代价，高于漏掉一封垃圾邮件。两者方向相反，原因在于两个场景中"漏判"和"误判"各自对应的业务代价不同，没有放之四海而皆准的"最优阈值"。</details>

| 要点 | 一句话 |
