## 二、学习率（Learning Rate）：训练这艘船开多快

神经网络训练的本质是"不断调整权重，让输出更接近目标"。每一轮计算当前预测的"误差"（Loss），然后朝着能减小误差的方向调整一步。**学习率决定这一步迈多大。**

**学习率设得不合适会怎样？**

| 学习率 | 后果 | 为什么会这样（机制） |
|---|---|---|
| 太大 | Loss 剧烈震荡，极端情况数值发散变成 **NaN**（训练崩溃） | 每一步迈得太猛，**越过了误差最小的那个点**；下一步朝反方向调整又同样迈过头，于是来回"打摆子"，严重时误差越调越大、彻底失控 |
| 太小 | 收敛极慢，还容易在局部最优的"小坑"里打转 | 每一步迈得太碎，走到真正最优点要花极多轮次，稍微陷进一个不太好的"小坑"也很难靠小步子走出来 |

**为什么学习率太大表现为"震荡"，而不是直接"卡住不动"？** 想象你要走到房间正中间：正常步幅能精准停在中间附近；但如果你每步都迈三米，你会从中间这一侧直接跨到另一侧，再从那一侧跨回来，不停来回跨——这就是"震荡"。步子越大跨得越离谱，极端情况下误差会越调越大，数值彻底失控变成 NaN。

**常用应对**：**学习率调度（Learning Rate Scheduling）**——训练初期用稍大学习率快速逼近，中后期逐步减小做精细调整。常见做法还有 **Warmup**（刚开始学习率从很小值逐渐升到目标值）。**为什么需要 Warmup？** 因为模型刚初始化时权重还很不稳定，如果一上来就用大步子调整，很容易把这些还没站稳的权重直接冲乱；让学习率从很小值慢慢升上去，相当于先给模型一个"热身"的过程，等权重稳定一些了再放开步子走。

> 🔑 **判别口诀**：Loss **震荡/发散** → 步子迈太大；Loss **纹丝不动/下降极慢** → 步子迈太小。记不住就想"走到房间中间"的类比：迈三米的人在来回跨，迈半厘米的人在原地挪。

## 三、Batch Size：一次看多少数据再调整一步

> Batch Size：每次参数更新所使用的样本数量。

| | Batch Size 较大 | Batch Size 较小 |
|---|---|---|
| 梯度估计 | 更稳定，噪声小 | 噪声大，方向不够准 |
| 训练速度（单步） | 能更充分利用硬件并行，单步更快 | 单步计算量小但步数更多 |
| 内存占用 | 更大 | 更小 |
| 泛化能力 | **可能更差**——容易收敛到"尖锐"局部最优 | 小批次噪声反而有正则化效果，有时泛化更好 |

> ⚠️ **反直觉点**：**"Batch Size越大、训练越快越好"是错的**——大Batch Size单位时间处理更多数据，但不等于模型最终效果更好。

**为什么大 Batch Size 反而可能泛化更差？** 把误差函数想象成一片高低起伏的地形：有又窄又深的"尖锐坑"，也有又宽又浅的"平缓坑"。大 Batch Size 梯度估计很稳定、噪声小，容易一头扎进离起点最近的那个坑，哪怕它是个尖锐坑；小 Batch Size 的梯度噪声反而像"不停轻轻晃动"，容易把模型从尖锐坑里晃出来，停在更平缓、更稳健的坑里。尖锐坑对训练数据拟合得很紧，但换一批新数据（验证集/测试集）稍微偏一点点就可能大幅掉出坑外——这就是"泛化能力更差"的来源。

这和"Kappa高不代表标注真的好""WER为0不代表任务设计没问题"是同一类思维模式：**表面的效率/一致性指标，不能替代对最终目标的直接检验。**

> 🔑 **判别口诀**：Batch Size 的权衡不是"越大越好"也不是"越小越好"，而是**速度与泛化的权衡**——赶工期、对泛化要求不高的原型实验可以偏大；正式要上线、必须保效果的模型，不能只看训练速度去选 Batch Size。

## 四、Epoch 与过拟合/欠拟合：动手跑出那条反直觉的曲线

> Epoch：模型完整遍历一次全部训练数据。
> Iteration 数 = 训练集样本总数 ÷ Batch Size

举例：10000条训练数据，Batch Size设100，一个Epoch包含100次权重更新。

- **Epoch太少**：欠拟合——模型还没来得及学到数据里的规律，训练就结束了，训练集上表现本身就不好
- **Epoch太多**：过拟合——训练到后期，模型开始"死记硬背"训练数据里的具体细节（包括噪声）。这些细节对训练集"有用"，但对没见过的新数据毫无意义甚至起反作用

**光说"死记硬背"可能没概念，我们在真实数据上跑一遍，看这个现象具体长什么样。**

打开 Jupyter，运行下面这段代码（数据为 `数据集/credit_data.csv`，2000条客户信用数据；用 `max_iter=1 + warm_start=True` 让每次调用 `fit` 相当于多训练 1 个 Epoch，便于逐个 Epoch 打点观察）：

```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.neural_network import MLPClassifier
from sklearn.metrics import log_loss, accuracy_score

d = pd.read_csv("../数据集/credit_data.csv")
d["age"] = d["age"].mask((d.age < 18) | (d.age > 100), d.age.median())
d["monthly_income"] = d["monthly_income"].fillna(d["monthly_income"].median())

F = ["age", "monthly_income", "debt_ratio", "credit_history_months", "late_payment_times", "credit_lines"]
X, y = d[F], d["is_default"]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)
sc = StandardScaler().fit(Xtr)
Xtr_s, Xte_s = sc.transform(Xtr), sc.transform(Xte)

clf = MLPClassifier(hidden_layer_sizes=(32, 16), solver="adam", max_iter=1,
                     warm_start=True, random_state=42, learning_rate_init=0.01)

checkpoints = [5, 50, 200, 1000]
for epoch in range(1, 1001):
    clf.fit(Xtr_s, ytr)
    if epoch in checkpoints:
        train_loss = log_loss(ytr, clf.predict_proba(Xtr_s))
        val_loss = log_loss(yte, clf.predict_proba(Xte_s))
        train_acc = accuracy_score(ytr, clf.predict(Xtr_s))
        val_acc = accuracy_score(yte, clf.predict(Xte_s))
        print(f"epoch={epoch:4d}  训练Loss={train_loss:.3f}  验证Loss={val_loss:.3f}  "
              f"训练Acc={train_acc:.1%}  验证Acc={val_acc:.1%}")
```

**运行结果**（已验证，你的结果应与此基本一致）：

```
epoch=   5  训练Loss=0.371  验证Loss=0.387  训练Acc=85.1%  验证Acc=84.3%
epoch=  50  训练Loss=0.333  验证Loss=0.467  训练Acc=87.1%  验证Acc=82.8%
epoch= 200  训练Loss=0.351  验证Loss=0.947  训练Acc=89.8%  验证Acc=79.3%
epoch=1000  训练Loss=0.372  验证Loss=2.188  训练Acc=93.2%  验证Acc=79.7%
```

把它整理成对比表：

| | epoch=5 | epoch=50 | epoch=200 | epoch=1000 |
|---|---|---|---|---|
| 训练Acc | 85.1% | 87.1% | 89.8% | **93.2%**（持续上涨） |
| 验证Acc | 84.3% | 82.8% | 79.3% | **79.7%**（掉头向下） |
| 验证Loss | 0.387 | 0.467 | 0.947 | **2.188**（涨近6倍） |

**看这组数字**：训练Acc从85.1%一路涨到93.2%，涨了8个百分点，看起来模型越训越好。但验证Acc从84.3%跌到79.3%附近、验证Loss更是涨了近6倍。**训练集指标在涨，验证集指标在跌——这就是过拟合正在发生。**

> 💡 注意：这段代码里训练Loss并不是严格单调下降的（在0.33～0.40之间来回波动），这不是代码写错了——小批量/随机优化本身自带噪声是正常现象。**判断过拟合要看验证集的整体趋势，不要求训练Loss必须每一步都严格下降。**

**怎么判断该停在哪个Epoch？** 同时监控训练集Loss和验证集Loss：

> 训练集Loss一直下降，但验证集Loss从某点开始不降反升——这个拐点就是该停止训练的信号（**Early Stopping，早停**）。

**为什么不能只盯训练集Loss判断该不该停？** 因为训练集Loss几乎总是能持续下降（哪怕是靠"死记硬背"压下去的），单看它永远发现不了过拟合已经发生——上表epoch=1000时训练Loss（0.372）甚至和epoch=5时（0.371）差不多，但验证Loss已经从0.387暴涨到2.188。**只盯着训练集这一侧看的人，会完全错过这个危险信号。**

**现在回答开头的判断**：训练100个Epoch、**训练集**准确率99%，这是好事吗？**不一定**——如果没有同步监控验证集表现，这个99%很可能和上面实验里的93.2%一样，只是"死记硬背"训练数据的结果。具体数字不需要刚好涨到99%才算过拟合，**现象的本质是一样的：训练指标在涨、验证指标在跌，这和"只看一致率不看Kappa""只看WER不看任务设计是否合理"是完全相同的陷阱结构：单一指标持续变好，不代表真实目标达成了，必须有一个独立于该指标之外的检验手段。**

> 🔑 **判别口诀**：欠拟合是"训练集自己都学不好"；过拟合是"训练集学得越来越好，验证集却越来越差"。**只看一个数据集的表现永远诊断不出过拟合——必须两个数据集对照着看。**

## 五、动手验证二：学习率过大，真的会"发散"吗

上一节讲到学习率太大会震荡甚至发散，我们固定其他设置不变，只改学习率，跑一组真实对比：

```python
from sklearn.neural_network import MLPClassifier
from sklearn.metrics import accuracy_score

for lr in [0.01, 50.0]:
    clf = MLPClassifier(hidden_layer_sizes=(32, 16), solver="sgd", max_iter=60,
                         learning_rate_init=lr, random_state=42, momentum=0,
                         n_iter_no_change=1000, tol=0.0)
    clf.fit(Xtr_s, ytr)
    lc = clf.loss_curve_
    print(f"学习率={lr}")
    print(f"  前3轮Loss：{[round(x, 3) for x in lc[:3]]}")
    print(f"  末3轮Loss：{[round(x, 3) for x in lc[-3:]]}")
    print(f"  最终 训练Acc={accuracy_score(ytr, clf.predict(Xtr_s)):.1%}  "
          f"验证Acc={accuracy_score(yte, clf.predict(Xte_s)):.1%}\n")
```

**运行结果**（已验证）：

```
学习率=0.01
  前3轮Loss：[0.706, 0.669, 0.637]
  末3轮Loss：[0.404, 0.403, 0.402]
  最终 训练Acc=84.5%  验证Acc=84.5%

学习率=50.0
  前3轮Loss：[4006.63, 131592416.23, 131546367.87]
  末3轮Loss：[129128646.92, 129083457.43, 129038287.2]
  最终 训练Acc=84.5%  验证Acc=84.5%
```

学习率0.01：Loss从0.706平稳降到0.402，这是正常收敛。学习率50：Loss从4006.63，**下一轮直接跳到1.3亿**，后面一直在上亿的量级里打转，再也没回到正常范围。

> ⚠️ 这里没有出现字面意义上的NaN，但Loss涨到1.3亿这种天文数字，同样代表训练已经彻底失控——**数值发散不一定表现为NaN，本质都是"训练失败、权重被巨大更新步长破坏"，不要死记"必须变成NaN才算"。**

细心的话你会发现两组实验**最终Acc都是84.5%**——这不是说明学习率50也训好了，而是因为这个数据集里存在占多数的类别，哪怕权重已经被破坏得毫无意义，模型也可能退化成"无脑预测多数类"，碰巧对出同样的准确率。**这正说明：不能只看最终Acc一个数字判断训练是否正常，必须结合Loss曲线的走势——一个在合理范围内平稳下降，一个已经飞出天际，后者不管再训多久都没有意义。**

**"多大算太大"有没有一个统一数字？** 没有。这组数据在学习率1甚至10的时候都还能正常收敛，直到50才彻底发散——**这说明阈值取决于具体的数据、网络结构和特征缩放，不能死记一个固定数字。** 判断的办法是训练时盯着Loss曲线：曲线在合理范围内波动下降是正常的，曲线脱离合理量级往上飞，就是学习率过大的信号，不管它最后有没有变成字面意义的NaN。

## 六、实操题怎么考：给现象，让你反推超参数问题

| 现象 | 最可能的原因 | 调整方向 |
|---|---|---|
| Loss几乎不下降，训练很多轮都没起色 | 学习率太小/模型欠拟合 | 适当增大学习率，或检查模型复杂度是否够 |
| Loss剧烈震荡，甚至出现NaN | 学习率太大 | 减小学习率，必要时加入梯度裁剪 |
| 训练集Loss很低，验证集Loss很高且持续上升 | 训练轮数过多/模型过拟合 | Early Stopping，减少Epoch，或增加正则化 |
| 训练速度慢、显存吃紧但模型效果还行 | Batch Size设置需要权衡 | 可适当调小Batch Size，需重新验证泛化效果 |

> 🔑 记住这张表的**诊断逻辑**比记住"现象对应哪个原因"更重要：先定位是"学不动"（欠拟合/学习率小）还是"学过头"（过拟合/学习率大/epoch多），再决定调哪个参数。实际考题的现象描述会千变万化，但判断路径固定。

**为什么要强调诊断逻辑、而不是直接背这张表？** 因为上一节"学习率=50"的真实实验里，Loss并没有变成字面意义的NaN，而是涨到了1.3亿；如果只是死记"学习率过大=变成NaN"，遇到这种换了说法的现象描述就可能对不上号。但只要掌握"先判断学不动还是学过头，再定位具体参数"这条路径，不管现象怎么换说法都能分析定位。**本课题两组真实实验（过拟合曲线、学习率发散曲线），就是让你亲眼见过这条诊断路径在真实、会变化的数字上是怎么用的——数字本身可以变，诊断路径不变。**

## 考点清单

| 考点 | 考试怎么考 | 易错点 |
|---|---|---|
| 学习率过大/过小的后果 | 单选/实操反推 | 混淆"震荡"（过大）和"不降"（过小）两种现象 |
| Batch Size反直觉结论 | 单选/判断高频 | 认为"Batch Size越大效果越好" |
| 过拟合判断依据 | 实操核心 | 只看训练集Loss下降就判断"训练效果好" |
| Iteration计算 | 单选计算题 | 公式记反（样本数÷Batch Size，不是Batch Size÷样本数） |

## 随堂练习

**练习 1**：某团队训练图像分类模型，发现前几个Epoch Loss下降很快，但到第20个Epoch左右开始剧烈震荡，最后几轮出现NaN。最可能是什么问题？

<details><summary>答案</summary>学习率过大（或训练后期学习率未衰减）。调整方向：减小学习率，或引入学习率调度在训练中后期逐步衰减，必要时加入梯度裁剪。</details>

**练习 2**：另一团队把Batch Size从32直接加大到2048，未调整学习率，结果模型收敛后验证集准确率反而更低。可能的原因有哪些？

<details><summary>答案</summary>①Batch Size增大后梯度估计更平滑，容易收敛到泛化能力较差的"尖锐"局部最优；②Batch Size与学习率需要联动调整——未按比例放大学习率，导致有效步长相对变小、收敛位置和小Batch Size时不同；③大批次减少的噪声本身具有的"正则化"效果消失了。</details>

**练习 3**：如果只被告知"这个模型训练了100个Epoch，训练集准确率达到了99%"，你会追问哪个关键信息，才能判断这个模型是不是真的训练得好？

<details><summary>答案</summary>会追问验证集（或测试集）上的准确率表现。单独的训练集准确率无法说明模型是否具备泛化能力，99%的训练集准确率完全可能是过拟合（死记硬背训练数据）的结果，必须对比验证集表现才能判断模型真实效果。</details>

**练习 4**：Early Stopping的判断依据是什么？为什么不能只看训练集Loss决定何时停止训练？

<details><summary>答案</summary>判断依据是验证集Loss的变化趋势——当训练集Loss持续下降，但验证集Loss从某个点开始不降反升时，这个拐点就是该停止训练的信号。只看训练集Loss会让训练持续到过拟合阶段而不自知，因为训练集Loss几乎总是随Epoch增加而持续下降，它反映不出模型是否已经开始"死记硬背"训练数据。</details>

**练习 5**：为什么说"记住诊断逻辑比记住现象对应表更重要"？

<details><summary>答案</summary>因为实际考题给出的现象描述会千变万化，用词可能和复习时见过的标准表述完全不同。如果只是死记"某种现象对应某个原因"，遇到换了说法的现象描述就可能对不上号；但如果掌握了"先判断是学不动还是学过头，再定位具体参数"这条诊断路径，任何新的现象描述都能用这条路径分析定位，不受具体措辞影响。</details>

| 学习率 | 太大震荡/NaN，太小收敛慢 |
