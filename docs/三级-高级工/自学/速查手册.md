# 三级/高级工 考前速查手册

本手册用于考前快速复习，默认你已学过正式课程或读过教案/讲义，仅做提纲式速查，不含讲解过程。

全书贯穿主线：**单一指标变好 ≠ 真实目标达成，必须有一个独立于该指标之外的检验手段。**（一致率 vs Kappa、训练集 Loss vs 验证集、准确率 vs 召回率、整体指标 vs 分群下钻，均是这条主线的不同体现）

## 课题 0-1：三级能力跃迁与考试结构

**核心考点**
- 职业定义四关键词：数据库管理 / 算法参数设置 / 人机交互设计 / 性能测试跟踪
- 等级能力重心：五级+四级＝数据采集和处理、数据标注、智能系统运维；**三级**＝业务分析、智能训练、智能系统设计、**培训与指导**
- 三级本质是模块整体切换，不是四级的熟练版
- 两科考核（理论/操作技能）均需各自 ≥60 分，分开判定合格

**关键规则**
- 判别口诀：任务问的是"在现有标准/流程内，做得对不对"，还是"现有标准/流程本身对不对、该不该改"？前者→四级范畴（执行与审核）；后者→三级范畴（设计与判断）

**易错点**
- 漏记或混淆"人机交互设计"与"产品设计"
- 把三级任务误判为四级深化版（熟练度≠判断力）
- 遗漏三级理论涵盖的"培训与指导"模块

**配套题库**：单选 1–3、判断 1–2。

## 课题 0-2：机器学习范式与神经网络基础

**核心考点**
- 监督学习 / 无监督学习 / 强化学习三范式判断
- 不同范式对训练师工作重心的不同要求
- 神经网络结构：输入层—隐藏层—输出层，训练＝调整权重
- 深度学习（隐藏层多）与过拟合风险的关联

**关键规则**
- 判断公式：有没有"标准答案"？有→监督学习；没有但有数据结构→无监督学习；没有标准答案但有反馈/奖励信号、允许试错→强化学习
- 判别口诀：答案是不是训练前就预先定好的？是→监督学习；不是→强化学习
- 监督学习工作重心＝标注数据质量；强化学习工作重心＝设计奖励机制、监控策略收敛方向、警惕"奖励黑客"
- 板书规律：参数越多 → 记忆容量越大 → 数据和标注质量没跟上 → 死记硬背（过拟合）

**易错点**
- 把"用到历史数据"等同于监督学习，忽略强化学习的动态反馈特征
- 只答范式名称，不答对训练师工作内容的影响
- 混淆"深度学习"与"神经网络"的包含关系（深度学习是神经网络的子集，不是并列概念）

**配套题库**：单选 15–28、判断 3。

## 课题 0-3：数据合规红线与职业道德

**核心考点**
- 职业守则三条：诚实公正严谨求是 / 遵章守法恪尽职守 / 勤勉好学追求卓越
- 三条数据合规红线及各自判断标准
- 在具体业务场景中识别违规点并提出整改方案

**关键规则**
- 红线一·数据来源合法性：这批数据的使用范围，使用者本人是否知情并同意？（审查授权"是否具体"，笼统协议≠针对该具体用途的有效知情同意）
- 红线二·敏感信息脱敏：标注环节也要做访问控制，不只是采集/存储阶段
- 红线三·特殊群体特殊保护：未成年人、残障人士等需监护人"明确、单独"授权
- 方法论：先抓题干反复强调的细节，再给方案，不对关键词条件反射
- 多条红线同时触发时：先问"数据能不能合法进门"（来源合法性是前提，脱敏是合法前提下的后续处理）

**易错点**
- 看到"敏感信息"就条件反射答"脱敏"，忽略题干真正强调的授权细节——本课题最高频失分陷阱
- 以为脱敏只发生在采集/存储阶段，忽视标注环节的访问控制
- 认为"用户协议里笼统提过"就等于有效同意

**配套题库**：单选 4–14、判断 4–6。

## 课题 1-1：业务数据采集 / 处理 / 审核流程设计

**核心考点**
- 完整流程：采集 → 清洗 → 归类 → 标注 → 质检，各环节质量控制点
- 流程是可反向反馈优化的闭环，不是单向流水线
- 三级能力：先探查数据现状，再针对性设计流程（区别于四级"拿到规范去执行"）

**关键规则**
- 五环节质量控制点：采集（合规把关）、清洗（阈值要有业务依据）、归类（粒度影响标注效率与一致性）、标注（规范清晰无歧义）、质检（抽检/复核，是倒推修正前面环节的反馈点）
- 质检发现一致率低时：先倒推排查更前面的环节（归类标签体系、标注规范本身），而不是直接要求重新标注

**易错点**
- 只写正向步骤罗列，不写质量控制点与异常处理方式（评分表单独配分，漏写大量丢分）
- 凭空设计理想流程，不先探查真实数据现状，导致方案与实际问题脱节
- 把问题归到最后一环（质检），忽视根因可能在更早的环节

**配套题库**：单选 29–36、多选 7–9、判断 7–9；实操 1.1.1。

## 课题 1-2：业务模块问题识别与优化方案

**核心考点**
- 漏斗分析方法：曝光→点击→加购→下单→支付
- 全局瓶颈 vs 局部异常的区分
- 优化方案须含问题定位、根因假设、优化方案、可度量成功指标、推动实现路径

**关键规则**
- 核心方法：先看总体转化率定位"哪个环节整体最差"（全局瓶颈），再分维度下钻（渠道/时间/人群），识别局部异常——全局瓶颈和局部异常可能同时存在，需完全不同的优化方案
- 可度量目标须有具体数字和观察周期（如"下单率从10.8%提升到15%，观察4周"），不能写"尽可能提升"

**易错点**
- 找到一个问题就停止分析，漏掉数据中同时存在的第二个独立问题
- 只看总体汇总数字，不做维度（渠道/时间/人群）下钻
- 优化方案写"提升转化率"而非具体可验证的数字目标

**配套题库**：单选 37–68、多选 10–11、判断 10–11；实操 1.1.2。

## 课题 2-2：标注规范制定与质量评估（Kappa / IoU / WER）

**核心考点**
- Kappa 相对一致率的改进点：刨除"偶然一致"，只留真实共识
- 四种标注错误类型的判别依据与修复方案一一对应
- 标注规范的完整要素
- 指标选型：分类→Kappa，空间区域→IoU，序列文本→WER（三个名字，一个逻辑）

**关键公式/规则**
- Kappa = (观测一致率 − 期望偶然一致率) / (1 − 期望偶然一致率)
- Kappa 判读区间：<0.2 很差；0.2–0.4 一般；0.4–0.6 中等；0.6–0.8 良好；>0.8 几乎完全一致
- IoU = 两框重叠面积 ÷ 并集面积；常用阈值 IoU≥0.5 视为"一致"（更严格取 0.7）
- WER = (替换词数+删除词数+插入词数) ÷ 参考文本总词数；商用成熟 ASR 常见 WER 5%~10%，15% 属"中等偏可用"（不可笼统说"质量很差"）
- 四种错误类型判别口诀：
  - 标准不一致 vs 边界模糊：把手册写得再细，这个样本能不能确定地归入某一类？能→标准不一致（手册问题，补细则）；不能→边界模糊（数据固有，设"待裁定"类+仲裁机制）
  - 体系缺陷 vs 标注员偏见：是所有人都在同一批样本上分歧，还是某个人持续偏向？所有人→体系问题（重新设计分类体系）；某个人→个人偏见
  - 标注员偏见修复须按顺序、不可跳步：①量化偏差程度 ②抽样复核 ③与本人沟通了解来源 ④确认是理解偏差后才针对性培训
- 诊断流程：低 Kappa → 抽样查看分歧样本（关键动作，不能只看汇总数字）→ 判断属于四类中的哪种（或多种并存）→ 对症下药
- 反直觉实证：不均衡组一致率 87.8%/Kappa 0.217；均衡组一致率 76.2%/Kappa 0.524——一致率更高的那组 Kappa 反而更低，机制是标签分布不均衡抬高了偶然一致率

**易错点**
- 只答"样本分布不平衡"（原因），说不出"抬高偶然一致率"这层机制，实操题只能拿一半分
- 判错四种错误类型的方向，导致修复方案整个用反
- 题干带"而不是简单地说重新培训"提示时，仍跳过诊断直接答培训
- 把 WER 15% 说成"质量很差"（应为中等偏可用）
- 认为 WER=0 就代表任务没问题（忽视转写/标注标准本身可能定错）

**配套题库**：单选 83–100、多选 19–21、判断 19–21。

## 课题 2-3：训练超参数与过拟合 / 欠拟合诊断

**核心考点**
- 学习率、Batch Size、Epoch 的含义及设置不当的后果
- 依据训练现象反推超参数问题（诊断逻辑优先于死记现象表）
- 过拟合/欠拟合判别依据与应对（Early Stopping）

**关键公式/规则**
- Iteration 数 = 训练集样本总数 ÷ Batch Size
- 学习率太大→震荡/NaN；太小→收敛慢、易卡局部最优
- Batch Size 越大≠效果越好：梯度更稳但可能收敛到"尖锐"局部最优，泛化能力可能更差；需与学习率联动调整
- Early Stopping 判断依据：训练集 Loss 持续下降，但验证集 Loss 从某点开始不降反升，该拐点即停止信号
- 诊断表：Loss不降→学习率太小/欠拟合→增大学习率；Loss震荡/NaN→学习率太大→减小学习率+梯度裁剪；训练集Loss低但验证集Loss高且上升→过拟合→Early Stopping/减少Epoch/加正则化；训练慢显存紧但效果尚可→权衡调小Batch Size并重新验证泛化
- 诊断逻辑：先判断"学不动"（欠拟合/学习率小）还是"学过头"（过拟合/学习率大/epoch多），再定位具体参数——比死记现象对应表更重要

**易错点**
- 混淆"震荡"（学习率过大）和"不降"（学习率过小）两种现象
- 认为"Batch Size 越大、训练越快越好"（反直觉考点，高频）
- 只看训练集 Loss 下降就判断"训练效果好"，不监控验证集
- Iteration 计算公式记反（是样本数÷Batch Size，不是反过来）

**配套题库**：多选 22、判断 22（超参数专属考点）；实操 2.2.1。

## 课题 2-4：算法测试与错误分析（混淆矩阵 / P / R / F1 / ROC）

**核心考点**
- 混淆矩阵与准确率、精确率、召回率、F1 的计算
- 准确率在类别不均衡下的失效（最高频考点）
- 精确率 vs 召回率的业务代价权衡
- AUC 的意义与阈值调整

**关键公式/规则**
- 准确率 Accuracy = (TP+TN) / 总数
- 精确率 Precision = TP / (TP+FP)——预测为正中真正为正的比例
- 召回率 Recall = TP / (TP+FN)——真正为正中被找出的比例
- F1 = 精确率和召回率的调和平均
- AUC 不依赖具体阈值，衡量模型整体判别能力（随机模型 AUC=0.5）
- 没有万能最优阈值，阈值须依据业务代价调整：风控审批/医疗筛查优先保召回率（漏判代价高）；垃圾邮件过滤优先保精确率（误判代价高）
- 实证：违约率15.5%数据上，模型准确率84.7%，"全判不违约"基线84.5%——模型几乎白训练；违约类召回率仅0.097；AUC=0.768说明模型本身有判别力，问题在阈值非模型；阈值从0.5降到0.3，召回率从0.097升到0.366，精确率仅从0.529降到0.500

**易错点**
- 只看准确率就判断模型可用，不对比基线、不拆解混淆矩阵
- 死记"高精确率好"，不结合业务场景判断该保哪个指标
- 把 AUC 和准确率混为一谈
- 认为只有重新训练模型才能改善效果，忽视调阈值这个更低成本的手段

**配套题库**：单选 101–116、多选 23–25、判断 23–25；实操 2.2.1。

## 课题 3-1：智能系统监控与优化（数据漂移、模型退化）

**核心考点**
- 数据漂移（输入数据分布变化）vs 模型退化（模型本身判别能力下降）的区分
- 分析报告结构
- 监控指标体系设计（业务/模型/数据质量/时效四类指标）

**关键规则**
- 数据漂移对策：补充新结构的训练数据；模型退化对策：重新训练/优化模型本身——两者混在一起看会误判
- 分析报告结构：结论先行 → 关键指标 → 分群下钻 → 问题定位（每个独立因素分别归因）→ 优化建议（分别给方案）→ 验证方案
- 通用诊断方法论：先看总体趋势，再分群下钻，再分别归因（与课题1-2漏斗分析、课题2-2标注诊断同一套方法论）
- 数据质量问题（如埋点bug）不要误判为模型问题，须在报告中单独指出

**易错点**
- 看到整体指标下滑就直接归因"模型退化，需要重新训练"，不做分群下钻验证
- 分析报告只给数字，不给结论和建议
- 用一个方案覆盖所有问题，未区分不同成因分别给方案
- 把埋点bug等数据质量问题误判为模型能力问题

**配套题库**：单选 117–124、多选 26–29、判断 26–29；实操 3.1.1。

## 课题 3-2：人机交互流程设计

**核心考点**
- 人机协同基本模式：全自动 / AI建议+人工确认 / 人工兜底转接 / 人工复核抽检
- 依据数据（置信度区间的实测正确率 + 人工/AI成本差异）设计分层交互流程
- 完整设计须含的要素

**关键规则**
- 核心问题"什么情况用哪种模式"的答案是数据，不是经验判断
- 分层依据示例：高置信度区间正确率高→全自动；中置信度区间→AI建议+人工确认；低置信度区间→直接转人工
- 人工处理成本可能远高于AI（教学案例约20倍），交互设计须同时权衡准确率和成本，不是单纯技术最优解
- 没有万能最优阈值，须结合场景的正确率分布与成本结构确定
- 完整设计四要素：分段依据（含数据支撑）、流程图（含分支条件）、异常与降级路径、效果度量指标

**易错点**
- 设计流程时只考虑"怎么让准确率最高"，得出"全部转人工"的不可行结论，忽视人工成本权衡
- 置信度分段阈值没有数据支撑，凭经验拍定
- 流程设计缺少异常/降级路径（如人工坐席全忙时的预案）

**配套题库**：单选 125–132、多选 30–33、判断 30–33；实操 3.2.1。

## 课题 4-1：培训讲义编写与技术指导

**核心考点**
- 三级确实考核"培训与指导"模块，有独立实操试题代码 **4.2.1**（易被误判为仅二级/技师考核）
- 培训讲义的基本结构
- 指导的核心原则：讲依据，不只讲结论
- 指导五级/四级从业者的常见问题方向

**关键规则**
- 讲义结构：培训目标 → 受众与前置知识 → 内容要点 → 案例 → 练习 → 考核方式
- 面向五级/四级受众的讲义内容应定位在"怎么正确执行"层面，不讲三级层面的"设计/诊断"内容
