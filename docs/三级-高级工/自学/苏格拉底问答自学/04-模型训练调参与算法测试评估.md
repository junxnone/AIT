## 第一部分：三个超参数，与过拟合/欠拟合诊断（课题 2-3）

### 1. 学习率：训练这艘船开多快

神经网络训练的本质是"不断调整权重，让输出更接近目标"。每一轮计算当前预测的误差（Loss），然后朝着能减小误差的方向调整一步，**学习率决定这一步迈多大**。

**先自己想：学习率设得太大和太小，分别会出现什么现象？**

太大——步子迈太猛，容易"迈过头"，Loss曲线剧烈震荡，极端情况数值发散变成NaN（训练崩溃）。太小——步子太碎，收敛极慢，还容易在局部最优的"小坑"里打转，浪费计算资源。常用应对是学习率调度：训练初期用稍大学习率快速逼近，中后期逐步减小精细调整；还有Warmup——刚开始学习率从很小值逐渐升到目标值，避免一上来步子太大把刚初始化、还很不稳定的权重冲乱。

### 2. Batch Size：一次看多少数据再调整一步

**这里有一个你很可能会想当然的判断，我们来验证一下。** 你是不是觉得"Batch Size越大、训练越快越好"？

这个判断是错的。大Batch Size确实能更充分利用硬件并行、单步更快，但不等于模型最终效果更好——大Batch Size容易收敛到"尖锐"的局部最优，泛化能力反而可能更差；小批次的噪声反而有正则化效果，有时泛化更好。

**这个反直觉结论属于哪个套路？** 跟上一篇"Kappa高不代表标注真的好"、"WER为0不代表任务设计没问题"是同一类思维模式：**表面的效率指标，不能替代对最终目标（模型真实泛化能力）的直接检验。**

### 3. Epoch：数据集要被完整看几遍

Epoch是模型完整遍历一次全部训练数据。一个公式要记住：Iteration数 = 训练集样本总数 ÷ Batch Size（注意不是反过来）。举例：10000条训练数据，Batch Size设100，一个Epoch包含100次权重更新。

Epoch太少→欠拟合，训练集上表现本身就不好；Epoch太多→过拟合，训练集越学越好，但学到后期开始"死记硬背"训练数据细节，验证集/测试集上表现反而变差。

**怎么判断该停在哪个Epoch？** 同时监控训练集Loss和验证集Loss——训练集Loss一直下降，但验证集Loss从某点开始不降反升，这个拐点就是该停止训练的信号，叫Early Stopping（早停）。

### 4. 现在回答开场那道题

训练100个Epoch、训练集准确率99%，这是好事吗？**不一定**——如果没有同步监控验证集表现，这个99%很可能只是"死记硬背"。这和"只看一致率不看Kappa"、"只看WER不看任务设计是否合理"是完全相同的陷阱结构：**单一指标持续变好，不代表真实目标达成了，必须有一个独立于该指标之外的检验手段。** 你发现没有，这条主线已经在三个完全不同的场景里出现过了——标注质检、Batch Size、现在的训练轮数，逻辑分毫不差。

### 5. 实操怎么考：给现象，让你反推超参数问题

记一张诊断表，但更要记诊断逻辑本身：

| 现象 | 最可能的原因 | 调整方向 |
|---|---|---|
| Loss几乎不下降 | 学习率太小/模型欠拟合 | 增大学习率，或检查模型复杂度 |
| Loss剧烈震荡甚至NaN | 学习率太大 | 减小学习率，必要时加梯度裁剪 |
| 训练集Loss很低、验证集Loss很高且上升 | 过拟合/训练轮数过多 | Early Stopping，减少Epoch，或加正则化 |
| 训练速度慢、显存吃紧但效果还行 | Batch Size需要权衡 | 适当调小Batch Size，重新验证泛化效果 |

**为什么我说"记住诊断逻辑比记住这张表更重要"？** 因为实际考题给出的现象描述会千变万化，用词可能和你复习时见过的完全不一样。但如果你掌握的是"先判断是学不动（欠拟合/学习率小）还是学过头（过拟合/学习率大/epoch多），再决定调哪个参数"这条路径，任何新的现象描述都能用这条路径分析，不受具体措辞影响。

## 第二部分：算法测试与错误分析——一个会颠覆你对"准确率"理解的真实案例（课题 2-4）

### 1. 先把四个基本概念过一遍

混淆矩阵：实际为正、预测为正是TP（真正例）；实际为正、预测为负是FN（假负例，漏判）；实际为负、预测为正是FP（假正例，误判）；实际为负、预测为负是TN（真负例）。

准确率=(TP+TN)/总数，整体判对的比例；精确率=TP/(TP+FP)，预测为正的样本中真正是正的比例；召回率=TP/(TP+FN)，真正是正的样本中被模型找出来的比例；F1是精确率和召回率的调和平均。

### 2. 现在用一个真实信用评分模型案例，重新理解"准确率"

场景：训练一个信用评分模型，预测客户是否会违约，2000条记录。实测这批数据的**违约率是15.5%**。训练一个逻辑回归模型之后，在测试集上得到：

```
混淆矩阵：
[[499   8]
 [ 84   9]]

              precision    recall  f1-score
       未违约      0.856     0.984     0.916
        违约      0.529     0.097     0.164

accuracy = 0.847　AUC = 0.768
```

**在往下看之前，自己算一笔账**：如果什么都不做，把所有人都判断为"不违约"，准确率会是多少？

违约率15.5%，意味着"全判不违约"的准确率是**84.5%**。而我们辛辛苦苦训练出来的模型，准确率是**84.7%**——**只比什么都不做高了0.2个百分点。**

再看违约类的召回率：**0.097**。意思是，100个真实会违约的客户里，模型只找出了约10个，剩下90个全部被放过。**对风控场景而言，这个模型形同虚设。**

**这是本课程最有力的一次主线实证**：准确率84.7%看起来不错，但它几乎全靠"大多数人本来就不违约"撑起来的——这和"一致率92%但Kappa仅0.15"是同一个陷阱结构。**类别不均衡时，准确率会严重失真，必须拆解混淆矩阵看每个类别的表现。**

### 3. 模型是无能，还是阈值选错了？——先别急着判模型死刑

AUC=0.768，说明模型本身有判别力（随机模型AUC应为0.5，0.768明显高于随机水平）。问题更可能出在**决策阈值**——默认阈值是0.5，但这不一定是最适合业务目标的阈值。

把阈值从0.5降到0.3会发生什么？实测：违约类**召回率从0.097升到0.366**（提升3.8倍），**精确率仅从0.529降到0.500**（只降2.9个百分点）。

**用很小的精确率代价，换来大幅召回率提升**——这正是风控场景该做的权衡：漏判一个真实违约客户的代价（坏账），远高于误判一个正常客户（多审核一次）。

**这一步想教你的是**：遇到模型效果不理想，不要第一反应就是"重新训练模型"。先看AUC判断模型本身有没有判别力，如果有，那问题可能只是阈值没选对——调阈值是比重新训练成本低得多的手段，这也是三级实操题里容易被忽视的考点。

### 4. 精确率和召回率，该保哪个？没有标准答案，看业务代价

| 场景 | 该优先保什么 | 为什么 |
|---|---|---|
| 风控审批 | 召回率 | 漏判一个违约客户（坏账）代价远高于误判一个正常客户 |
| 垃圾邮件过滤 | 精确率 | 误判一封正常邮件为垃圾（用户丢失重要信息）代价高于漏掉一封垃圾邮件 |
| 医疗筛查 | 召回率 | 漏诊的代价远高于误诊后进一步检查的代价 |

**没有"万能最优阈值"，阈值必须依据业务代价调整**——这也是三级"设计者"能力的体现：四级执行既定阈值，三级要能判断阈值该不该调、往哪个方向调。

### 5. ROC曲线与AUC，一句话理解

ROC曲线描绘的是：随着判定阈值变化，真正例率（召回率）和假正例率如何权衡。AUC衡量模型整体的判别能力，**不依赖具体阈值选择**——这正是为什么AUC能告诉我们"模型本身有没有用"，而准确率在类别不均衡时做不到这一点。

## 串起来看：调参和测试，本质都在回答同一个问题

这一篇看起来是两套完全不同的技能——调超参数是"训练前/训练中"的事，算法测试是"训练后"的事。但你有没有发现，它们都在回答同一个问题：**"看起来好"的指标，是不是真的好？** 训练集准确率99%看起来好，但可能是死记硬背；整体准确率84.7%看起来凑合，但可能是类别不均衡撑起来的假象。这条主线从标注质检一路延续到这里，而且还没完——下一篇讲系统监控的时候，它会以第四种面貌再出现一次。
