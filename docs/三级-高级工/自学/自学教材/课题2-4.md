## 一、先把"对不对"拆开看：混淆矩阵与四个指标

判断一个分类模型能不能用，不能只看一个笼统的"整体对不对"，必须先把"对"和"错"各自拆成两种情况，一共四种，这就是混淆矩阵：

| | 预测为正（违约） | 预测为负（不违约） |
|---|---|---|
| 实际为正（真违约） | TP 真正例 | FN 假负例（漏判） |
| 实际为负（真不违约） | FP 假正例（误判） | TN 真负例 |

在往下看定义之前，先自己做一道小题检验一下理解：**如果一个模型把100个真实违约客户里的95个都放过去了（预测成"不违约"），这95个属于混淆矩阵里的哪一格？**

（答案：FN，假负例/漏判——真实是正例，却被预测成了负例）

有了四格概念，四个指标就很好理解了：

- **准确率（Accuracy）= (TP+TN) ÷ 总数**——只看"整体判对了多少"，**不区分判对的是正例还是负例**。这正是它会骗人的地方，下一节你会亲眼看到这件事能骗到什么程度。
- **精确率（Precision）= TP ÷ (TP+FP)**——回答的是："我模型说'是违约'的这些人里，真正违约的占多少？"衡量的是"宁可错杀会不会错太多"。
- **召回率（Recall）= TP ÷ (TP+FN)**——回答的是："真正会违约的人里，我模型抓出来了多少？"衡量的是"有没有漏网之鱼"。
- **F1**：精确率和召回率的调和平均，用于两者都要兼顾、又需要一个数字给模型排序的时候。

记住一句话打底：**准确率看的是"整体对不对"，精确率和召回率看的是"对哪一类、漏了哪一类"**——这就是为什么只报一个准确率永远不够。

## 二、准确率为什么会骗人：先看一个极端例子

在看真实案例之前，先用一个故意走极端的例子把"机制"看清楚，再回到真实数据就不会被数字唬住。

假设一个数据集，99%的样本都是"不违约"，只有1%是"违约"。现在训练一个全世界最懒的模型——**它什么都不学，不管收到什么样本，一律判"不违约"**。问自己：这个模型的准确率是多少？

算一下：既然99%的样本本来就是"不违约"，这个零智能模型蒙对的比例就是 **99%**。

这个模型**连一行判断逻辑都没有**，99%的准确率纯粹是靠数据本身的分布"白捡"来的。这就是类别不均衡数据集的共同陷阱：

> **类别越不均衡，"什么都不做"的基线准确率天然就越高——准确率这个数字本身，天生就混进了一部分"蒙对"的成分。** 一个真正训练出来的模型，要证明自己有价值，必须明显超过这个"白捡"基线，而不是贴着它。

带着这个机制，再往下看真实数据会更有感觉：如果某数据集违约率只有15.5%，"全判不违约"的基线准确率是多少？自己心算一下——答案是 **84.5%**。先记住这个数字，下一节揭晓它和真实模型跑出来的结果有多接近。

## 三、亲手验证：训练一个信用评分模型

现在把开头那份"84.7%准确率"的报告自己跑一遍、拆开看看是怎么回事。打开Jupyter，敲下面这段代码：

```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix, classification_report, roc_auc_score

d = pd.read_csv("../数据集/credit_data.csv")
print("违约率:", d["is_default"].mean())
print("缺失:", d.isnull().sum()[lambda s: s > 0].to_dict())

# 先处理缺失与异常——课题2-1学过的数据清洗规范，这里要用上
d["age"] = d["age"].mask((d.age < 18) | (d.age > 100), d.age.median())
d["monthly_income"] = d["monthly_income"].fillna(d["monthly_income"].median())

F = ["age","monthly_income","debt_ratio","credit_history_months","late_payment_times","credit_lines"]
X, y = d[F], d["is_default"]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)
sc = StandardScaler().fit(Xtr)
model = LogisticRegression(max_iter=1000).fit(sc.transform(Xtr), ytr)

pred = model.predict(sc.transform(Xte))
proba = model.predict_proba(sc.transform(Xte))[:, 1]

print(confusion_matrix(yte, pred))
print(classification_report(yte, pred, target_names=["未违约","违约"], digits=3))
print("AUC =", round(roc_auc_score(yte, proba), 3))
```

**三个容易踩的坑，自学时自己对照检查一遍**：

1. `train_test_split` 里的 `stratify=y` 不能漏——漏了的话，训练集/测试集里违约样本的比例可能不一致，你跑出来的数字会和下面给出的实测值有偏差，不容易复现本课的关键对比。
2. `StandardScaler` 必须只在训练集上 `fit`，测试集只能 `transform`，不能用测试集的数据去算标准化参数——这是数据泄漏，四级阶段应该已经接触过这个坑，这里顺带复查一遍。
3. 代码里对 `age` 的异常值做了处理（小于18或大于100的替换为中位数）——这正是课题2-1数据清洗规范的落地应用，如果你自己写代码时漏掉这一步，说明那部分知识还没有变成习惯。

运行后，你应该得到和下面完全一致（或非常接近）的结果：

## 四、揭晓：84.7%的准确率，到底是不是好消息

现在回到第二节留下的问题：如果这批数据什么都不做、全部判"不违约"，基线准确率是 **84.5%**（违约率15.5%）。

而我们辛辛苦苦训练出来的模型，准确率是 **84.7%**——**只比什么都不做高了0.2个百分点**。

现在正式回答开篇的问题：**这份报告能不能签字通过？** 答案是不能。花了时间精力训练模型、调参数、挑特征，换来的提升只有0.2个百分点，这个模型"几乎是白训练的"。

**为什么会这样？** 机制在第二节已经讲清楚了：这批数据里本来就只有15.5%的人会违约，"全判不违约"这种零智能策略天然就能蒙对84.5%。**数据的类别越不均衡，这个"白捡"的基线就越高**——单独看一个84.7%，完全判断不出模型好不好，你必须先问"基线是多少"，再看模型比基线高了多少，这才是有意义的比较。

再往深处看一层——拆开混淆矩阵看违约类这一行：**精确率0.529，召回率只有0.097**。

召回率0.097是什么意思？换算一下：**100个真实会违约的客户里，模型只找出了约10个，剩下90个全部被放过**，系统会把他们当成"安全客户"正常放款。对一家做信用审批的公司来说，这意味着大量真实坏账客户会被当作安全客户正常放款——**这个模型对风控场景而言形同虚设**，而且这90个漏判的客户，恰恰是模型最应该抓住的那一类：越是难判断的违约客户，才越需要模型的判别价值，而不是靠数据分布自动蒙对的那85%"显而易见不会违约"的客户。

> ⚠️ **这是本课程最有力的一次主线实证**：准确率84.7%看起来不错，但它几乎全靠"大多数人本来就不违约"撑起来的——这和课题2-2里"一致率87.8%但Kappa仅0.217"是同一个陷阱结构：**一个指标数字好看，不代表它排除了"白捡"的成分**。类别不均衡时，准确率会严重失真，必须拆解混淆矩阵看每个类别的表现，不能停在整体数字上。

## 五、模型是真的无能，还是阈值选错了

先别急着下结论说"这个模型没用、要重新选算法"。看一眼AUC：**AUC = 0.768**，明显高于随机瞎猜的0.5，这说明**模型本身是有判别力的**，不是什么都没学到。

那问题出在哪？出在**决策阈值**——scikit-learn默认阈值是0.5（预测违约概率超过50%才判"违约"），但这个数字不是为这批数据、这个业务场景量身定做的，只是一个默认值，没人检查过它是否适合当前场景。

把阈值调低试试，降到0.3，意味着只要预测概率超过30%就判"违约"，放宽判定违约的标准：

```python
pred_03 = (proba >= 0.3).astype(int)
print(confusion_matrix(yte, pred_03))
print(classification_report(yte, pred_03, target_names=["未违约","违约"], digits=3))
```

实测结果对比：

| | 阈值0.5 | 阈值0.3 |
|---|---|---|
| 召回率 | 0.097 | 0.366 |
| 精确率 | 0.529 | 0.500 |

召回率从0.097升到0.366，**提升了3.8倍**；精确率只从0.529降到0.500，**只降了2.9个百分点**。**用很小的精确率代价，换来大幅召回率提升**——这就是为什么训练师要会调阈值，而不是拿到一个默认阈值下的结果就直接下结论"模型不行"。

这件事也说明：**模型本身没有任何改变，只是换了判定门槛，召回率和精确率就此消彼长**——"模型能力"和"阈值选择"是两件完全不同的事情，前者由训练过程决定，后者是上线前可以随时按业务需要调整的旋钮。

## 六、把所有阈值都看一遍：ROC曲线与AUC

刚才我们只手动试了阈值0.5和0.3两个点。如果把所有可能的阈值都试一遍会怎样？这正是ROC曲线在做的事：**横轴是假正例率，纵轴是召回率（真正例率），画出阈值从1滑到0时这两个值如何此消彼长**。

**AUC就是这条曲线下方的面积**。它的意义在于：**不依赖你具体选了哪个阈值**，只衡量模型把正负样本"排序排得对不对"这件整体能力——随机瞎猜的模型AUC是0.5，完美区分正负样本的模型AUC是1。我们这个模型AUC是0.768，说明它确实学到了违约和不违约之间的差异，只是默认阈值没有把这份能力用好。

这也正是为什么AUC能回答"模型本身有没有用"，而准确率在类别不均衡时做不到——准确率的高低会被某一个具体阈值和数据分布一起带偏，AUC不会。

> 🔑 **判别口诀**：拿到一份评测结果，先看AUC，再判断问题出在哪——**AUC接近0.5 → 模型本身没学到东西，调阈值也救不回来；AUC明显高于0.5，但某个阈值下召回率很差 → 问题大概率在阈值，不在模型。** 本例AUC为0.768，明显高于0.5，属于后一种情况：不需要换模型、换算法，调阈值就能大幅改善效果。

## 七、精确率 vs 召回率：该保哪个，没有标准答案，只有业务代价

每个场景里"漏判"和"误判"各自对应的实际后果不一样，所以不存在一个放之四海而皆准的"最优阈值"。看三个典型场景：

| 场景 | 该优先保什么 | 为什么 |
|---|---|---|
| 风控审批 | 召回率 | 漏判一个违约客户（坏账）代价远高于误判一个正常客户（多审一次） |
| 垃圾邮件过滤 | 精确率 | 误判一封正常邮件为垃圾（用户丢失重要信息）代价高于漏掉一封垃圾邮件 |
| 医疗筛查 | 召回率 | 漏诊的代价远高于误诊后进一步检查的代价 |

注意：表格里"该优先保召回率"出现了两次（风控、医疗），但**原因不能照抄**——风控怕的是"坏账"，医疗怕的是"漏诊致命"，结论看起来一样，业务代价的具体内容完全不同。

> 🔑 **判别口诀**：遇到任何一个新场景，先别急着套用已知结论，问自己一句——**漏掉一个的代价大，还是错抓一个的代价大？** 代价在"漏" → 保召回率；代价在"错抓" → 保精确率。这把尺子能用在任何没见过的新场景上，死记"风控=召回率"这种对照表做不到这一点。

### 自测一下：换个没见过的新场景

光记住上面三个场景的答案没有用，真正的能力是能把判别口诀用到新场景上。试试这一道：

**某电商平台的"高价值客户流失预警模型"，用来识别哪些VIP客户即将流失，以便客服提前挽留。这个模型该优先保精确率还是召回率？**

不要因为都叫"预警模型"就照抄风控的答案，自己先想一遍"漏判代价"和"误判代价"分别是什么，再看下面的推理：

- **漏判代价**：一个真正要流失的VIP客户没被识别出来，公司就失去了提前挽留的机会，直接损失这个高价值客户。
- **误判代价**：把一个本来不会流失的VIP客户也标成"即将流失"，后果通常只是客服多打一个电话、多发一张优惠券——**代价很小**。

两相比较，漏判代价（永久损失一个高价值客户）远高于误判代价（多做一次低成本的挽留动作），所以**依然应该优先保召回率**——但注意，这个结论是通过比较两种代价得出的，不是因为它"看起来像风控"。如果换一个误判代价很高的场景（比如误判会导致客户被过度打扰、大量投诉甚至流失），结论就可能反过来。**这才是三级训练师该有的能力：不是记住几个场景的标准答案，而是每次都重新用代价这把尺子量一遍。**

> **没有"万能最优阈值"，阈值必须依据业务代价调整**——这也是三级"设计者"能力和四级"执行者"能力的分界线：四级执行既定阈值，三级要能判断阈值该不该调、往哪个方向调。

## 八、自我诊断：三条常见的错误判断，你能看出问题吗

下面三条判断语句，都是实际工作中容易脱口而出的错误结论。读之前先自己判断一下哪里有问题，再看解析——这比直接看答案更能检验你是不是真的理解了前面几节的机制。

| 错误语句 | 问题出在哪 |
|---|---|
| "模型准确率84.7%，比基线84.5%高，所以模型有效" | 没有对比召回率等细分指标，只凭准确率的微小领先就下结论，忽视了召回率仅0.097这一致命问题——这正是第四节揭示的陷阱 |
| "这个模型召回率这么低，说明模型本身学得不好，要重新选算法" | 跳过了"先看AUC判断模型是否有判别力"这一步。AUC0.768说明模型是有效的，问题更可能出在阈值而非算法选型，直接提出换算法是诊断顺序错了 |
| "AUC是0.768，所以这个模型的准确率也差不多是76.8%" | 把AUC和准确率混为一谈。AUC衡量的是排序能力，不依赖具体阈值；准确率是在某一个具体阈值下算出来的判对比例，两者没有换算关系 |

把这三条和第六节的判别口诀对照一遍：**先看AUC判断模型本身有没有判别力，再查阈值是否合适，最后才轮到考虑是否需要换模型/换算法**——这是一套固定的诊断顺序，颠倒顺序是实际工作中最容易出的错。

## 九、这节课在整个课程主线里的位置

回顾一下，本课题是本课程"单一指标变好≠真实目标达成"这条主线的第四次实证：

- **课题2-2**：标注一致率87.8%，但Kappa系数仅0.217——一致率被类别不均衡的标注任务本身的"偶然一致"成分抬高了；
- **课题2-3**：训练集准确率很高，但模型只是死记硬背（过拟合），遇到新数据表现会崩；
- **本课题（2-4）**：测试准确率84.7%，几乎贴着"什么都不做"的基线84.5%，少数类召回率仅0.097，模型对真正该解决的问题（抓出违约客户）几乎没有贡献。

三次实证的共同点：**一个看起来不错的单一指标背后，可能藏着"蒙对的成分"或"没有解决真正问题"的真相，必须拆解到更细的层面才能看清楚。**

留一个问题带去下一课题：这节课我们把AUC、精确率、召回率都核实过了，模型评测合格了，是不是就意味着这个模型可以一劳永逸地用下去？**不一定**——模型上线后面对的真实数据会随时间推移慢慢变化，今天测出来达标的指标，不代表半年后依然达标。这是本课程主线的第五次实证，会在课题3-1"智能系统监控与优化"里详细展开：模型上线时各项指标都达标，但几个月后效果会在用户毫不知情的情况下悄悄变差——这就是数据漂移和模型退化。

## 考点清单

| 考点 | 考试怎么考 | 易错点 |
|---|---|---|
| **准确率在不均衡数据下失效** | 实操核心，最高频考点 | **只看准确率就判断模型可用，不对比基线、不拆混淆矩阵** |
| 精确率vs召回率的业务选择 | 实操/简答 | 死记"高精确率好"，不结合场景判断；或把结论相同的场景（风控/医疗都保召回率）误以为原因也相同 |
| AUC的意义 | 单选/判断 | 把AUC和准确率混为一谈，以为AUC数值可以直接当准确率用 |
| 阈值调整的影响 | 实操 | 认为只有重新训练模型才能改善效果，忽视调阈值这个更低成本的手段 |
| 诊断顺序 | 实操/简答 | 跳过"先看AUC"直接建议换模型/换算法 |

## 自测练习

把下面5题当作对自己的最终检验，先自己想清楚答案，再看展开的参考答案核对。

**练习 1**：某模型在违约率仅2%的数据集上，准确率达到98%。这是否说明模型效果好？你会追问什么？

**答案**：不能直接判断。98%的准确率可能仅略高于"全判不违约"的98%基线（因为违约率只有2%）。必须追问：违约类的召回率和精确率分别是多少？混淆矩阵长什么样？如果召回率接近0，说明模型实际上没有学到任何有效的违约判别能力。

**练习 2**：本课题信用评分模型准确率84.7%，全判不违约基线84.5%，为什么说"模型几乎白训练"？

**答案**：因为花费时间精力训练出的模型，准确率只比什么都不做（全判不违约）高0.2个百分点，几乎没有体现出模型的价值。更关键的是，违约类的召回率仅0.097，意味着100个真实违约客户中模型只找出约10个，对风控场景而言这个模型实际上没有提供有效的判别能力。

**练习 3**：AUC为0.768，但模型在阈值0.5下的召回率只有0.097，这说明问题出在哪里？

**答案**：AUC不依赖具体阈值，衡量的是模型整体的判别能力，0.768明显高于随机水平（0.5），说明模型本身是有判别力的。问题更可能出在决策阈值的选择上——默认阈值0.5不适合这批类别不均衡的数据，调低阈值后召回率有显著提升，说明"模型无能"的判断是错的，真正的问题是阈值设置不当。

**练习 4**：阈值从0.5降到0.3后，召回率从0.097升到0.366，精确率仅从0.529降到0.500。为什么说这个权衡在风控场景下是合理的？

**答案**：风控场景中，漏判一个真实违约客户（造成坏账）的代价，远高于误判一个正常客户（只是多了一次审核环节）。召回率提升3.8倍，而精确率只下降了2.9个百分点，用很小的代价换来了大幅提升的风险识别能力，符合风控业务对漏判代价的权衡逻辑。

**练习 5**：垃圾邮件过滤场景和信用风控场景，在精确率/召回率的权衡方向上有何不同？为什么？

**答案**：信用风控场景优先保召回率——漏判一个违约客户的代价高，宁可误判也不能放过。垃圾邮件过滤场景优先保精确率——误判一封正常邮件为垃圾邮件（用户可能丢失重要信息）的代价，高于漏掉一封垃圾邮件。两者方向相反，原因在于两个场景中"漏判"和"误判"各自对应的业务代价不同，没有放之四海而皆准的"最优阈值"。

## 小结

| 要点 | 一句话 |
|---|---|
| 准确率陷阱 | 类别不均衡时严重失真，必须对比基线并拆解混淆矩阵 |
| 本例实证 | 84.7%准确率≈84.5%基线，召回率仅0.097，模型形同虚设 |
| 阈值 vs 模型 | AUC高说明模型有判别力，问题可能在阈值而非模型本身 |
| 业务代价 | 精确率/召回率的取舍没有标准答案，取决于"漏判"和"误判"各自的代价 |
| 诊断顺序 | 先看AUC → 再查阈值 → 最后才考虑换模型/算法 |
