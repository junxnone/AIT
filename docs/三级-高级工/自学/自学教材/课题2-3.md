## 第一部分：学习率——训练这艘船一步迈多大

神经网络训练的本质是：每一轮算出当前预测的误差（Loss），然后朝着能减小误差的方向调整一步。**学习率，决定的就是这一步迈多大。**

学习率设得不合适会怎样？

| 学习率 | 后果 | 为什么会这样（机制） |
|---|---|---|
| 太大 | Loss 剧烈震荡，极端时数值发散甚至变成 **NaN**（训练崩溃） | 每一步迈得太猛，**越过了误差最小的那个点**；下一步朝反方向调整又同样迈过头，于是来回"打摆子"，严重时误差越调越大，彻底失控 |
| 太小 | 收敛极慢，容易在局部最优的"小坑"里打转 | 每一步迈得太碎，走到真正最优点要花极多轮次，还容易陷进一个不太好的"小坑"出不来 |

**追问自己一句：为什么学习率太大会表现为"震荡"，而不是直接"卡住不动"？**

想象你要走到房间正中间：正常步幅能精准停在中间附近；但如果你每步都迈三米，你会从中间这一侧直接跨到另一侧，再从那一侧跨回来，不停来回跨——这就是"震荡"。步子越大跨得越离谱，极端情况下误差会越调越大，数值彻底失控变成 NaN。倒车入库时方向盘打得过猛、不断来回修正方向，也是同一种结构。

**常用应对手段**：**学习率调度（Learning Rate Scheduling）**——训练初期用稍大学习率快速逼近，中后期逐步减小做精细调整。还有一个常见做法叫 **Warmup**——刚开始学习率从很小值逐渐升到目标值。

**为什么需要 Warmup？** 因为模型刚初始化时权重还很不稳定，如果一上来就用大步子调整，很容易把这些还没站稳的权重直接冲乱；让学习率从很小值慢慢升上去，相当于先给模型一个"热身"过程，等权重稳定一些了再放开步子走。

> 🔑 **判别口诀**：Loss **震荡/发散** → 步子迈太大；Loss **纹丝不动/下降极慢** → 步子迈太小。记不住就想"走到房间中间"的类比：迈三米的人在来回跨，迈半厘米的人在原地挪。

## 第二部分：Batch Size——一次看多少数据再调整一步

Batch Size，就是每次调整参数之前，先看多少条数据。这里有一个三级考试最爱考的反直觉结论——**不是 Batch Size 越大越好**。

| | Batch Size 较大 | Batch Size 较小 |
|---|---|---|
| 梯度估计 | 更稳定，噪声小 | 噪声大，方向不够准 |
| 训练速度（单步） | 能更充分利用硬件并行，单步更快 | 单步计算量小但步数更多 |
| 内存占用 | 更大 | 更小 |
| 泛化能力 | **可能更差**——容易收敛到"尖锐"局部最优 | 小批次噪声反而有正则化效果，有时泛化更好 |

直觉上，大 Batch Size 看的数据更多、梯度更准，应该学得更好才对。**为什么反而"泛化能力可能更差"？**

把误差函数想象成一片高低起伏的地形：有又窄又深的"尖锐坑"，也有又宽又浅的"平缓坑"。大 Batch Size 因为梯度估计很稳定、噪声小，容易一头扎进离初始点最近的那个坑，哪怕它是个尖锐坑；小 Batch Size 的梯度噪声反而像"不停轻轻晃动"，容易把模型从尖锐坑里晃出来，停在更平缓、更稳健的坑里。尖锐坑对训练数据拟合得很紧，但换一批新数据（验证集/测试集）稍微偏一点点就可能大幅掉出坑外——这就是"泛化能力更差"的来源。

这和"Kappa 高不代表标注真的好""WER 为 0 不代表任务设计没问题"是同一类思维模式：**表面的效率/一致性指标，不能替代对最终目标的直接检验。**

这不是说大 Batch Size 一无是处。如果手头的训练任务对训练速度要求极高、对泛化能力要求一般（比如只是内部实验原型），优先选大 Batch Size 没问题——超参数选择要结合业务场景权衡，不是非黑即白。

> 🔑 **判别口诀**：Batch Size 的权衡不是"越大越好"也不是"越小越好"，而是**速度与泛化的权衡**——赶工期、对泛化要求不高的原型实验可以偏大；正式要上线、必须保效果的模型，不能只看训练速度去选 Batch Size。

## 第三部分：Epoch、过拟合与欠拟合——亲手跑出那条反直觉曲线

Epoch，指模型完整遍历一次全部训练数据。还有一个常考公式：

> **Iteration 数 = 训练集样本总数 ÷ Batch Size**

举例：训练集 10000 条数据，Batch Size 设 100，一个 Epoch 就包含 100 次权重更新。

Epoch 设置不当的后果：

| Epoch | 后果 | 机制 |
|---|---|---|
| 太少 | **欠拟合**——训练集上表现本身就不好 | 模型还没来得及学到数据里的规律，训练就结束了 |
| 太多 | **过拟合**——训练集越学越好，验证集/测试集表现反而变差 | 训练到后期，模型开始"死记硬背"训练数据里的具体细节（包括噪声），这些细节对训练集"有用"，但对没见过的新数据毫无意义甚至起反作用 |

光说"死记硬背"可能没概念。下面在真实数据上跑一遍，看这个现象具体长什么样——**请你真的打开 Jupyter，照抄运行这段代码**（数据用 `数据集/credit_data.csv`；用 `max_iter=1 + warm_start=True` 让每次调用 `fit` 相当于多训练 1 个 Epoch，便于逐个 Epoch 打点观察）：

```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.neural_network import MLPClassifier
from sklearn.metrics import log_loss, accuracy_score

d = pd.read_csv("../数据集/credit_data.csv")
d["age"] = d["age"].mask((d.age < 18) | (d.age > 100), d.age.median())
d["monthly_income"] = d["monthly_income"].fillna(d["monthly_income"].median())

F = ["age", "monthly_income", "debt_ratio", "credit_history_months", "late_payment_times", "credit_lines"]
X, y = d[F], d["is_default"]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)
sc = StandardScaler().fit(Xtr)
Xtr_s, Xte_s = sc.transform(Xtr), sc.transform(Xte)

clf = MLPClassifier(hidden_layer_sizes=(32, 16), solver="adam", max_iter=1,
                     warm_start=True, random_state=42, learning_rate_init=0.01)

checkpoints = [5, 50, 200, 1000]
for epoch in range(1, 1001):
    clf.fit(Xtr_s, ytr)
    if epoch in checkpoints:
        train_loss = log_loss(ytr, clf.predict_proba(Xtr_s))
        val_loss = log_loss(yte, clf.predict_proba(Xte_s))
        train_acc = accuracy_score(ytr, clf.predict(Xtr_s))
        val_acc = accuracy_score(yte, clf.predict(Xte_s))
        print(f"epoch={epoch:4d}  训练Loss={train_loss:.3f}  验证Loss={val_loss:.3f}  "
              f"训练Acc={train_acc:.1%}  验证Acc={val_acc:.1%}")
```

**运行结果**（已验证，你的结果应与此基本一致，个别位数可能因环境有极小波动）：

```
epoch=   5  训练Loss=0.371  验证Loss=0.387  训练Acc=85.1%  验证Acc=84.3%
epoch=  50  训练Loss=0.333  验证Loss=0.467  训练Acc=87.1%  验证Acc=82.8%
epoch= 200  训练Loss=0.351  验证Loss=0.947  训练Acc=89.8%  验证Acc=79.3%
epoch=1000  训练Loss=0.372  验证Loss=2.188  训练Acc=93.2%  验证Acc=79.7%
```

整理成对比表看得更清楚：

| | epoch=5 | epoch=50 | epoch=200 | epoch=1000 |
|---|---|---|---|---|
| 训练Acc | 85.1% | 87.1% | 89.8% | **93.2%**（持续上涨） |
| 验证Acc | 84.3% | 82.8% | 79.3% | **79.7%**（掉头向下） |
| 验证Loss | 0.387 | 0.467 | 0.947 | **2.188**（涨近6倍） |

**看这组数字**：训练 Acc 从 85.1% 一路涨到 93.2%，涨了 8 个百分点，表面上看模型越训越好。但验证 Acc 从 84.3% 跌到 79.3% 附近、验证 Loss 更是从 0.387 涨到 2.188，涨了近 6 倍。**训练集指标在涨，验证集指标在跌——这就是过拟合正在真实发生，不是书上的假设。**

> 💡 **一个容易让人疑惑的细节**：这段代码里训练 Loss 并不是严格单调下降的（在 0.33～0.40 之间来回波动），这**不是代码写错了**——小批量/随机优化本身自带噪声是正常现象。判断过拟合要看验证集的整体趋势，不要求训练 Loss 必须每一步都严格下降。

**怎么判断该停在哪个 Epoch？** 同时监控训练集 Loss 和验证集 Loss：训练集 Loss 一直下降，但验证集 Loss 从某个点开始不降反升——这个拐点就是该停止训练的信号，这个做法叫 **Early Stopping（早停）**。

**为什么不能只盯训练集 Loss 判断该不该停？** 因为训练集 Loss 几乎总是能持续下降（哪怕是靠"死记硬背"压下去的），单看它永远发现不了过拟合已经发生——上表 epoch=1000 时训练 Loss（0.372）甚至和 epoch=5 时（0.371）差不多，但验证 Loss 已经从 0.387 暴涨到 2.188。只盯着训练集这一侧看的人，会完全错过这个危险信号。

**现在回答开篇的判断题**：训练 100 个 Epoch、训练集准确率 99%，这是好事吗？**不一定**——如果没有同步监控验证集表现，这个 99% 很可能和上面实验里的 93.2% 一样，只是"死记硬背"训练数据的结果。具体数字不需要刚好涨到 99% 才算过拟合，**现象的本质是一样的：训练指标在涨、验证指标在跌**。这和"只看一致率不看 Kappa""只看 WER 不看任务设计是否合理"是完全相同的陷阱结构：**单一指标持续变好，不代表真实目标达成了，必须有一个独立于该指标之外的检验手段。**

> 🔑 **判别口诀**：欠拟合是"训练集自己都学不好"；过拟合是"训练集学得越来越好，验证集却越来越差"。**只看一个数据集的表现永远诊断不出过拟合——必须两个数据集对照着看。**

## 第四部分：动手验证二——学习率过大，真的会"发散"吗

第一部分讲到学习率太大会震荡甚至发散，但光听结论印象不深，下面同样用真实数据验证一次。固定其他设置不变，只改学习率，对比两组结果：

```python
from sklearn.neural_network import MLPClassifier
from sklearn.metrics import accuracy_score

for lr in [0.01, 50.0]:
    clf = MLPClassifier(hidden_layer_sizes=(32, 16), solver="sgd", max_iter=60,
                         learning_rate_init=lr, random_state=42, momentum=0,
                         n_iter_no_change=1000, tol=0.0)
    clf.fit(Xtr_s, ytr)
    lc = clf.loss_curve_
    print(f"学习率={lr}")
    print(f"  前3轮Loss：{[round(x, 3) for x in lc[:3]]}")
    print(f"  末3轮Loss：{[round(x, 3) for x in lc[-3:]]}")
    print(f"  最终 训练Acc={accuracy_score(ytr, clf.predict(Xtr_s)):.1%}  "
          f"验证Acc={accuracy_score(yte, clf.predict(Xte_s)):.1%}\n")
```

**运行结果**（已验证）：

```
学习率=0.01
  前3轮Loss：[0.706, 0.669, 0.637]
  末3轮Loss：[0.404, 0.403, 0.402]
  最终 训练Acc=84.5%  验证Acc=84.5%

学习率=50.0
  前3轮Loss：[4006.63, 131592416.23, 131546367.87]
  末3轮Loss：[129128646.92, 129083457.43, 129038287.2]
  最终 训练Acc=84.5%  验证Acc=84.5%
```

学习率 0.01：Loss 从 0.706 平稳降到 0.402，这是正常收敛。学习率 50：Loss 从 4006.63，**下一轮直接跳到 1.3 亿**，后面一直在上亿的量级里打转，再也没回到正常范围。

> ⚠️ **容易踩的坑**：这里没有出现字面意义上的 NaN，但 Loss 涨到 1.3 亿这种天文数字，同样代表训练已经彻底失控——**数值发散不一定表现为 NaN，本质都是"训练失败、权重被巨大更新步长破坏"，不要死记"必须变成 NaN 才算"。**

细心的话你会发现两组实验**最终 Acc 都是 84.5%**——这不是说明学习率 50 也训好了，而是因为这个数据集里存在占多数的类别，哪怕权重已经被破坏得毫无意义，模型也可能退化成"无脑预测多数类"，碰巧对出同样的准确率。**这正说明：不能只看最终 Acc 一个数字判断训练是否正常，必须结合 Loss 曲线的走势**——一个在合理范围内平稳下降，一个已经飞出天际，后者不管再训多久都没有意义。

**"多大算太大"有没有一个统一数字？** 没有。这组数据在学习率 1 甚至 10 的时候都还能正常收敛，直到 50 才彻底发散——**这说明阈值取决于具体的数据、网络结构和特征缩放，不能死记一个固定数字。** 判断的办法是训练时盯着 Loss 曲线：曲线在合理范围内波动下降是正常的，曲线脱离合理量级往上飞，就是学习率过大的信号，不管它最后有没有变成字面意义的 NaN。

## 第五部分：诊断路径——现象描述换了说法，你还认得出来吗

前面两段实验，你已经亲手见过"过拟合的验证 Loss 曲线"和"学习率过大的发散曲线"长什么样。接下来是本课题真正的难点，也是最容易在考试里失分的地方。

**本课题最大的坑**：很多人会把"现象→原因"做成一张死记硬背的对照表，一旦考题换个说法描述同一个现象（比如用"验证集指标不升反降"代替"过拟合"这个词），就对不上号了。正确的做法是记住**诊断逻辑**本身：

> **先判断是"学不动"还是"学过头"，再定位具体是哪个参数。**
> 学不动 → 欠拟合 / 学习率太小
> 学过头 → 过拟合 / 学习率太大 / Epoch 太多

试着自己诊断下面这四种现象，判断原因、想出调整方向，想完再对照参考答案：

| 现象 | 最可能的原因 | 调整方向 |
|---|---|---|
| Loss 几乎不下降，训练很多轮都没起色 | 学习率太小 / 模型欠拟合 | 适当增大学习率，或检查模型复杂度是否够 |
| Loss 剧烈震荡，甚至数值变得极大（不一定是字面意义的 NaN） | 学习率太大 | 减小学习率，必要时加入梯度裁剪 |
| 训练集 Loss 很低，验证集 Loss 很高且持续上升 | 训练轮数过多 / 模型过拟合 | Early Stopping，减少 Epoch，或增加正则化 |
| 训练很快、效果一般，调大 Batch Size 后效果反而更差 | Batch Size 增大需同步调整学习率，否则梯度估计变化导致收敛位置不同 | 按比例调整学习率后重新验证，不能只调 Batch Size 不调学习率 |

**自学者最容易在这里犯的一个具体错误**：把"Loss 剧烈震荡甚至数值变得极大"误判为"过拟合"。提醒自己回忆一下——过拟合的典型标志是**训练集表现好、验证集表现差**，而震荡/发散是训练过程本身就不稳定，这两者的区别在于："过拟合"时训练本身是正常收敛的，只是收敛到了一个对新数据没用的地方；"发散"时训练本身就没有正常收敛。对照第三部分和第四部分亲手跑出的两条曲线，这个区别应该能感受得更清楚。

**为什么要反复强调"诊断逻辑"而不是直接背这张表？** 因为第四部分"学习率=50"的真实实验里，Loss 并没有变成字面意义的 NaN，而是涨到了 1.3 亿；如果只是死记"学习率过大=变成 NaN"，遇到这种换了说法的现象描述就可能对不上号。但只要掌握"先判断学不动还是学过头，再定位具体参数"这条路径，不管现象怎么换说法都能分析定位。本课题两组真实实验，就是让你亲眼见过这条诊断路径在真实、会变化的数字上是怎么用的——**数字本身可以变，诊断路径不变。**

## 第六部分：这课题和实操考试（2.2.1）是什么关系

本课题对应的实操试题代码是 **2.2.1——智能信用评分模型开发与测试**，但该题的评分表主要聚焦在模型训练完成后的混淆矩阵判读（这部分由下一课题 2-4 重点展开）。

本课题训练的"依据训练现象诊断超参数问题"这项能力，是让你能**先把模型训练到一个正常收敛、可供评测的状态**的前置能力——如果学习率设得过大导致训练发散，或者 Epoch 设置不当导致严重过拟合，后面再怎么拆解混淆矩阵、调阈值都无从谈起。所以本课题不单独对应 2.2.1 评分表中的某一项，而是为课题 2-4 的评分点打基础。你可以把本课题理解为："先确保训练过程本身没问题，下一课题才轮到评价训练结果好不好"。

## 回扣主线：这是本套教材第几次见到这个陷阱

如果你是按顺序学过来的，这其实是同一个陷阱第三次出现：

- 课题 2-2：一致率 87.8%，但 Kappa 只有 0.217——表面一致率很高，真实标注质量很差；
- 课题 2-2：WER 等于 0，但转写标准本身就定义错了——表面指标完美，任务设计本身有问题；
- **本课题（实测）**：训练集 Acc 从 85.1% 涨到 93.2%，验证集 Acc 却从 84.3% 跌到 79.3% 附近——表面训练指标在涨，真实泛化能力在跌。

**单一指标持续变好 ≠ 真实目标达成。必须有一个独立于该指标之外的检验手段。** 这条主线会在下一课题（算法测试与错误分析）第四次出现：准确率 84.7% 看起来不错，但和"什么都不做"的基线相比可能只高 0.2 个百分点。带着这个问题进入下一课题的学习，会更容易抓住重点。

## 本课题考点清单

| 考点 | 考试怎么考 | 易错点 |
|---|---|---|
| 学习率过大/过小的后果 | 单选/实操反推 | 混淆"震荡"（过大）和"不降"（过小）两种现象 |
| Batch Size 反直觉结论 | 单选/判断高频 | 认为"Batch Size 越大效果越好" |
| 过拟合判断依据 | 实操核心 | 只看训练集 Loss 下降就判断"训练效果好" |
| Iteration 计算 | 单选计算题 | 公式记反（样本数÷Batch Size，不是 Batch Size÷样本数） |

## 小结

| 要点 | 一句话 |
|---|---|
| 学习率 | 太大震荡/数值发散，太小收敛慢 |
| Batch Size | 越大不等于越好，需要和学习率联动 |
| Epoch/过拟合 | 必须同时看验证集 Loss，Early Stopping 判断拐点 |
| 诊断方法 | 先判断"学不动"还是"学过头"，再定位具体参数 |

## 自测练习

**练习 1**：某团队训练图像分类模型，发现前几个 Epoch Loss 下降很快，但到第 20 个 Epoch 左右开始剧烈震荡，最后几轮出现 NaN。最可能是什么问题？

**答案**：学习率过大（或训练后期学习率未衰减）。调整方向：减小学习率，或引入学习率调度在训练中后期逐步衰减，必要时加入梯度裁剪。

**练习 2**：另一团队把 Batch Size 从 32 直接加大到 2048，未调整学习率，结果模型收敛后验证集准确率反而更低。可能的原因有哪些？

**答案**：① Batch Size 增大后梯度估计更平滑，容易收敛到泛化能力较差的"尖锐"局部最优；② Batch Size 与学习率需要联动调整——未按比例放大学习率，导致有效步长相对变小、收敛位置和小 Batch Size 时不同；③ 大批次减少的噪声本身具有的"正则化"效果消失了。

**练习 3**：如果只被告知"这个模型训练了 100 个 Epoch，训练集准确率达到了 99%"，你会追问哪个关键信息，才能判断这个模型是不是真的训练得好？

**答案**：会追问验证集（或测试集）上的准确率表现。单独的训练集准确率无法说明模型是否具备泛化能力，99% 的训练集准确率完全可能是过拟合（死记硬背训练数据）的结果，必须对比验证集表现才能判断模型真实效果。

**练习 4**：Early Stopping 的判断依据是什么？为什么不能只看训练集 Loss 决定何时停止训练？

**答案**：判断依据是验证集 Loss 的变化趋势——当训练集 Loss 持续下降，但验证集 Loss 从某个点开始不降反升时，这个拐点就是该停止训练的信号。只看训练集 Loss 会让训练持续到过拟合阶段而不自知，因为训练集 Loss 几乎总是随 Epoch 增加而持续下降，它反映不出模型是否已经开始"死记硬背"训练数据。

**练习 5**：为什么说"记住诊断逻辑比记住现象对应表更重要"？

**答案**：因为实际考题给出的现象描述会千变万化，用词可能和复习时见过的标准表述完全不同。如果只是死记"某种现象对应某个原因"，遇到换了说法的现象描述就可能对不上号；但如果掌握了"先判断是学不动还是学过头，再定位具体参数"这条诊断路径，任何新的现象描述都能用这条路径分析定位，不受具体措辞影响。
