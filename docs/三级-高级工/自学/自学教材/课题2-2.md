## 二、一致率的根本缺陷

想弄清楚 87.8% 这个数字到底靠不靠谱，先看一个更极端的思想实验。

假设某标注任务只有"是 / 否"两个选项，你找来两个**完全不懂业务、闭着眼睛随机选**的人来标。他们俩的一致率大概是多少？

稍微想一下——答案是**约 50%**，纯靠概率。两个人各自瞎蒙，蒙对蒙错是独立事件，碰巧选到同一个答案的概率就是 1/2。

这说明一件很重要的事：**一致率这个指标的起点不是 0，是 50%。** 在二分类任务里，什么判断力都不需要，纯靠瞎蒙就能白拿 50 分的一致率。

更麻烦的还在后面。如果这个任务的标签分布本身很不均衡——比如 95% 的样本本来就该标"否"——这两个什么都不懂的人**学聪明了，一律标"否"**。这时一致率是多少？

**100%。** 完美的一致率。但这批标注有任何价值吗？**零。他们根本没有在做判断，只是蒙对了多数类。**

> 📌 **问题的本质**
>
> **一致率里混进了"碰巧一致"的成分，而且标签分布越不均衡，这个成分越大。**

现在回到第一节那个 87.8%。如果"是否礼貌"这个任务里，客服本来 90% 的时候就是礼貌的，那么两个标注员哪怕根本不认真判断，一致率也能轻松冲到 80% 以上——**87.8% 这个数字，很可能几乎全是碰巧撞上的，而不是两人真的达成了一致的判断标准。**

这就是为什么"一致率高"不能直接等同于"标注质量好"：它没有刨除"靠分布蒙对"这一部分。

## 三、Cohen's Kappa：把"碰巧"从一致率里减掉

既然问题出在一致率里混进了"碰巧"，那解决思路也很直接：**把碰巧那部分减掉**。这正是 Cohen's Kappa 要做的事。

```
          观测一致率 − 期望偶然一致率
Kappa = ──────────────────────────────
             1 − 期望偶然一致率
```

逐项拆开看：

- **分子**：你实际观测到的一致率，减去"纯靠标签分布就能蒙到的一致率"。减完之后剩下的，才是**真正因为标注标准统一而产生的一致**，不含运气成分。
- **分母**：1 减去偶然一致率，代表"扣除碰巧之后，理论上最多还能有多少一致空间"。用它做分母，是把分子放进一个"合理的满分"里做归一化。

所以 Kappa 回答的问题其实是：**在所有"非碰巧"的一致空间里，两位标注员真正达成了多少？**

用两个极端值建立直觉：

- 如果观测一致率**恰好等于**偶然一致率，分子为 0，**Kappa = 0**——意思是"你们俩的一致性和瞎标没有任何区别"；
- 如果两人**完全一致**，分子等于分母，**Kappa = 1**——意思是"彻底排除运气后，依然完全一致"。

### Kappa 值怎么判读

| Kappa 值 | 一致性水平 |
|---|---|
| < 0.2 | 很差，标注标准可能存在严重问题 |
| 0.2 – 0.4 | 一般 |
| 0.4 – 0.6 | 中等 |
| 0.6 – 0.8 | 良好 |
| > 0.8 | 几乎完全一致 |

> 💡 **考试不会让你手算 Kappa 公式。** 真正要考的是：给你一个 Kappa 值，你能不能判断质量水平、能不能解释"一致率高但 Kappa 低"这种反差、能不能据此提出下一步该怎么做。公式本身用 `sklearn` 一行代码就能算，不需要背推导。

## 四、动手验证：亲手跑出那个反直觉的结果

光看文字讲解还不够，下面这段代码你应该在自己的环境里实际跑一遍——这是本课题认知冲突真正落地的地方。

打开 Jupyter，新建一个 Notebook，运行：

```python
import pandas as pd
from sklearn.metrics import cohen_kappa_score

for path, name in [
    ("../数据集/annotation_agreement.csv",          "不均衡组（90% 为'是'）"),
    ("../数据集/annotation_agreement_balanced.csv", "均衡组（约 50/50）"),
]:
    df = pd.read_csv(path)
    a = df["标注员甲_是否礼貌"]
    b = df["标注员乙_是否礼貌"]

    agreement = (a == b).mean()          # 观测一致率
    kappa = cohen_kappa_score(a, b)      # Cohen's Kappa

    print(f"{name}")
    print(f"  标签分布：{a.value_counts(normalize=True).round(3).to_dict()}")
    print(f"  观测一致率：{agreement:.1%}")
    print(f"  Cohen's Kappa：{kappa:.3f}\n")
```

**运行结果**（已实测验证，你跑出来的结果应与此完全一致）：

```
不均衡组（90% 为'是'）
  标签分布：{'是': 0.864, '否': 0.136}
  观测一致率：87.8%
  Cohen's Kappa：0.217

均衡组（约 50/50）
  标签分布：{'否': 0.504, '是': 0.496}
  观测一致率：76.2%
  Cohen's Kappa：0.524
```

把两组数字并排放在一起看：

| | 不均衡组 | 均衡组 |
|---|---|---|
| 观测一致率 | **87.8%** | 76.2% |
| Kappa | 0.217 | **0.524** |
| 按一致率判断 | 看起来更好 ✅ | 看起来更差 ❌ |
| 按 Kappa 判断 | 一般，逼近"很差" ❌ | 中等 ✅ |

> ⚠️ **一致率更高的那一组，Kappa 反而更低。** 这和直觉完全相反——按理说一致率 87.8% 应该比 76.2% 更让人放心才对。

### 为什么会这样？——说出机制，而不是只说现象

这是本课题最高频的考点，也是大多数人只能答对一半的地方。现在检查一下你自己：如果刚才让你解释这个反差，你心里冒出来的第一反应是不是"因为样本不平衡"？

**❌ 只答"样本分布不平衡"**——这说出了**原因**，但没说出**机制**：为什么不平衡会导致一致率虚高？不平衡本身不是原因的终点，它是通过某个具体的作用路径才影响到指标的。如果你在实操题里只写到这一步，**只能拿一半分**。

**✅ 完整答案需要两句话，缺一不可**：

> **原因**：标签分布严重不均衡（90% 都是"是"）。
>
> **机制**：不均衡本身就抬高了偶然一致率——两个标注员哪怕完全不认真判断，光靠"多数样本本来就该标是"这个分布规律，碰巧标出一样结果的概率就很高。Kappa 把这部分"靠分布蒙对"的水分扣掉后，发现**几乎没有超出偶然一致的真实共识**，所以只剩 0.217。
>
> **结论**：这两位标注员**对真正有判断难度的那一小部分样本，根本没有形成稳定一致的判断标准**。87.8% 是多数类"垫"出来的数字假象，不是两人判断力的体现。

### 回到开头那个判断

现在回答第一节留下的问题：**那批 87.8% 一致率的语音质检数据，能交付吗？**

**不能。** 算出 Kappa 只有 0.217，落在"一般"区间、逼近"很差"。交付出去，模型会在真正有价值的少数类样本（标注员意见真正有分歧的那部分）上学到一堆噪声，而不是有效信号。

## 五、四种标注错误类型：诊断比计算更重要

算出一个低 Kappa 值之后，**不要直接"重新标一遍"了事**。正确的下一步是先诊断这个低 Kappa 背后的错误属于哪一类——**四种类型的根因和修复方法完全不同，判错方向等于白干**，甚至会把本来没问题的人送去"重新培训"，真正的问题（手册或体系）却一点没改。

### 类型一：标准不一致（Inconsistent Criteria）

**定义**：标注手册对某个判断标准描述模糊，不同标注员各自按自己的理解去标，于是产生分歧。

**典型表现**：

> "这个产品质量真不咋地，不过客服态度还行"
> 甲标**负面**（因为提到了质量差），乙标**中性**（因为夸了客服）。

**根因**：**手册本身没有定义"混合情感该如何判定主次"。**

**修复**：把这条规则补充进标注手册，并附上细则和边界案例。

> 💡 这里要特别提醒自己一件容易想岔的事——**不是标注员不认真**。甲和乙都认认真真地标了，只是手册没告诉他们该怎么处理这种混合情况。这类问题去培训标注员是无效的：手册不改，换一批人来标，照样会出现同样的分歧。

### 类型二：边界模糊（Boundary Ambiguity）

**定义**：两个类别之间天然存在一片灰色地带，无论手册写得多细，总有一些样本客观上难以归入唯一一类。

**典型表现**：

> "你们这物流也太慢了吧，大概还要多久到"
> 这句话既像抱怨（该归入"投诉"），又像单纯问进度（该归入"咨询"）。

**这一类和类型一很容易混为一谈**——两者表现都是"标注员意见不一"。区分它们，问自己一句话就够了：

> 🔑 **判别口诀**：把手册写得再细，这个样本能不能确定地归入某一类？
> **能** → 标准不一致（问题在手册）。**不能** → 边界模糊（问题在数据本身）。

对照表帮你记牢：

| | 标准不一致 | 边界模糊 |
|---|---|---|
| 根因在 | **手册**没写清 | **数据**本身固有 |
| 把手册写细能否解决 | **能** | **不能** |
| 修复方案 | 补充细则与边界案例 | 引入"模糊 / 待裁定"中间类 + 仲裁机制 |

**修复**：既然写多细都没用，就不要死磕"把规则定得更精确"，而是直接设一个"模糊 / 待裁定"的中间类别，交给专人仲裁，承认灰色地带客观存在。

### 类型三：标签体系缺陷（Taxonomy Flaw）

**定义**：问题不在某一条判断标准上，而在整个分类体系的设计本身——维度混乱、类别之间互斥性不足，或者缺失了实际存在的类别。

**典型表现**：

> 客诉分类体系设有"物流问题""态度问题""退款问题"三类。
> 一条真实对话："物流延迟导致我要求退款，客服态度还很差"——**三类全部沾边**。

**根因**：**分类体系的维度从设计之初就互相重叠。** "物流 / 态度"其实是"问题来源"这一个维度，"退款"却是"用户诉求"这另一个维度，两个不同维度被硬并列成了一组单选类别，任何一条同时涉及来源和诉求的数据都会三类全中。

**修复**：重新设计分类体系。比如拆成两个独立维度分别标注——来源维度标一个、诉求维度标一个，而不是挤在一个单选框里。

> 💡 这一类问题**最容易被误判成"标注员水平差"**，于是去做培训，但体系不改，换谁来标都会在同一批样本上出现分歧。判别信号很明确：**全体标注员都在同一批样本上出现分歧**，而不是某一个人显得特别奇怪。这句话也是接下来要讲的"类型四"的分界线，先记住它。

### 类型四：标注员系统性偏见（Annotator Bias）

**定义**：某一个标注员在某类判断上**持续偏向同一个方向**，而不是随机出错。

**典型表现**：

> 标注员 A 把几乎所有"轻微负面"的评论都标成了"强烈负面"，其他标注员都没有这个倾向。

**根因**：手册和体系**可能完全没有问题**，是具体的这个人产生了系统性偏差——可能是理解有误，也可能是个人的情绪感知阈值和大多数人不同。

**修复——必须按顺序走，不可跳步**：

1. **量化偏差程度**——先确认这是系统性的单方向偏移，还是随机波动造成的巧合；
2. **抽样复核 A 标注过的样本**——看偏差是在所有类别上都存在，还是只集中在"负面情绪"这一个维度；
3. **与 A 沟通、展示具体错误案例**——了解偏差到底从哪来：是对"轻微 / 强烈"的分级理解有误，还是个人情绪敏感度本来就和别人不一样；
4. **确认确实是理解偏差之后，才做针对性培训**；如果是难以通过培训纠正的个人倾向，就调整他负责的任务类型，或者提高对他的复核频次。

> ⚠️ **这是本课题最高频的失分点，务必牢记**
>
> 实操题经常这样设计题干：
> 『……你会怎么处理，**而不是简单地说"A 标注不认真，重新培训"**？』
>
> 这句提示**不是在否定"培训"这个动作本身**，而是在否定"**不经过诊断就直接跳到培训**"这个顺序。出题人专门用这种句子，筛掉跳步给方案的答案。
>
> 同样的套路在合规类题目里也会出现：看到"敏感信息"四个字就条件反射答"脱敏"，却没有去核对题干真正强调的是"授权范围是否具体"。**做三级的题，先抓题干里反复强调的那个细节，再给方案，不要看到关键词就条件反射。**

### 怎么区分"体系缺陷"和"标注员偏见"？

两者都可能表现为"某些样本标注结果乱"，区分方法同样是一句判别口诀：

> 🔑 **判别口诀**：是**所有人**都在同一批样本上分歧，还是**某一个人**持续偏向同一方向？
> **所有人** → 体系问题（类型三）。**某个人** → 个人偏见（类型四）。

### 四类错误速查

| 类型 | 根因在 | 修复方向 |
|---|---|---|
| 标准不一致 | 手册 | 补细则 + 边界案例 |
| 边界模糊 | 数据固有 | 设"待裁定"类 + 仲裁机制 |
| 标签体系缺陷 | 体系设计 | 重设体系 / 改多维标签 |
| 标注员系统性偏见 | 具体的人 | 量化 → 复核 → 沟通 → 才培训 |

## 六、诊断流程：拿到低 Kappa 之后该怎么做

```
低 Kappa 值
   ↓
抽样查看分歧样本        ← 关键动作，不能只看汇总数字
   ↓
判断属于四类中的哪一种（或多种并存）
   ↓
对症下药
```

中间这一步是整个流程里最容易被跳过、也最重要的一步：**不要只盯着一个汇总数字就下结论**，一定要把标注员意见不一致的具体样本挑出来，人工逐条看一遍。往往一眼就能看出属于四类中的哪一种。

> 这个"先看汇总指标、再下钻到具体样本"的思路，不是标注环节专属的技巧。下一课题（2-3，模型训练与超参数）讲模型评测指标时还会再用一次——这是训练师通用的诊断方法论：**指标异常只是报警器，报警之后一定要去现场看，不能只在控制室里猜。**

## 七、Kappa / IoU / WER：三个名字，一个逻辑

前面讲的 Kappa，针对的是**离散标签**任务（文本分类这一类）。但实际工作中你还会遇到图像、语音这类任务，它们的质检指标名字完全不同——不过本质是同一件事。

| 任务输出形式 | 典型任务 | 质检指标 | 指标在问什么 |
|---|---|---|---|
| **离散分类** | 文本情感、意图识别、图像分类 | **Kappa** | 两人的标签是否相同（扣除碰巧） |
| **空间区域** | 目标检测、语义分割、车道线 | **IoU**（交并比） | 两人画的框 / 区域重叠程度 |
| **序列文本** | 语音转写（ASR） | **WER**（词错误率） | 转写结果差多少次编辑操作 |

### IoU（Intersection over Union，交并比）

> IoU = 两个框的重叠面积 ÷ 两个框的并集面积

为什么图像任务不能沿用"一致 / 不一致"的离散判断？因为两个标注员画的框几乎不可能像素级完全重合——按严格标准几乎全会被判成"不一致"，这个指标就失去了区分优劣的能力。IoU 给出的是一个连续的重叠程度数值，能真实反映两人框得有多接近。业界常用阈值 **IoU ≥ 0.5**（更严格的场景取 0.7）视为"一致"。

### WER（Word Error Rate，词错误率）

> WER = (替换词数 + 删除词数 + 插入词数) ÷ 参考文本总词数

**WER 15% 的准确含义是**：每 100 个参考词中，平均有 15 个词存在替换、删除或插入错误。

> ⚠️ 商用成熟 ASR 系统的 WER 常年维持在 5%~10%，所以 15% 应该被描述为"**中等偏可用**"，而不是笼统地说"质量很差"。训练师要用具体数字做判断、用准确的程度词描述，不能用模糊定性代替数据——这也是考试评分时对用词精度的要求。

### 三者共同的逻辑

> **独立的标注结果之间，到底有多少是真实共识，多少是巧合或噪声？**

Kappa、IoU、WER 问的是同一个问题，区别只在于任务的**输出形式**不同，衡量"重合程度"用的数学方式也就跟着不同。

> 🔑 **迁移规则（应对陌生任务的万能方法）**：考试如果给你一个从没见过的任务，**不要去死记"这个任务该用什么指标"**。只问自己一句话：**这个任务的输出是分类、是空间框、还是序列文本？** 三选一，指标自然就定了。

### 最后一个陷阱：指标满分就等于没问题吗？

抛给你一个问题，花 30 秒想清楚再往下读：

**如果一个语音转写任务的 WER 做到了 0，是不是就说明标注完全没有问题？**

**不是。** WER = 0 只能说明"转写结果和参考文本逐词吻合"。但如果**参考文本的转写标准本身就定错了**呢？

比如某团队规定"所有语气词'嗯、啊'一律不转写"——而这个项目恰恰是要训练一个**语气分析**模型，语气词正是关键信息。那么哪怕所有标注员都完美遵守了这条规则、WER 做到 0，产出的数据对训练目标来说**依然是系统性错误的**。

> 📌 **这是贯穿本课题（也是贯穿整个课程）的主线，这一课里你已经看到它出现了三次**：
>
> - 一致率 87.8%，但 Kappa 只有 0.217（指标好看，真实共识却很低）；
> - WER = 0，但转写标准本身就定错了（指标满分，目标却没达成）；
> - 全体标注员高度一致，但分类体系本身有缺陷（一致性没问题，体系设计有问题）。
>
> **单一指标变好 ≠ 真实目标达成。必须有一个独立于该指标之外的检验手段去交叉验证。**
>
> 提前预告：下一课题讲模型训练，你会在"训练集 Loss 一直降，但模型其实在死记硬背"这个现象上看到第四次。

## 九、实操：制定一份可交付的标注规范

### 任务背景

某电商平台要训练商品评价情感识别模型，标签体系为**积极(1) / 消极(0)** 两类。原始数据见 `数据集/data.csv`。你作为三级训练师，需要**制定这份情感识别标注规范**。这个任务直接对应操作技能试题代码 **2.1.1** 中"标注规范制定"的部分（清洗部分见课题 2-1）。

### 先探查数据，再动笔

**不要凭空想象规范条款。** 先看真实数据长什么样：

```python
import pandas as pd

df = pd.read_csv("../数据集/data.csv")
print(df.shape)
print(df["review_text"].sample(20, random_state=1).to_string())
```

看完这 20 条真实样本，你会发现混合情感、否定句式、纯广告、纯表情符号都真实存在——规范必须覆盖这些实际情况，而不是只覆盖理想中的"纯粹正面"或"纯粹负面"评论。

### 规范必备要素（按这个结构撰写）

```
一、适用范围与标注目标
二、标签定义
    1 = 积极：……（要给出可操作的判定依据，不能只写"表达正面情绪"）
    0 = 消极：……
三、判定优先级规则        ← 本任务的核心难点
    · 混合情感如何定主次
    · 否定句式如何处理
    · 与商品无关的内容如何处理
四、边界案例库（至少 5 条，含原文 + 应标标签 + 判定理由）
五、不确定样本处理方式
六、质检方式与合格线
    · 抽检比例、一致性指标（指标选型需说明理由）、合格阈值
```

### 三个最容易写得不合格的地方

1. **标签定义写空话。** 写"积极 = 表达正面情绪"等于没写，标注员照样会分歧。要写成可操作的判定依据（比如具体给出哪些词、哪些句式归属哪一类）。
2. **漏掉判定优先级。** 这份数据里有大量"质量一般，但客服态度不错"这种混合情感的评论。**规范里不写清楚主次判定规则，就是在亲手制造第五节讲的"类型一：标准不一致"错误。**
3. **质检方式不说理由。** 只写"用 Kappa"是不够的，要写成"**因为本任务输出是离散二分类，故选用 Cohen's Kappa；考虑到实际标签分布可能不均衡，不以一致率作为验收依据**"——把第二、三节讲的内容用回到自己的方案里。实操题评分表里，"理由"是单独配分的。

## 十二、自测练习（含完整参考答案）

> 这是一份自学材料，答案直接写在题目下方，不做折叠隐藏。**请先自己独立作答、写下你的答案，再往下看参考答案核对**——这一步不能跳过，否则起不到检验学习效果的作用。

### 练习 1（判断 + 说明机制）

某标注任务一致率 95%，Kappa 0.12。项目经理说"一致率这么高，质量没问题"。他说得对吗？请说出**机制**，不要只说现象。

**参考答案**：

**不对。**

**机制**：Kappa 仅 0.12 说明标签分布极不均衡，偶然一致率本身就接近 95%。两位标注员"碰巧一致"的部分几乎占满了全部一致性，扣除后剩余的真实共识几乎为零。

**结论**：这批标注员对有判断难度的少数类样本没有统一标准，95% 是多数类造成的假象，数据不可交付。

**下一步**：抽样查看分歧样本，判断属于四种错误类型中的哪一类，再对症修复。

### 练习 2（类型判定）

三位标注员对"北京大学第三医院"的实体边界标法各不相同：有人整体标为一个机构实体，有人拆成"北京大学"+"第三医院"两个。

这属于哪一类错误？如何修复？

**参考答案**：

**类型一：标准不一致。**

**判别依据**：套用口诀——把手册写细能不能解决？**能**。只要手册明确定义"嵌套机构名的边界切分规则"（如"医疗机构全称整体标注为一个机构实体"），分歧即可消除。说明根因在手册，不在数据本身。

**修复**：补充实体边界切分细则到标注手册，并附典型示例（含嵌套机构、含分院、含科室等情形）。

**易错**：误判为"边界模糊"。区别在于——边界模糊是**写多细都解决不了**的数据固有灰色地带，而实体切分规则是**可以人为约定**的。

### 练习 3（类型判定 + 处理顺序）

质检发现：标注员 B 标注的"中性"样本比例显著低于其他所有人，且其标为"负面"的样本中，复核判定应为中性的占 40%。

这属于哪一类？**你的下一步是什么**（注意：不要简单回答"重新培训"）？

**参考答案**：

**类型四：标注员系统性偏见。**

**判别依据**：偏差集中在**某一个人**身上（其他人无此倾向），且方向单一（持续把中性判为负面），而非随机出错。

**处理顺序（四步，不可跳步）**：

1. **量化偏差程度**——统计 B 在各类别上的标注分布与他人的差异幅度，确认是系统性单方向偏移而非随机波动；
2. **抽样复核 B 的标注样本**——确认偏差是全类别存在，还是仅在"情感负向判断"这一维度；
3. **与 B 沟通、展示具体错误案例**——了解偏差来源：是对"中性 / 轻微负面"的分级理解有误，还是个人情绪敏感度确实不同；
4. **确认是理解偏差后，才做针对性培训**（补充中性 vs 负面的边界案例）；若属难以通过培训纠正的个人倾向，则调整其负责的任务类型，或将增加复核频次作为长期机制。

**为什么不能直接答"重新培训"**：跳过诊断就无法确定偏差来源。如果根因是个人敏感度而非理解偏差，培训无效，白白消耗成本还延误交付。

### 练习 4（指标选型）

一个自动驾驶团队要标注"车道线检测"任务（给图像中的车道线画出轮廓），他们打算用"一致率"衡量标注质量。合适吗？该用什么？

**参考答案**：

**不合适，应该用 IoU。**

**理由**：车道线轮廓是**连续的空间区域**（甚至是曲线 / 多边形），两个标注员几乎不可能画出像素级完全重合的轮廓。用"一致 / 不一致"这种离散判断毫无意义——按严格标准几乎全部判为不一致，按宽松标准又无法区分优劣。

IoU 给出连续的重叠程度数值，能真实反映两人判断的接近程度。可设定 IoU ≥ 0.5（或更严格的 0.7）作为"一致"的判定阈值。

**迁移规则**：先判断任务输出形式——这是**空间区域**，所以用 IoU；若是离散标签用 Kappa；若是序列文本用 WER。

### 练习 5（综合判断）

一套"用户反馈"分类体系含"功能建议""BUG 反馈""体验吐槽"三类。实际标注中发现，大量反馈同时属于后两类（如"每次打开都闪退，体验太差了"），标注员各凭感觉选。

这属于哪一类错误？为什么不是"标注员偏见"？如何修复？

**参考答案**：

**类型三：标签体系缺陷。**

**为什么不是标注员偏见**：套用口诀——是**所有人**都在同一批样本上分歧，而不是**某个人**持续偏向某方向。偏见的特征是单人、单方向；这里是全员、无规律。

**根因**：体系的**维度混乱**。"BUG 反馈"描述的是**问题性质**，"体验吐槽"描述的是**表达情绪**，两个不同维度被并列成单选项，必然出现一条数据同时命中的情况。"功能建议"则是第三个维度（用户诉求）。

**修复**：重新设计分类体系，改为多维度标签，例如：

- **反馈类型**（单选）：功能建议 / BUG / 使用咨询 / 其他
- **情绪倾向**（单选）：正面 / 中性 / 负面

这样"每次打开都闪退，体验太差了"可标为 `反馈类型=BUG` + `情绪倾向=负面`，不再冲突。

**易错**：此类问题最容易被误判为"标注员水平差"而去做培训——方向完全错误，体系不改，培训多少次都没用。
