## 二、试题正文

某电商平台计划训练一个商品评价**情感识别模型**，标签体系为**积极(1) / 消极(0)** 两类。现已采集到原始评价数据 `data.csv`，字段说明如下：

| 字段 | 含义 |
|---|---|
| `review_id` | 评价唯一标识 |
| `product_id` | 商品标识 |
| `review_text` | 评价正文 |
| `rating` | 用户评分（正常取值 1–5） |
| `review_time` | 评价时间 |

你作为该项目的人工智能训练师，需完成以下工作：

**第 1 题（10 分）** 制定该情感识别任务的**数据清洗标准**，并据此完成数据清洗，将清洗后的数据保存为 **`data_cleaned.csv`**。

要求：
- 以文字列出清洗规则（每条规则须说明**处理对象、处理方式、判定依据**）；
- 提交可运行的清洗代码；
- 输出清洗前后的数据量对比，并说明各类问题的记录数。

**第 2 题（10 分）** 针对"积极(1) / 消极(0)"两类标签，制定**情感识别标注规范**。

规范须包含：
- 标签定义（须给出可操作的判定依据）；
- **判定优先级规则**，至少覆盖：混合情感如何定主次、否定句式如何处理、与商品无关内容如何处理；
- 边界案例库，不少于 5 条（原文 + 应标标签 + 判定理由）；
- 不确定样本的处理方式。

**第 3 题（5 分）** 说明该标注任务完成后的**质检方案**。

要求：说明抽检比例、采用的一致性评估指标**及选型理由**、合格阈值，并说明若指标不达标时的诊断步骤。

## 四、参考答案

> ⚠️ 以下代码与数值均在 **Python 3.11.17 + pandas 2.3.3** 环境下**实际运行验证通过**。

### 第 1 题参考答案（10 分）

**清洗规则**

| 序号 | 处理对象 | 处理方式 | 判定依据 |
|---|---|---|---|
| 1 | 完全重复记录 | 整行去重 | 重复样本会使模型对特定表述过拟合，且虚增数据量 |
| 2 | `review_id` 重复 | 按主键去重，保留首条 | 主键须唯一，重复表示采集或合并环节出错 |
| 3 | HTML 标签 | 正则剥离 `<...>` | 标签属采集残留，非用户语义内容 |
| 4 | emoji 与装饰符号 | 正则剔除 | 本任务判别依据为文本语义；emoji 虽含情感信息，但分布稀疏且与文本情感高度重合，统一剔除以保证特征一致性 |
| 5 | 个人信息（手机号、邮箱） | 替换为 `[手机号]` / `[邮箱]` 占位符 | 合规要求：训练数据不得含可识别个人信息。用占位符而非删除整条，以保留该样本的情感语义 |
| 6 | 空文本与纯空白 | 整条剔除 | 无任何可学习的语义信息 |
| 7 | 超短文本（< 3 字） | 整条剔除 | 如"好""差""。"，单字难以稳定判定情感倾向，易引入标注噪声 |
| 8 | 超长文本（> 200 字） | 整条剔除 | 经查为"好评"重复刷屏样本，非真实评价，且会干扰文本长度相关特征 |
| 9 | 非法 `rating` 取值 | 剔除 `rating` 不在 1–5 的记录 | 字段定义域为 1–5，0 或 6 属埋点或录入错误 |

> 💡 规则 4 和 7、8 的阈值均需说明依据——评分点 1.2 考的正是这一项。**只给数字不给理由会扣分。**

**清洗代码**

```python
import re
import pandas as pd

df = pd.read_csv("data.csv")
n_raw = len(df)
report = {}

# 规则 1：整行去重
report["完全重复行"] = int(df.duplicated().sum())
df = df.drop_duplicates()

# 规则 2：主键去重
report["review_id 重复"] = int(df.duplicated(subset=["review_id"]).sum())
df = df.drop_duplicates(subset=["review_id"])

# 规则 3–5：文本净化
df["review_text"] = df["review_text"].astype(str)
df["review_text"] = df["review_text"].str.replace(r"<[^>]+>", "", regex=True)   # HTML

emoji_pat = re.compile(
    "[" "\U0001F300-\U0001FAFF" "\U00002600-\U000027BF" "★☆❤" "]+",
    flags=re.UNICODE,
)
df["review_text"] = df["review_text"].apply(lambda s: emoji_pat.sub("", s))     # emoji

df["review_text"] = df["review_text"].str.replace(r"1[3-9]\d{9}", "[手机号]", regex=True)
df["review_text"] = df["review_text"].str.replace(
    r"[\w.+-]+@[\w-]+\.[\w.]+", "[邮箱]", regex=True)
df["review_text"] = df["review_text"].str.strip()

# 规则 6：空文本
report["空文本"] = int((df["review_text"].str.len() == 0).sum())
df = df[df["review_text"].str.len() > 0]

# 规则 7–8：长度过滤
length = df["review_text"].str.len()
report["超短文本(<3字)"] = int((length < 3).sum())
report["超长文本(>200字)"] = int((length > 200).sum())
df = df[(length >= 3) & (length <= 200)]

# 规则 9：非法评分
report["非法 rating"] = int((~df["rating"].between(1, 5)).sum())
df = df[df["rating"].between(1, 5)]

df.to_csv("data_cleaned.csv", index=False, encoding="utf-8-sig")

print(f"清洗前：{n_raw} 行")
print(f"清洗后：{len(df)} 行   保留率 {len(df) / n_raw:.1%}")
for k, v in report.items():
    print(f"  {k}: {v} 条")
```

**实际运行输出**

```
清洗前：1040 行
清洗后：883 行   保留率 84.9%
  完全重复行: 40 条
  review_id 重复: 0 条
  空文本: 31 条
  超短文本(<3字): 57 条
  超长文本(>200字): 19 条
  非法 rating: 10 条
```

### 第 2 题参考答案（10 分）

**一、标签定义**

| 标签 | 定义（可操作判定依据） |
|---|---|
| **1 = 积极** | 评价中对商品或服务的**主要评价对象**持肯定态度，表现为：明确赞扬质量/功能/外观/服务，或表达满意、推荐、复购意愿。 |
| **0 = 消极** | 评价中对**主要评价对象**持否定态度，表现为：指出质量问题/功能缺陷/服务不佳，或表达不满、失望、退货意愿、不推荐。 |

> 定义中"主要评价对象"是关键——它把判断锚定在一个可操作的指向上，避免"整体感觉"式的主观发挥。

**二、判定优先级规则**

1. **混合情感定主次**（本任务最高频情形）

   按以下优先级裁定：
   - ① **以商品本身的评价为主**，服务/物流等周边因素为次。
     例："这个产品质量真不咋地，不过客服态度还行" → **0（消极）**，因商品质量为主体评价对象。
   - ② 若商品与周边评价方向一致，直接按该方向标注。
   - ③ 若**仅涉及周边因素**而未评价商品，按周边因素的情感方向标注。
     例："东西还可以，就是物流太慢了" → 商品正向、物流负向，依规则 ① 取商品 → **1（积极）**。
   - ④ 若正负评价均针对商品本身且强度相当、无法分主次 → 标记为**待裁定**，不强行二选一。

2. **否定句式处理**

   以**语义实际指向**为准，不按字面否定词数量判断。
   - "不能说不好，但也谈不上多好" → 双重否定表达的是保留态度，整体偏负向 → **0**
   - "没有想象中那么差" → 实际表达好于预期 → **1**
   - 判定方法：将句子改写为肯定陈述后再判断情感方向。

3. **与商品无关内容处理**

   以下情形**不参与情感标注**，统一标记为 `无效` 并在清洗阶段剔除：
   - 纯广告 / 引流（如"加微信xxx领优惠券"）
   - 纯符号 / 纯表情
   - 与商品无关的闲聊（如"今天天气真不错"）
   - 抢位留言（如"第一""沙发"）

**三、边界案例库**

| # | 原文 | 标签 | 判定理由 |
|---|---|---|---|
| 1 | 这个产品质量真不咋地，不过客服态度还行 | **0** | 混合情感，依优先级 ①：商品质量为主体评价对象，方向为负 |
| 2 | 东西还可以，就是物流太慢了，等得我都快忘了 | **1** | 混合情感，商品正向、物流（周边）负向，依优先级 ① 取商品 |
| 3 | 价格便宜是真的，质量也是真的一般 | **待裁定** | 正负均针对商品本身（价格、质量），强度相当，依优先级 ④ |
| 4 | 不能说不好，但也谈不上多好 | **0** | 否定句式，改写为肯定陈述后为"质量平平"，偏负向 |
| 5 | 没有想象中那么差 | **1** | 否定句式，实际表达好于预期 |
| 6 | 外观我很喜欢，但是用了两天就出故障了 | **0** | 均针对商品，但"出故障"属功能性缺陷，严重度高于外观偏好 |
| 7 | 加微信xxx领优惠券 | **无效** | 与商品无关的广告内容，不参与情感标注 |

**四、不确定样本处理方式**

1. 标注员遇到无法依规范判定的样本，**一律标记为 `待裁定`，不得自行推断**。
2. `待裁定` 样本汇总后由项目负责人或业务方**统一终裁**。
3. 终裁结果**回写入边界案例库**，作为规范的增补条款，后续同类样本按新条款处理。
4. 若某类 `待裁定` 样本占比超过 **5%**，说明规范存在系统性缺口，应回头修订判定优先级规则，而非逐条裁定。

> 💡 第 4 条体现的是三级能力：**把个案处理反馈回规范设计**，这是"设计者"而非"执行者"的做法。

### 第 3 题参考答案（5 分）

**一、抽检比例**

- 标注初期（前 10% 工作量）：**全检**，用于快速暴露规范缺口；
- 稳定期：按 **10%** 比例分层抽检，其中"待裁定"样本与少数类样本**全检**；
- 另设 **5%** 双标样本（同一批数据由两名标注员独立标注），用于计算一致性指标。

**二、一致性评估指标及选型理由**

**选用 Cohen's Kappa。**

理由：
1. 本任务输出形式为**离散二分类**（积极/消极），符合 Kappa 的适用范围；
2. **不以一致率作为验收依据** —— 本任务的标签分布很可能不均衡（电商好评通常多于差评），此时一致率会因偶然一致率被抬高而虚高，无法反映真实共识；
3. 若后续扩展为多分类或引入"待裁定"类，Kappa 同样适用。

**三、合格阈值**

- **Kappa ≥ 0.75** 为合格（介于"良好"区间内，考虑到情感判断的主观性，不要求达到 0.8 以上）；
- 0.6 ≤ Kappa < 0.75：有条件接收，须针对分歧样本补充规范后复检；
- **Kappa < 0.6：判定不合格**，暂停标注，进入诊断流程。

**四、指标不达标时的诊断步骤**

```
Kappa 低于阈值
   ↓
① 抽样导出全部分歧样本（不能只看汇总数字）
   ↓
② 人工复核分歧样本，判断错误类型：
     · 手册写细能否解决？ 能 → 标准不一致  不能 → 边界模糊
     · 是所有人还是某个人？ 所有人 → 体系缺陷  某个人 → 标注员偏见
   ↓
③ 对症处理：
     标准不一致 → 补充细则与边界案例，重新培训后返工该批次
     边界模糊   → 增设"待裁定"类，建立仲裁机制
     体系缺陷   → 重新设计标签体系（如改多维度标签）
     标注员偏见 → 量化偏差 → 抽样复核 → 沟通确认来源 → 再决定培训或调岗
   ↓
④ 修订后重新抽检，确认 Kappa 回升至阈值以上再恢复批量标注
```

> ⚠️ 第 ③ 步中"标注员偏见"的处理**必须保留前三个诊断动作**。若直接写"对该标注员重新培训"，按评分标准 3.3 要扣分——这是三级实操题刻意设置的筛选点。
