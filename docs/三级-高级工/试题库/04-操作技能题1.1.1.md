**第3题（5分）** 假设该流程运行一段时间后，质检环节发现标注一致率显著偏低，请说明你会如何倒推排查，可能是流程哪一环节的问题。

## 四、参考答案

> ⚠️ 数据统计结果在 **Python 3.11.17 + pandas 2.3.3** 下实测验证，数据由固定随机种子生成，考生复现结果应一致。

### 第1题参考答案

**数据探查**

```python
import pandas as pd
d = pd.read_csv("customer_service_raw_sample.csv")
print(d.shape)
print(d.isna().sum())
print(d["客服工号"].value_counts(dropna=False))
print(d["问题是否解决"].value_counts(dropna=False))
```

**实测发现**（共200条记录）：

| 问题 | 数量/占比 |
|---|---|
| 渠道字段缺失（NaN） | 9条（4.5%） |
| 客服工号为"未知" | 9条（4.5%） |
| 满意度评分缺失 | 40条（20%） |
| "问题是否解决"字段存在是/否/y/Y四种取值混用 | 全量字段格式不统一 |
| 会话内容为空 | 36条（18%） |

**流程设计**

| 环节 | 质量控制点 | 针对本数据的处理方案 |
|---|---|---|
| 采集 | 渠道、工号等关键字段必须在采集时强制校验非空 | 对渠道缺失的9条记录，回溯采集日志补录；若无法补录，标记为"渠道未知"而非留空，避免后续分析时被静默忽略 |
| 清洗 | 统一字段取值枚举；空会话内容过滤 | "问题是否解决"统一映射为标准枚举{是,否}（y→是，Y→是）；空会话内容（36条）若无法补录则标记为无效样本，不进入训练集 |
| 归类 | 按渠道、客服工号分组，核查工号"未知"记录的归属 | 对工号为"未知"的9条记录单独归类，人工核实后补全，不与正常记录混入同一批统计 |
| 标注 | 按既定规范对会话内容做质量/情感标注 | 满意度缺失的40条记录，标注时需明确标记"无原始评分"，不能用默认值填充掩盖缺失事实 |
| 质检 | 多人标注一致性检验+抽样专家复核 | 对格式统一后的"是否解决"字段做逻辑自检：若判定"已解决"但满意度评分<=2，抽样复核是否存在标注矛盾 |

### 第2题参考答案

```python
# 一致性：统一字段取值
d["问题是否解决"] = d["问题是否解决"].replace({"y":"是","Y":"是"})
print(d["问题是否解决"].value_counts())

# 准确性：逻辑冲突自检（示例：已解决但满意度极低，需复核）
suspect = d[(d["问题是否解决"]=="是") & (d["满意度评分"]<=2)]
print("疑似标注矛盾记录数:", len(suspect))   # 实测: 12条

# 可用性：缺失字段显式标记，而非静默填充
d["渠道"] = d["渠道"].fillna("渠道未知")
d["满意度评分_是否缺失"] = d["满意度评分"].isna()
```

**技术手段说明**：
- **准确性**：对字段间的逻辑关系做自动化校验（如本例"已解决"与"低满意度"的矛盾组合），抽样复核异常组合；
- **一致性**：统一字段取值的枚举映射，避免同一含义的多种写法（是/y/Y）分散为不同类别；
- **可用性**：缺失值不做静默填充（如直接填"是"），而是显式标记缺失状态，让下游使用者知道这是"未知"而非"确定的某值"。

### 第3题参考答案

> 质检发现标注一致率低，优先怀疑**归类环节**的标签体系设计是否存在歧义，或**标注规范**本身是否清晰。排查步骤：
> 1. 抽样查看分歧样本（不能只看汇总的一致率数字）；
> 2. 判断分歧属于标准不一致（手册未覆盖的情形）、边界模糊（数据本身存在灰色地带）、标签体系缺陷（分类维度设计重叠）还是标注员偏见（某个人持续偏向）中的哪一种；
> 3. 根据诊断结果倒推至对应环节修正——若是体系缺陷，需回头调整"归类"阶段的标签体系；若是标注员偏见，走量化-复核-沟通-培训的四步流程，而非直接判定"流程失败重做"。

> 💡 本题与课题2-2的诊断方法论完全一致，体现"先看汇总指标、再下钻具体样本"这一通用方法论的跨场景迁移应用。
