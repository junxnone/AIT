## 一、教学目标

### （一）知识目标
1. **能说明六维度检测方法在图像数据场景下的具体化方式**，尤其是"标注↔图像对应关系"这一在结构化数据检测中不会遇到的新环节。
2. **能说明"内部检查"与"交叉核查"的本质区别**：前者只看一份文件本身，后者要对照两份文件（或多方标注结果）。
3. **能说明六维度方法在文本标注数据场景下的具体化方式**，尤其是"同一条记录被多人标注、结果却不一致"这类问题应归入哪个维度。

### （二）技能目标
1. **图像数据集审核**：检测分辨率不一致、损坏/重复图像、类别分布不均衡、标注文件与图像文件**双向**不匹配（标注指向不存在的图像、图像无对应标注）。
2. **文本标注数据审核**：检测标签缺失、标注依据缺失、标签取值是否落在合法定义域内、同一对象被多人标注时结果是否一致。
3. **结构化/销售数据审核**：在课题1-1已检测项基础上，补充唯一性检测（主键是否重复），并能把六维度清单完整套用到任意新数据集，不因换了数据集就漏查某个维度。
4. 能针对三类数据分别产出可交付的质量检测报告，并对发现的每类问题给出处理建议。

### （三）素养目标
1. 建立"**同一套六维度方法要适配不同数据形态**"的迁移意识——换了数据类型，变的是"怎么检测"的具体动作，不变的是"要不要查、查哪六个维度"这把尺子本身。

---

## 二、教学重点与难点

**重点**：标注-图像对应关系核查（标注指向不存在的图像、图像无对应标注两类问题）。

**难点**：学员容易只检查标注文件内部的问题（坐标是否合法），忽视标注文件与图像文件集合之间的**交叉核查**。

---

## 三、学情分析与前置知识

**前置知识**：课题1-1（数据质量六维度与检测方法，使用 `cosmetics_sales.csv` 完成过完整性/准确性/一致性/有效性检测）。

**学情判断**：学员已具备数值/字段层面的检测经验（`isna()`、`value_counts()`、`duplicated()` 等调用熟练），但课题1-1处理的始终是"**一份文件内部**"的问题——所有判断依据都在同一张表里。本课题引入的"图像+标注文件"是学员第一次遇到"**需要对照两份文件才能发现的问题**"，容易把审核思路局限在单一文件内部，这正是本课题难点所在。此外，"同一条数据被多个人标注，结果不一样"这种情况学员此前也未处理过，容易误判其所属维度。

---

## 四、教学方法与手段

1. **分层递进法**：先讲单文件内部检测（坐标合法性，学员已会），再讲跨文件/跨标注员的交叉核查（学员未学过），体现难度递进。
2. **集合运算演示法**：用集合差集运算直观展示"交叉核查"的实现原理，并强调差集运算有**方向性**——两个方向分别对应两类不同问题。
3. **类比迁移法**：把课题1-1的六维度框架原样搬到图像、文本两种新数据形态上，强调"框架不变，具体动作变"。
4. **任务驱动法**：以"产出三类数据的综合质量检测报告"作为本课题终产物，对接实操题四-1。

### 环节一：导入——三份"已验收通过"的数据，能上线吗？（0–10′）

**教师活动**——投影展示（不给结论）：

> "三个项目组分别给我汇报进度：
> 图像标注组说，100张图片都抽查过几眼，没发现问题；
> 文本标注组说，900条标注都填完了，意图分类做完了；
> 销售数据组说，800条订单字段都填齐了。
>
> 三份数据，都'看起来'可以验收上线了。你们觉得能直接用吗？"

**预期学员反应**：多数学员会倾向于"抽查过、填完整了，应该没问题"。

**教师追问**：

> "先记住你的判断。这节课我们会用真实代码把这三份数据**各自的六维度**都过一遍——看看'抽查几眼没问题'和'真的没问题'之间，差得有多远。"

**设计意图**：不直接否定，让"想当然没问题"的直觉判断先被公开表达，后面用真实检测结果逐一推翻，三次反差叠加，冲击力更强。

### 环节二：新授——图像数据六维度审核清单（10–25′）

**讲授脚本**：

> "课题1-1教的六维度方法，不是只能用在表格数据上。换一种数据类型，六个维度还是那六个，只是**具体检查的动作**会变。我们先看图像数据。"

**逐项讲解**（板书 + 对照1-1的定义）：

| 维度 | 在表格数据里怎么查（1-1） | 在图像数据里怎么查（本课题） |
|---|---|---|
| 完整性 | 字段是否为空（`isna()`） | **双向**：标注是否缺对应图像？图像是否缺对应标注？ |
| 有效性 | 数值是否在业务允许范围内 | 坐标是否越界、是否 x2<x1（非法矩形框） |
| 唯一性 | 主键是否重复 | 有无内容完全相同的重复图像 |
| 一致性 | 同一字段写法是否统一 | 标注风格是否统一（下节课题2-2用 Kappa 深入量化，本课题先不展开） |
| 时效性 | 数据是否还在有效期内 | 图像采集时间是否还能代表当前业务场景 |
| 准确性 | 数值是否反映真实情况 | 标注框是否准确框住目标物体 |

**关键讲授点（本课题新增、1-1未遇到过的概念）**：

> "大家注意完整性这一行，我写了**'双向'**两个字。表格数据里，完整性就是查一个字段有没有值，方向只有一个。但图像数据有**两份独立的文件**——标注表和图像文件夹——完整性要分两个方向查：
> 第一，**这条标注，对应的图像还在不在**？
> 第二，**这张图像，有没有被标注过**？
> 这两个方向互相不能替代，查了一个方向，另一个方向的问题照样会被完全漏掉。这就是本课题的核心难点，待会实操一会让你们亲手验证。"

**学员活动**：记录对照表，口头举一个例子说明"为什么图像的完整性检查需要两个方向"。

### 环节三：实操一——标注↔图像双向交叉核查（难点突破，25–65′）

**教师先提问**：

> "标注表 `transport_labels.csv` 有 106 条记录，图像文件夹 `transport_images/` 有 100 张图片。数量不一致，说明了什么？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "标注表比图片多，可能有重复标注" | 追问："一张图可以被标注多次吗？比如一张图里有两辆车，是不是就会产生两条标注记录？"——引导意识到"记录数>图片数"本身不一定是问题，一张图多个目标很正常 |
| "可能有标注指向了已经删除/丢失的图片" | 肯定："对，这是一个方向。还有没有相反的可能？"——引导思考第二个方向 |
| 答不上来第二个方向 | 引导："如果有人漏标了一张图，这张图会不会出现在标注表里？"——引导意识到漏标的图完全不会在标注表里留下任何痕迹 |

**教师收束**：

> "所以差集运算要做**两次，两个方向**：
> `标注表的图像名集合 − 真实图像文件名集合` → 标注指向不存在的图像；
> `真实图像文件名集合 − 标注表的图像名集合` → 图像存在但完全没有被标注。
> 两次运算谁都不能省，省了哪个方向，哪个方向的问题就会被完全漏掉——不是漏查一部分，是**一条都查不出来**。"

**投影代码**（学员照抄运行，核心代码对应实操题四-1的评分点，务必准确）：

```python
import pandas as pd
from pathlib import Path

labels = pd.read_csv("../数据集/transport_labels.csv")
images = set(p.name for p in Path("../数据集/transport_images").glob("*.jpg"))
labeled = set(labels["image_file"])

missing_img = labeled - images        # 方向一：标注指向不存在的图像
no_label    = images - labeled        # 方向二：图像存在但无任何标注

print("标注记录总数:", len(labels))
print("标注指向不存在图像数:", len(missing_img))
print("图像存在但无标注记录数:", len(no_label))

print("坐标非法(x2<x1):", (labels.x2 < labels.x1).sum())
print("坐标越界(y2>480):", (labels.y2 > 480).sum())
print("类别分布:", labels["label"].value_counts().to_dict())
```

**实测结果（已验证，学员结果应一致）**：

```
标注记录总数: 106
标注指向不存在图像数: 4
图像存在但无标注记录数: 3
坐标非法(x2<x1): 3
坐标越界(y2>480): 4
类别分布: {'bus': 66, 'car': 20, 'bicycle': 11, 'truck': 5, 'tram': 4}
```

**教师点评**：

> "这4条'标注指向不存在图像'和3张'图像无标注'，是两类完全不同的问题——前者可能是图像文件丢失、后者可能是标注任务遗漏，处理方式也不一样：前者要核实图像是否真的丢失，若确认丢失就删除对应标注记录；后者要退回标注环节补标。**如果只做了一个方向的检查，另一个方向的问题会被当作'数据集没问题'一直带到模型训练里。**"

**补充代码（完整六维度清单里"分辨率一致性"与"重复图像"两项，用代码把清单补全）**：

```python
from PIL import Image
import hashlib

sizes = set()
hashes = {}
for f in Path("../数据集/transport_images").glob("*.jpg"):
    with Image.open(f) as im:
        sizes.add(im.size)
    h = hashlib.md5(f.read_bytes()).hexdigest()
    hashes.setdefault(h, []).append(f.name)

print("分辨率种类:", sizes)
print("重复图像组数:", sum(1 for v in hashes.values() if len(v) > 1))
```

**实测结果**：分辨率种类 `{(640, 480)}`（只有一种，一致）；重复图像组数 `0`。

**教师强调**：

> "这两项检测结果都是'干净'的——**这不代表检测白做了**。课题1-1最后一个环节就强调过：检测的意义不是找茬证明数据有问题，有问题的要揪出来，没问题的也要确认清楚、写进报告。今天这5项清单（双向交叉核查、坐标合法性、类别分布、分辨率一致性、重复图像），缺一项都不叫'完整检测'，哪怕其中几项结果是零。"

**学员活动**：运行全部代码，把5项检测结果填入自己的检测记录表；两人一组互相说一遍"为什么交叉核查要做两个方向"。

### 环节五：新授+实操二——文本标注数据六维度检测（75–105′）

**讲授脚本**：

> "图像处理的是'两份文件对不对得上'的问题。现在换一种更常见的数据形态——**同一条数据被多个人标注**。这是标注类工作里最常见的场景，六维度框架同样适用，但会冒出一个新问题。"

**场景介绍**：

> "`service_annotations.csv` 记录了某电商客服对话的意图分类标注：300条对话，每条对话分别由3位标注员（A01/A02/A03）独立标注'咨询 / 投诉 / 闲聊'三类意图之一，一共900行记录。"

**投影代码**：

```python
import pandas as pd

d = pd.read_csv("../数据集/service_annotations.csv")
legal = {"咨询", "投诉", "闲聊"}

print("总行数:", len(d), "｜唯一对话数:", d["对话ID"].nunique())
print("意图标签缺失:", d["意图标签"].isna().sum())
print("标注依据缺失:", d["标注依据"].isna().sum())
print("非法取值(不在合法标签集内):",
      (d["意图标签"].notna() & ~d["意图标签"].isin(legal)).sum())

agree = d.groupby("对话ID")["意图标签"].apply(lambda s: s.nunique(dropna=False) == 1)
print("三人标签完全一致的对话数:", agree.sum(), "/", len(agree))
```

**实测结果（已验证）**：

```
总行数: 900 ｜唯一对话数: 300
意图标签缺失: 3
标注依据缺失: 12
非法取值(不在合法标签集内): 6
三人标签完全一致的对话数: 166 / 300
```

**学员活动**：运行代码，把前三行结果对照六维度分类：

| 问题 | 属于哪个维度 |
|---|---|
| 意图标签缺失3条 | |
| 标注依据缺失12条 | |
| 非法取值（"其他""咨询类"）6条 | |

**关键提问（本环节核心）**：

> "最后一行最特殊——'三人标签完全一致的对话只有166个，剩下134个，300条对话里三个人标的不完全一样'。这算六维度里的哪一类问题？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "有效性问题，因为标错了" | 追问："有效性问题的标志是什么？是'值不在合法范围内'。这134个对话里，三个人标的'咨询''投诉''闲聊'哪个不合法？"——引导意识到每个标签单独看都合法，问题不在取值本身 |
| "一致性问题" | 肯定并展开："对。课题1-1学的一致性是'同一字段在不同记录里写法是否统一'（比如S001和s001）。这里是同一个思路的另一种体现——**同一个对象（这条对话）被不同人处理，结果是否统一**。只是对象从'同一个字段'变成了'同一条标注任务'。" |
| 答不上来 | 引导：用1-1的例子类比——"门店编码S001和s001算不算一致性问题？这里是不是同一个逻辑：同一个东西，不同人（或不同记录）写法/判断不统一？" |

**用真实例子展示：这不是随机噪声，而是有规律的系统性差异**

```python
sub = d[d["对话内容"] == "运费是多少"]
print("涉及对话数:", sub["对话ID"].nunique())
print(pd.crosstab(sub["标注员"], sub["意图标签"], dropna=False))
```

**实测结果**：同样一句"运费是多少"，对应55个独立对话。A01在55次里标了51次"咨询"；A02标了53次"咨询"；而A03只标了33次"咨询"、却标了22次"投诉"。

**教师收束**：

> "同一句话，A01、A02几乎都判定为'咨询'，A03却有将近四成判成'投诉'。这不是随手标错几条的偶然波动，**是某个标注员在同一类内容上持续偏向同一个方向**。
>
> 这节课我们先学会用'三人标签是否完全一致'这种最朴素的方式发现一致性问题。下一课题（课题2-2的进阶版，三级会详细讲）会教你怎么用 Kappa 这类指标**量化**这种不一致有多严重，以及怎么判断这到底是标注手册写得不够细，还是某个标注员本身有系统性偏差。今天的任务是——**先学会发现它、能说出它属于六维度里的'一致性'，不要求你现在就诊断根因**。"

**判别口诀（板书）**：

> **只看一条记录本身是否合法 → 内部检测（有效性/完整性）；对照同一个对象被不同人处理的结果是否相同 → 一致性/交叉检测。**

## 七、板书设计

**主板书区**

```
                    六维度方法 → 迁移到不同数据形态
          图像                    文本标注               销售(续1-1)
完整性    标注↔图像(双向!)         标签/依据是否缺失        见1-1
有效性    坐标是否越界/非法         标签是否在定义域内        见1-1
一致性    标注风格(→2-2 Kappa)     同一对话多人标注是否一致   门店编码写法(见1-1)
唯一性    有无重复图像             —                      订单号是否重复

┌──────────── 实测：图像双向交叉核查 ────────────┐
│ 标注指向不存在图像：4条   图像无任何标注：3张    │
│ → 两个方向都要查，漏一个方向，那类问题就是0发现 │
└─────────────────────────────────────────────────┘

┌──────────── 实测：文本一致性 ────────────┐
│ 300个对话 → 166个(55.3%) 三人完全一致     │
│          → 134个(44.7%) 三人标签不一致    │
└───────────────────────────────────────────┘
```

**副板书区（内部检测 vs 交叉核查 判别）**

```
                内部检测                  交叉核查/一致性检测
只看            一份文件/一条记录本身       两份文件，或同一对象的多方结果
本课例子        坐标是否越界                标注表↔图像是否对应
                标签是否在定义域内           同一对话多人标注是否一致

判别口诀：只看一份→内部检测；对照两份(或多人结果)→交叉核查
```
