## 一、教学目标

### （一）知识目标

1. 能说明优化建议书的结构：现状与问题→根因分析→优化方案→预期收益→实施计划与风险。
2. **能说明"合格建议书"与"不合格建议书"的本质区别**——问题是否量化、方案是否具体、指标是否可验证。
3. **能区分一个问题的根因属于"采集环节"还是"处理环节"**，并说明根因所在位置为什么决定了方案的方向（治标还是治本）。
4. 能说明建议书为什么必须包含成本与可行性考量，以及"实施计划与风险"部分具体应包含哪些内容（步骤、涉及角色、潜在风险）。

### （二）技能目标

1. **能针对给定场景撰写完整优化建议书**。
2. 能为建议定义可度量的验证指标。
3. **能针对给定问题判断其根因所在环节，并据此提出分优先级的优化方案**。

### （三）素养目标

1. 建立"书面成果必须经得起'具体怎么做、如何验证、要花多少代价'这三问追问"的职业意识——这是本模块（课题1-1至1-4"数据采集和处理"职业功能的收官课题）承前启后的关键能力：把前三个课题积累的技术判断，转化为能真正推动上级决策的书面成果。

---

## 二、教学重点与难点

### 重点

建议书须包含成本与可行性考量，不能只谈理想方案。

### 难点

学员容易写成"问题罗列+笼统建议"，缺少可验证的验证指标和成本考量，导致建议书无法真正推动落地。这个难点包含两个需要分别突破的子问题：

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| **难点A：验证指标缺失** | 写出"提升数据质量""加强数据治理"这类无法验证达成与否的目标，自己也说不清"做到什么程度算完成" | 用不合格/合格范例直接对比，提炼出"**当前基线数值 → 具体方案 → 目标数值 → 观察周期**"四件套，要求学员对照四件套逐条自查 |
| **难点B：成本与可行性考量缺失** | 只给"理想方案"（如"立即全面重构采集系统"），不说明谁来做、要多久、代价多大，方案听起来正确但无法落地 | 用"治标vs治本"案例对比低成本可行方案与理想化方案，强调建议书要**分阶段、分优先级**，并讲清"实施计划与风险"须包含步骤/角色/风险三要素 |

## 三、学情分析与前置知识

**前置知识**：课题1-1（数据质量六维度检测）、课题1-2（图像/文本/销售数据质量检测实操）、课题1-3（数据处理方法优化）。

**学情判断**：

- 学员已学完课题1-1至1-3，积累了大量检测结果（销售额缺失15%、会员等级缺失18%、门店编码8种大小写混用、SKU003/011/022异常偏离30-45倍等）和处理方法优化经验（中位数填充、门店编码归一化、向量化提速、字段降存），本课题要求把这些发现整合写成一份能实际推动落地的正式书面建议——这是四级阶段第一次正式的书面表达/汇报训练。
- 课题1-3作业已经要求学员写过一份"数据处理方法优化报告"草稿，并在预习环节留下了悬念——"把这份报告升级成正式优化建议书，还需要补充哪些要素"。本课题正是回答这个悬念：建议书比报告草稿多出的部分，恰恰是**根因分析（要区分到采集还是处理环节）、可验证的预期收益、实施计划与风险、成本可行性说明**这四块。
- 部分学员技术判断能力不错（能准确说出哪里有问题、该用哪种处理方法），但写作组织能力偏弱，容易把"我知道该怎么做"和"我能让别人看懂并同意我该怎么做"混为一谈，需要重点关注后者。

---

## 四、教学方法与手段

1. **对比示范法**（核心）：用合格与不合格范例的直接对比，让标准可感知、可模仿；用"治标vs治本""理想vs可行"两组对比强化判断标准。
2. **互评法**：学员互评彼此的建议书草稿，在评价他人的过程中反向巩固自己的判断标准。
3. **任务驱动法**：以"把课题1-3的报告草稿升级为一份可交付的完整优化建议书"作为本课题的终产物，首尾呼应课题1-3预留的悬念。

### 环节一：导入——一份"问题都查清楚却被打回"的建议书（0–10′）

**教师活动** —— 投影展示（不给结论）：

> 学员小李提交的《化妆品门店销售数据采集与处理流程优化建议书》写道：
>
> **现状与问题**：销售额字段缺失率15%（120条），且存在严重长尾分布（均值3689.6，中位数194.0，相差近19倍）；SKU003、SKU011、SKU022销售额均值偏离同类SKU正常水平（800-900元）约30-45倍，疑似数量级录入错误；门店编码存在8种大小写混用写法（应归并为4种）；销售数量字段出现24条负值/零值记录。
>
> **优化建议**：建议统一采集和处理流程规范，加强数据质量管控，提升整体数据可靠性。
>
> 项目负责人看完后把建议书打了回来，批注只有一句话：**"问题你写得比我还清楚，但接下来要做什么，我一个字都看不出来。"**

**提问话术**：

> "大家看一下'现状与问题'这部分——写得怎么样？数字详不详实？"

（预期：学员普遍认可"写得很详细，该查的都查到了"）

> "那为什么还是被打回来了？先记住你此刻的判断，这节课结束前我们回头看小李该怎么把建议书改到能通过。"

**设计意图**：不直接否定，让"问题分析详实=建议书合格"的直觉先被公开认可，后面用"但依然被打回"的结果制造认知冲突——本课题要讲的不是"怎么分析问题"（前三个课题已经讲完），而是"分析完之后，怎么把它写成一份能推动落地的建议"。

---

### 环节二：新授——建议书标准结构（10–25′）

**讲授脚本**：

> "前三节课，大家分别练了'检测问题'（1-1、1-2）和'处理问题'（1-3）。今天要解决的是最后一步：**把这些发现，写成一份别人看了就能照着做的正式建议书。**
>
> 这不是随便写写就行，它有固定的五段结构。"

**板书五段结构**：

```
现状与问题（量化描述） → 根因分析 → 优化方案 → 预期收益（可度量） → 实施计划与风险
```

**逐段说明**：

> "**现状与问题**：这部分大家已经很熟练了，就是1-1、1-2、1-3查出来的那些数字。
>
> **根因分析**：这是很多人会漏掉或写得很敷衍的一环。它的作用不是'再重复一遍现象'，而是说明问题产生的**深层原因**，为后面选什么方案提供依据——这句话很重要，稍后会专门用一节课讲。
>
> **优化方案**：针对根因给出的具体动作。
>
> **预期收益**：方案做完之后，一个可以验证的、量化的结果。
>
> **实施计划与风险**：方案不是写完就结束，还要说清楚怎么推进、谁来做、可能遇到什么阻力。"

**补充考点**：

> "还有一点要记住：建议书不是凭空写出来的，它**通常建立在业务/数据分析发现的问题基础上**——也就是说，没有1-1、1-2、1-3扎实的检测和分析工作，建议书的'现状与问题'这一段根本写不出来。这也是为什么这节课要放在模块的最后一个课题。"

**学员活动**：记录五段结构及各段作用，口头复述一遍。

### 环节三：新授+范例对比——合格vs不合格建议书（难点A突破，25–55′）

**教师先展示不合格范例，不说明问题，让学员自己找茬**：

> "销售数据存在质量问题，建议加强数据治理。"

**提问**：

> "这句话有什么问题？"

**预期学员反应**：多数能感觉到"有点空"，但说不清具体哪里空。

**教师引导**：

> "问题在哪？——'存在质量问题'，什么问题？多严重？'加强数据治理'，具体怎么加强？谁来做？做到什么程度算完成？**三个问题都答不上来，这就是空洞。**"

**再展示合格范例**：

> "销售额字段缺失率15%，当前无填充机制；SKU003/011/022存在疑似数量级错误。建议：①建立销售额缺失自动告警机制，缺失率超过5%时触发人工核查；②对销售额异常高（超过同类SKU均值10倍以上）的记录自动标记待复核。预期将销售额字段的有效性从当前85%提升至98%以上，观察周期1个月。"

**教师点出差异**：

> "问题量化了（缺失率15%），方案具体了（阈值5%、10倍），指标可验证了（85%→98%，1个月周期）。这就是四级要交付的书面成果的标准。"

**提炼四件套**（本环节核心产出，板书）：

```
合格的优化目标 = 当前基线数值 → 具体方案 → 目标数值 → 观察周期
```

**学员活动**：对照四件套，把自己此前的认知补成表格：

| | 不合格 | 合格 |
|---|---|---|
| 当前基线数值 | 无 | 有效性85% |
| 具体方案 | 无（"加强治理"） | 缺失告警机制+异常标记规则 |
| 目标数值 | 无 | 98%以上 |
| 观察周期 | 无 | 1个月 |

**巩固提问**：

> "回头看环节一小李的那份建议书，它的'优化建议'部分，四件套占了几件？"

（预期学员答出"一件都没有"——现状与问题写得再详实，优化建议部分依然是空话）

### 环节四：实操一——给课题1-3报告草稿"打补丁"（55–90′）

**教师指令**：

> "拿出你们课题1-3的作业——那份《数据处理方法优化报告》草稿。里面有三类建议：异常SKU核实修正方案、缺失值填充方法选择理由、门店编码归一化说明。现在请你用环节三学到的四件套，给每一条建议'打补丁'。"

**任务要求（投影+讲义附）**：

> 为报告草稿中的每一条建议，补齐：
> 1. **当前基线数值**（如"销售额字段有效性当前为X%"，复用1-1/1-3已验证的数字，不编造新数字）；
> 2. **具体方案**（不是"建议处理"，要写清楚具体动作和触发条件）；
> 3. **目标数值**（这条建议做完之后，预期达到什么水平）；
> 4. **观察周期**（多久之后回头检查效果）。

**巡回指导要点**：

- 检查学员是否直接复用1-1/1-3的真实检测数字作为基线（如销售额缺失15%、均值3689.6/中位数194.0），而不是凭空编一个数字。
- 检查"门店编码归一化"这条建议是否被学员补出了目标数值——这条建议最容易被写成"已完成"而没有后续可验证的观察指标（如"归一化后门店编码取值数从8种降至4种，观察下一批次新数据是否仍出现超过4种取值"）。

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| 把"目标数值"写成"质量变好" | 追问："'变好'怎么验证？参照环节三的范例，目标必须是一个具体数字或具体状态，比如'异常SKU数量从3个降为0个'。" |
| 不知道"观察周期"该写多久 | 引导："观察周期取决于数据更新频率——如果数据按月汇总，至少观察1个月；如果按周更新，1-2周就能看到效果。没有标准答案，但必须写一个具体时长，不能空着。" |

**学员活动**：补齐四件套，形成升级版建议清单。

### 环节六：新授——根因分析：采集环节 vs 处理环节（难点突破二，100–130′）

**教师提问**：

> "还记得1-3里，我们怎么处理门店编码大小写混用的问题的吗？"

（学员：用 `.str.upper()` 做归一化，8种取值合并为4种）

**关键追问**：

> "如果这批数据处理完、报表也交上去了，明天系统又导入一批新的销售记录，门店编码还会不会再次出现大小写混用？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "会，因为问题没有真正解决" | 肯定："对。1-3的归一化只是把**已经产生的**脏数据清理了一遍，新数据进来，脏数据还会再产生一遍。这叫**治标**——问题在处理环节被动补救，不会消失，只会反复出现，每次都要重新清洗一次。" |
| "不会，归一化之后就统一了" | 追问："归一化代码改的是哪一步？是采集的时候就不让人输入小写，还是数据到手之后再统一转换？"——引导意识到归一化发生在数据已经产生之后 |

**板书核心句**：

> **处理环节能解决"已经脏了的数据"，解决不了"为什么会脏"。**

**追问引出治本方案**：

> "那怎么才能让门店编码**不再**出现大小写混用？"

（引导学员想到：从采集端下手——录入界面改成下拉选择，或由系统自动生成编码，不允许自由文本输入）

**对比表（板书+讲义）**：

| | 处理环节优化（治标） | 采集环节优化（治本） |
|---|---|---|
| 动作 | 每次拿到数据后做清洗（如 `.str.upper()`） | 从录入端改为下拉选择/系统校验，禁止自由文本输入 |
| 效果 | 已产生的问题被清理，但新数据仍会复发 | 问题从源头被杜绝，后续数据天然规范 |
| 成本 | 看似每次成本很低，但长期重复执行、累积维护成本高 | 有一次性改造成本，但一劳永逸 |

**点明根因分析的价值（呼应知识目标）**：

> "这就是'根因分析'存在的意义——**它不是重复现象，而是回答'这个问题到底出在哪个环节'，从而决定方案该往哪个方向使劲。** 不做根因分析、拿到问题直接给处理方案，很容易把力气一直花在'每次都要重新做一遍'的治标上，却从没有真正碰过源头。"

**判别口诀**（板书）：

> **下一批新数据还会不会复发同样的问题？会 → 到采集环节找根因。不会 → 处理环节内部解决就够了。**

**学员活动**：讨论课题1-1/1-2中发现的其他问题（销售额缺失15%、会员等级缺失18%、销售数量负值24条、transport图像标注指向不存在图像4条），逐条判断其根因更可能在采集环节还是处理环节。

**教师巡回要点**：对"销售额缺失15%"这条，引导学员发现：如果缺失是因为门店收银系统未强制要求录入销售额字段，根因在**采集环节**（需在收银系统加必填校验）；如果缺失是因为数据汇总脚本在合并多个来源时丢失了部分字段，根因则在**处理环节**（需修复合并逻辑）——同一个现象，根因可能不同，必须具体排查，不能套公式。

### 环节七：新授——成本可行性与实施计划（难点B突破，130–150′）

**教师提问**：

> "既然采集环节能治本，那是不是建议书应该直接写：'立即把采集系统全面推倒重做，所有字段都加上强校验'？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "合理，一步到位最彻底" | 追问："这个方案要花多少成本？由谁来改造——IT部门要排期多久？改造期间门店收银系统能不能正常使用？如果答不上来，这个方案和'加强数据治理'有本质区别吗？" |
| "不合理，成本和影响范围没考虑" | 肯定："对。治本的方向是对的，但**怎么治本、分几步治本**，才是建议书真正要写清楚的内容。" |

**板书核心句**：

> **理想方案 ≠ 可行方案。理想方案只回答"该怎么做最彻底"，可行方案还要回答"用多大代价、花多久时间、谁来推进"。**

**正例——分阶段方案**：

> "更合格的写法是分优先级：
> ①**优先**对影响范围最大、改动成本最低的门店编码字段，先在前端加一个下拉选择框（改动小，1-2周可上线）；
> ②销售额/销售数量的自动化异常检测规则，作为**后续阶段**，先在异常率最高的门店试点，验证有效后再全面推广。
>
> 这样写，既保住了'治本'的方向，又给出了对方能接受、能落地的节奏。"

**展开"实施计划与风险"三要素**：

> "'实施计划与风险'这一段，很多人直接漏掉或者只写一句'尽快实施'。合格的写法必须包含三样东西：
>
> **步骤**——先做什么、后做什么（就像刚才的①②两步）；
> **涉及角色**——谁来改、谁来验收（比如'IT部门负责前端改造，数据组负责验收新采集数据的合规率'）；
> **潜在风险**——可能遇到什么阻力（比如'采集系统改造涉及IT部门排期，短期内可能增加门店录入操作步骤，一线人员或有抵触，需提前培训说明'）。
>
> 这三样一样都不写，'实施计划'就是一句空话，和没写没有区别。"

**学员活动**：针对环节六讨论出的"门店编码治本方案"，补充成本/可行性说明和实施计划三要素。

### 环节八：实操二——撰写完整优化建议书（终产物，150–200′）

**任务书**（投影+讲义附）：

> 请你作为四级训练师，基于课题1-1~1-3对 `cosmetics_sales.csv` 的质量检测与处理方法优化发现，撰写一份完整的《化妆品门店销售数据采集与处理流程优化建议书》。

**建议书必备要素**（教师给模板，学员填充）：

```
一、背景说明（本建议书基于课题1-1~1-3对cosmetics_sales.csv的质量检测与处理方法优化发现撰写）
二、现状与问题（量化，逐条列出，可直接复用1-1/1-3已验证数据）
三、根因分析（逐条问题标注根因所在环节：采集环节 / 处理环节，并简述根因）
四、优化方案（按环节分类列出，并标注优先级：立即可做 / 短期 / 中长期）
五、预期收益（每条方案对应"当前基线 → 目标数值 → 观察周期"四件套）
六、实施计划与风险（步骤、涉及角色、潜在风险）
七、成本与可行性说明
```

**教师点拨要点**：

> "三个地方最容易写得不合格：
>
> **第一，根因分析只写现象，不标环节。** 写'销售额缺失15%'不够，要接着写'根因：门店收银系统未强制要求录入销售额字段，属采集环节问题'。
>
> **第二，优化方案全部堆在处理环节。** 环节六讲过，这是治标不治本。看看你的方案清单里，有没有至少一条是指向采集源头的。
>
> **第三，预期收益没有数字。** 每条方案后面必须跟着四件套，不能写'质量会提升'这种话。"

**巡回指导**：重点检查学员是否区分了根因环节、是否至少有一条采集环节的方案、是否每条方案都有可验证的预期收益——这三项是区分"写了"和"写合格"的关键项。

## 七、板书设计

**主板书区**

```
                    优化建议书五段结构
现状与问题(量化) → 根因分析(采集/处理) → 优化方案(分优先级) → 预期收益(可度量) → 实施计划与风险

┌──────────────── "打回"案例 ────────────────┐
│ 问题写清楚了：缺失15%／8种大小写／偏离30-45倍 │
│ 建议写空了：  "加强数据治理"                  │
│ → 问题分析详实 ≠ 建议书合格                   │
└────────────────────────────────────────────────┘

合格目标四件套：当前基线 → 具体方案 → 目标数值 → 观察周期
示例：有效性 85% → 建立告警+复核规则 → 98%以上 → 观察1个月
```

**副板书区（治标 vs 治本 / 理想 vs 可行）**

```
                处理环节优化(治标)        采集环节优化(治本)
动作            每次用数据前清洗           从录入端校验/改下拉选择
效果            问题反复出现               一次性消除，后续数据天然规范
成本            看似为0，长期重复消耗大    一次性改造成本，一劳永逸

判别口诀：
  下一批新数据还会不会复发？  会→找采集环节根因   不会→处理环节内解决
  理想方案≠可行方案：         理想方向 + 分阶段 + 谁来做/多久/什么风险 = 可行方案
```
