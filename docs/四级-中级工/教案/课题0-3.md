## 四、教学方法与手段

1. **演示+跟做法**：每个新API先演示，学员当场跟着敲代码，不是听完理论再统一练习。
2. **决策树讲解法**：把"缺失值该怎么处理""重复值该怎么处理"做成判断树，而不是罗列孤立的方法。

4. **任务驱动法**：以"独立完成一份端到端数据清洗脚本"作为本课题技能目标的落地检验。

### 环节一：导入——一个预测钩子（0–10′）

**教师活动** —— 投影展示真实数据前几行（已验证，`cosmetics_sales.csv` 前3行）：

```
     订单号  门店编码     SKU 会员等级  销售数量      销售额        销售日期
0  CS000000  S002  SKU028   普通     5  1019.28  2026-03-18
1  CS000001  S002  SKU019   黄金     1      NaN  2026-02-15
2  CS000002  s001  SKU027   白银     3   220.97  2026-02-21
```

**提问话术**：

> "这是我们本课题要用的真实销售数据，字段齐全，表格也规整。如果现在要你把这批数据直接拿去做销售预测建模，你会说'能用'还是'不能用'？花十五秒，写下你的判断。"

（预期：多数学员观察不出问题，倾向于"看起来能用"）

> "好，先记住这个判断。这节课我们会亲手跑代码，看看这批'看起来没问题'的数据里到底藏了什么——提示一下，光是刚才这三行里就已经出现了两个问题，你看出来了吗？"

**设计意图**：不直接指出"第2行销售额是NaN、第3行门店编码是小写s001"，留一个悬念，驱动学员在后续实操中带着目的去检测，而不是被动看演示。

### 环节二：三大范式回顾+训练/验证/测试集（10–40′）

**讲授脚本**：

> "判断一个AI任务属于哪种学习范式，不要去记任务名字，要去问一句话：**这个任务有没有预先固定的标准答案？**
>
> 有标准答案 → **监督学习**，比如给图片打'猫/狗'标签去训练分类模型；
> 没有标准答案，但数据本身有结构可以被发现 → **无监督学习**，比如不告诉算法任何分类标准，让它自己把用户分成几群；
> 没有标准答案，但有一个不断反馈的信号（奖励/惩罚）→ **强化学习**，比如推荐系统根据用户是否点击、是否停留来动态调整推荐策略。"

**板书判断公式**：

> 有标准答案→监督；无标准答案但有数据结构→无监督；无标准答案但有反馈信号→强化。

**学员活动**：对3个场景现场判断范式（如"自动驾驶车辆根据路况试错调整转向策略""给10万条客服对话按相似度自动分组""给带标签的商品图片训练分类器"）。

**讲授脚本（训练/验证/测试集）**：

> "再看另一个知识点：为什么一个模型项目要切出训练集、验证集、测试集三份，而不是一份数据反复用？
>
> **训练集**用于模型学习参数；**验证集**用于调参和判断该不该提前停止训练（避免过拟合）；**测试集**用于最终评估模型的真实效果。"

**关键追问（为什么不能混用）**：

> "如果你拿测试集的反馈去调整模型参数，会发生什么？"

（引导学员意识到：测试集一旦参与了"调整"这个动作，它就变相参与了训练过程，之后再用它来评估，得到的分数只是"模型记住了测试集"的结果，不能反映模型在真正未见过数据上的表现——这和开头导入环节"看起来没问题"的陷阱是同一类问题：**看到的好结果，可能是假象。**）

**设计意图**：把本环节的抽象规则落回到"为什么"层面，并和导入环节的悬念形成呼应，而不是孤立的知识点罗列。

**逐行拆解示范**（投影）：

**学员活动**：教师随机挑3-4位学员，指着某一行代码问"这行在做什么"，要求用大白话复述（不要求说出函数名）。

| 学员反应 | 教师应对 |

### 环节六：新授——numpy基础（numpy是pandas的底层引擎）（95–115′）

**讲授脚本**：

> "课题名字里还有一个'numpy'，我们现在正式认识它。
>
> 你可能会问：我一直在用pandas，为什么还要学numpy？因为**pandas的Series，本质上就是一个带了索引标签的numpy数组**。你每次对一整列做 `df['销售额'] * 1.1` 这种整列运算，背后真正干活的就是numpy。"

**投影代码**：

```python
import numpy as np

arr = np.array([1, 2, 3, 4, 5])
print(arr * 2)                     # 向量化运算：整个数组同时乘2，不需要写for循环
print(arr.mean(), arr.sum())       # 常用统计函数

# 对比：pandas整列运算背后就是numpy在工作
print((df["销售额"] * 1.1).head())  # 整列打九折后再涨价10%的场景，不需要逐行写循环
```

**讲授脚本（为什么要用向量化）**：

> "如果不用numpy/pandas的这种'整体运算'方式，而是写一个 `for` 循环去逐条处理80万条、800万条数据，Python解释器要一行行地转换和执行，开销很大；而向量化运算是把整批数据一次性交给底层更高效的实现去处理。**数据量越大，这个差距越明显。** 这也是为什么pandas能处理几十万、上百万行数据还能跑得动的根本原因。"

**学员活动**：在Notebook里对 `df["销售数量"]` 做一次向量化运算（如 `df["销售数量"] * 10` 模拟"件数换算成某单位"），观察输出是整列同时变化，而不是一条条变。

**板书核心句**：

> **pandas的Series = 带索引的numpy数组；向量化运算用整体替代逐条循环。**

**设计意图**：不孤立地教numpy语法，而是直接点明它与pandas的关系和存在的意义，避免学员觉得"学了pandas为什么还要学numpy"的割裂感。

### 环节七：实操一——缺失值/重复值/异常值处理决策训练（难点二突破，115–175′）

**教师指令**：

> "现在回到开头的悬念。我们正式'体检'这批数据，看看到底藏了哪些问题。"

**投影代码（学员照抄运行）**：

```python
import pandas as pd
d = pd.read_csv("../数据集/cosmetics_sales.csv")

print("销售额缺失:", d["销售额"].isna().sum())
print("会员等级缺失:", d["会员等级"].isna().sum())
print("整行重复:", d.duplicated().sum())
print("订单号重复:", d["订单号"].duplicated().sum())
print("销售数量<=0的条数:", (d["销售数量"] <= 0).sum())
print("销售数量 最小值/最大值:", d["销售数量"].min(), d["销售数量"].max())
print("均值:", d["销售额"].mean().round(1), " 中位数:", d["销售额"].median())
```

**实测结果（已验证，学员结果应完全一致）**：

```
销售额缺失: 120           （占比15%）
会员等级缺失: 144         （占比18%）
整行重复: 0
订单号重复: 0
销售数量<=0的条数: 24
销售数量 最小值/最大值: -7 7
均值: 3689.6  中位数: 194.0
```

**教师提问（缺失值决策）**：

> "销售额有15%缺失，第一反应是什么？"

**预期学员反应**：直接说"用均值填充"。

**教师追问**：

> "填均值之前，有没有先看一眼这个字段的分布？均值3689.6，中位数只有194.0——差了将近19倍，这说明什么？数据是均匀分布的吗？"

**引导学员得出决策路径**：

> "正确的决策顺序是：① 能不能补录（联系原始数据源核实）？② 不能补录，这批缺失数据占比大不大、删除影响大不大？③ 如果必须填充，看分布形态——**均值和中位数差异这么大，就是长尾分布的警报信号**（少数大额订单把均值拉得很高），长尾分布用中位数更稳健，均值会被极端值带偏。**这是一棵决策树，不是一个万能公式。**"

**教师提问（重复值）**：

> "再看重复值：整行重复0条，订单号重复也是0条。这说明什么？是不是就意味着'重复值'这个知识点在这份数据里不用学了？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "这份数据没有重复，所以不用管" | 纠正："检测的意义不是'一定要找到问题'，而是**系统性地把每一类都查一遍，有问题处理、没问题也要在报告里写清楚'已检测，无重复'**，不能因为这次没发现就跳过这一步" |
| 能说出"下次遇到有重复的数据，应该用 `drop_duplicates()`" | 肯定，并补充示范：`pd.DataFrame({"a":[1,1,2]}).duplicated()` 这种最小示例，确认语法记忆准确 |

**教师提问（异常值，会员等级该怎么处理？与销售额处理方式一样吗？）**：

> "会员等级缺失144条，占比18%，比销售额缺失还多。能不能也用'均值/中位数'的思路处理？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "也用中位数/众数填充" | 追问："会员等级是'普通/白银/黄金/铂金'这种类别，不是数字，中位数怎么算？"——引导意识到类别型字段不能直接套用数值型的填充逻辑 |
| 意识到类别字段不能用均值/中位数 | 肯定并引导："类别型缺失，常见做法是归入一个明确的新类别（如'未知/未注册'），或者结合业务规则判断——比如这批缺失是不是'未注册会员'本来就没有等级，那就不是真正的'缺失'，而是业务规则决定的正常空值" |

**现场验证**：学员在练习数据上分别计算均值和中位数，对比19倍的差异，直观感受决策的必要性；并尝试对 `会员等级` 做 `value_counts(dropna=False)`，观察NaN单独成一类的现象。

**教师总结话术**：

> "这节课最该记住的一课：**看到均值和中位数差异很大，就是一个警报信号**，提示这个字段可能是长尾分布，不能无脑套用均值填充的默认做法；而类别型字段的缺失，连'均值/中位数'这个选项都不存在，要先判断它是不是业务规则导致的正常空值。"

### 环节九：新授+演示——数据类型转换与字符串处理（205–230′）

**讲授脚本**：

> "刚才留了两个疑问：一是门店编码大小写不统一导致分组被拆散；二是环节四里 `df['门店编码']=='S001'` 筛选不全。现在一次性解决。"

**投影代码（字符串处理修复大小写）**：

```python
d2 = d.copy()
d2["门店编码"] = d2["门店编码"].str.upper()   # 统一转大写

print("标准化前唯一值数:", d["门店编码"].nunique())
print("标准化后唯一值数:", d2["门店编码"].nunique())
```

**实测结果（已验证）**：

```
标准化前唯一值数: 8
标准化后唯一值数: 4
```

**教师话术**：

> "一行 `.str.upper()`，8种取值收敛成4种，真正对应的4家门店。再回头做 `groupby`，就只剩4行，和业务常识一致了。"

**投影代码（日期类型转换）**：

```python
print(d2["销售日期"].dtype)              # 转换前：object（字符串）
d2["销售日期"] = pd.to_datetime(d2["销售日期"])
print(d2["销售日期"].dtype)              # 转换后：datetime64
print(d2["销售日期"].dt.month.value_counts().sort_index())   # 按月统计
```

**教师讲授脚本**：

> "`销售日期` 这一列，读进来的时候是字符串类型（`object`），看起来是日期，但pandas不知道它是日期——你没法对字符串做'晚于某天''按月汇总'这类操作。`pd.to_datetime` 把它转换成真正的日期类型后，才能用 `.dt.month` 这类日期专属功能。**类型不对，很多看起来该有的功能用不了**，这是数据类型转换存在的意义。"

**学员活动**：跟做以上两段代码，确认自己的输出和投影一致；用标准化后的 `门店编码` 重新做一次 `groupby`，对比和环节八的结果有什么不同。

**板书核心句**：

> **大小写/格式不统一，机器眼里就是"不同的类别"；类型不对，对应的功能就用不了。**

### 环节十一：分组代码走查与常见错误现场纠错（260–290′）

**教师活动**：投影展示3段预先准备的典型错误代码，组织学员分组诊断问题所在。

**典型错误代码**：

```python
# 片段A
df_vip = df[df["会员等级"] == "黄金"]
df_vip["销售额打折"] = df_vip["销售额"] * 0.9   # 报 SettingWithCopyWarning

# 片段B
print(df[df["销售额"] == "NaN"].shape)           # 永远是(0, 7)，没有正确识别缺失值

# 片段C
df_s001 = df[df["门店编码"] == "s001"]            # 漏掉了大写的S001，结果不完整但不报错
```

**预期诊断点**：

| 片段 | 应诊断出的问题 |
|---|---|
| A | 在筛选出来的子表上直接赋值新列，没有先 `.copy()`，容易引发未定义行为；正确写法是 `df_vip = df[df["会员等级"]=="黄金"].copy()` |
| B | 用字符串 `"NaN"` 去匹配缺失值是错误的，缺失值在pandas里不是字符串"NaN"，应该用 `isna()` 判断 |
| C | 没有先用 `.str.upper()` 统一大小写就直接按固定字符串筛选，悄悄漏掉了一半数据，**这类错误最危险——不报错，但结果是错的** |

**学员活动**：分组讨论，每组派代表指出至少1处问题并给出修改建议。

**教师点评要点**：

> "片段C最值得警惕——**它不报错，只是结果悄悄错了**。代码报错至少你知道要修，结果'看起来正常但其实漏了数据'，往往要等到后续分析结果离谱才会被发现。这也是为什么我们反复强调'体检三件套'和'先统一格式再筛选'的原因。"

┌───────── 门店编码标准化前后 ─────────┐
│ 标准化前：8种取值（大小写混用）       │
│ 标准化后：4种取值 → S001~S004         │
