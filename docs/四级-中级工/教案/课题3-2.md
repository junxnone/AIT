# 教案 · 课题 3-2：基于数据分析的系统功能优化

| 项目 | 内容 |
|---|---|
| 所属等级 | 四级 / 中级工 |
| 对应国标 | 职业功能3 智能系统运维 · 3.2 智能系统功能优化 |
| 学时 | **2 学时**（理论 1 + 实操 1，共 120 min） |
| 授课类型 | 理论与研讨一体化 |
| 教学场地 | 计算机机房 |

---

## 一、教学目标

### （一）知识目标
1. **能说明从使用数据中发现功能问题的分析路径**（埋点指标→异常定位→分群/条件下钻→根因假设→验证），并说出其中最容易被跳过的一步。

### （二）技能目标
1. **能根据数据分析结果对智能系统功能提出优化方案**。
2. **能区分"模型问题"与"产品/流程问题"**，并说出判别依据而非凭直觉下结论。

### （三）素养目标
1. 建立"**先对比、再归因**"的诊断习惯——不把"看起来像是模型的问题"当作终点，养成用数据交叉验证假设的职业态度，避免在错误方向上消耗训练资源。

---

## 二、教学重点与难点

### 重点
1. 区分"识别率低"背后的真实原因——可能是模型本身判别能力不足，也可能是采集端环境或产品/流程设计导致（如交互引导不清晰、采集环境噪声大）。
2. 对比不同条件下的表现差异，是判定问题层面最直接可靠的方法。

### 难点

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| 把所有效果不理想都归因于"模型不够好" | 学员习惯性把所有效果不理想都归因于模型不够好，不去排查产品/流程层面的因素（如用户引导不清晰、采集环境噪声大等），看到"识别率低"就直接脱口而出"重新训练模型" | 用语音助手嘈杂环境案例制造认知冲突：先让学员公开给出"重新训练模型"的直觉判断，再引导其亲自设计"安静 vs 嘈杂"的对比实验，用实验结果倒逼其意识到——不对比就下结论，等于把预算和时间投入到一个本身没有问题的方向上 |

---

## 三、学情分析与前置知识

**前置知识**：课题 3-1（智能系统维护与场景部署）。

**学情判断**：

- 学员已学完课题 3-1，具备基本的系统运维知识，但"识别率低""点击率低"这类效果问题，习惯性地被有技术背景的学员归因为"模型不行"——这是技术背景学员的常见思维定式，需要用真实案例扭转。
- 本课题是**四级 13 个课题的收官课题**，学员此前已在课题 1-1（均值 vs 中位数该用哪个）、课题 2-3（标注差异该归因体系还是个人）等多处练习过"**先诊断、再处方**"的方法论。本课题是这条主线在"智能系统运维"场域里的最后一次应用——不是全新的知识，而是同一套判断习惯换了一个新场景。
- 由于只有 2 学时，内容密度不能照搬 4 学时课题的节奏：**不铺开讲多个子知识点，而是把一个判别方法讲透、用两个真实场景反复验证其迁移能力**。

---

## 四、教学方法与手段

1. **认知冲突法**（核心）：先让学员公开给出误判方向，再用对比实验结果推翻直觉。
2. **案例对比法**：用语音助手环境案例与车载场景接口排查案例并置，归纳出同一条判别逻辑的迁移性，防止学员把方法论当成"只适用于这一个案例"的孤立知识。
3. **任务驱动法**：以"为给定使用数据写出一份优化方案"作为本课题的产出物。

## 六、教学过程设计

### 总表

|---|---|---|---|---|
| 0–15′ | 导入：识别率低，锅在谁身上？ | 展示语音助手嘈杂环境案例，提问"你的第一反应是什么" | 判断并说明理由 | 暴露"效果差就怪模型"的直觉误区，制造悬念 |

### 环节一：导入（0–15′）

**教师活动** —— 投影展示（不给结论）：

> "某智能音箱厂商收到大量用户反馈：'语音助手经常听不懂我说话'。客服统计后发现，这类反馈高度集中在一种场景——用户在厨房做饭、或者开着电视的时候提问。如果这份报告摆在你面前，你的第一反应是什么？"

**预期学员反应**：多数学员会说"模型识别能力不足，应该重新训练模型/扩充训练数据"。

**教师话术**：

> "先记住你刚才的判断，不用告诉我对不对。这节课要做的事，就是回头检验这个判断到底靠不靠谱。"

**板书核心句**：

> "识别率低 = 模型不行"？——先别急着下结论。

**设计意图**：不直接否定，让"看到效果差就怪模型"的直觉判断先被公开表达，后面的推翻才有冲击力。

---

### 环节二：新授——分析路径（15–35′）

**讲授脚本**：

> "要回答'问题到底出在哪'，不能凭感觉，要有一套系统的分析路径。"

**板书五步**：

```
埋点指标 → 异常定位 → 分群/条件下钻 → 根因假设 → 验证
```

**逐步讲解话术**：

> "**埋点指标**：系统后台记录的使用数据，比如识别成功率、响应时长、用户重复提问次数——这是发现问题的'眼睛'，没有埋点，问题发生了你都不知道。
>
> **异常定位**：从总体指标里找出'哪里不对劲'。比如整体识别率 83%，看起来还行，但这是个平均数，背后可能掩盖了某个场景下只有四成的严重问题。
>
> **分群/条件下钻**：这是最关键的一步——把总体数据按不同条件（环境、设备、用户群体、时间段等）切开来看，比较各组表现差异。
>
> **根因假设**：看到条件差异后，提出'为什么会这样'的假设。
>
> **验证**：用进一步的数据或实验验证假设是否成立，而不是假设一提出就直接当结论用。"

**提问**：

> "这五步里，哪一步最容易被人跳过？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "分群下钻和验证都容易被跳过" | 肯定并追问："具体是怎么跳的？是看到'识别率低'就直接假设'模型不行'，然后直接去重新训练，对吗？" |
| 答不上来 | 引导："如果你是客服，收到'听不懂我说话'的反馈，最快但最懒的做法是什么？是不是直接说'模型不行'，然后把锅甩给训练团队？" |

**教师小结**：

> "这正是我们接下来要解决的典型错误——跳过'分群下钻'和'验证'，直接把'模型问题'当成默认答案。记住这五步，下面我们就回到开头那个案例，看看跳步会导致什么后果。"

**学员活动**：记录五步法，口头说出"如果是自己常用的某个 App（外卖/视频软件），这个分析路径可以怎么套"的一个例子。

---

### 环节三：难点突破——模型问题 vs 产品/流程问题（35–60′）

**讲授脚本（回到案例）**：

> "回到开头那个语音助手案例。你的第一反应可能是'模型不行，重新训练'。按照刚讲的五步法，你漏掉了哪一步？"

**预期学员反应与教师应对**：

| 学员反应 | 教师应对 |
|---|---|
| "漏了验证，应该先看看效果" | 追问："具体怎么验证？你会去对比什么？"——引导到"对比不同条件下的表现" |
| "漏了分群下钻，应该分场景看" | 肯定："对，这正是关键。继续往下想——分哪个条件？" |
| 答不上来 | 引导："厨房做饭、开着电视的时候，和安静书房里问问题，有什么环境差异？"——提示"噪声"这个变量 |

**揭示判断路径**：

> "假设你真的去做了这个对比，发现：**安静环境下识别率表现正常，只有在嘈杂环境下才明显下降**。这说明了什么？
>
> 说明模型本身的判别能力没有问题——同样的模型，换一个安静的环境表现就恢复正常了。问题出在**噪声干扰了输入信号的质量**，这是采集端/产品层面的问题，不是模型能力的问题。这种情况下应该优先考虑**产品层面的降噪硬件或算法前处理**，而不是直接归咎于模型、去重新训练模型。"

**学员活动**：填写对比表

| | 安静环境 | 嘈杂环境 |
|---|---|---|
| 识别率表现 | 正常 | 显著下降 |
| 结论 | | |

**为什么这个判别方法成立？——机制讲解**：

> "为什么'对比不同条件下的表现'能把问题分开？因为模型的判别能力是训练完成之后就固定下来的一套参数，它不会因为环境变了就自己变聪明或变笨。如果同一个模型在干净的输入下表现正常、在带噪声的输入下表现骤降，变化的是**输入信号的质量**，不是模型的能力本身。反过来，如果模型在所有条件下表现都不好——包括最理想的安静环境——那就排除了'外部条件干扰'这个变量，说明问题确实出在模型本身的判别能力上。"

**判别口诀**（板书）：

> **条件变了，表现跟着大幅变 → 产品/流程问题；条件怎么变，表现都一样差 → 模型问题。**

**如果误判了，后果是什么？**：

> "如果把这类问题误判成模型问题，去重新训练一个本身没有缺陷的模型会怎样？训练要消耗算力和时间，而噪声是物理层面的输入质量问题，模型训练解决不了'麦克风采集到的信号里混了多少噪声'这件事。于是投入大量资源，上线后嘈杂环境下的识别率可能几乎没有改善，真正该做的降噪工作还摆在原地，错过了本该优先处理的窗口期。"

**第二个真实场景——强化迁移**：

> "换一个场景：某语音识别系统从安静的客服场景扩展部署到车载场景，上线后发现接口响应经常超时。你的第一反应会不会也是'模型变慢了，要换个更快的模型'？
>
> 参考排查顺序是——先查**网络时延**（车载网络本身不如室内稳定），再查**并发量**是否超出设计容量，再查**数据接口与采样格式**是否匹配，最后才轮到模型本身的推理耗时。这和识别率的例子是同一个逻辑：**先看外部环境/接口因素，最后才怀疑模型。**"
>
> （该案例对应试题库操作技能题"四-6"第 2 题，供学员课后对照参考答案）

**教师总结话术**：

> "这是一个简单但极容易被忽视的判别方法——对比不同条件下的表现差异。如果模型在所有条件下表现都不好，才是真正的模型问题；如果只在特定条件下表现差，往往是产品/流程问题。**做判断前，先做对比，不要直接归因。**"

**板书核心句**：对比不同条件下的表现差异，定位问题层面。

---

### 环节四：实操——给定使用数据，提优化方案（60–95′）

**任务书**（投影 + 讲义附）：

> 某推荐系统的埋点数据显示，**老用户群体的点击率显著高于新用户群体，且这个差距在近三个月持续稳定存在**。产品经理认为"模型对新用户的理解能力不够，建议扩大模型规模重新训练"。
>
> 请你：
> 1. 运用本课的五步分析路径，说明你会如何验证这个判断是否成立；
> 2. 判断这更可能是模型问题还是产品/流程问题，并说明判别依据；
> 3. 给出具体的优化方案。

**方案必备要素**（教师给模板，学员填充）：

```
一、问题现象描述（用数据/现象，不用模糊结论）
二、分群/下钻对比设计（你会对比哪些条件）
三、根因判断（模型 or 产品/流程，并给出判别依据）
四、优化方案（具体动作，不是"优化一下"这种空话）
五、预期验证方式（方案上线后怎么确认是否有效）
```

**巡回指导要点**：

- 检查学员是否只给"方案"而跳过"判别依据"这一步——这是实操评分最常见的失分点。
- 对直接下结论"模型不行、扩大规模"的学员，追问："你怎么验证这不是新用户缺少历史行为数据导致的问题，而是模型容量真的不够？"
- 提醒学员注意：这个案例里"新老用户"是一个**自然存在的分群条件**，和前面"安静/嘈杂"是同一类判别逻辑——先比较分群表现，再谈根因。

**参考要点**（用于点评对照，不提前展示给学员）：

> 这更可能是**产品/流程问题**——新用户没有历史行为数据，不是模型判别能力不行，而是"用什么策略给没有数据的用户做推荐"这个流程设计问题（即"冷启动"问题）。优化方向包括：针对新用户设计基于内容/热门榜单的过渡期推荐策略、引入少量显式偏好收集（如新手引导问卷）、给新用户更快积累有效反馈的曝光策略等。

**点评**（穿插在 60–95′ 内，约 10 分钟）：抽样投影 1–2 份方案，重点点评"判别依据是否写清楚"，而非只看方案本身是否合理。

---

### 环节五：变式迁移——第二场景快速判断（95–110′）

**教师指令**：

> "最后再来一个快速判断。某客服对话情绪识别系统，在**金融行业客户**里的误判率明显高于**零售行业客户**。这是模型问题还是产品/流程问题？用五步法快速过一遍：你会分群对比什么条件？"

**学员活动**：小组讨论 2 分钟，抽 2–3 组口头回答。

**预期讨论方向与教师引导**：

> 这个案例容易被学员套用"条件变了就是产品问题"的口诀，直接答"产品/流程问题"。教师需要在此处补一层区分：
>
> "注意，不是所有'分群表现有差异'都指向产品/流程问题，还要看**差异背后的变量本质**。前两个案例（噪声、网络时延）的差异来自**外部环境/接口干扰**，模型接收到的'真实信号'被破坏了；而这个案例里，金融行业客户用词专业、术语密集，如果训练数据里金融场景的对话样本覆盖不足，模型本身就没学过这类表达方式——这种差异来自**训练数据对该场景的覆盖程度**，依然要归为模型（或训练数据）问题，而不是产品/流程问题。"

**板书核心句**：

> **判别口诀要补一句**：条件差异来自外部环境或接口 → 产品/流程问题；条件差异来自训练数据对该场景的覆盖程度 → 仍属模型（或训练数据）问题。

**设计意图**：防止学员把"对比条件差异"这把尺子用得过于机械——引导其理解分类的关键在于差异背后变量的本质，而不是"有没有差异"本身，这也是实操评分中区分优秀答卷与及格答卷的地方。

---

### 环节六：小结与作业（110–120′）

**知识回顾**（请学员口述，教师补全）：

1. 从使用数据发现功能问题的分析路径是什么？
2. 怎么判断"识别率低"是模型问题还是产品/流程问题？
3. 今天讨论的几个场景里，哪些是模型问题，哪些是产品/流程问题？为什么？

**回扣主线**：

> "这节课的核心不是记住'对比条件'这四个字，而是延续我们四级课程从课题 1-1 开始就在训练的那个习惯——看到一个不理想的数字，先别急着下结论，先问'这背后可能有几种解释，我该怎么用数据把它们分开'。从课题 1-1 判断'均值还是中位数该用哪个'，到今天判断'锅在模型还是在产品/流程'，都是同一套底层功夫：**先诊断，再处方。**"

**收束四级课程**：

> "到这里，四级 13 个课题全部结束了。四级这一路，你的角色从五级的'执行者'，变成了'审核者+改进者'——不只是把事情做完，还要判断别人做的对不对、现有做法能不能改进。接下来进入三级，角色还会再跃迁一次：从'审核、改进现有的东西'，变成'从零设计规范、流程和系统'。这是下一阶段要适应的变化，带着今天这个'先诊断、再处方'的习惯去读三级的内容，你会发现它仍然管用。"

## 七、板书设计

**主板书区**

```
识别率低的两类可能原因
┌──────────────┐        ┌────────────────────┐
│   模型问题    │        │   产品/流程问题      │
│ 同等条件下    │        │ 采集环境、交互引导    │
│ 判别能力不足  │        │ 等外部因素导致       │
└──────────────┘        └────────────────────┘
       ↑                          ↑
  重新训练/优化模型          优化产品设计/流程

分析路径：埋点指标 → 异常定位 → 分群/条件下钻 → 根因假设 → 验证

┌───────────────── 判别口诀 ─────────────────┐
│ 条件变了，表现跟着大幅变 → 产品/流程问题    │
│ 条件怎么变，表现都一样差 → 模型问题         │
│ （补充：差异来自训练数据覆盖不足时，        │
│   仍属模型/训练数据问题）                  │
└─────────────────────────────────────────────┘
```

**副板书区（两个真实场景对照，保留至下课）**

```
场景              条件变化              表现            判定
语音助手          安静 vs 嘈杂          嘈杂下显著更低   产品/流程（噪声）
车载语音部署      接口响应超时          —              先查网络/并发/接口，最后才查模型

核心教训：先对比，再归因；不要直接认定是模型问题
```
