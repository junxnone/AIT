# 教案 · 课题 1-1：数据质量六维度与检测方法

| 项目 | 内容 |

## 一、教学目标

### （一）知识目标
1. **能说明数据质量六个维度**：完整性、准确性、一致性、唯一性、时效性、有效性，并能区分最容易混淆的两组：完整性 vs 有效性、准确性 vs 一致性。
2. 能说明各维度典型问题表现与业务影响。
3. **能说明检测阈值必须有业务依据**，而不是凭经验拍一个数字。

### （二）技能目标
1. **能为给定业务数据集设计完整的质量检测方案**（覆盖六个维度，不是只查缺失值）。
2. **能依据字段的分布特征（是否长尾）判断缺失值该用均值还是中位数填充**，并说出判断依据。
3. 能针对检测出的问题，区分其属于"完整性问题"还是"有效性问题"，并给出对应的下一步处理建议。

### （三）素养目标
1. 建立"**算出数字只是第一步，判断数字背后的含义才是训练师的价值**"的职业意识——这是本课题承接课题0-3"学会怎么算"向"学会怎么判断"的关键一跃。

---

## 二、教学重点与难点

### 重点
1. 六维度的定义与区分，尤其完整性 vs 有效性、准确性 vs 一致性。
2. 缺失值处理方式的选择依据（均值 vs 中位数）。
3. 检测方案要素的完整性（覆盖六维度，而非只查缺失）。

### 难点

| 难点 | 学员典型错误预判 | 突破方式 |
|---|---|---|
| 长尾分布字段的缺失值处理方式选择 | 检测出"销售额缺失120条"后，**直接用均值填充**，忽视销售额呈长尾分布这一事实，导致填充值严重失真 | 让学员亲手算出均值3689.6与中位数194.0，用近19倍的巨大反差制造认知冲突，引导其建立"**均值/中位数差异大 → 警惕长尾分布**"的判断习惯 |
| 完整性 vs 有效性 的区分 | 发现"销售数量出现负数"后，**误判为完整性问题**（以为是数据采集时丢了东西），说不清为什么这不算完整性问题 | 给判别口诀："完整性问题的表现是**该有值的地方是空的**（NaN）；有效性问题的表现是**有值，但值不符合业务定义域**（如销售数量不能为负）。"让学员用这把尺子去判断新发现的负数/零值记录该归为哪一类 |

## 三、学情分析与前置知识

**前置知识**：课题0-3（pandas基础）。

**学情判断**：学员已不陌生缺失值检测的代码操作（`isna().sum()` 这类调用上手很快），但课题0-3训练的是"**学会怎么算**"，本课题要求的是"**学会怎么判断该用什么方式处理**"——这是从工具能力到判断能力的一次提升。部分学员会停留在"代码跑出数字就算完成任务"的层次，教师需要用追问把思考引向"算出来之后，这个数字说明了什么、该怎么处理"。

---

## 四、教学方法与手段

1. **认知冲突法**（核心）：用均值与中位数的巨大差异制造认知冲击，强化"看数字背后含义"的意识。
2. **讲授+案例法**：六维度逐个讲解配合真实案例。
3. **任务驱动法**：以"产出一份可执行的质量检测方案"作为本课题的终产物。

### 环节一：导入（0–10′）

**教师活动** —— 投影展示（不给结论）：

> "这是某门店上报的销售记录截图，字段齐全，数值看起来也都正常，表格排版工工整整。如果现在要你把这批数据直接喂给后续的销量预测模型，你会同意吗？"

**预期学员反应**：多数学员会倾向于"看起来没问题，可以用"。

**教师追问**：

> "先记住你的判断。接下来我们用真实代码来检测这批数据——你会发现'看起来没问题'和'真的没问题'之间，差得有多远。"

**设计意图**：不直接否定，让"想当然没问题"的直觉判断先被公开表达，后面用真实检测结果推翻，冲击力更强。

---

### 环节二：六维度讲解（10–35′）

**讲授脚本**：

> "判断一批数据'能不能用'，不能靠感觉，要有一把系统的尺子——这就是数据质量的六个维度。"

**逐项讲解**（板书 + 举例）：

| 维度 | 定义 | 典型问题表现 | 业务影响 |
|---|---|---|---|
| 完整性 | 该有值的字段是否缺失 | 销售额、会员等级出现空值 | 统计结果偏小，模型训练样本不完整 |
| 准确性 | 记录的数值是否反映真实情况 | 销售额录入时多打一个0 | 决策依据失真 |
| 一致性 | 同一含义的字段在不同记录里写法是否统一 | 门店编码一会儿"S001"一会儿"s001" | 分组统计时被误判为不同门店，统计结果错误拆分 |
| 唯一性 | 是否存在不应该重复的记录 | 同一笔订单被重复上传两次 | 销售额被重复计算，虚增业绩 |
| 时效性 | 数据是否还在有效时间窗口内 | 用三年前的价格体系数据做今年的定价参考 | 决策依据过时 |
| 有效性 | 字段取值是否落在业务允许的范围内 | 销售数量出现负数 | 值本身不符合业务逻辑，不能直接用 |

**易混淆点提问（重点突破）**：

> "完整性和有效性都会让数据'看起来有问题'，怎么快速区分？"

**判别口诀**（板书）：

> **完整性问题：该有值的地方是空的（NaN）。有效性问题：有值，但值不符合业务定义域。**

> "准确性和一致性呢？准确性问的是'这个值本身对不对'，一致性问的是'同一个意思，写法是不是统一'——即使每条记录单独看都'对'，写法不统一照样是质量问题。"

**学员活动**：记录六维度定义，口头举一个自己熟悉场景（如考勤系统、购物软件）里六维度各自可能出现的问题。

### 环节三：实操一——质量检测（35–55′）

**教师指令**：

> "打开 Jupyter，我们来真刀真枪检测一下导入环节那份'看起来没问题'的数据集。"

**投影代码**（学员照抄运行）：

```python
import pandas as pd
d = pd.read_csv("../数据集/cosmetics_sales.csv")
print("销售额缺失:", d["销售额"].isna().sum())
print("会员等级缺失:", d["会员等级"].isna().sum())
print("门店编码取值:", d["门店编码"].value_counts().to_dict())
print("均值:", d["销售额"].mean(), "中位数:", d["销售额"].median())
```

**实测结果（已验证，学员结果应一致）**：

```
销售额缺失: 120            （占比15%）
会员等级缺失: 144          （占比18%）
门店编码取值: {'S001': ..., 's001': ..., 'S002': ..., 's002': ..., ...}  # 大小写混用，4家门店被拆成8种取值
均值: 3689.6  中位数: 194.0
```

**学员活动**：运行代码，对照六维度把发现的问题分类填表：

| 问题 | 属于哪个维度 |
|---|---|
| 销售额缺失120条 | |
| 会员等级缺失144条 | |
| 门店编码大小写混用 | |

**设计意图**：先让学员亲手跑出真实问题，再回到导入环节的判断——"看起来没问题"的数据，一跑检测就发现至少三类问题，直接推翻直觉。

### 环节四：关键讨论——均值填充陷阱（难点一突破，55–75′）

**教师追问**：

> "现在大家都算出了均值3689.6、中位数194.0。如果这120条缺失记录要填充，你会选哪个？"

**预期学员反应与应对**：

| 学员反应 | 教师应对 |
|---|---|
| "均值，因为均值更常用" | 追问："均值3689.6，中位数只有194.0，差了近19倍。这说明什么？数据是均匀分布的吗？" —— 引导意识到这么大的差异说明分布严重偏斜 |
| "中位数，因为差异这么大肯定有问题" | 肯定："对，看到均值和中位数差这么多，就要警惕——这是长尾分布的信号。填充应该用能代表'典型水平'的中位数，而不是被少数大额订单拉高的均值。" |
| 答不上来 | 引导：用一个极端小例子演示——"假设5条销售额记录是 100,120,110,90,8000，均值是多少？中位数是多少？哪个更能代表'大多数订单的真实水平'？" |

**学员活动**：填写对比表并讨论：

| | 数值 |
|---|---|
| 均值 | 3689.6 |
| 中位数 | 194.0 |
| 倍数差异 | 约19倍 |
| 应该用哪个填充？为什么？ | |

**教师总结话术**：

> "这是本课题最该记住的一课：**看到均值和中位数差异很大，就是一个警报信号**，提示你这个字段不是正态分布（大概率是销售额这类'少数大单'主导的长尾分布），不能无脑套用均值填充的默认做法。"

### 环节六：新授——检测阈值须有业务依据（85–110′）

> 📌 **教学提示**：这一环节支撑"知识目标2"，是此前版本教案里提到目标却从未展开讲授的内容，本轮补齐。

**讲授脚本**：

> "六维度讲完了，但光知道'哪里有问题'还不够。实际工作中你还要回答一个问题：**多大的缺失率、多大的异常比例，算'严重'，需要上报或暂停使用？** 这个界限不能拍脑袋定。"

**反例**（先给错误做法，制造认知冲突）：

> "有同学可能会说：缺失率超过10%就算不合格。这个数字哪来的？"
>
> （停顿，等待反应）
>
> "如果是随便定的，换一个业务场景立刻会出问题。比如会员等级这个字段，缺失18%，如果这18%恰好是'未注册会员'这类本来就不该有等级的正常情况，那这个'缺失'根本不是质量问题，是业务规则决定的正常空值。"

**正例**：

> "正确做法是：**先搞清楚缺失/异常的业务原因，再决定阈值**。比如销售额这类核心业务字段，缺失率哪怕只有5%也可能影响后续统计的可信度，阈值应该设得严格；而像'会员等级'这种允许存在合理空值的字段，阈值可以适当放宽，但要在检测方案里明确写出'允许空值的业务原因'，而不是放任不管。"

**板书核心句**：

> **阈值不是经验数字，是业务规则的量化表达。**

**学员活动**：针对本课题数据集，讨论"销售额缺失率15%"和"会员等级缺失率18%"分别应该定一个什么样的处理阈值，并说明理由。

**预期诊断点**：

| 典型错误 | 应诊断出的问题 |
|---|---|
| 方案只写了"销售额缺失120条，建议填充" | 遗漏唯一性、时效性检测；没说明用什么值填充、为什么 |

### 环节九：变式练习——有效性维度新发现（难点二突破，160–190′）

**教师指令**：

> "刚才大家检测的是销售额和会员等级。现在换一个字段——`销售数量`。用同样的方法检测一下，看看这次会发现什么。"

**投影代码**：

```python
import pandas as pd
d = pd.read_csv("../数据集/cosmetics_sales.csv")
print("销售数量<=0的条数:", (d["销售数量"] <= 0).sum())
print("销售数量 最小值/最大值:", d["销售数量"].min(), d["销售数量"].max())
```

**实测结果（已验证）**：

```
销售数量<=0的条数: 24
销售数量 最小值/最大值: -7 7
```

**关键提问（难点二突破核心）**：

> "销售数量出现负数和0，一共24条。这属于六维度里的哪一类问题？"

**预期学员反应与应对**：

| 学员反应 | 教师应对 |
|---|---|
| "完整性问题，因为数据不对" | 追问："完整性问题的标志是什么？是'该有值的地方是空的'。这24条记录有没有缺失？是不是都有具体的数字，只是这个数字不对？" —— 引导意识到这不是"没有值"，而是"有值但值错了" |
| "有效性问题，因为销售数量不该是负数" | 肯定："对。销售数量的业务定义域应该是正整数，出现负数和0，是'值落在了业务允许范围之外'——这是典型的有效性问题，不是完整性问题。" |

**追加提问（迁移巩固）**：

> "再问一句，`订单号`这一列，大家顺手查一下有没有重复——结果会是什么？"

（学员运行 `d["订单号"].duplicated().sum()`，实测结果为 **0**，订单号完全唯一）

> "这说明什么？不是每个维度都一定有问题，**唯一性这一项在这批数据里是干净的**。检测的意义不是'找茬证明数据有问题'，而是系统地过一遍六个维度，有问题的揪出来，没问题的也要确认清楚、写进报告，不能因为'没发现问题'就跳过不写。"

### 环节十：阶段性小测（190–210′）

**回扣主线**：

## 七、板书设计

**主板书区**

```
                      数据质量六维度
完整性(该有值的地方是否为空)    准确性(数值本身对不对)
一致性(同一含义写法是否统一)    唯一性(有无不应有的重复)
时效性(数据是否过期)           有效性(取值是否在业务允许范围内)

┌──────────────── 实测反差 ────────────────┐
│ 销售额  均值 3689.6   中位数 194.0        │
│ → 差近19倍，长尾分布，缺失值该用中位数填充 │
└────────────────────────────────────────────┘

有效性新发现：销售数量 <=0 共24条（min=-7, max=7）→ 有效性问题，非完整性问题
```

**副板书区（完整性 vs 有效性 判别）**

```
                完整性              有效性
表现            该有值的地方是空的   有值，但值不符合业务定义域
本课题例子      销售额缺失120条      销售数量出现负数/0共24条

判别口诀：先问"有没有值"，再问"值对不对"
```
