## 课题0-1：四级能力定位与职业守则进阶

**核心考点**
- 人工智能训练师（职业编码4-04-05-05）定义：使用智能训练软件，在人工智能产品实际使用过程中进行数据库管理、算法参数设置、人机交互设计、性能测试跟踪及其他辅助作业的人员；含**数据标注员、人工智能算法测试员**两个工种。
- 四级与五级**职业功能模块名称相同**（数据采集和处理/数据标注/智能系统运维），但能力动词不同：五级是"做"，四级是"审+优化"。
- 四级角色定位：**质检员+工艺改进员**——不只是把活干完，还要判断别人干的活对不对、现有干法能不能改进。
- 职业守则三条：诚实公正、严谨求是；遵章守法、恪尽职守；勤勉好学、追求卓越。

**关键规则**

| 职业功能 | 五级（做） | 四级（审+优化） |
|---|---|---|
| 数据采集和处理 | 完成原始数据采集、整理归类与汇总 | 审核业务数据质量、提出优化建议 |
| 数据标注 | 完成清洗、完成标注 | 聚类分析发现关联、审核标注准确性完整性、纠正错误、筛选数据 |
| 智能系统运维 | 开启、简单使用、记录 | 维护、部署、基于数据分析提出优化方案 |

**易错点**
- 误以为四级只是"标得更准的五级"，忽视核心能力转变是角色性质转变（做→审）而非技术熟练度提升。
- 把"批量纠正错误"误判为五级执行，忽视纠正的前提是先要有判断"这是错的"的审核能力。

**配套题库**：单选1-3、判断1-2。

## 课题0-2：数据安全法规与合规实务

**核心考点**
- 国标明列：《劳动法》《劳动合同法》《网络安全法》《知识产权法》；延伸内容：《数据安全法》《个人信息保护法》。
- 合规风险点贯穿数据全生命周期：**采集→存储→标注→共享**，不止在采集一环。
- **最小必要原则**：采集和处理范围应与业务目的相匹配，不是"越少越好"，而是"不超范围采集"。
- **最易忽视环节：标注**——标注员/外包团队接触原始（未脱敏）数据同样需要访问控制。

**关键规则（全流程风险点与整改）**

| 环节 | 风险点 | 整改措施 |
|---|---|---|
| 采集 | 未明示收集目的、未取得同意 | 告知-同意流程须具体到用途 |
| 存储 | 未加密、访问权限过大 | 加密存储、权限最小化分配 |
| 标注 | 标注员能看到可识别身份的原始信息 | 脱敏后再交付标注，访问权限只开放标注所需字段 |
| 共享 | 超出原始授权范围与第三方共享 | 共享前核实是否需要重新取得用户同意 |

**易错点**
- 只关注采集环节是否取得同意，忽视标注、共享环节的风险。
- 误解最小必要原则为"数据越少越好"（应为"不超范围"）。

**配套题库**：单选4-14、判断3-6。

## 课题0-3：AI原理与pandas/numpy数据处理基础

**核心考点**
- 机器学习三大范式判断公式：**有标准答案→监督学习；无标准答案但有数据结构→无监督学习；无标准答案但有反馈信号→强化学习**。
- 训练集/验证集/测试集：训练集学习参数、验证集调参与早停、测试集最终评估，三者应相互独立，不能混用。
- pandas核心工具箱：读写(`read_csv`/`to_csv`)、查看(`head`/`info`/`describe`)、缺失(`isnull`/`fillna`/`dropna`)、重复(`duplicated`/`drop_duplicates`)、聚合(`groupby`/`agg`/`pivot_table`)。
- 缺失值处理决策顺序：①能补录就补录 ②不能补录+影响小→删除 ③不能补录+影响大→填充（看分布形态，**长尾分布用中位数**，接近对称分布可用均值）。

**关键代码**
```python
df.isnull().sum()                 # 按列统计缺失
df.duplicated().sum()             # 整行重复统计
df["col"].fillna(df["col"].median())
df.groupby("category")["amount"].agg(["mean","sum","count"])
df.pivot_table(index="category", columns="region", values="amount", aggfunc="sum")
```

**易错点**
- 不假思索用均值填充，忽视长尾分布会导致均值失真。
- 三大范式判断混淆（尤其无监督vs强化学习的区分）。
- 混用训练/验证/测试集导致评估结果虚高失真。

**配套题库**：单选15-28、判断7。

## 课题1-1：数据质量六维度与检测方法

**核心考点**
- 数据质量六维度：**完整性、准确性、一致性、唯一性、时效性、有效性**。
- **完整性 vs 有效性** 判别口诀：先问"有没有值"，再问"值对不对"——该有值的地方是空的(NaN)→完整性问题；有值但值不符合业务定义域→有效性问题。
- **准确性 vs 一致性**：准确性问"这一条记录本身对不对"；一致性问"不同记录里同一个意思是不是用统一写法表达"。
- **阈值不是经验数字，是业务规则的量化表达**——不能拍脑袋定缺失率/异常率阈值，须先搞清业务原因再定。
- 检测的意义是系统性过一遍六维度，没问题的也要写进报告确认，不能因"没查出问题"就跳过不写。

**关键规则/数据**
- 实测案例：销售额均值3689.6 vs 中位数194.0，相差约19倍→长尾分布信号，应优先用中位数填充。
- 均值/中位数差异大 → 警惕长尾分布。

**易错点**
- 不看分布形态直接用均值填充（本课题实操核心易错点）。
- 把"销售数量出现负数"误判为完整性问题（应为有效性问题）。
- 认为门店编码"S001"和"s001"是不同门店（应归为一致性问题，需归一化）。

**配套题库**：单选29-40、多选1-2、判断8-9；实操 四-2。

## 课题1-2：质量检测实操：图像/文本/销售数据

**核心考点**
- 图像数据集审核清单：标注↔图像交叉核查、坐标合法性、类别分布是否均衡、分辨率是否一致、有无重复图像。
- **交叉核查**须用集合运算（差集）才能发现"标注指向不存在图像""图像无对应标注"，仅看标注表内部坐标合法性发现不了。
- 结构化数据审核要点：缺失值、异常值、字段逻辑冲突（如发货日期早于下单日期）、主键重复。

**关键代码**
```python
missing_img = set(labels["image_file"]) - images   # 标注指向不存在的图像
(labels.x2 < labels.x1).sum()      # 坐标非法
(labels.y2 > 480).sum()            # 坐标越界
labels["label"].value_counts()     # 类别分布
```
实测参考：bus占62% vs tram仅4%（类别严重不均衡）；4条标注指向不存在图像；3条x2<x1、4条y2越界。

**易错点**
- 只检查标注文件内部的坐标合法性，忽视与图像文件的交叉核查。
- 发现类别分布不均衡但未提出处理建议（如过采样/针对性补充采集）。

**配套题库**：单选41-52、多选3、判断10；实操 四-1。

## 课题1-3：数据处理方法优化

**核心考点**
- 两类"看起来异常"的数据，处理方式完全不同：**正常长尾分布的高值→统计手段处理；数量级录入错误→核实修正，不能用统计手段掩盖**。
- 判别依据：偏离正常范围的倍数是否离谱（本课题案例：30-45倍提示录入错误，几倍到十几倍的差异通常是正常业务波动）。
- 门店编码归一化（`.str.upper()`）解决的是一致性问题，不是完整性问题。

**关键规则/数据**
- 实测：SKU003均值39700.6、SKU022均值28900.9、SKU011均值27164.2，正常SKU均值约800-900，相差约30-45倍→数量级录入错误（如单价多打两个0），应核实修正而非用中位数掩盖。
- 归一化后4个门店编码从8种取值合并为4种，分布趋于均衡（192-205条/店）。

**易错点**
- 把录入错误和正常长尾分布混为一谈，都用统计手段（如中位数替代）处理。
- 不加区分地套用"填充/删除"模板。

**配套题库**：单选53-64、多选4、判断11；实操 四-2（续）。

## 课题1-4：采集与处理流程优化建议书撰写

**核心考点**
- 建议书标准结构：**现状与问题（量化）→根因分析→优化方案→预期收益（可度量）→实施计划与风险**。
- 合格建议书三要素：**问题量化、方案具体、指标可验证**；且须包含**成本与可行性考量**，不能只谈理想方案。
- "现状与问题"是表面现象，"根因分析"是深层原因，跳过根因分析直接给方案容易治标不治本。

**关键规则（合格vs不合格对比）**
- 不合格："销售数据存在质量问题，建议加强数据治理。"（问题模糊、建议空洞、无验证指标）
- 合格："销售额字段缺失率15%……建议①②……预期将有效性从85%提升至98%以上，观察周期1个月。"（问题量化+方案具体+指标可验证）

**易错点**
- 写成"问题罗列+笼统建议"，缺少可验证的验证指标。
- 只谈理想方案，不考虑实施成本与可行性。
- 只有问题分析没有具体优化方案（等于只完成一半工作）。

**配套题库**：单选65-72、判断12；实操 四-2（完整版）。

## 课题2-1：聚类分析与数据内在关联

**核心考点**
- 聚类（如K-Means）属于**无监督学习**，与分类的根本区别：分类有标准答案，聚类没有。
- **做聚类分析前必须先检查各特征量纲是否一致**（用`describe().loc[["min","max"]]`），量纲不一致须先标准化（`StandardScaler`），否则聚类结果会被量纲最大的特征主导。
- 聚类结果还需判断**是否具有业务意义**，不能止步于得到几个数学分组。

**关键规则/数据**
- StandardScaler：把特征转换为均值0、标准差1的分布，公式(x-均值)/标准差。
- ARI（调整兰德系数）衡量聚类结果与真实分群吻合度，1为完全吻合。
- 实测：客单价11.61-4983.21元 vs 下单数0-25，量纲差异悬殊；未标准化ARI仅0.533，标准化后提升到0.905。

**易错点**
- 不做标准化直接聚类，结果被量纲大的特征（如客单价）主导。
- 只给出聚类结果，不判断是否有业务价值。

**配套题库**：单选73-84、多选5-6、判断13；实操 四-3。

## 课题2-2：归类定义与标签体系设计

**核心考点**
- 良好标签体系三要求：**互斥性**（一条数据唯一归入一类）、**完备性**（覆盖所有实际情形，不漏类）、**粒度适当**（不过粗不过细）。
- **互斥性检验方法**：拿几条真实数据去试标，若经常"好几个类别都说得通"，说明体系存在维度混乱，需重新设计，而非要求标注员"自己选一个"。
- 常见体系缺陷根因：把"问题来源维度"和"用户诉求维度"混在同一套单选标签里。

**关键规则**
- 反例：客诉分类"物流问题/态度问题/退款问题"三类并列——"物流/态度"是问题来源维度，"退款"是用户诉求维度，混入同一单选会导致数据同时命中多类。
- 改进方向：拆成两个独立维度各自单选（问题来源：物流/质量/服务态度/其他；用户诉求：退款/换货/解释说明/投诉记录）。

**易错点**
- 把维度混乱误判为标注员水平问题。
- 该用多维度标签的场景强行塞进单选。
- 记混互斥性与完备性的定义。

**配套题库**：单选85-96、多选7、判断14；实操 四-3（续）。

## 课题2-3：标注数据准确性与完整性审核

**核心考点**
- 两个审核维度：**完整性审核**（该标的字段有没有漏标）vs **准确性审核**（标注取值对不对、是否在规范内）。
- 诊断流程：**发现差异→不下结论→抽样复核→再归因**，不能跳过中间两步直接下结论。
- 标注员分布差异的非能力原因：①任务批次分配不均 ②原始数据本身特征不同。

**关键规则/数据**
- 实测：标注依据缺失12条（完整性问题）；意图标签出现"其他""咨询类"非法取值（准确性问题）；A03咨询116/投诉155，与A01(207/58)、A02(205/64)明显相反，但不能直接下结论，需抽样复核。
- 抽样比例与重点类别全检是互补关系：常规抽样（如10%）用于整体把关，关键类别/异常类别/异常标注员应全检。

**易错点**
- 发现分布差异就直接下结论"标注员有问题"，不做抽样复核验证。
- 混淆完整性与准确性两个维度。

**配套题库**：单选97-108、多选8-9、判断15-16；实操 四-4。

## 课题2-4：审核报告撰写、错误纠正与数据筛选

**核心考点**
- 审核报告结构：**审核对象与范围→方法与样本→问题清单（分类分级）→量化结论→处置建议**。
- 错误类型对应不同纠正方式，**不能一刀切**："重新标注"不是唯一处理方式。
- 数据筛选三档：**可用/需返工/应剔除**，每一档都须说明判定依据。

**关键规则**

| 错误类型 | 举例 | 纠正方式 |
|---|---|---|
| 单点错误 | 个别记录标签打错字 | 直接修正这几条，不动其他数据 |
| 批量同类错误 | 大量记录犯同一类错误（如脚本bug） | 规则批量批改，并回溯检查遗漏 |
| 规范理解偏差 | 标注员系统性理解有误 | 返工该部分数据+补充细则到手册 |

**易错点**
- 对所有问题都用同一种方式处理（如都要求重新标注），未区分规模和性质。
- 只给筛选结果，不说明判定依据。
- 因标注员存在偏见就一刀切剔除其全部数据（应为需返工后重新审核分档）。

**配套题库**：单选109-130、多选10-11、判断17-19；实操 四-4（续）、四-5。

## 课题3-1：智能系统维护与场景部署

**核心考点**
- 智能系统基本组成四层：**数据层→模型层→服务层→应用层**。
- 日常维护记录三要素：**功能使用情况 / 运行是否正常 / 异常现象描述**——记录要写现象，不要只写结论。
- **部署六要素**：硬件与算力、网络与时延、数据接口与格式、并发量评估、安全与权限、回滚方案——六项缺一不可。
- 常见问题排查顺序：**先查外部环境与接口，最后才怀疑模型本身**（模型排查成本最高）。

**关键规则（排查顺序表）**

| 现象 | 排查顺序 |
|---|---|
| 新环境运行报错 | 先查环境依赖版本是否一致，再查数据格式是否匹配 |
| 接口超时 | 先查网络时延，再查并发量是否超出设计容量 |
| 权限不足 | 查账号权限分配是否与新环境同步 |

**易错点**
- 只写硬件算力，遗漏接口格式/并发量/回滚方案等"非硬件类"要素（最易被忽视）。
- 排查顺序颠倒（如接口超时直接怀疑模型而非先查网络和并发）。
- 把"异常现象描述"写成结论（如直接写"系统坏了"而非具体现象）。

**配套题库**：单选131-137、判断20；实操 四-6。

## 课题3-2：基于数据分析的系统功能优化

**核心考点**
- 分析路径：**埋点指标→异常定位→分群/分条件下钻→根因假设→验证**。
- 判别方法核心：**对比不同条件（环境/渠道/用户群体）下的表现差异**，定位问题在模型层面还是产品/流程层面。
- 判断规则：模型在**所有条件下**表现都不好→真正的模型问题；只在**特定条件**下表现差→产品/流程问题。

**关键规则**
- 案例：语音助手嘈杂环境识别率低，若安静环境识别率正常→模型本身没问题，应优化降噪硬件/前处理算法，而非重新训练模型。
- 重新训练一个本身没问题的模型，既浪费资源又解决不了真正问题（如采集端物理噪声）。

**易错点**
- 把所有效果不理想都归因于"模型不够好"，不排查产品/流程层面因素。
- 未做对比实验就直接下结论要重新训练模型。

**配套题库**：多选12、判断21。
