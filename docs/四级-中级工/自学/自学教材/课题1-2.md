## 一、同一把尺子，换一种数据形态：六维度方法要怎么迁移

课题1-1教的六维度方法（完整性/有效性/唯一性/一致性/时效性/准确性），不是只能用在表格数据上。换一种数据类型，六个维度本身不变，变的是**每个维度具体怎么检查**。这是贯穿本课题全部内容的一条主线，先把这张对照表记在心里：

| 维度 | 在表格数据里怎么查（课题1-1） | 在图像数据里怎么查（本课题） |
|---|---|---|
| 完整性 | 字段是否为空（`isna()`） | **双向**：标注是否缺对应图像？图像是否缺对应标注？ |
| 有效性 | 数值是否在业务允许范围内 | 坐标是否越界、是否 x2<x1（非法矩形框） |
| 唯一性 | 主键是否重复 | 有无内容完全相同的重复图像 |
| 一致性 | 同一字段写法是否统一 | 标注风格是否统一（下一阶段用 Kappa 深入量化，本课题先不展开） |
| 时效性 | 数据是否还在有效期内 | 图像采集时间是否还能代表当前业务场景 |
| 准确性 | 数值是否反映真实情况 | 标注框是否准确框住目标物体 |

表里"完整性"这一行写了**"双向"**两个字，这是本课题引入的、课题1-1完全没遇到过的新概念，也是后面要重点突破的难点，先留个印象，下一节马上展开。

## 二、图像数据集审核：你的第一次"跨文件"核查

### 2.1 为什么完整性检查必须分两个方向

课题1-1处理的`cosmetics_sales.csv`，所有判断依据都在**同一张表**里——查完整性，就是看这张表自己有没有空值。但图像数据不一样：**标注信息和图像本身是两份独立的文件**，一份是`transport_labels.csv`标注表，一份是`transport_images/`图像文件夹。这就让"完整性"从单方向的事变成了需要分**两个方向**检查的事。

自己想清楚这个问题再往下读：**如果有人标注的时候漏标了一张图，这张图会不会出现在标注表里？**

答案是**不会**——它压根就没被标注过，所以标注表里根本不存在任何跟它有关的记录。这意味着：**只检查标注表内部的问题（比如坐标是否合法），永远不可能发现"图像存在但没人标注"这件事**，因为这个问题的全部线索都在图像文件夹那一侧，标注表里一个字都不会提到它。

反过来同理：如果一条标注指向了一张已经被删除或改名的图像，这条记录会原样留在标注表里，但对应的图像已经不存在了——这个问题的线索又全在标注表这一侧，图像文件夹里什么痕迹都留不下。

两个方向互相不能替代，缺了哪个方向，哪个方向的问题就是**彻底的零发现**——不是"发现得少"，是**一条都查不出来**。这正是本课题的核心难点。

### 2.2 动手跑代码：双向交叉核查 + 坐标合法性 + 类别分布

标注表 `transport_labels.csv` 有 106 条记录，图像文件夹 `transport_images/` 有 100 张图片——数量不一致本身不一定是问题（一张图里可能有多个目标，一张图就会产生多条标注记录），但也可能藏着上面说的两类问题。跑代码验证：

```python
import pandas as pd
from pathlib import Path

labels = pd.read_csv("../数据集/transport_labels.csv")
images = set(p.name for p in Path("../数据集/transport_images").glob("*.jpg"))
labeled = set(labels["image_file"])

missing_img = labeled - images        # 方向一：标注指向不存在的图像
no_label    = images - labeled        # 方向二：图像存在但无任何标注

print("标注记录总数:", len(labels))
print("标注指向不存在图像数:", len(missing_img))
print("图像存在但无标注记录数:", len(no_label))

print("坐标非法(x2<x1):", (labels.x2 < labels.x1).sum())
print("坐标越界(y2>480):", (labels.y2 > 480).sum())
print("类别分布:", labels["label"].value_counts().to_dict())
```

**实测结果（已验证，你跑出来应该一致）**：

```
标注记录总数: 106
标注指向不存在图像数: 4
图像存在但无标注记录数: 3
坐标非法(x2<x1): 3
坐标越界(y2>480): 4
类别分布: {'bus': 66, 'car': 20, 'bicycle': 11, 'truck': 5, 'tram': 4}
```

两次集合差集运算，分别对应两个方向：`标注表的图像名集合 − 真实图像文件名集合` 找到标注指向不存在的图像；`真实图像文件名集合 − 标注表的图像名集合` 找到图像存在但完全没被标注。4条和3张，是两类完全不同的问题——前者可能是图像文件丢失，处理方式是核实是否真的丢失，若确认丢失就删除对应标注记录；后者可能是标注任务遗漏，处理方式是退回标注环节补标。**如果只做了一个方向的检查，另一个方向的问题会被当成"数据集没问题"，一路带到模型训练里去。**

坐标非法3条、坐标越界4条，这两项和"双向交叉核查"性质不同——它们**只看标注表内部的字段数值**就能判断，不涉及图像文件，属于"内部检测"就能发现的问题（有效性问题：坐标不满足"矩形框右边界大于左边界""坐标不超出图像尺寸"这类逻辑约束）。类别分布一项，`bus`占66/106（约62%），`tram`仅占4/106（约4%），差距悬殊——这种不均衡会让模型倾向于学习数量占多数的类别，对数量稀少的类别学习不充分，实际应用中对`tram`的识别准确率会明显偏低，处理方向是对少数类过采样或针对性补充采集。

记住这条判别口诀：

> **只看一份文件本身能不能查出这个问题？能 → 内部检查就够了（如坐标合法性）。不能，必须对照另一份文件 → 交叉核查（如标注↔图像对应关系）。**

### 2.3 把清单补完整：分辨率一致性与重复图像——"干净"的结果也要写进报告

图像数据的六维度清单里还有两项没查：分辨率是否一致、有没有重复图像。继续跑代码：

```python
from PIL import Image
import hashlib

sizes = set()
hashes = {}
for f in Path("../数据集/transport_images").glob("*.jpg"):
    with Image.open(f) as im:
        sizes.add(im.size)
    h = hashlib.md5(f.read_bytes()).hexdigest()
    hashes.setdefault(h, []).append(f.name)

print("分辨率种类:", sizes)
print("重复图像组数:", sum(1 for v in hashes.values() if len(v) > 1))
```

**实测结果**：分辨率种类只有 `{(640, 480)}` 一种，一致，没问题；重复图像组数为 `0`，没有重复。

这两项结果都是"干净"的——**但不代表这两步白做了**。检测的意义不是"找茬证明数据有问题"，而是系统地把清单上每一项都过一遍：有问题的揪出来，没问题的也要确认清楚、写进报告。今天图像数据的完整检测清单一共有五项——双向交叉核查、坐标合法性、类别分布、分辨率一致性、重复图像——缺一项都不叫"完整检测"，哪怕其中几项结果是零。

## 三、文本标注数据审核：当一条数据被多个人标注

图像处理的是"两份文件对不对得上"的问题。现在换一种更常见的数据形态——**同一条数据被多个人标注**，这是标注类工作里最普遍的场景，六维度框架依旧适用，但会冒出一个新问题。

### 3.1 内部检测能查到的三类问题

`service_annotations.csv` 记录了某电商客服对话的意图分类标注：300条对话，每条分别由3位标注员（A01/A02/A03）独立标注"咨询 / 投诉 / 闲聊"三类意图之一，共900行记录。

```python
import pandas as pd

d = pd.read_csv("../数据集/service_annotations.csv")
legal = {"咨询", "投诉", "闲聊"}

print("总行数:", len(d), "｜唯一对话数:", d["对话ID"].nunique())
print("意图标签缺失:", d["意图标签"].isna().sum())
print("标注依据缺失:", d["标注依据"].isna().sum())
print("非法取值(不在合法标签集内):",
      (d["意图标签"].notna() & ~d["意图标签"].isin(legal)).sum())

agree = d.groupby("对话ID")["意图标签"].apply(lambda s: s.nunique(dropna=False) == 1)
print("三人标签完全一致的对话数:", agree.sum(), "/", len(agree))
```

**实测结果（已验证）**：

```
总行数: 900 ｜唯一对话数: 300
意图标签缺失: 3
标注依据缺失: 12
非法取值(不在合法标签集内): 6
三人标签完全一致的对话数: 166 / 300
```

前三行——意图标签缺失3条、标注依据缺失12条、非法取值6条（出现了"其他""咨询类"这两个不在"咨询/投诉/闲聊"合法标签集内的取值）——单独看一条标注记录就能判断出问题，分别属于完整性和有效性问题，这是**内部检测**就能发现的。

### 3.2 第四个问题：同一对话，三人标注结果不一致——这属于哪个维度

最后一行最特殊："三人标签完全一致的对话只有166个，剩下134个（约44.7%），300条对话里三个人标的不完全一样"。先自己判断一下：**这算六维度里的哪一类问题？**

如果你的第一反应是"有效性问题，因为标错了"——先检验一下：有效性问题的标志是"值不在合法范围内"，这134个对话里，三个人标的"咨询""投诉""闲聊"，哪一个单独拿出来看是不合法的？答案是：每个标签单独看都合法，问题不在取值本身。

正确答案是**一致性问题**。回忆课题1-1学的一致性：门店编码一会儿写"S001"一会儿写"s001"，同一个意思写法不统一。这里的逻辑完全一样——只是对象从"同一个字段怎么写"变成了"同一条标注任务被不同人处理，结果统不统一"。单独看任何一条标注记录，标签本身都合法，问题只有把**同一个对话的三条标注放在一起对比**才能看出来，这正是"交叉检测"而非"内部检测"的特征。

记住这条判别口诀：

> **只看一条记录本身是否合法 → 内部检测（完整性/有效性）；对照同一个对象被不同人处理的结果是否相同 → 一致性/交叉检测。**

### 3.3 这不是随机噪声，是系统性差异

发现"134个对话三人标签不一致"只是第一步，接下来要搞清楚：这是随手标错几条的偶然波动，还是有规律的系统性问题？把其中一句高频内容单独拎出来看：

```python
sub = d[d["对话内容"] == "运费是多少"]
print("涉及对话数:", sub["对话ID"].nunique())
print(pd.crosstab(sub["标注员"], sub["意图标签"], dropna=False))
```

**实测结果**：同样一句"运费是多少"，对应55个独立对话。

| | A01 | A02 | A03 |
|---|---|---|---|
| 标"咨询"次数（共55次） | 51 | 53 | 33 |
| 标"投诉"次数 | 1 | 1 | 22 |

A01在55次里标了51次"咨询"，A02标了53次"咨询"，而**A03只标了33次"咨询"、却标了22次"投诉"**。同一句话，A01、A02几乎都判定为"咨询"，A03却有将近四成判成"投诉"。这不是随手标错几条的偶然波动，**是某个标注员在同一类内容上持续偏向同一个方向**——一种系统性差异，而不是随机噪声。

本课题要求你做到的，是先学会用"三人标签是否完全一致"这种最朴素的方式**发现**一致性问题，能说出它属于六维度里的"一致性"即可，不要求现在就诊断根因。更深一层的诊断——用 Cohen's Kappa 这类指标**量化**不一致有多严重，判断这到底是标注手册写得不够细还是标注员本身有系统性偏差——是下一阶段（三级课题2-2会详细讲）的内容。"先学会发现、再学会量化诊断"，是一条逐步加深的学习路径，本课题完成的是第一步。

## 四、销售数据：被1-1漏掉的那一项维度——唯一性

课题1-1已经把 `cosmetics_sales.csv` 的完整性（销售额缺失120条/15%、会员等级缺失144条/18%）、一致性（门店编码S001/s001大小写混用）挖得很细。但六维度清单上还有一项1-1没专门检测过——**唯一性**。自己动手补上：

```python
import pandas as pd
d = pd.read_csv("../数据集/cosmetics_sales.csv")
print("订单号重复数:", d["订单号"].duplicated().sum())
```

**实测结果**：订单号重复数 `0`。

先自己想一想：结果是0，这项检测是不是白做了？

答案是：**没发现问题，和没有查这个问题，完全是两回事**。前者是"确认过，这里是干净的"，后者是"根本不知道这里干不干净"。质量检测报告里，结果是"合格"也要写进去，**不能因为没问题就跳过不记录**。六维度要对每一个新数据集都完整走一遍，不能因为换了个数据集名字就沿用上次没查全的清单——尤其容易漏查的就是唯一性和时效性这两项，因为代码不会自动提示你"还没查这个"，必须自己对照清单一项项确认。

做完这一步，把1-1已发现的销售额缺失、门店编码不一致两项问题也一并记入检测记录，不需要重新计算，只是确认清单完整覆盖。

## 五、产出综合质量检测报告：四要素 + 三个真实出现过的典型错误

到这里，图像、文本、销售三类数据你都已经各自走完了六维度清单。本课题最终要产出的是一份综合质量检测报告，下面是必备的四个要素：

```
一、三类数据集基本信息（各自的记录数/文件构成）
二、各类数据六维度检测结果
    图像：双向交叉核查 / 坐标合法性 / 类别分布 / 分辨率一致性 / 重复图像
    文本：标签缺失 / 依据缺失 / 非法取值 / 标注一致性
    销售：引用课题1-1已检测项 + 本课题新增的唯一性
三、每类问题的处理建议
四、优先级排序（哪类问题必须先处理）
```

下面三份是真实出现过的"看起来写得还可以"、实际上不合格的报告片段。建议你先自己诊断问题出在哪，再看后面揭晓的答案——这组练习对应实操考试里最容易被扣分的三种典型错误。

| 典型错误片段 | 先自己诊断：问题出在哪？ |
|---|---|
| 图像部分只写"标注指向不存在图像4条" | （先想一想再往下看） |
| 文本部分把"三人标签不一致"写成"标注质量不行，重新标" | （先想一想再往下看） |
| 销售部分唯一性检测结果为0，报告里完全不提 | （先想一想再往下看） |

**答案揭晓**：

- **第一份**：遗漏了"图像无标注"这个方向（3张），交叉核查没做完整——只报了一个方向，另一个方向的问题（图像存在但没人标注）完全没被发现，这正是第二节反复强调的"双向都要查"。
- **第二份**：没有先把问题归类到"一致性"维度就直接跳到处理方案，而且处理方案本身也跳过了"先诊断根因"这一步——直接说"重新标"，既没说清楚问题性质，也没有像三级课题2-2那样先排查是标注手册不细还是标注员系统性偏差，就直接下结论处理。
- **第三份**：结果合格不等于不用写。六维度检测清单要**完整留痕**，哪怕某一项结果是零，也要写进报告，不能因为"没问题"就省略。

巡回检查自己报告的时候，重点核对两处最容易遗漏的地方：图像部分是否把"双向"交叉核查都写了（最常见遗漏是只写"标注指向不存在图像"，漏写"图像无标注"方向）；文本部分是否把"三人标签不一致"正确归入一致性维度，而不是笼统写成"标注质量差"。

## 六、迁移巩固：按标注员拆解缺失分布——先查制度，再查人

前面发现标注依据缺失一共12条。现在自己写代码，看看这12条缺失是平均分布在三位标注员身上，还是集中在某一个人身上：

```python
d = pd.read_csv("../数据集/service_annotations.csv")
print(d[d["标注依据"].isna()]["标注员"].value_counts())
```

**实测结果（已验证）**：`A02: 6, A01: 3, A03: 3`

A02的缺失数量是另外两人的两倍。先自己想一想：这说明什么？下一步该怎么做？

如果你的第一反应是"A02不认真，批评一下"——先冷静检查一下样本量：12条里A02占6条，另外两人各3条，差距是2倍，但样本量才12条，这个差距够不够"悬殊到异常"的地步，能不能仅凭12条就下"A02不认真"这个结论？

更稳妥的做法是：**先假设是任务分配或界面操作习惯等制度性原因，而不是人的态度问题**，比如先看看A02负责的对话类型是不是本身更容易缺填标注依据（比如某类对话场景设计上就容易漏填）。这就是"先查制度、再查人"的职业素养——处理任何数据异常，先排查流程和制度层面的原因，不要急于把问题归咎到具体某个人身上，这个原则会在下一阶段（三级课题2-2处理标注员系统性偏见）里再次用到。

## 九、自测练习

下面五题取自本课题配套练习，建议你先独立完成每一题（哪怕只是在脑中组织答案），再对照参考答案核对，而不要直接跳到答案。

**练习 1**：某图像数据集标注文件有500条记录，图像文件夹有490张图片。可能存在什么问题？该怎么核查？

**答案**：可能存在标注指向不存在图像的情况（多出的10条可能对应已删除或丢失的图像文件），也可能存在图像重复使用多条标注的情况。应用集合运算核查标注文件中的image_file字段与实际图像文件名的差集，定位具体是哪些记录存在问题，且要做双向差集，不能只做一个方向。

**练习 2**：为什么只检查标注表内部的坐标合法性，无法发现"标注指向不存在图像"这类问题？

**答案**：因为坐标合法性检查（如x2是否大于x1、坐标是否越界图像尺寸）只涉及标注表自身的字段数值，不涉及与图像文件的对应关系。"标注指向不存在图像"是标注表和图像文件集合之间的关系问题，必须用两者的集合运算（差集）才能发现，单看标注表内部数据是看不出来的。

**练习 3**：类别分布中bus占62%、tram仅占4%，这种不均衡会对模型训练造成什么影响？

**答案**：模型会倾向于学习数量占多数的类别（bus），对数量稀少的类别（tram）学习不充分，导致模型在实际应用中对tram类别的识别准确率明显偏低。处理方向包括对少数类过采样、或针对性补充采集更多tram类样本。

**练习 4**：坐标字段中x2小于x1，这属于什么类型的问题？

**答案**：有效性问题——坐标数据不符合逻辑定义域（矩形框的右边界应该大于左边界），属于明显的非法取值，需要退回标注环节核实修正，而不能直接使用这条记录。

**练习 5**：图像数据集质量审核的完整检查清单应包含哪些项目？

**答案**：应包含：标注与图像的交叉核查（标注指向不存在图像/图像无对应标注）、坐标合法性检查、类别分布均衡性检查、分辨率一致性检查、重复图像检查。五项检查覆盖了"跨文件关系"和"文件内部质量"两个层面，缺一不可。

## 十、小结

| 要点 | 一句话 |
|---|---|
| 核心方法 | 标注与图像须做双向交叉核查，不能只看标注表内部 |
| 文本标注新概念 | 同一对象被多人标注、结果不一致 → 属于一致性维度，不是有效性 |
| 销售数据提醒 | 检测结果为0也要写进报告，六维度不能因换数据集而漏查 |
| 职业素养 | 发现标注员个体差异时，先查制度/任务分配，再考虑是否是个人问题 |

本课题真正要你记住的不是"标注指向不存在图像4条"这些具体数字，而是它背后的方法论：**六维度这把尺子换数据类型不换，换的只是每个维度的具体检查动作**。图像要做双向差集运算，文本要看多人标注是否一致，销售要补齐唯一性检测——以后遇到任何新的数据类型，先问自己"六维度各自该怎么落地"，而不是从零去找新方法。
