# 自学教材 · 课题 1-4：采集与处理流程优化建议书撰写

> **对应国标**：职业功能1 数据采集和处理 · 1.2 数据处理方法优化 ｜ **学时参考**：4 学时 ｜ **前置知识**：课题1-1（数据质量六维度检测）、课题1-2（图像/文本/销售数据质量检测实操）、课题1-3（数据处理方法优化）
> **预计自学时间**：35-40 分钟（含自测与两个动手练习）

本教材不依赖课堂，你可以从头读到尾独立学完。前三个课题你已经练过"怎么查出数据问题"（1-1、1-2）和"怎么处理数据问题"（1-3）——这是整个模块（课题1-1至1-4，职业功能"数据采集和处理"）最后一块拼图：**把查出来、处理好的东西，写成一份别人看了就能照着推动的正式书面建议**。技术判断再准确，写不成别人能照着做的书面成果，价值也传递不出去——这正是四级阶段第一次正式的书面表达/汇报训练，也是本课题的全部意义所在。

---

## 学习目标

学完本课题，你应该能够：

1. 能说明优化建议书的结构：现状与问题 → 根因分析 → 优化方案 → 预期收益 → 实施计划与风险；
2. **能说明"合格建议书"与"不合格建议书"的本质区别**——问题是否量化、方案是否具体、指标是否可验证；
3. **能区分一个问题的根因属于"采集环节"还是"处理环节"**，并说明根因所在位置为什么决定了方案的方向（治标还是治本）；
4. 能说明建议书为什么必须包含成本与可行性考量，以及"实施计划与风险"部分具体应包含哪些内容（步骤、涉及角色、潜在风险）；
5. **能针对给定场景撰写完整的优化建议书**，并能为建议定义可度量的验证指标，针对给定问题判断其根因所在环节、据此提出分优先级的方案。

## 开篇：先立一个判断，读完再回头验证

学员小李提交了一份《化妆品门店销售数据采集与处理流程优化建议书》，内容是这样的：

> **现状与问题**：销售额字段缺失率15%（120条），且存在严重长尾分布（均值3689.6，中位数194.0，相差近19倍）；SKU003、SKU011、SKU022销售额均值偏离同类SKU正常水平（800-900元）约30-45倍，疑似数量级录入错误；门店编码存在8种大小写混用写法（应归并为4种）；销售数量字段出现24条负值/零值记录。
>
> **优化建议**：建议统一采集和处理流程规范，加强数据质量管控，提升整体数据可靠性。

项目负责人看完，把建议书打了回来，批注只有一句话：**"问题你写得比我还清楚，但接下来要做什么，我一个字都看不出来。"**

现在请你做一个判断：**"现状与问题"这部分写得扎实不扎实？** 多数人看完会觉得"写得很详细，该查的都查到了"。那么问题来了——**既然写得这么扎实，为什么还是被打回了？**

把你的判断记在心里（或写下来），先不要翻后面找答案。读完这篇教材，你会发现"把问题分析透"和"写出一份合格的建议书"之间，还隔着好几步，而小李恰恰只走完了第一步。

## 一、建议书的五段结构：为什么一段都不能少

先把整体框架立起来：

```
现状与问题（量化描述） → 根因分析 → 优化方案 → 预期收益（可度量） → 实施计划与风险
```

前三个课题练的都是"**现状与问题**"这一段——怎么查出问题（1-1、1-2）、怎么处理问题（1-3）。本课题要解决的是后面四段：怎么把"查出来、处理好"的东西，写成一份正式的推动性文件。

**为什么必须是这五段，少一段都不行？** 逐段拆开看：

- **现状与问题**：你已经很熟练了，就是1-1、1-2、1-3查出来的那些数字——缺失率、偏离倍数、混用写法种类、负值条数。
- **根因分析**：这是最容易被漏掉或写得敷衍的一环。它的作用不是"再重复一遍现象"，而是说明问题产生的**深层原因**，为后面选什么方案提供依据。少了这一段，别人不知道该往哪个方向使劲，很容易把方案用错方向（第三节会专门展开讲这个）。
- **优化方案**：针对根因给出的具体动作。
- **预期收益**：方案做完之后，一个可以验证的、量化的结果。少了它，没人知道方案做完算不算成功，也没法验收。
- **实施计划与风险**：方案不是写完就结束，还要说清楚怎么推进、谁来做、可能遇到什么阻力。少了它，方案永远停留在纸面，没人知道第一步该干什么。

还有一点容易被忽视：**建议书不是凭空写出来的，它通常建立在业务/数据分析发现的问题基础之上**——没有1-1、1-2、1-3扎实的检测和处理工作打底，"现状与问题"这一段根本写不出来。这也是为什么这个课题要放在模块的最后一个：前面三课攒的技术判断，是这一课的原材料。

## 二、合格与不合格建议书：差距到底在哪

把两份建议书的"优化建议"部分并排放在一起看。

**不合格**：

> "销售数据存在质量问题，建议加强数据治理。"

**合格**：

> "销售额字段缺失率15%，当前无填充机制；SKU003/011/022存在疑似数量级错误（销售额均值是同类SKU的30-45倍）。建议：①建立销售额缺失自动告警机制，缺失率超过5%时触发人工核查；②对销售额异常高（超过同类SKU均值10倍以上）的记录自动标记待复核。预期将销售额字段的有效性从当前85%提升至98%以上，观察周期1个月。"

先自己判断一下这两段差在哪，再看拆解：不合格的那句话有三个问题答不上来——**"存在质量问题"，什么问题？多严重？"加强数据治理"，具体怎么加强？谁来做？做到什么程度算完成？** 三个问题都答不上来，这就是"空洞"的真正含义，不是字数少的问题。合格的范例把这三个问题全答上了：问题量化了（缺失率15%），方案具体了（阈值5%、10倍），指标可验证了（85%→98%，1个月周期）。

### 把差距提炼成一个可以直接套用的公式

```
合格的优化目标 = 当前基线数值 → 具体方案 → 目标数值 → 观察周期
```

对照合格范例填一遍这张表，你会看到"四件套"一样不少，而不合格范例一件都没有：

| | 不合格 | 合格 |
|---|---|---|
| 当前基线数值 | 无 | 有效性85% |
| 具体方案 | 无（"加强治理"） | 建立缺失告警机制 + 异常标记规则 |
| 目标数值 | 无 | 98%以上 |
| 观察周期 | 无 | 1个月 |

这就是四级阶段要交付的书面成果的标准：**不是把问题说清楚就够了，优化建议本身也要满足"可验证"这条硬标准**。

### 回到开头的判断

现在回头审视小李的建议书。"现状与问题"部分确实扎实——15%、120条、30-45倍、8种混用、24条负值，数字一个不少，这部分没有问题。**问题出在"优化建议"部分**："统一采集和处理流程规范，加强数据质量管控"，套进四件套检查一下：当前基线没有、具体方案没有、目标数值没有、观察周期没有，**一件都不占**。这正是问题的本质——现状分析做得再详实，只要优化建议部分空洞，整份建议书依然会被打回。这也是为什么本课题不再练"怎么查问题"（前三课已经练够了），而是专门练"查完之后怎么写"。

## 三、动手练习一：给一份"半成品"报告打补丁

现在把刚学到的四件套用到你自己手上的材料上——如果你学过课题1-3，应该写过一份《数据处理方法优化报告》草稿，里面大概率包含三类建议：异常SKU核实修正方案、缺失值填充方法选择理由、门店编码归一化说明。

**任务**：为报告草稿中的每一条建议，补齐四件套：

1. **当前基线数值**（如"销售额字段有效性当前为X%"，直接复用1-1/1-3已验证的真实数字，不要编造新数字）；
2. **具体方案**（不是"建议处理"，要写清楚具体动作和触发条件）；
3. **目标数值**（这条建议做完之后，预期达到什么水平）；
4. **观察周期**（多久之后回头检查效果）。

做这个练习时，提醒自己留意两个最容易踩的坑：

- **把"目标数值"写成"质量变好"**。这不是一个合格的目标数值。参照第二节的范例，目标必须是一个具体数字或具体状态，比如"异常SKU数量从3个降为0个"——"变好怎么验证"答不上来，这条建议就还停在不合格的水平。
- **不知道"观察周期"该写多久**。这里没有标准答案，但有一条原则：观察周期取决于数据更新频率——如果数据按月汇总，至少观察1个月；如果按周更新，1-2周就能看到效果。唯一不允许的是空着不写。

这个练习里最容易被漏掉的一条是"门店编码归一化"这条建议——它很容易被写成"已完成"，而没有后续可验证的观察指标。正确的写法应该类似："归一化后门店编码取值数从8种降至4种，观察下一批次新数据是否仍出现超过4种取值。" 把这一条单独核对一遍，是检验你是否真正理解了"可验证"这个要求的试金石。

## 四、根因分析：找对问题不等于找对方向

### 先做一个预测

课题1-3里，门店编码大小写混用（S001/s001等8种写法）的问题，当时是怎么处理的？——用 `.str.upper()` 做归一化，8种取值合并成了4种。

**现在预测一下**：如果这批数据处理完上线了，明天系统又导入一批新的销售记录，门店编码还会不会**再次**出现大小写混用？先在心里给出答案，再往下看。

### 答案：会，而且会一直复发

1-3的归一化操作，解决的是"**已经产生的**脏数据"，但它没有触碰"**为什么会产生**脏数据"这个根源——门店录入编码时用的是自由文本输入框，谁都可以随手打成大写、小写，系统不做任何校验。只要这个录入方式不变，新数据进来，照样会混入新的大小写变体。

> **机制**：处理环节能清理已经脏了的数据，但清理不掉"为什么会脏"。每做一次归一化，只是把这一批数据擦干净了，下一批还得重新擦一遍。

把这组对比摆出来看会更清楚：

| | 处理环节优化（治标） | 采集环节优化（治本） |
|---|---|---|
| 动作 | 每次拿到数据后做清洗（如 `.str.upper()`） | 从录入端改为下拉选择/系统校验，禁止自由文本输入 |
| 效果 | 已产生的问题被清理，但新数据仍会复发 | 问题从源头被杜绝，后续数据天然规范 |
| 成本 | 看似每次成本很低，但长期重复执行、累积维护成本高 | 有一次性改造成本，但一劳永逸 |

### 这就是"根因分析"存在的意义

根因分析不是把现象再重复一遍（"门店编码有8种写法"这句话谁都会写），它要回答的是：**这个问题到底出在哪个环节**。只有先确定了环节，优化方案才知道该往哪个方向使劲。不做根因分析、拿到问题直接堆处理方案，很容易一直在"治标"上反复用力，却从没碰过源头。

> **判别口诀**：下一批新数据还会不会复发同样的问题？**会 → 到采集环节找根因。不会 → 处理环节内部解决就够了。**

### 注意：同一个现象，根因可能不同，不能套公式

不要死记"门店编码问题=采集环节问题"这种对应关系。拿"销售额字段缺失15%"这个现象举例，背后至少有两种完全不同的可能：

- 如果是门店收银系统**没有强制要求**录入销售额字段——根因在**采集环节**，方案应该是给收银系统加必填校验；
- 如果销售额本身都录入了，只是后台在合并多个门店数据源时脚本逻辑有漏洞、把部分字段弄丢了——根因在**处理环节**，方案应该是修复合并脚本的逻辑。

同一个"缺失15%"的现象，背后可能是完全不同的根因，必须具体排查，这正是根因分析比现象描述更难、也更有价值的地方。

### 自测：给你留的四个现象，先自己判断一遍

课题1-1/1-2里还查出过这几个现象：会员等级缺失18%（144条）、销售数量字段24条负值/零值记录、transport类图像标注指向不存在图像（4条）。拿前面学到的判别口诀问自己一遍：**如果明天来一批新数据，同样的问题还会不会复发？** 如果答案是"会"，说明根因更可能在采集或前置环节；如果答案是"不会"（比如只是这一批历史数据里偶然出现的个例，机制上不会规律性重现），处理环节内部修正就足够。

这里不直接给你"标准答案"，是因为这几个现象是否会复发，取决于具体业务场景里"数据是怎么产生的"这一层事实——这正是根因分析必须"具体排查、不能套公式"的地方，和死记硬背答案背道而驰。你可以参照上面"销售额缺失15%"的两种可能性，给每个现象都想出至少一种会导致它复发、一种不会导致它复发的具体场景，训练自己从现象倒推机制的思维习惯。

## 五、成本可行性与实施计划：为什么"理想方案"也会被打回

第四节讲到采集环节能治本，那是不是建议书应该直接写："立即把采集系统全面推倒重做，所有字段都加上强校验"？

**先判断一下**：这个方案合理吗？

### 答案：方向对，但这么写同样会被打回

这个方案听起来很彻底，但负责人看完大概率会追问：**要花多少成本？由谁来改造——IT部门要排期多久？改造期间门店收银系统还能不能正常使用？** 如果这些问题答不上来，"立即全面重构"和开头那句"加强数据治理"其实是同一种空话，只是听起来更有技术含量而已——**两者的共同缺陷都是：只说了方向，没说清楚怎么走到那个方向、要付出什么代价**。

> **机制**：理想方案只回答"该怎么做最彻底"；可行方案还要回答"用多大代价、花多久时间、谁来推进"。少了后半句，再正确的方向也无法落地，负责人没法基于一句"推倒重做"做决策。

### 更合格的写法：分阶段、分优先级

> ①**优先**对影响范围最大、改动成本最低的门店编码字段，先在前端加一个下拉选择框（改动小，1-2周可上线）；
> ②销售额/销售数量的自动化异常检测规则，作为**后续阶段**，先在异常率最高的门店试点，验证有效后再全面推广。

这样写，既保住了"治本"的方向，又给出了负责人能接受、能落地的节奏——这就是"成本与可行性考量"在建议书里真正发挥的作用：**不是让方案变得保守，而是让正确的方向变得可执行**。

> **判别口诀**：理想方案 ≠ 可行方案。**理想方向 + 分阶段 + 说清楚谁来做/多久/什么风险 = 可行方案。**

### 实施计划与风险的三个必备要素

很多人把"实施计划与风险"这一段直接漏掉，或者只写一句"尽快实施"。这一段有明确的三个必备要素，缺一不可：

1. **步骤**——先做什么、后做什么（就是上面的①②两步）；
2. **涉及角色**——谁来改、谁来验收（例如"IT部门负责前端改造，数据组负责验收新采集数据的合规率"）；
3. **潜在风险**——可能遇到什么阻力（例如"采集系统改造涉及IT部门排期，短期内可能增加门店录入操作步骤，一线人员或有抵触，需提前培训说明"）。

**为什么这三样缺一不可？** 少了"步骤"，负责人不知道从哪里开始推进；少了"角色"，方案容易变成"谁都该做、谁都没做"；少了"风险"，一旦推进中遇到预料外的阻力（比如一线门店抵触改用下拉选择框），团队毫无准备，项目很容易半途而废。这三样信息合在一起，才能让一个"方向正确"的方案真正被推进下去，这也是为什么"实施计划与风险"和"优化方案"必须是两个独立的段落，不能合并成一句话带过。

## 六、动手练习二：撰写完整的优化建议书（本课题的终产物）

现在把前面五节的内容合成一份完整产出。

**任务**：假设你是一名四级训练师，基于课题1-1~1-3对 `cosmetics_sales.csv` 的质量检测与处理方法优化发现，撰写一份完整的《化妆品门店销售数据采集与处理流程优化建议书》。

**建议书必备七段模板**（照这个结构填充）：

```
一、背景说明（本建议书基于课题1-1~1-3对cosmetics_sales.csv的质量检测与处理方法优化发现撰写）
二、现状与问题（量化，逐条列出，可直接复用1-1/1-3已验证数据）
三、根因分析（逐条问题标注根因所在环节：采集环节 / 处理环节，并简述根因）
四、优化方案（按环节分类列出，并标注优先级：立即可做 / 短期 / 中长期）
五、预期收益（每条方案对应"当前基线 → 目标数值 → 观察周期"四件套）
六、实施计划与风险（步骤、涉及角色、潜在风险）
七、成本与可行性说明
```

写之前，先把三个最容易写得不合格的地方记牢，动笔时逐条对照自查：

- **第一，根因分析只写现象，不标环节。** 写"销售额缺失15%"不够，要接着写"根因：门店收银系统未强制要求录入销售额字段，属采集环节问题"。
- **第二，优化方案全部堆在处理环节。** 第四节讲过，这是治标不治本。写完之后回头看看自己的方案清单，有没有至少一条是指向采集源头的。
- **第三，预期收益没有数字。** 每条方案后面必须跟着四件套，不能写"质量会提升"这种话。

这三项是区分"写了"和"写合格"的关键项，写完之后请逐一对照检查。

## 七、自我诊断：三类常见的不合格建议书

因为自学没有同学互评这一环，这里直接给你三份预先诊断好的"典型不合格建议书"案例，供你对照自己刚写的建议书，检查是否也踩中了同样的坑：

| 案例 | 场景描述 | 应诊断出的问题 |
|---|---|---|
| A | 建议书把1-1/1-3发现的问题列得很全，但"优化方案"只写"统一处理流程规范，加强数据质量管控" | 方案空洞，缺乏四件套——正是开篇"打回"案例的翻版 |
| B | 建议书方案详实，但全部聚焦处理环节（"继续用中位数填充""继续做门店编码归一化"），完全没有采集环节的方案 | 治标不治本，没有做根因环节区分。自测方法：问自己"如果明天又进一批新数据，这些方案能不能防止问题再次出现" |
| C | 建议书提出"立即重构整个采集与处理系统，一步到位解决所有问题"，但没有分阶段、没有成本说明、没有实施步骤和角色分工 | 理想化方案，缺乏成本可行性和实施计划三要素。自测方法：按第五节的三要素逐条检查，步骤、角色、风险分别写了没有 |

把你自己写的建议书拿出来，逐条对照这三类案例的特征，看看有没有相似的影子。这是自学场景下替代"同学互评"的核查方式。

## 八、回到开头：小李的建议书该怎么改

现在把前面几节的内容合起来，重新审视开篇小李那份被打回的建议书。

"现状与问题"部分不用动，数据已经足够详实。问题出在"优化建议"部分，需要按以下方式重写：

1. **区分根因环节**：销售额缺失、SKU数量级错误更可能是**处理/核实环节**问题（需要排查录入流程和核实价格表）；门店编码混用更可能是**采集环节**问题（录入时未做格式校验）。
2. **分优先级给方案**：先做成本低、见效快的（如门店编码改下拉选择），再做需要试点验证的（如异常值自动标记规则）。
3. **每条方案补上四件套**：例如"销售额有效性当前85% → 建立缺失告警+异常标记规则 → 目标98%以上 → 观察1个月"。
4. **补上实施计划与风险**：写清步骤、涉及的IT/数据组角色、以及可能遇到的一线抵触风险。
5. **补上成本与可行性说明**：哪些改动成本低可以立即做，哪些需要排期和预算。

把这五点补齐，"统一采集和处理流程规范，加强数据质量管控"这句空话，就能变成一份负责人能直接拍板推进的正式建议书。

**本模块（课题1-1至1-4）走的是同一条主线**：先学会检测问题（1-1/1-2）→ 再学会处理问题（1-3）→ 最后学会把它写成能推动别人行动的建议（1-4）。技术判断再准确，写不成别人能照着做的书面成果，价值也传递不出去——这就是本课题要教给你的最后一块拼图。

## 考点清单

| 考点 | 考试怎么考 | 易错点 |
|---|---|---|
| 建议书可度量性 | 实操核心 | **写成"问题罗列+笼统建议"，没有可验证的指标**——记住四件套：当前基线→具体方案→目标数值→观察周期 |
| 根因分析（采集 vs 处理环节） | 实操 / 判断 | 跳过根因分析直接给方案，容易治标不治本；或死记"某类问题=某环节"的固定对应关系，而不具体排查 |
| 成本可行性 | 实操 | 只谈理想方案，不考虑实施成本、周期、责任人 |
| 实施计划与风险 | 实操 | 漏写步骤/角色/风险三要素中的一项或多项，或只写"尽快实施"这类空话 |

## 自测练习

以下练习直接取自配套随堂练习，建议先独立作答、写下自己的答案，再核对参考答案。

**练习 1**：把"建议优化数据采集流程"这句话改写成一个可度量的优化目标。

**答案**：示例——"当前数据采集环节人工录入错误率约8%，建议引入自动化校验规则（如字段格式校验、取值范围校验），预期将录入错误率降至2%以下，观察周期2周。"关键是给出当前基线数值、具体方案、目标数值和观察周期。

**练习 2**："销售数据存在质量问题，建议加强数据治理"这句话存在哪些具体问题？

**答案**：三个问题都没有回答：①"存在质量问题"没有说明是什么问题、有多严重（缺乏量化）；②"加强数据治理"没有说明具体怎么做、谁来做（方案空洞）；③没有说明做到什么程度算完成、怎么验证效果（缺乏可验证指标）。这三点缺一不可，是建议书是否合格的核心判断标准。

**练习 3**：建议书中为什么必须包含成本与可行性考量？

**答案**：因为脱离成本和可行性的"理想方案"即使技术上正确，也可能因为资源不足、周期过长等原因无法落地。建议书的目的是推动实际改进，而不是展示理想状态，必须让读者（通常是决策者）能判断这个方案现实中能不能做、值不值得做。

**练习 4**：优化建议书的"根因分析"环节，和"现状与问题"环节有什么区别？

**答案**："现状与问题"描述的是观察到的表面现象（如销售额字段缺失率15%），"根因分析"要回答这个现象背后的深层原因（如为什么会缺失——是采集环节没有强制校验，还是系统对接存在遗漏）。根因分析的质量直接决定了后续优化方案是否对症，跳过根因分析直接给方案容易"治标不治本"。

**练习 5**：一份建议书只写了详实的问题分析，但没有给出具体优化方案，这份建议书合格吗？

**答案**：不合格。建议书的核心价值在于"建议"，即提出可执行的优化方案，仅有问题分析没有解决方案等于只完成了一半工作。四级的能力要求是"对业务数据处理方法提出优化建议"，缺少建议部分无法体现这项核心技能。

## 小结

| 要点 | 一句话 |
|---|---|
| 建议书结构 | 现状 → 根因 → 方案 → 可度量收益 → 实施计划，一段都不能少 |
| 合格标准 | 问题量化、方案具体、指标可验证、考虑成本——四件套：基线→方案→目标→周期 |
| 根因分析的价值 | 决定方案该往采集环节（治本）还是处理环节（治标）使劲，同一现象根因可能不同，不能套公式 |
| 实施落地的前提 | 理想方案≠可行方案，须补齐步骤/角色/风险三要素 |
