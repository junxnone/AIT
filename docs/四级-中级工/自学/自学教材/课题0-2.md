## 学习目标

读完本教材，你应当能够：

1. 说明《劳动法》《劳动合同法》《网络安全法》《知识产权法》（国标明列的四部）与数据工作的关联点；
2. 说明《数据安全法》《个人信息保护法》（国标里的延伸内容）的核心要求，并解释为什么这两部在实际工作中触发频率远高于前面四部；
3. **能识别数据采集、存储、标注、共享各环节的合规风险点，并提出整改措施**（这是本课题的核心技能目标，也是考试和实际工作中分量最重的部分）；
4. 理解"标注环节本身也需要访问控制"这个容易被忽视的素养要求。

## 写在最前面：你正在完成一次角色升级

如果你是从五级一路学上来的，先弄清楚一件事：五级阶段的合规意识训练，教的是**个人行为层面**的判断——"我作为标注员，哪些具体动作不能做"，比如不能把数据带出工作场所、不能用私人设备存储等等。那套"个人违规清单"你应该已经很熟了。

但四级要求的是完全不同维度的能力：**审核者视角**。面对一个别人交上来的、看起来已经走完流程的数据项目，你能不能系统地把全流程的合规风险点挑出来，并且给出整改意见？这是从"管好自己手上的动作"到"审核别人的流程是否合规"的一次角色升级。

这次升级最大的陷阱是：很多人会不自觉地把五级那张"个人违规清单"直接当成四级的"审核清单"来套用——清单里列过的点，一查就能查到；清单之外的环节（尤其是标注、共享这两环），反而容易被系统性地漏掉，而且漏掉的人自己完全意识不到漏掉了什么。本教材接下来的内容，就是要把这张"审核清单"从"个人动作"升级成"全流程链路"。

### 先做个判断（请务必写下来再继续）

你是某人脸识别数据项目本季度的四级合规审核负责人。审核员提交的报告上写着：

> **"已核实采集环节取得用户同意，审核通过。"**

项目经理拿着这份报告，准备签字结项。

**花三十秒判断：这份报告能签字通过吗？**

把你的判断写在这里：___________________

记住这个判断。读完"一、全流程合规风险排查"这一节，你会发现，这份看起来"挑不出毛病"的报告，恰恰漏掉了审核工作里最容易被漏掉的部分——而且大多数人第一反应都会倾向于"采集都合规了，应该没问题"。

## 一、合规不是只看采集阶段——全流程风险排查

很多人以为"合规审核"就是查一下采集时有没有取得用户同意，标注、存储、共享这些中间环节就不用特别管了——**这正是开头那份审核报告在犯的错**。一个完整的数据项目流程是：

```
采集 → 存储 → 标注 → 共享
```

每一环都有独立的合规风险点，不能只查其中一环就收工：

| 环节 | 风险点 | 整改措施 |
|---|---|---|
| 采集 | 未明示收集目的、未取得同意 | 告知-同意流程须具体到用途 |
| 存储 | 未加密、访问权限过大 | 加密存储、权限最小化分配 |
| **标注** | **标注员能看到可识别身份的原始信息**（最容易被漏查的一环） | **脱敏后再交付标注，访问权限只开放标注所需字段** |
| 共享 | 超出原始授权范围与第三方共享 | 共享前核实是否需要重新取得用户同意 |

### 代入一个真实场景，自己先排查一遍

某公司的人脸识别数据项目：**采集**（线下门店摄像头）→**存储**（云服务器）→**标注**（外包团队远程标注）→**共享**（与算法供应商共享训练数据）。

在继续往下读之前，请拿张纸，花 3 分钟，把你能想到的这四个环节里各自的合规风险点写下来——真实的培训现场里，几乎每一组学员第一轮讨论都只能想到"采集环节是否取得同意"这一个点，**标注环节几乎是全员第一轮都会漏掉的**。如果你也只写出了采集这一个点，完全正常，这正是接下来要讲的内容要解决的问题。

标准答案要点是：

- 采集：是否已告知并取得同意，是否有明示收集目的
- 存储：是否加密，访问权限是否最小化
- **标注：外包团队是否签署保密协议，标注过程能否看到可识别身份信息（应脱敏后标注）**
- 共享：与第三方共享是否超出原始授权范围，是否需要重新取得同意

### 为什么"标注"是最容易被漏掉的一环？

这不是偶然，背后有一个认知上的具体原因：**合规培训历来第一课永远是"采集前要取得同意"**，这个点几乎所有人都从入职第一天就刻在脑子里了。但标注环节是近几年才大规模外包化、流程复杂化的，很多团队的合规制度和培训重点还停留在"管好采集"的阶段，没有同步升级到"管好标注"。**制度和培训没跟上，审核人员脑子里的检查清单自然也没跟上**——这不是哪个审核员粗心，而是整个行业的合规意识更新速度，暂时跟不上业务外包化的速度。这个机制你一旦理解了，以后遇到任何"新出现的业务环节"都可以套用同一个判断：越是新近才普及的流程环节，越容易因为"制度没跟上"而成为合规死角，审核时要刻意多留意。

现在回头看开头那份判断题：**这份审核报告不能签字。** 它只核实了采集环节，而外包标注团队在远程标注时，能接触到的很可能是原始的、未脱敏的人脸图像——这个风险点完全没有被审核到。对照一下你自己最初的判断，如果你当时判断"可以签字"，说明你也踩进了这个高发陷阱里，这恰恰证明了这套思维训练的必要性。

### 审核时该怎么查？—— 链路型思维

正确的做法不是死记几个风险点，而是建立一种思维习惯：

> **拿到任何数据项目的审核任务，先把"采集→存储→标注→共享"这条链路完整过一遍，每一环都问一遍："谁能看到数据，看到的是不是已经处理过（脱敏/限权）的数据？"**

这叫**链路型思维**，区别于只盯着采集环节、查完一个点就觉得"查完了"的**单点思维**。四级训练师和五级标注员最本质的区别之一，就在于五级只需要管好自己手上那一个环节，四级要能审出别人整条链路上任何一环的漏洞。

**记忆口诀**：单点思维只问"这一环合不合规"；链路思维要问"整条链路，每一环分别合不合规"——少问一环，就等于没查。

## 二、国标四部法规：管的是"关系"和"底线"

国标明列的相关法律法规一共四部：《劳动法》《劳动合同法》《网络安全法》《知识产权法》。不需要逐条背条文，只需要记住每一部和数据工作的具体关联点：

| 法规 | 与数据工作的关联点 | 讲解要点 |
|---|---|---|
| 《劳动法》《劳动合同法》 | 保障从业者的劳动权利义务关系 | 这两部约束的是"你和公司之间"的关系，不直接管你怎么处理数据，但涉及外包标注团队时，公司要确认外包人员的用工关系是否合规，这也属于审核范围的一部分 |
| 《网络安全法》 | 保障网络运行安全与数据安全，是数据安全的"底线法" | **方向性要求**：促进数据依法有序流通的同时，保障网络运行安全。不是"限制流通"，也不是"放任自由"，而是在安全前提下流通 |
| 《知识产权法》 | 涉及训练数据和模型产出的权属问题 | 训练数据本身（如采购的图片库、文本语料）可能涉及版权；训练出的模型产出物权属也要厘清——这是数据工作里最容易被忽视的一部，因为它不直接管"隐私"，而管"谁拥有这份数据/这个结果" |

你可能会发现，日常工作里真正天天打交道的，其实不是这四部——这一点我们在下一节展开。

---

## 三、延伸两部法规：为什么它们才是日常真正的雷区

《数据安全法》《个人信息保护法》是国标里的延伸内容，不在明列四部之内，但有一个结论要先立住：**这两部法规在实际工作中触发频率远高于那四部。**

### 为什么会这样？—— 先自己想一下原因

在往下看答案之前，想一想：《劳动法》管的是你和公司之间的关系，一年可能就入职、离职时碰一次；《数据安全法》《个人信息保护法》管的是什么？你每天工作要不要碰到它管的那些内容？

答案的机制是这样的：**《劳动法》《劳动合同法》管的是你和公司之间"一次性"或"低频"的关系**，入职签一次合同，基本就定了；《知识产权法》只在涉及版权素材时才用上。但**《数据安全法》《个人信息保护法》管的是你每天都在做的具体动作**——处理、标注、审核数据。只要你打开一条含用户信息的样本、导出一份数据、转发一张截图，理论上都受这两部法规约束。这就是为什么新人最容易"踩坑"的，不是劳动合同条款，而是这两部延伸法规——**它们管的是你每天都在做的具体动作，而不是入职签一次字就完事的条款。**

**记忆口诀**：国标四部管"低频的关系"，延伸两部管"天天做的动作"——越是天天做的事，踩雷概率越高，这就是为什么延伸法规更常触发。

### 两部延伸法规的核心要求

| 法规 | 核心要求 |
|---|---|
| 《数据安全法》 | 数据分类分级保护；重要数据和核心数据需要更高的保护等级和审批流程 |
| 《个人信息保护法》 | 处理个人信息须遵循**合法正当必要、公开透明、目的明确**等原则；**不是"利益最大化"** |

**易混淆点（考试高发坑）**：有人会把"合法利用数据创造最大商业价值"误当成个人信息保护的一条合规原则——这是把"商业目标"和"合规原则"搞混了。个人信息保护法的原则清单里从来没有"利益最大化"，考试遇到"下列哪项不属于个人信息处理应遵循的原则"这类题，看到"利益最大化"选项直接排除即可。

## 四、最小必要原则：不是"越少越好"

### 先做个判断

某项目组为了"保险起见"，把业务其实不需要的字段（比如用户的婚姻状况、学历）也统一采集下来，理由是"以后万一用得上，不缺"。

**这样做符合最小必要原则吗？**先写下判断，再往下看。

### 答案与机制

答案是**不符合**。很多人对"最小必要"的理解走偏到了另一个极端——以为意味着"数据越少越安全"，于是该采的也不敢采、不该采的也顺手采了"以防万一"。**这两种做法都错了**：

- 监管检查最小必要原则，核验的是**"采集范围是否与声明的业务目的匹配"**，不是看采集字段的绝对数量多少；
- 如果业务明明需要某个字段却因为"怕违规"而不采，反而会倒逼业务人员通过非正式渠道（私下询问、线下记录）去补采，这制造的是**新的、更难管控的合规风险**，而不是减少了风险；
- 反过来，"以防万一"多采的字段，一旦用户追问"这个字段你们用来做什么"，答不出来对应的业务目的，就是最直接的违规证据。

**判别口诀**：遇到"这个字段该不该采"的问题，别去数数量，问自己一句——**这项数据是不是实现这个业务目的所必须？是 → 该采；不是 → 不该采，无论"将来可能用得上"这个理由听起来多合理。**

### 最常被忽视的环节：标注环节的访问控制

很多人默认"脱敏是采集/存储阶段的事"，但实际上标注员在打标签过程中接触到的原始数据同样要做访问控制——比如医疗影像标注任务，标注人员能看到影像但不应看到患者姓名、身份证号等关联信息。

**为什么标注环节的风险比采集环节更隐蔽、更容易出事？**

因为采集环节通常由公司内部、相对固定的人员负责，流程也经过多次合规审计打磨；而标注环节大量依赖**外包团队**，人员流动性高、所在地分散、设备和网络环境不受公司直接管控。一旦标注环节的访问权限没有做限制，相当于在整条合规链路的中间开了一个没有把关的口子——**采集和存储做得再严密，标注这一环松了，前面的努力就全部归零。**

## 五、真实个案：工作群截图算不算违规

### 场景

某标注员觉得一条标注规则写得不清楚，为了向同事请教，把一张**含有用户手机号的原始样本截图**发到了工作群里讨论。

**这是工作群，又不是私人聊天，而且出发点是认真讨论工作——这样做违规吗？**先写下你的判断。

### 答案：违规

即使是工作群、即使出发点是认真讨论问题，**未脱敏的用户手机号被发到群里（哪怕群里都是同事）也构成敏感信息扩散**。

### 关键认知：审的是客观结果，不是审动机

这里最容易出现的争议是："动机明明是好的，为什么也算违规？"

答案是：**审核工作审的是客观结果，不是审动机。** 审核员没法要求自己去猜每一次操作背后的动机是好是坏，审核标准必须是客观、可执行的——判断依据只能是"这条信息有没有脱敏就进入了不受控的传播范围"，而不是"操作人当时是怎么想的"。如果"动机正当"可以免责，那几乎任何一次违规操作，操作人事后都能找到一个听起来合理的理由，审核标准就彻底失去了约束力。

换个角度想：群里的同事，是不是每一个人都被授权可以看到未脱敏的用户手机号？这条信息一旦进了群，公司还能不能管控它接下来会被转发到哪里？只要答案是"不能"，这件事客观上就已经脱离受控范围，违不违规已经不取决于发群的人是怎么想的了。

**判别口诀**：遇到"要不要把含用户信息的内容发出去"这类情况，先问自己一句——**这条信息离开我手上之后，去了一个受公司管控、能追责的地方，还是一个管不着、也追不到的地方？** 去受控渠道（如正式工单系统）通常没问题；去工作群、个人社交账号、私人设备，都属于管不着的地方，一律先脱敏或先问。

正确做法应该是：先对截图做脱敏处理（遮挡手机号），或者干脆不附截图、只用文字描述问题本身，再通过正式渠道反馈给负责制定规范的人。

## 六、违规后果：为什么"小动作"代价不成比例

很多人觉得"截图发个群""拷贝一份带回家"顶多算"不太规范"，不会有什么实质后果。这个想法低估了问题的严重性，分三层看后果：

| 层面 | 具体后果 |
|---|---|
| 对用户 | 手机号、地址一旦流出，轻则被骚扰电话、精准诈骗盯上；医疗、金融类敏感数据流出可能被用于更严重的身份冒用 |
| 对公司 | 根据《数据安全法》《个人信息保护法》，公司对外部泄露负有合规责任，轻则被监管部门处罚、客户索赔，重则项目被叫停、公司资质受影响 |
| 对操作人本人 | 造成泄露的具体操作人需要承担相应责任，情节严重的甚至要承担法律责任，不是"批评教育"就能了结 |

这也是为什么合规培训反复强调"截图""私拷"这类看起来很小的动作——**代价和动作的大小完全不成比例**，一次随手的截图外发，后果可能远超当事人的预期。这正好回应了上一节那场"动机正当算不算免责"的争议：不是审核标准"小题大做"，是后果链条真实存在且不对称——小动作可能引发大后果，审核才必须守住客观标准，不能因为"动机听起来合理"就放松。

## 七、迁移应用：为外包标注团队撰写合规管理清单

现在把前面学到的内容整合起来，做一次实战应用。回到第一节的人脸识别项目场景：标注环节是外包团队负责，是风险最集中的一环。假设你是这个项目的四级训练师，需要为外包标注团队撰写一份**合规管理清单**，提交审核通过后才允许外包团队开工。

一份合格的清单应包含以下五个模块：

```
一、准入条件
    · 是否签署保密协议（明确双方权责）
    · 是否完成合规培训并留存记录
二、访问权限与范围
    · 限定数据访问权限（只开放标注所需的脱敏数据）
    · 是否存在可识别身份信息的残留（姓名/手机号/证件号等）
三、环境管控
    · 标注环境是否满足基本安全管控（如禁止个人设备接入、禁止截图外发）
四、数据生命周期
    · 明确数据使用期限
    · 明确任务结束后的数据销毁或退回要求
五、违规处理机制
    · 发现违规行为后的上报、整改、追责流程
```

### 两个最容易漏掉的地方

**第一，只写"签保密协议"，不写"限定访问权限与范围"。** 协议是事后追责的依据，权限控制才是事前防范——两者缺一不可，这也是题库里考"外包管理应包括什么"时的标准得分点。把两者分开列为独立条目，而不是合并成一句"签个协议就行"，是评分时的一个关键区分点。

**第二，漏掉"数据销毁"这一项。** 外包任务结束后，数据有没有被留存在外包方本地设备上，是审核工作最容易被忽视、但出了事最难追责的一环。

把这份清单和第一节的"链路型思维"对照一下，你会发现：五个模块其实就是把"标注"这一个环节，按照"谁能接触、接触范围多大、环境是否受控、数据何时销毁、出事怎么办"重新拆成了五个更细的检查点——这是同一套链路型思维在更细颗粒度上的应用。不能因为是外包就降低合规管理的标准，外包方同样要纳入统一的合规管理体系。

## 自测练习

完成下面 5 道练习，建议先独立作答，再对照答案核查。答案已直接展开（自学材料不设折叠），但请先自己写出答案再看。

**练习 1**：某标注外包团队在远程标注医疗影像时，能同时看到患者姓名和病历号。这是否合规？

**答案**：不合规。标注环节同样需要访问控制，应在交付标注前对患者身份信息做脱敏处理，标注员只应看到标注所需的影像本身。

**练习 2**：某人脸识别数据项目的流程是"采集→存储→标注→共享"，为什么说"标注"是最容易被忽视的合规风险环节？

**答案**：因为很多人默认合规只是采集阶段的事（取得用户同意），一旦采集合规了就觉得"没问题了"，却忽视了标注环节同样会接触到原始的、未脱敏的数据——尤其是外包远程标注场景，标注人员本身是否可信、能否看到可识别身份的信息，都是容易被遗漏的风险点。

**练习 3**：与第三方算法供应商共享训练数据时，除了保证数据已脱敏，还需要额外核实什么？

**答案**：需要核实这次共享是否超出了用户最初授权的使用范围。即使数据已脱敏，如果用户当初的授权范围不包括"共享给第三方算法供应商训练模型"这一具体用途，仍然需要重新取得用户同意，而不能仅凭"已脱敏"就认为共享合规。

**练习 4**：最小必要原则是否意味着"采集的数据越少越好"？

**答案**：不是。最小必要原则的核心是采集和处理范围应与业务目的相匹配，既不能超范围采集，也不是为了"少"而刻意遗漏业务所需的必要数据。判断依据是"是否为实现该业务目的所必需"，而不是单纯追求数据量最小化。

**练习 5**：外包标注团队处理敏感数据时，合规管理应包含哪些要素？

**答案**：应包括：签署保密协议明确双方权责；限定数据访问权限与范围（只开放标注所需的脱敏数据）；对标注环境做必要的安全管控；明确数据使用期限和销毁要求。不能因为是外包就降低合规管理的标准，外包方同样要纳入统一的合规管理体系。
