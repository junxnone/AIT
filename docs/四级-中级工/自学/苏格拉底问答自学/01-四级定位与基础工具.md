## 开场：先问你一个问题

你刚从五级考上来，或者刚开始接触四级的内容。我想先问你一句——**你觉得四级比五级难在哪？**

## 一、四级到底"新"在哪里

### 1. 先看职业的"地图"

人工智能训练师（职业编码4-04-05-05）的官方定义是这样写的：

> 使用智能训练软件，在人工智能产品实际使用过程中进行**数据库管理、算法参数设置、人机交互设计、性能测试跟踪**及其他辅助作业的人员。

这四个关键词——数据库管理、算法参数设置、人机交互设计、性能测试跟踪——几乎是整个职业五个等级共用的"地图"。不同等级只是在地图的不同区域深挖。这个职业还包含两个工种：**数据标注员**、**人工智能算法测试员**。四级两个工种都要懂。

### 2. 五级和四级，模块名字一模一样——这才是最容易踩的坑

现在来做个对照。把五级和四级的职业功能模块名字摆在一起看：

- 数据采集和处理
- 数据标注
- 智能系统运维

**一字不差**。那四级到底在"新"什么？

先别急着翻答案，自己想一想：如果模块名字完全相同，国标要怎么写，才能让两个等级看起来"不一样"？

……

答案是：**改动词**。请看这张对照表：

| 职业功能 | 五级（做） | 四级（审+优化） |
|---|---|---|
| 数据采集和处理 | 完成原始数据采集、整理归类与汇总 | **审核**业务数据质量、**提出优化建议** |
| 数据标注 | 完成清洗、完成标注 | **聚类分析**发现关联、**审核**标注准确性完整性、**纠正**错误、**筛选**数据 |
| 智能系统运维 | 开启、简单使用、记录 | **维护**、**部署**、**基于数据分析提出优化方案** |

看出规律了吗？五级那一列的动词是"完成""开启""使用"——都是**执行动作本身**。四级这一列的动词是"审核""优化""纠正""筛选""部署"——都是**对别人（或对系统现状）的产出做判断、做改进**。

现在回到开场的问题："四级比五级难在哪？"——**不是同一件事做得更熟练，是从"做这件事的人"变成"判断这件事做得好不好、能不能改进的人"。**

打个比方：五级是生产线上的操作工，四级是**质检员+工艺改进员**。质检员不需要比操作工手更快，但需要有一套操作工不需要具备的判断能力——"这批货合格吗？""这道工序能不能改进？"

### 3. 一个小实验检验你有没有真的理解

某标注员提交了1000条标注数据，要求对其进行准确性抽检并输出审核报告。这是五级的技能要求还是四级的？

花十秒想一想，再往下看。

……

**四级**。因为这不是"做标注"这个动作本身，而是"审核别人的产出、输出审核报告"——判断能力在前，报告产出在后，这正是"质检员"角色的体现。

再追问一句：如果审核中发现了50条标注错误，你去把它们批量改对，这个"改错"的动作，算不算又绕回了五级那种"执行"？

……

**不算**，依然是四级。因为批量纠正错误的前提是**你已经判断出"这是错的"**——这个判断本身就是审核能力的体现，纠正只是审核流程往下走的自然延伸，不是独立于审核之外的另一件事。

> 🔑 **判别口诀**：看一个动作算五级还是四级，别看"手上在干什么"，看这个动作**依不依赖一个判断**。不依赖判断、照章执行 → 五级；依赖对别人产出或现状做判断 → 四级。

最后再提醒一句容易被忽视的误区：有学员会说"我五级标注经验丰富，四级肯定比五级简单"。这个想法只对了一半——标注经验确实是审核时的重要基础（没亲手标过数据，审核时缺乏判断依据），**但"审核他人产出、发现问题、提出优化"本身是一套新技能**，不会因为标注熟练就自动具备，需要专门训练。

职业守则三条，顺手记一下：**诚实公正、严谨求是；遵章守法、恪尽职守；勤勉好学、追求卓越。**

## 二、合规红线：不只是"采集时要取得同意"这么简单

### 先做个判断

某标注外包团队在远程标注医疗影像时，能同时看到患者姓名和病历号。

**这是否合规？** 花三十秒想一想你的判断，再往下看。

……

大多数人第一反应是"看采集阶段取没取得患者同意"。但请注意，题干问的根本不是采集阶段，而是**标注这个环节**。这就是本节要纠正的第一个思维习惯。

### 1. 合规风险点贯穿全流程，不止在"入口"

一个完整的数据项目流程是：

```
采集 → 存储 → 标注 → 共享
```

很多人默认"合规=采集时取得同意"，一旦采集环节没问题就松了一口气，却忘了后面三个环节各自都有独立的风险点：

| 环节 | 风险点 | 整改措施 |
|---|---|---|
| 采集 | 未明示收集目的、未取得同意 | 告知-同意流程须具体到用途 |
| 存储 | 未加密、访问权限过大 | 加密存储、权限最小化分配 |
| **标注** | **标注员能看到可识别身份的原始信息** | **脱敏后再交付标注，访问权限只开放标注所需字段** |
| 共享 | 超出原始授权范围与第三方共享 | 共享前核实是否需要重新取得用户同意 |

现在回答开头那个判断题：**不合规**。问题出在标注环节的访问控制——标注员在打标签的过程中接触到的原始数据，同样需要做脱敏和权限管控，不是"采集/存储阶段管好了，后面就自动安全了"。这家外包团队的标注人员，本应只看到脱敏后的影像本身，不应该同时看到患者姓名和病历号这些关联身份的信息。

**为什么标注环节最容易被忽视？** 因为大多数人对"合规"的第一反应就是"取得用户同意"，这个反应在采集环节是对的，但很容易让人产生一种错觉——"合规是入口的事，后面的环节只要别出大乱子就行"。而标注环节恰恰是**原始的、未脱敏的数据**被人眼直接接触最多的一环（标注员要看着原始影像/原始文本去打标签），风险密度其实比存储、共享更高，却最容易被遗漏。

国标明列的相关法规有《劳动法》《劳动合同法》《网络安全法》《知识产权法》；延伸内容还包括《数据安全法》《个人信息保护法》——这些法律条文背后对应的，正是上表里这四个环节的风险点。

### 2. 最小必要原则：一个常被曲解的概念

再出一道判断题：**最小必要原则，是不是意味着"采集的数据越少越好"？**

……

**不是**。最小必要原则的核心是**采集和处理范围应与业务目的相匹配**——既不能超出业务目的去多收集，也不是为了"少"而刻意遗漏业务所必须的数据。判断依据是"这项数据是不是实现该业务目的所必需的"，而不是单纯追求数据量越小越好。

举个极端的反例帮你记住：如果一个风控模型业务上必须用到用户的收入区间，你因为"要少采集"而不采这个字段，模型根本没法训练——这不叫合规，这叫"用合规的名义不干正事"。

### 3. 与第三方共享时，脱敏够不够？

再问一道题：与第三方算法供应商共享训练数据时，只要保证数据已经脱敏，是不是就合规了？

……

**不够**。脱敏只解决了"这批数据会不会暴露具体是谁"的问题，但还有另一个独立的问题没解决：**这次共享的用途，是否在用户最初授权的范围之内**。即使数据已脱敏，如果用户当初的授权不包括"共享给第三方供应商训练模型"这个具体用途，依然需要重新取得同意。

> 🔑 **判别口诀**：脱敏解决的是"**谁**能看到"，授权范围解决的是"**用来干什么**"，两者是并列的两条线，一条合格不代表另一条也合格。

## 三、AI基础回顾 + pandas工具箱：没有这把"尺子"，后面所有实操都做不了

### 1. 三大范式，判断公式只有一句话

机器学习三大范式，你在五级应该已经接触过，这里快速过一遍，重点是**判断公式**：

> 有标准答案 → **监督学习**；没有标准答案，但有数据结构 → **无监督学习**；没有标准答案，但有反馈/奖励信号、允许试错 → **强化学习**。

典型例子：图像分类（带标签）是监督学习；用户聚类（没人告诉你分几类）是无监督学习；推荐系统根据用户停留时长动态调整策略是强化学习。

还有一个经常被考的概念：**训练集/验证集/测试集**。它们各自的职责是——训练集学参数，验证集用来调参和判断是否该"早停"，测试集做最终的真实效果评估。

追问一句：**这三者能不能混用？比如拿训练集的数据直接当测试集用一遍，图个方便？**

……

**不能**。混用会导致评估结果虚高失真——用训练集数据做最终评估，模型"看过"这些数据、已经把它们的细节都记下来了，测出来的准确率自然很好看，但这完全反映不出模型在"没见过的新数据"上的真实表现。这也是后面课题里会反复出现的一个思路雏形：**评估一个东西好不好，必须用它没接触过的数据去检验，不能用它已经"背过"的数据给自己打分**。

### 2. pandas工具箱：这是你接下来12个课题都要用到的"手"

四级开始，大量的质量检测、审核、聚类工作都要落到代码上完成。先把最常用的几个操作过一遍：

```python
import pandas as pd

df = pd.read_csv("data.csv")          # 读取
print(df.head())                       # 查看前几行
print(df.info())                       # 查看字段类型与非空数
print(df.describe())                   # 数值字段统计摘要

# 缺失值
print(df.isnull().sum())               # 统计各字段缺失数
df["col"] = df["col"].fillna(df["col"].median())   # 填充
df = df.dropna(subset=["key_col"])     # 删除关键字段缺失的行

# 重复值
print(df.duplicated().sum())
df = df.drop_duplicates()

# 分组聚合
agg = df.groupby("category")["amount"].agg(["mean","sum","count"])
pivot = df.pivot_table(index="category", columns="region", values="amount", aggfunc="sum")
```

记住两个最容易混的方法：`df.isnull().sum()` 是**按列**统计缺失值数量；`df.duplicated().sum()` 是对**整行**记录做重复性判断，统计的是重复行的总数。一个看列，一个看行，别搞反。

### 3. 缺失值该怎么填？——这是整个四级课程里出现频率最高的判断题

拿到一批缺失数据，很多人的第一反应是"均值填充走起"。先别急。正确的决策顺序是这样一步一步来的：

```
① 能不能补录？（比如联系原始数据源核实）→ 能，就去补录
② 不能补录，这批缺失数据占比大不大、删了影响大不大？→ 影响小，直接删除
③ 不能补录、删除代价又太大 → 必须填充，这时候才轮到"均值还是中位数"这个问题
```

到了第③步，怎么选？关键看**数据分布形态**：

> 长尾分布（比如销售额，大多数订单金额不高，少数大额订单极高）用**中位数**更稳健；接近对称分布可以用均值。

为什么长尾分布下均值会"失真"？用一个小例子体会一下：假设5条销售额记录是 100、120、110、90、8000，均值是2884，中位数是110。**哪个数字更能代表"大多数订单的真实水平"？** 显然是110——均值2884是被那一条8000的大单硬生生拉上去的，没有任何一条记录真的接近2884。

这个小例子不是编的巧合，后面课题1-1会给你看一组货真价实的实测数据，规模比这个例子更夸张——提前预告一下：均值和中位数会相差将近19倍。带着"为什么会差这么多"这个问题进入下一篇，你会对这个机制有更扎实的体感。

> 🔑 **记住这条判断捷径**：不需要画直方图，**只要把均值和中位数拿出来一比，差得越多，长尾信号越强，越应该用中位数**。这个方法贯穿整个四级课程的数据质量检测工作。
