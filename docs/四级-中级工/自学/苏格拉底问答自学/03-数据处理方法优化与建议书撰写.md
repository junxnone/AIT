## 一、两类"看起来异常"的数据，处理方式完全不同

先看真实数据。对化妆品销售数据按SKU分组算均值：

```python
import pandas as pd
d = pd.read_csv("../数据集/cosmetics_sales.csv")
sku_mean = d.groupby("SKU")["销售额"].mean().sort_values(ascending=False)
print(sku_mean.head(5))
```

**实测**：SKU003均值39700.6、SKU022均值28900.9、SKU011均值27164.2，而正常SKU均值通常在800-900左右——**相差约30-45倍**。

现在把上一篇讲的"长尾分布"案例和这里的"30-45倍"摆在一起对比一下：

| | 上一篇：销售额长尾分布 | 这一篇：SKU003异常均值 |
|---|---|---|
| 现象 | 均值3689.6 远高于中位数194.0 | SKU003均值39700.6 远高于正常SKU（约800-900） |
| 差异倍数 | 约19倍 | 约30-45倍 |
| 根本原因 | 少数大额订单真实存在，只是数量少、金额高 | 很可能是单价多打了一两个零——**数据本身是错的** |
| 正确处理方式 | 用中位数填充缺失值（统计手段） | 核实原始价格表，确认是录入错误后按正确值修正 |

**看出区别了吗？** 上一篇的大额订单是**真实发生过的业务**，只是在统计上显得"极端"；这一篇的SKU003均值异常，大概率是**数据录入环节出了错**，这几条记录本身就是假的、错的。

> ⚠️ **核心教训**：如果看到这几个SKU销售额偏高就直接用中位数"拉平"处理，是错误做法。**统计手段（如中位数替代）适用于处理正常数据的长尾/缺失问题，不适用于已确认的录入错误**。数量级错误应该先排查确认（比如核实原始价格表），然后按正确值修正，而不是用统计手段把问题本身掩盖过去。

**追问一句：为什么说"统计手段掩盖"和"核实修正"是两种性质完全不同的处理方式？**

……

统计手段掩盖的前提是**数据本身没有错**，只是数值比较极端——这种处理不改变"这是真实数据"这个假设；核实修正针对的是**确认存在的录入错误**，处理的是"数据本身是错的"这个事实。如果把录入错误当成正常极端值用统计手段处理，相当于用一个编造出来的数字掩盖了真实的错误，而没有真正解决问题根源——下次同样的录入环节出错，你还是发现不了。

### 判别依据：倍数是否离谱

那怎么区分"正常长尾高值"和"数量级错误"呢？**判别依据是偏离正常范围的倍数是否离谱。**

正常业务波动造成的长尾高值通常是几倍到十几倍的差异（比如大客户一次性批量采购，单笔金额确实比普通订单高出不少，但这是真实发生的业务）；而本案例里30-45倍这种量级的差异，已经远超正常业务能解释的范围，更可能是价格多打了一两个零这类录入错误。

**追问一步：发现数量级错误后，除了修正这一条记录，还应该做什么？**

……

应该检查是否存在**同类遗漏**——核实这批数量级错误是否集中出现在某个录入环节或某个时间段，排查是否还有其他未被发现的类似错误记录，而不是只修正已经发现的这几条就宣告结束。这是四级"审核"思维的一个具体体现：发现一个问题，要顺着这个问题往外扩一圈，看看是不是还有同类的问题藏在别处。

## 二、门店编码归一化：顺手解决的另一类问题

还记得上一篇提到门店编码存在大小写混用吗（S001/s001等8种取值应归并为4种）？处理方式很简单：

```python
d["门店编码"] = d["门店编码"].str.upper()
print(d["门店编码"].value_counts())
```

归一化后，4个门店编码的记录数从8种取值（大小写混用）合并为4种，分布趋于均衡（192-205条/店）。

**这一步解决的是六维度中的哪个问题？** 自己先想一遍再看答案。

……

**一致性问题**——同一个门店用了两种不同的大小写书写方式表示同一个含义，归一化（统一转大写）让同一含义的数据合并统计，才能得到真实的门店分布情况。注意，这**不是**完整性问题（字段都有值，没有缺失），也不是有效性问题（S001和s001本身都是"合法"的字符串格式），纯粹是"同一个意思，写法不统一"的一致性问题。

## 三、从"发现问题"到"写成能落地的建议"：优化建议书怎么写

前面两节是"发现问题、判断该怎么处理"，这一节要解决下一个问题：**怎么把这些发现，写成一份能真正推动改进的建议书？**

### 先看一个反例

假设你把前面发现的所有问题汇总，写了这样一句话交上去：

> "销售数据存在质量问题，建议加强数据治理。"

**这份建议书能用吗？花十秒判断。**

……

**不能用。** 这句话犯了三个具体的错，而不是笼统地"写得不够好"：

1. "存在质量问题"——**没有说明是什么问题、有多严重**（缺乏量化）；
2. "加强数据治理"——**没有说明具体怎么做、谁来做**（方案空洞）；
3. 整句话——**没有说明做到什么程度算完成、怎么验证效果**（缺乏可验证指标）。

### 再看一份合格的

> "销售额字段缺失率15%，当前无填充机制；SKU003/011/022存在疑似数量级错误（销售额均值是同类SKU的30-45倍）。建议：①建立销售额缺失自动告警机制，缺失率超过5%时触发人工核查；②对销售额异常高（超过同类SKU均值10倍以上）的记录自动标记待复核。预期将销售额字段的有效性从当前85%提升至98%以上，观察周期1个月。"

**把两份建议并排看一眼，区别在哪？**

| | 不合格版本 | 合格版本 |
|---|---|---|
| 问题描述 | "存在质量问题" | "缺失率15%""均值是同类SKU的30-45倍" |
| 方案 | "加强数据治理" | "缺失率超5%触发人工核查""异常超10倍自动标记复核" |
| 验证指标 | 无 | "有效性从85%提升至98%以上，观察周期1个月" |

区别就在三件事：**问题量化、方案具体、指标可验证**。而且你会发现，合格版本里的每一句话，都能在前面两节的真实发现里找到出处——"缺失率15%"是1-1篇的检测结果，"30-45倍"是本篇第一节的发现。**一份好的建议书不是凭空想出来的漂亮话，是把前面检测/审核的发现，翻译成具体的、可执行的、可验证的行动项。**

### 建议书的标准结构

把上面的例子抽象成一个通用结构：

```
现状与问题（量化描述）→ 根因分析 → 优化方案 → 预期收益（可度量）→ 实施计划与风险
```

**追问一句："现状与问题"和"根因分析"有什么区别，为什么不能直接从现状跳到方案？**

……

"现状与问题"描述的是观察到的**表面现象**（比如"销售额字段缺失率15%"）；"根因分析"要回答这个现象背后的**深层原因**（比如为什么会缺失——是采集环节没有强制校验？还是系统对接存在遗漏？）。根因分析的质量直接决定了后续优化方案是否对症——跳过根因分析直接给方案，容易"治标不治本"：比如缺失的真正原因是前端表单没做必填校验，你却只是建了个"事后告警"机制，告警是告警了,但录入缺失的情况还会持续发生。

**最后一个常被忽视的要素：成本与可行性。** 建议书不能只谈理想方案而不管实施成本，否则技术上再正确也推不动落地——决策者看到建议书，首先要判断的是"这个方案现实中能不能做、值不值得做"，脱离成本谈方案等于只完成了一半的说服工作。

## 小结：这一篇真正在教你的是什么

把两个课题串起来看，这一篇的核心不是"又多学了几个处理技巧"，而是在训练一种**诊断先于处方**的习惯：

- 看到数值异常，先问"这是真实的极端值，还是数据本身就是错的"，再决定用统计手段还是核实修正；
- 看到一堆问题，先把它们量化、找到根因，再给方案——而不是看到问题就脱口而出"建议加强管理"这种正确的废话。

这个"先诊断、再处方"的习惯，会在接下来的数据标注模块（课题2-1到2-4）里反复出现，是贯穿整个四级课程的核心能力。
