## 先做个判断

某门店上报了一批销售记录：字段齐全，销售额、会员等级、门店编码、销售数量样样不缺，表格排版也工工整整。负责人扫了一眼说：

> "这批数据看着没问题，直接喂给销量预测模型就行。"

**先别急着附和，花三十秒判断：这批数据真的能直接用吗？**

把你的判断写在心里。读完这一篇，你会发现"字段齐全、数值像那么回事"和"真的可以用"之间，可能差着好几处你用眼睛完全看不出来的坑，而且差距大到足以让后续的预测模型学出一堆错误结论。

## 一、六维度：不是凭感觉，是一把系统的尺子

判断一批数据"能不能用"，不能靠"看着挺整齐"的直觉。表面整齐只能说明**排版**没问题，不代表**内容**没问题。四级训练师需要一把系统的尺子，逐项过一遍——这就是数据质量的六个维度：

| 维度 | 含义 | 典型问题 |
|---|---|---|
| 完整性 | 字段是否缺失 | 销售额为空 |
| 准确性 | 数值是否正确反映真实情况 | 录入错误导致数值异常 |
| 一致性 | 同一含义是否用统一写法表示 | 门店编码S001/s001混用 |
| 唯一性 | 有无重复记录 | 同一订单号出现两次 |
| 时效性 | 数据是否过期、是否反映当前状态 | 使用半年前的用户画像 |
| 有效性 | 是否符合字段定义域 | 年龄字段出现负数 |

先别急着往下记，自己想一个问题：**这六个维度里，哪两组名字听起来最像、最容易被搞混？**

……

大部分人会答"完整性和有效性"，以及"准确性和一致性"。没错，这正是本篇要重点拆解的两组易混概念。在拆解之前，先建立一个认知：六个维度不是平行罗列、各管各的，每个维度背后都对应一种**具体的业务伤害**：

| 维度 | 一旦出问题，具体会怎样 |
|---|---|
| 完整性 | 统计结果系统性偏小，模型训练时相当于少喂了一部分样本 |
| 准确性 | 单条记录数值本身就是错的，所有基于它的决策都失真 |
| 一致性 | 同一个门店因为写法不同被当成两家，分组统计直接拆错 |
| 唯一性 | 同一笔业务被重复计入，业绩、销量被无端"虚增" |
| 时效性 | 用过时的状态做当下的决策，结论本身就滞后于现实 |
| 有效性 | 数值"看起来是数字"，但不符合业务逻辑，不能直接拿去用 |

先记两条判别口诀，下面的真实案例会反复用到它们：

> 🔑 **完整性 vs 有效性**：先问"**有没有值**"，再问"**值对不对**"。该有值的地方是空的（NaN）→ 完整性问题；有值，但值不符合业务定义域（如数量出现负数）→ 有效性问题。

> 🔑 **准确性 vs 一致性**：准确性问的是"**这一条记录本身对不对**"；一致性问的是"**不同记录里，同一个意思是不是用统一写法表达**"。

## 二、均值填充陷阱：一个会让你重新理解"缺失值处理"的真实案例

现在用一份真实的化妆品销售数据（`cosmetics_sales.csv`）来检验前面说的"六维度"。跑一下这几行代码：

```python
import pandas as pd
d = pd.read_csv("../数据集/cosmetics_sales.csv")
print("销售额缺失:", d["销售额"].isna().sum())
print("会员等级缺失:", d["会员等级"].isna().sum())
print("门店编码取值:", d["门店编码"].value_counts().to_dict())
print("均值:", d["销售额"].mean(), " 中位数:", d["销售额"].median())
```

**实测结果**：销售额缺失120条（15%），会员等级缺失144条（18%），门店编码存在大小写混用（S001/s001等8种取值应归并为4种）。**均值约3689.6，中位数约194.0——相差近19倍。**

回到开头那个判断："这批看起来没问题的数据"，一跑检测就暴露出至少三类真实问题——两个字段缺了近两成，门店编码把4家门店活活拆成了8种取值。**"字段齐全"只保证了表格排版，不保证字段里装的东西是干净的。**

**为什么均值和中位数差这么多？** 销售额呈**长尾分布**——绝大多数订单金额不高，但少数大额订单极高，把均值硬生生拉高。前一篇用过一个小例子：5条记录100、120、110、90、8000，均值2884，中位数110——中位数更能代表"大多数订单的真实水平"。眼前这组真实数据是这个小例子的放大版：均值3689.6 远高于中位数194.0，说明少数大额订单正在"绑架"整体均值。

**追问一步：如果无视这个机制，直接用均值填充，会造成什么实际后果？** 相当于把120条缺失记录，统一按"系统性偏高近19倍"的标准补了进去——这些记录会被当成"接近均值水平的普通订单"，但真实情况是大多数订单远没有这么高。**填充本身没有制造新数据，却悄悄篡改了这批数据的分布形态**，后续所有基于这批数据得出的结论（比如"本月平均客单价"）都会被这19倍的偏差带偏。

> ⚠️ **核心教训**：拿到缺失值问题，不要条件反射用均值填充。先把均值和中位数拿出来一比，**差异越大，长尾信号越强，越应该优先用中位数**——这个判断不需要画图，两个数字一对比，答案自己就出来了。

## 三、完整性 vs 有效性：销售数量里的新发现

讲完缺失值，再看另一个字段——`销售数量`：

```python
print("销售数量<=0的条数:", (d["销售数量"] <= 0).sum())
print("销售数量 最小值/最大值:", d["销售数量"].min(), d["销售数量"].max())
```

**实测结果**：销售数量 ≤ 0 的记录共 **24条**，最小值 **-7**，最大值 7。

**现在考你一下：这24条记录属于六维度中的哪一个？** 先别看答案，用前面给的口诀自己推一遍。

……

很多人的第一反应是"完整性问题，因为数据不对"。但套用口诀检验一下：完整性问题的标志是"**该有值的地方是空的**"——这24条记录有没有缺失？**没有**，每一条都有一个具体的数字，只是这个数字（负数、0）不符合"销售数量不能为负"这条业务常识。

**所以正确答案是有效性问题，不是完整性问题。** 完整性回答的是"有没有"，有效性回答的是"值对不对"。

**追问一步：归错类会有什么后果？** 如果把它误判成完整性问题，下一步很可能会想"那就把这些记录删掉或填充一个默认值"——但真正该做的是先搞清楚**为什么会出现负数**（比如是不是退货记录被错误地计入了销售数量字段，负数其实代表退货单）。归类错了，处理方向也会跟着错。

顺带再查一个维度——唯一性：

```python
print("订单号重复条数:", d["订单号"].duplicated().sum())
```

实测结果为 **0**，订单号完全唯一，这一项是干净的。这里有个容易被忽视的认知：**检测的意义不是"找茬证明数据有问题"，而是系统地把六个维度都过一遍**——有问题的揪出来写进报告，**没问题的也要确认清楚、同样写进报告**。如果你只写代码里"顺手跑出来"的那几项，漏掉唯一性和时效性，别人看你的检测方案会以为你根本没查过这两项。

## 四、阈值怎么定？——"拍脑袋"是四级考试最爱挑的刺

光知道"哪里有问题"还不够。现实工作里还有一个更难的问题：**多大的缺失率、多大的异常比例，算"严重"，需要上报或暂停使用？**

有人会说"缺失率超过10%就算不合格"。先追问一句：**这个10%是哪来的？**

如果答不上来，这个数字就是拍脑袋定的，换一个业务场景立刻会出问题。比如本案例里会员等级字段缺失18%，如果这18%恰好对应"未注册会员"这类**本来就不该有等级**的正常情况，那这个"缺失"根本不是质量问题，是业务规则决定的正常空值——强行按10%的阈值打回去反而是错的。

**正确做法**：先搞清楚缺失或异常背后的业务原因，再决定阈值该设多严。比如销售额这类直接影响核心统计结论的字段，缺失率哪怕只有5%也可能动摇后续分析的可信度，阈值就该设得严；而像会员等级这种允许存在合理空值的字段，阈值可以放宽，但**必须在检测方案里写清楚"为什么允许这部分空值存在"**，而不是对缺失视而不见。

> 📌 **一句话记住**：阈值不是经验数字，是**业务规则的量化表达**。拿到一个缺失率/异常率数字，先问"这背后的业务原因是什么"，再决定要不要设阈值、设多严。

把这几节串起来，一份合格的质量检测方案必须包含四部分：

```
一、数据集基本信息（字段、记录数）
二、六维度逐项检测结果（六个都要写，查过的"没问题"也要写清楚结论）
三、每类问题的处理建议（含阈值设定依据，不能只写"建议处理"）
四、优先级排序（哪类问题必须先处理，哪类可以后置）
```

## 五、换一种数据类型：图像数据集怎么审

前面讲的都是结构化数据（销售记录这类表格数据）。现在换一个场景——你拿到一份交通工具图像数据集，连同一份标注文件（`transport_labels.csv`），要审核质量。

先问自己：**图像数据和表格数据，审核思路一样吗？**

……

有相通之处（比如都要查类别分布、都要查异常值），但图像数据多了一个表格数据没有的审核维度——**标注文件和图像文件是两份独立的东西，它们之间需要"对得上"**。跑一下这段代码：

```python
import pandas as pd
from pathlib import Path

labels = pd.read_csv("../数据集/transport_labels.csv")
images = set(p.name for p in Path("../数据集/transport_images").glob("*.jpg"))

missing_img = set(labels["image_file"]) - images
print("标注指向不存在图像数:", len(missing_img))
print("坐标非法(x2<x1):", (labels.x2 < labels.x1).sum())
print("坐标越界(y2>480):", (labels.y2 > 480).sum())
print("类别分布:", labels["label"].value_counts().to_dict())
```

**实测结果**：类别分布bus占62%、tram仅4%，严重不均衡；**4条标注指向不存在的图像**；3条坐标x2<x1、4条y2越界。

**现在问你：这4条"标注指向不存在图像"的问题，只检查标注表内部的坐标是否合法（比如x2是否大于x1），能发现吗？**

……

**不能**。坐标合法性检查只涉及标注表自身的字段数值，不涉及标注表与图像文件之间的对应关系。"标注指向不存在图像"是**两个不同文件集合之间**的关系问题，必须用集合运算（代码里的差集 `set(labels["image_file"]) - images`）才能发现，光看标注表内部数据是看不出来的。

> ⚠️ **最容易被忽视的检查项**：只检查标注文件内部的问题，忘记做标注文件与图像文件集合之间的**交叉核查**——即"有没有标注指向根本不存在的图像""有没有图像完全没有标注记录"。

再追问一句：**类别分布中bus占62%、tram仅占4%，这种不均衡会对后续模型训练造成什么影响？**

……

模型会倾向于学习数量占多数的类别（bus），对数量稀少的类别（tram）学习不充分，导致实际应用中对tram的识别准确率明显偏低。发现不均衡不是检测工作的终点，还应该提出处理建议——比如对少数类过采样、或针对性补充采集更多tram类样本。只给出"不均衡"这个结论而不给建议，审核工作等于只做了一半。

最后提一下结构化数据（文本/销售数据）审核时同样要关注的几个要点：缺失值、异常值、字段逻辑冲突（比如发货日期早于下单日期，这种逻辑上不可能发生的组合）、主键重复。这些和图像数据的审核思路是相通的——**既要查"字段内部对不对"，也要查"字段之间的逻辑关系对不对"**。

## 小结：把两份讲义串成一条线

这一篇讲了两件事，它们其实是同一种能力的两种应用场景：

1. **六维度是一把通用的尺子**——不管是销售数据还是图像数据，拿到任何一批数据，先用六个维度过一遍，而不是凭"看着整齐"下结论。
2. **不同数据类型，检测手段要跟着调整**——结构化数据重点看分布形态（均值vs中位数）和字段逻辑，图像数据额外要做标注与文件的交叉核查。手段不同，但"系统性过一遍、不漏查、给结论要有依据"这个原则是共通的。
