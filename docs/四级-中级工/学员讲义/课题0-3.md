## 一、机器学习三大范式（回顾）

- **监督学习**：带标签数据训练，如图像分类
- **无监督学习**：无标签，发现数据结构，如用户聚类
- **强化学习**：试错+反馈信号，如推荐策略动态调整

判断公式：有标准答案→监督；无标准答案但有数据结构→无监督；无标准答案但有反馈信号→强化。

**训练集/验证集/测试集**：训练集用于模型学习，验证集用于调参和早停判断，测试集用于最终评估，三者应相互独立。

**为什么不能混用，尤其是测试集？** 设想一个反例：如果你拿测试集的反馈结果去反过来调整模型参数，会发生什么？——测试集一旦参与了"调整"这个动作，它实质上就变相参与了训练过程。之后你再用它来做"最终评估"，得到的高分只是"模型已经偷偷记住了测试集长什么样"的结果，并不能说明模型在**真正没见过的数据**上表现如何。这和开头那道判断题是同一类陷阱：**看到的好结果，可能是假象**——数据"看起来规整"不代表能用，模型"测试分数高"也不代表真的学会了。这条主线会在本课题的pandas实操里反复出现。

## 三、numpy：pandas 的底层引擎

课题名字里还有一个"numpy"，容易被忽略，但它值得单独说清楚。

你可能会问：一直在用pandas，为什么还要学numpy？**因为pandas的Series，本质上就是一个带了索引标签的numpy数组**。每次对一整列做批量运算（比如把销售额整列打折），背后真正在计算的就是numpy。

```python
import numpy as np

arr = np.array([1, 2, 3, 4, 5])
print(arr * 2)                     # 向量化运算：整个数组同时乘2，不需要写for循环
print(arr.mean(), arr.sum())       # 常用统计函数

# 对比：pandas整列运算背后就是numpy在工作
print((df["销售额"] * 1.1).head())  # 整列打九折后再涨价10%，不需要逐行写循环
```

**为什么要用"整列一起算"（向量化），而不是写 `for` 循环逐条处理？** 机制是：如果用循环逐条处理成千上万甚至几十万条记录，Python解释器要一行一行地重复做类型判断和函数调用，开销会随数据量线性甚至更快地增长；而向量化运算是把整批数据一次性交给底层更高效的实现去批量处理，省掉了逐条调度的开销。**数据量越大，这个差距越明显**——这也是pandas能处理几十万、上百万行数据依然能跑得动的根本原因。

**判别口诀**：遇到"要不要写for循环处理一整列数据"的场景，先问自己——这个操作能不能表达成"对整列做同一种运算"？能 → 用pandas/numpy的向量化写法；需要逐行引用"上一行的结果"这类强依赖关系 → 才考虑循环。

## 四、缺失值/重复值/异常值处理的判断依据

对本课题的销售数据做一次完整体检，结果如下（已验证，运行环境中结果应完全一致）：

```
销售额缺失: 120           （占比15%）
会员等级缺失: 144         （占比18%）
整行重复: 0
订单号重复: 0
销售数量<=0的条数: 24
销售数量 最小值/最大值: -7 7
均值: 3689.6  中位数: 194.0
```

### 缺失值：先别急着填均值

拿到15%缺失的销售额字段，很多人的第一反应是"用均值填充"。但填充之前，先看一眼这个字段的分布——**均值3689.6，中位数只有194.0，两者相差近19倍**。这个巨大的反差本身就是一个警报信号：**真实数据不是均匀分布的，而是长尾分布**（多数订单金额不高，少数大额订单极高）。如果不假思索地用均值3689.6去填充那15%的缺失值，相当于把"少数大额订单硬塞给了大多数本该是普通订单的缺失记录"，这会**系统性地高估**这批样本的真实水平。

**能补录就补录**（如联系原始数据源核实）；**不能补录且该行影响小**可以删除；**不能补录且删除会损失大量数据**则需要填充——此时填充用均值还是中位数，取决于数据分布：**长尾分布（如销售额）用中位数更稳健**，因为中位数只看"排在中间的那个值"，不会被少数极端值拉偏；均值则是把所有值加总再平均，极端值会把它直接拽走。

| | 用均值填充 | 用中位数填充 |
|---|---|---|
| 本例计算值 | 3689.6 | 194.0 |
| 是否受少数大额订单影响 | **是**，被拉高近19倍 | 否，不受极端值影响 |
| 填进缺失样本后的效果 | 把普通订单错误地"拔高"成大额订单水平 | 更接近这批数据"典型"的真实水平 |

**决策顺序（不是"遇到缺失就默认均值"的单一公式）**：① 先判断能不能补录；② 不能补录时，看这批缺失数据占比大不大、删除影响大不大，影响小可以直接删除；③ 必须填充时，再看字段的分布形态选均值还是中位数。

### 类别型缺失，连"均值/中位数"这个选项都不存在

再看会员等级缺失144条、占比18%，比销售额缺失的比例还高。能不能也套用"均值/中位数"的思路？**不能**——会员等级是"普通/白银/黄金"这类类别，根本没有数值意义上的"均值"可言。类别型字段缺失的常见做法是：归入一个明确的新类别（如"未知/未注册"），或结合业务规则判断——比如这批缺失是不是"未注册会员"本来就没有等级，那就不是真正意义上的"缺失"，而是业务规则决定的正常空值。

> 🔑 **判别口诀**：字段是数值型还是类别型？数值型 → 看分布形态选均值/中位数；类别型 → 根本没有均值/中位数可选，要么归为明确的新类别，要么按业务规则判断是否属于正常空值。

### 重复值：查出来是0，不代表这一步可以跳过

本例"整行重复"和"订单号重复"都检测为0条。这是不是意味着"重复值"这个知识点在这份数据里用不上？**不是**。检测的意义不在于"一定要找到问题"，而在于**系统性地把每一类问题都查一遍**——有问题就处理，没问题也要在质检报告里明确写清楚"已检测、无重复"。如果因为这次没查出问题就跳过这一步，下一批数据如果真的存在重复记录，同样的疏漏会被重复放大，而且没有任何检测记录可以证明这一批数据到底查没查过。

```python
print(df.duplicated().sum())
df = df.drop_duplicates()
```

### 异常值：不是所有"奇怪的数"都直接删

`销售数量` 最小值是 -7，最大值是 7，其中有24条记录销售数量小于等于0——这明显不符合业务常识（销售数量不可能是负数）。但"异常"不等于"立刻删除"：负数销售数量很可能对应"退货/录入异常"这类有业务含义的记录，直接删除会丢失"退货发生了多少次"这类信息；更合理的做法往往是先判断这24条记录的业务含义，再决定是单独标记统计，还是确认为纯录入错误后再删除。**异常值处理和缺失值处理是同一种思路：先搞清楚"为什么会出现这个异常"，再决定怎么处理，而不是看到数字不对劲就一删了之。**

## 五、字符串与类型：容易被忽略的"隐形坑"

回到"二"里留的那个疑问：用 `df["门店编码"] == "S001"` 筛选，为什么查出来的记录不完整？再看一个相关现象：如果直接对 `门店编码` 做分组统计，本来只有4家门店，`groupby` 之后却出来了8行结果。这是代码写错了吗？

**不是代码的问题，是数据本身的问题。** `groupby`、`==` 这类操作是严格按照字符串**完全相等**来判断的，`S001` 和 `s001` 在程序眼里就是两个完全不同的类别，就像"苹果"和"苹果 "（多一个空格）对程序来说也是两个不同的字符串。对本课题数据实测：

```python
d2 = d.copy()
d2["门店编码"] = d2["门店编码"].str.upper()   # 统一转大写
print("标准化前唯一值数:", d["门店编码"].nunique())
print("标准化后唯一值数:", d2["门店编码"].nunique())
```

```
标准化前唯一值数: 8
标准化后唯一值数: 4
```

一行 `.str.upper()`，8种取值收敛成4种，真正对应的4家门店。这也解释了开头留的疑问：`== "S001"` 之所以查不全，是因为有一部分记录写的是小写的 `s001`，被完全匹配的筛选条件漏掉了——**代码没有报错，结果却悄悄少了一部分**，这类错误比直接报错更危险，因为不会主动提醒你去检查。

**判别口诀**：字符串字段在做分组、筛选、关联这类"按值匹配"的操作之前，先问一句——这个字段的大小写、空格、全角半角有没有统一？没统一，一律先用 `.str.upper()` / `.str.strip()` 这类方法清洗，再做匹配类操作，顺序不能反。

类型问题还有一个常见场景——日期：

```python
print(d2["销售日期"].dtype)              # 转换前：object（字符串）
d2["销售日期"] = pd.to_datetime(d2["销售日期"])
print(d2["销售日期"].dtype)              # 转换后：datetime64
```

`销售日期` 读进来的时候是字符串类型（`object`），表面看起来是日期，但pandas并不知道它是日期——字符串没法直接做"晚于某天""按月汇总"这类操作。`pd.to_datetime` 把它转换成真正的日期类型后，才能用日期专属的功能。**类型不对，对应的功能就用不了**，这和字符串格式不统一是同一类问题的两种表现：**数据"看起来"是对的，不代表程序"认得出"是对的。**

## 回到开头

现在回答最开始那道判断题：这批"字段齐全、表格规整"的销售数据，能直接拿去建模吗？

**不能。** 光是前3行里就藏着两个问题：第2行销售额是缺失值（`NaN`），第3行门店编码写成了小写 `s001`。体检一遍整份数据后，问题比这更多——销售额缺失15%、会员等级缺失18%、24条销售数量异常、门店编码大小写混用导致本来4家门店被拆成8种取值。**这些问题单独看都不报错，数据表面上"看起来没问题"，正是最容易被直接喂给模型的危险数据。** 这正是本课题反复出现的同一个道理：**看起来规整的数据，不代表真的干净；看起来好看的指标（比如均值3689.6），也不代表真实——必须动手体检、动手验证，才能把"看起来"和"真的是"区分开。**

## 随堂练习

**练习 1**：某电商销售额字段存在长尾分布（多数订单金额不高，少数大额订单极高），缺失值该用均值还是中位数填充？

<details><summary>答案</summary>中位数。长尾分布下均值会被少数极端大额订单拉高，用均值填充会系统性高估大多数缺失样本的真实水平；中位数不受极端值影响，更能代表"典型"水平。</details>

**练习 2**：缺失值处理的正确决策顺序是什么？

<details><summary>答案</summary>①先判断能否补录（如联系原始数据源核实）；②不能补录时，判断这批缺失数据占比大不大、删除影响大不大，影响小可直接删除；③必须填充时，先看字段的分布形态，偏态（长尾）分布用中位数，接近对称分布可用均值。这是一个决策流程，不是"遇到缺失就默认用均值"的单一公式。</details>

**练习 3**：`df.isnull().sum()` 和 `df.duplicated().sum()` 分别统计什么？

<details><summary>答案</summary>`df.isnull().sum()`统计每一列的缺失值数量；`df.duplicated().sum()`统计整个数据框中重复行的总数量。前者按列统计，后者是对整行记录做重复性判断。</details>

**练习 4**：训练集、验证集、测试集三者的作用分别是什么？为什么不能混用？

<details><summary>答案</summary>训练集用于模型学习参数；验证集用于调参和判断何时该早停（避免过拟合）；测试集用于最终评估模型的真实效果。三者混用会导致评估结果失真——比如用训练集数据做最终评估，得到的准确率会虚高，无法反映模型在未见过数据上的真实表现。</details>

**练习 5**：为什么说"动手验证优于凭感觉判断"？结合本课题举一个例子。

<details><summary>答案</summary>因为很多直觉判断可能是错的，只有实际跑一遍数据才能确认。例如本课题中，很多人凭感觉认为"缺失值就该用均值填充"，但实际对比均值和中位数的计算结果后，会发现长尾分布下两者差异巨大，均值填充会带来系统性偏差——这个结论只有动手算一遍才能真正确信，仅凭"感觉均值填充很常见"是不够的。</details>
