## 一、数据质量六维度——不是凭感觉，是一把系统的尺子

判断一批数据"能不能用"，不能靠"看着挺整齐"的直觉。表面整齐只能说明**排版**没问题，不代表**内容**没问题。训练师需要一把系统的尺子，逐项过一遍——这就是数据质量的六个维度。

| 维度 | 含义 | 典型问题 |
|---|---|---|
| 完整性 | 字段是否缺失 | 销售额为空 |
| 准确性 | 数值是否正确反映真实情况 | 录入错误导致数值异常 |
| 一致性 | 同一含义是否用统一写法表示 | 门店编码S001/s001混用 |
| 唯一性 | 有无重复记录 | 同一订单号出现两次 |
| 时效性 | 数据是否过期、是否反映当前状态 | 使用半年前的用户画像 |
| 有效性 | 是否符合字段定义域 | 年龄字段出现负数 |

六个维度不是平行罗列、各管各的，每个维度背后都对应一种具体的业务伤害：

| 维度 | 一旦出问题，具体会怎样 |
|---|---|
| 完整性 | 统计结果系统性偏小，模型训练时相当于少喂了一部分样本 |
| 准确性 | 单条记录数值本身就是错的，所有基于它的决策都失真 |
| 一致性 | 同一个门店因为写法不同被当成两家，分组统计直接拆错 |
| 唯一性 | 同一笔业务被重复计入，业绩、销量被无端"虚增" |
| 时效性 | 用过时的状态做当下的决策，结论本身就滞后于现实 |
| 有效性 | 数值"看起来是数字"，但不符合业务逻辑，不能直接拿去用 |

**两组最容易混的概念，先给判别口诀，后面案例会反复用到：**

> 🔑 **完整性 vs 有效性**：先问"**有没有值**"，再问"**值对不对**"。
> 该有值的地方是空的（NaN）→ 完整性问题；有值，但值不符合业务定义域（如数量出现负数）→ 有效性问题。

> 🔑 **准确性 vs 一致性**：准确性问的是"**这一条记录本身对不对**"（哪怕只看它自己，数值合不合理）；一致性问的是"**不同记录里，同一个意思是不是用统一写法表达**"（单条看都"合理"，但写法不统一照样是质量问题）。

这两条口诀现在记下来，下面两节会用这批门店的真实数据把它们一一兑现。

## 二、均值填充陷阱：一个会让你重新理解"缺失值处理"的真实案例

**数据**：某化妆品销售数据（`数据集/cosmetics_sales.csv`）。

```python
import pandas as pd
d = pd.read_csv("../数据集/cosmetics_sales.csv")
print("销售额缺失:", d["销售额"].isna().sum())
print("会员等级缺失:", d["会员等级"].isna().sum())
print("门店编码取值:", d["门店编码"].value_counts().to_dict())
print("均值:", d["销售额"].mean(), " 中位数:", d["销售额"].median())
```

**实测**：销售额缺失120条（15%），会员等级缺失144条（18%），门店编码存在大小写混用（S001/s001等8种取值应归并为4种）。**均值约3689.6，中位数约194.0——相差近19倍。**

先回到开头的判断：这批"看起来没问题"的数据，一跑检测就暴露出至少三类真实问题——两个字段缺了近两成，门店编码把4家门店活活拆成了8种取值。**"字段齐全"只保证了表格排版，不保证字段里装的东西是干净的。**

**为什么均值和中位数差这么多？** 销售额呈**长尾分布**——绝大多数订单金额不高，但少数大额订单极高，把均值硬生生拉高。用一个夸张的小例子体会这个机制：假设5条销售额记录是 100、120、110、90、8000，均值是 2884，中位数是 110。显然**中位数 110 更能代表"大多数订单的真实水平"**，均值 2884 是被那一条 8000 的大单拉上去的，没有任何一条记录真的接近 2884。本课题的真实数据就是这个小例子的放大版：均值 3689.6 远高于中位数 194.0，说明少数大额订单正在"绑架"整体均值。

**如果无视这个机制，直接用均值填充会怎样？** 相当于把120条缺失记录的销售额，统一按"系统性偏高近19倍"的标准补了进去——这些记录在后续统计、建模里会被当成"接近均值水平的普通订单"，但真实情况是大多数订单远没有这么高。**填充本身没有制造数据，却悄悄篡改了这批数据的分布形态**，后续所有基于这批数据得出的结论（比如"本月平均客单价"）都会被这19倍的偏差带偏。

> ⚠️ **本课题核心教训**：拿到"缺失值"问题，不要条件反射用均值填充。先看数据分布形态（可以画直方图，或者像上面这样直接对比均值/中位数的差异），**差异越大，长尾信号越强，越应该优先用中位数**。这个判断不需要画图就能做——均值和中位数一对比，答案自己就出来了。

## 三、完整性 vs 有效性：销售数量里的新发现

讲完销售额和会员等级的缺失问题，再看另一个字段——`销售数量`。

```python
import pandas as pd
d = pd.read_csv("../数据集/cosmetics_sales.csv")
print("销售数量<=0的条数:", (d["销售数量"] <= 0).sum())
print("销售数量 最小值/最大值:", d["销售数量"].min(), d["销售数量"].max())
```

**实测结果**：销售数量 ≤ 0 的记录共 **24条**，最小值 **-7**，最大值 7。

**这24条记录属于六维度中的哪一个？** 这是最容易判断错的地方。

很多人的第一反应是"完整性问题，因为数据不对"。但套用前面的口诀检验一下：完整性问题的标志是"**该有值的地方是空的**"——这24条记录有没有缺失？没有，每一条都**有**一个具体的数字，只是这个数字（负数、0）不符合"销售数量不能为负"这条业务常识。

> **判别结论**：这是**有效性问题**，不是完整性问题。完整性问题回答的是"有没有"，有效性问题回答的是"值对不对"。销售数量的业务定义域应该是正整数，出现负数和0，是"值落在了业务允许范围之外"。

**为什么要较这个真，归错类有什么后果？** 如果把它误判成完整性问题，下一步很可能会想"那就把这些记录删掉或填充一个默认值"——但真正该做的是先搞清楚**为什么会出现负数**（比如是不是退货记录被错误地计入了销售数量字段，负数其实代表退货单），归类错了，处理方向也会跟着错。

**顺带再查一个维度——唯一性**：

```python
print("订单号重复条数:", d["订单号"].duplicated().sum())
```

实测结果为 **0**，订单号完全唯一，这一项是干净的。这一点同样值得记住：**检测的意义不是"找茬证明数据有问题"，而是系统地把六个维度都过一遍**——有问题的揪出来写进报告，**没问题的也要确认清楚、同样写进报告**，不能因为"没查出问题"就跳过不写，否则别人看到你的检测方案会以为你根本没查过这一项。

## 四、检测阈值须有业务依据，不能拍脑袋定

六维度讲完了，但光知道"哪里有问题"还不够。实际工作中你还要回答一个更难的问题：**多大的缺失率、多大的异常比例，算"严重"，需要上报或暂停使用？**

**常见的错误做法**：有人会说"缺失率超过10%就算不合格"。这个10%是怎么来的？如果答不上来，这个数字就是拍脑袋定的，换一个业务场景立刻会出问题。比如会员等级这个字段缺失18%，如果这18%恰好对应的是"未注册会员"这类**本来就不该有等级**的正常情况，那这个"缺失"根本不是质量问题，是业务规则决定的正常空值，强行按10%的阈值打回去反而是错的。

**正确做法**：先搞清楚缺失或异常背后的业务原因，再决定阈值该设多严。比如销售额这类直接影响核心统计结论的字段，缺失率哪怕只有5%也可能动摇后续分析的可信度，阈值就该设得严格；而像会员等级这种允许存在合理空值的字段，阈值可以适当放宽，但**必须在检测方案里写清楚"为什么允许这部分空值存在"的业务原因**，而不是对缺失视而不见。

> 📌 **一句话记住**：**阈值不是经验数字，是业务规则的量化表达。** 拿到一个缺失率/异常率数字，先问"这背后的业务原因是什么"，再决定要不要设阈值、设多严。

## 五、设计一份合格的质量检测方案

把前面几节串起来，一份合格的质量检测方案必须包含：

```
一、数据集基本信息（字段、记录数）
二、六维度逐项检测结果（六个都要写，查过的"没问题"也要写清楚结论）
三、每类问题的处理建议（含阈值设定依据，不能只写"建议处理"）
四、优先级排序（哪类问题必须先处理，哪类可以后置）
```

对照本课题的真实数据，一份具体的检测结论示例是这样的：

| 维度 | 检测结果 | 处理建议 |
|---|---|---|
| 完整性 | 销售额缺失120条（15%）、会员等级缺失144条（18%） | 销售额属核心字段，缺失率阈值从严；会员等级需先核实缺失是否为"未注册"正常空值 |
| 准确性 | （需结合具体字段逐条核实，本案例暂未发现系统性录入错误） | — |
| 一致性 | 门店编码大小写混用，4家门店拆成8种取值 | 统一归一化（如全部转大写）后再做分组统计 |
| 唯一性 | 订单号重复数为0 | 无需处理，写入报告确认该维度无异常 |
| 时效性 | （需结合数据采集时间核实） | — |
| 有效性 | 销售数量≤0共24条（min=-7, max=7） | 核实是否为退货记录误计入，不能直接删除或粗暴填充 |

**最容易遗漏的地方**：唯一性和时效性这两项，因为检测代码没有"现成提示"，最容易被学员忘记去查——但遗漏不等于不存在，一份完整的方案必须六个维度逐项交代，不能只写代码里"顺手跑出来"的那几项。

## 随堂练习

**练习 1**：某字段均值远高于中位数，这说明什么？该用哪个填充缺失值？

<details><summary>答案</summary>说明该字段存在少数极端大值，呈右偏（长尾）分布。应优先用中位数填充，因为中位数不受极端值影响，更能代表典型水平；用均值填充会系统性高估大多数缺失样本。</details>

**练习 2**：数据质量六维度中，"完整性"和"有效性"有什么区别？各举一个例子。

<details><summary>答案</summary>完整性关注字段是否缺失（如销售额字段为空），有效性关注取值是否符合定义域（如年龄字段出现负数，虽然字段不缺失，但取值本身不合法）。两者是不同的问题：完整性问题是"没有值"，有效性问题是"有值但值不对"。</details>

**练习 3**：门店编码存在"S001"和"s001"两种写法，这属于六维度中的哪一个问题？

<details><summary>答案</summary>一致性问题。这两种写法表示同一个含义（同一个门店），但书写形式不统一。一致性关注的正是"同一含义是否用统一方式表达"，需要归一化处理（如统一转为大写）后再做统计。</details>

**练习 4**：检测出"会员等级缺失144条（18%）"之后，下一步该做什么？

<details><summary>答案</summary>不能直接决定处理方式，而要先判断缺失的业务含义——是否可以通过其他渠道补录（如关联用户注册信息核实会员等级），缺失率18%是否超出可接受范围，以及是否需要单独设置"未知"类别而非强行填充某个具体等级。处理方式的选择需要结合业务场景，不是检测完就自动套用某个默认方法。</details>

**练习 5**：为什么"均值和中位数差异很大"可以作为识别长尾分布的简便方法？

<details><summary>答案</summary>因为均值会被极端值显著拉高或拉低，而中位数不受极端值影响。如果一个字段的真实分布是对称的（如正态分布），均值和中位数应该很接近；如果两者相差很大（如本课题中相差近19倍），说明存在少数极端值把均值拉偏了，这正是长尾/偏态分布的典型信号，不需要画图就能快速判断。</details>
