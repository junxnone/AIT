## 一、两类"看起来异常"的数据，处理方式完全不同

```python
import pandas as pd
d = pd.read_csv("../数据集/cosmetics_sales.csv")
sku_mean = d.groupby("SKU")["销售额"].mean().sort_values(ascending=False)
print(sku_mean.head(5))
```

**实测**：SKU003均值39700.6、SKU022均值28900.9、SKU011均值27164.2，而正常SKU均值通常在800-900左右——**相差约30-45倍**。

**这不是正常的销售波动，是数量级录入错误**（比如单价多打了两个0）。

> ⚠️ **核心教训**：如果看到这几个SKU销售额偏高就直接用中位数"拉平"，是错误做法。**统计手段（中位数替代）适用于处理正常数据的缺失/长尾问题，不适用于已确认的录入错误**。数量级错误应该先排查确认（如核实原始价格表），然后按正确值修正，而不是用统计手段掩盖问题本身。

**判别依据**：偏离正常范围的倍数是否离谱。正常长尾分布的高值通常是几倍到十几倍的差异，而30-45倍这种量级往往提示录入错误（如多打了一两个零）。

## 随堂练习

**练习 1**：某SKU的销售额均值是其他同类SKU均值的35倍，正确的处理思路是什么？

<details><summary>答案</summary>先核实是否为数量级录入错误（如价格多打了零），而非直接用中位数或其他统计手段替代掩盖。确认是错误后应按正确值修正；若核实后确实是真实的高价值SKU（如限量高端产品），则保留原值，不作处理。</details>

**练习 2**：为什么说"统计手段掩盖"和"核实修正"是两种完全不同性质的处理方式？

<details><summary>答案</summary>统计手段掩盖（如用中位数替代异常值）处理的前提是数据本身没有错误、只是数值比较极端，这种处理不改变数据的"真实性"假设；而核实修正针对的是确认存在的录入错误，处理的是"数据本身是错的"这个事实。把录入错误当作正常极端值用统计手段处理，相当于用一个编造的数字掩盖了真实的错误，而没有真正解决问题根源。</details>

**练习 3**：区分"正常长尾高值"和"数量级错误"的判别依据是什么？

<details><summary>答案</summary>偏离正常范围的倍数是否离谱。正常业务波动造成的长尾高值通常是几倍到十几倍的差异（比如大客户批量采购），而30-45倍这种量级的差异，已经远超正常业务能解释的范围，更可能是价格多打了一两个零这类录入错误。</details>

**练习 4**：门店编码"S001"和"s001"归一化之后，记录数从8种取值合并为4种，这一步解决的是数据质量六维度中的哪个问题？

<details><summary>答案</summary>一致性问题——同一个门店用了两种不同的大小写书写方式表示，归一化（统一转大写）让同一含义的数据合并统计，才能得到真实的门店分布情况。</details>

**练习 5**：发现数量级错误后，除了修正当前这条记录，还应该做什么？

<details><summary>答案</summary>应该检查是否存在同类遗漏——比如核实这批数量级错误是否集中出现在某个录入环节或某个时间段，排查是否还有其他未被发现的类似错误记录，而不是只修正已经发现的这一条就结束。</details>
