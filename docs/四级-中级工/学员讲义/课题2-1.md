## 二、聚类 vs 分类

聚类（如K-Means）属于**无监督学习**——不需要预先定义的标签，模型自己发现数据内在的分组结构。这和分类的根本区别在于：分类有"标准答案"，聚类没有。

**机制上的区别**：分类模型训练时，每条样本都配有正确答案（标签），模型的任务是学会"输入什么特征，应该对应哪个已知类别"，训练完之后可以直接拿预测结果和真实标签比对，对就是对，错就是错。聚类则完全没有标准答案可以对照，模型只能依据样本之间"像不像"（距离远近）来摸索分组，分完之后**连算法自己都不知道这堆应该叫什么名字**——这也是为什么聚类之后还需要人工解读业务含义（第五节会讲到）。

> 🔑 **判别口诀**：拿到一个任务先问——数据里有没有"标准答案"标签？**有** → 分类；**没有**，要靠模型自己发现结构 → 聚类。

## 三、一个会让你重新理解"标准化"的案例

**数据**：用户行为数据（`数据集/user_behavior.csv`），含访问次数、平均客单价、平均停留时长、近30天下单数四个特征，设计上真实存在4个可分离的用户群。

```python
import pandas as pd
from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import adjusted_rand_score

d = pd.read_csv("../数据集/user_behavior.csv")
F = ["访问次数","平均客单价","平均停留时长秒","近30天下单数"]
X = d[F]
print(d[F].describe().loc[["min","max"]])
```

**实测**：访问次数1-199，**平均客单价11.61-4983.21元**，平均停留时长6-3580秒，**近30天下单数0-25**。客单价的最大值比下单数的最大值大了约200倍。

```python
km_raw = KMeans(n_clusters=4, random_state=42, n_init=10).fit(X)
Xs = StandardScaler().fit_transform(X)
km_std = KMeans(n_clusters=4, random_state=42, n_init=10).fit(Xs)

print("未标准化 ARI:", adjusted_rand_score(d["_真实分群"], km_raw.labels_))
print("标准化后 ARI:", adjusted_rand_score(d["_真实分群"], km_std.labels_))
```

**实测**：未标准化聚类的ARI（调整兰德系数，衡量聚类结果与真实分群吻合度，1为完全吻合）仅**0.533**，标准化后提升到**0.905**。并排放一起看：

| | 不标准化 | 标准化后 |
|---|---|---|
| ARI | 0.533 | **0.905** |
| 距离计算中占主导的特征 | 客单价（量纲最大） | 各特征公平参与 |

**为什么**？K-Means基于距离计算分组，而距离的计算方式是各特征差值的**平方和**。**客单价数值可达数千，而下单数只有0-25，这个平方和里客单价的贡献天然占压倒性比重**，下单数、访问次数等特征的区分贡献被淹没——不是算法算错了，是输入数据本身的尺度不公平。标准化（如`StandardScaler`，把每个特征转换为均值0、标准差1的分布）把所有特征缩放到同一尺度，使每个特征都能公平参与距离计算，聚类结果才能真正反映数据的内在结构。

> ⚠️ **做聚类分析前，务必先检查各特征的量纲是否一致**（用`describe()`看一眼取值范围）。不一致时必须先标准化，否则聚类结果会被量纲最大的特征主导，这是最容易被忽视的技术细节。

> 🔑 **判别口诀**：各特征最大值相差几十倍以上 → 先标准化再聚类；相差不大 → 可以直接聚类。

## 四、K 值怎么选——不是拍脑袋先猜一个

读到这里你可能发现了一个问题：前面两次跑聚类，代码里都写了`n_clusters=4`——这个4是哪来的？

先做个判断：如果换一个你完全不了解的新数据集，要你决定分成几类，你会怎么定？凭感觉猜一个，还是有章可循？

K-Means有一个"先天要求"：**你必须在运行之前就告诉它分成几堆，它自己不会主动帮你决定**。常用的辅助判断方法有两种。

```python
from sklearn.metrics import silhouette_score

for k in range(2, 8):
    km = KMeans(n_clusters=k, random_state=42, n_init=10).fit(Xs)
    sil = silhouette_score(Xs, km.labels_)
    print(k, round(km.inertia_, 1), round(sil, 3))
```

**实测**（基于已标准化的数据Xs，已验证）：

| K | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|
| inertia（簇内平方和） | 1416.5 | 884.5 | 549.5 | 469.2 | 415.3 | 369.1 |
| 相邻降幅 | — | 37.6% | 37.9% | 14.6% | 11.5% | 11.1% |
| 轮廓系数 | 0.437 | 0.484 | **0.569** | 0.550 | 0.482 | 0.468 |

**肘部法则（Elbow Method）**：inertia（簇内平方和，衡量每个样本到自己所在簇中心的距离平方和，数值越小说明簇内越紧凑）一定会随K增大而减小——分得越细，当然越紧凑。但正常情况下，下降速度会在某个K之后明显放缓，像手肘一样弯折。看"相邻降幅"这一行：K=3→4还有37.9%的降幅，K=4→5骤降到14.6%，之后几乎都在11%左右打转——**K=4就是那个"肘部"**，再往后加K只是小修小补，收益急剧变小。

**轮廓系数（Silhouette Score）**：同时衡量簇内紧凑度和簇间分离度，数值范围-1到1，越大越好。它在K=4时达到全场最高的0.569，K=5反而回落到0.550。两个独立的方法在这批数据上相互印证，**都指向K=4**——这正好和数据集设计时的真实分群数4吻合。

> ⚠️ **局限性，别神化这两个方法**：
>
> 1. 肘部有时候没这么利落，曲线平滑下降看不出明显转折，这时候必须靠轮廓系数等方法交叉验证，不能只认一种办法。
> 2. 这两个指标衡量的都是数学上"紧不紧凑、分不分得开"，**不代表分出来的几堆对业务一定有意义**——这是下一节要讨论的问题，数学最优和业务可用是两回事。
> 3. 两个方法都需要你**先圈定一个候选范围**（比如2到7），把每个候选都跑一遍再比较，它们不会凭空告诉你"就该是4"。

> 🔑 **判别口诀**：遇到"K选多少"，先画出候选范围内的inertia和轮廓系数，**降幅骤减的拐点 + 轮廓系数的峰值**，两者一致时最可靠；不一致时别纠结哪个"更权威"，拿去对照业务意义（下一节）做最终判断。

## 五、聚类结果的业务意义判断

先做个判断：如果聚类结果显示有两个群体"访问次数都很高"，但一个客单价很高、一个客单价很低——这两个群体，运营团队应该当成同一类对象来对待吗？

写下你的判断：_______________

算法分完堆之后，不会告诉你这几堆"叫什么、该怎么运营"——这一步必须靠训练师结合业务知识补上。拿本课题的数据举例，4个群体可以用两个维度来描述：

| 维度 | 取值 |
|---|---|
| 活跃度（访问次数/停留时长） | 高频 / 低频 |
| 消费水平（客单价/下单数） | 高额 / 低额 |

两个维度交叉，恰好对应4类：**高频高额、高频低额、低频高额、低频低额（沉睡用户）**——这正是上一节里K=4之所以成立的业务解释：不是数学上凑出来的4堆，而是真实能对应到4种不同运营动作的用户画像（高频高额该做会员维系，沉睡用户该做唤醒触达……）。

现在回答开头的判断：**不能当成同一类。** "访问次数都很高"只是活跃度维度相同，消费水平维度不同，对应的运营动作完全不一样（一个该做复购激励，一个该做客单价提升）。如果强行合并成一类，两种本该区别对待的人会被塞进同一套运营策略里，效果会被稀释。

**为什么这一步不能省**：如果聚类完直接拿结果去用，不做业务解读，很可能出现"数学上分得很开，但谁都说不出这几堆代表什么"的情况。比如上一节讨论过的，K=5在轮廓系数上也不差（0.550），但如果这多出来的一类无法对应任何有意义的运营动作，就该退回K=4，而不是认为"轮廓系数稍高就该用它"。

> 🔑 **判别口诀**：聚类结果能不能用，不看"数学指标好不好看"，看**能不能对应到一个具体的、和其他群体不一样的业务动作**。对应不上，就要回头调整特征选择或K值，而不是硬给它编一个说法。

## 随堂练习

**练习 1**：某数据集包含"年龄（18-65）"和"年收入（万元，1-500）"两个特征用于聚类，未做任何处理直接聚类，结果几乎完全按年收入分组，年龄的影响微乎其微。为什么？

<details><summary>答案</summary>年收入的数值范围（1-500）远大于年龄（18-65），K-Means基于欧氏距离计算分组，年收入的数值差异在距离计算中占主导地位，淹没了年龄的区分贡献。应先对两个特征做标准化（如StandardScaler），使其处于同一量纲尺度，再进行聚类。</details>

**练习 2**：做聚类分析前，应该先做什么检查？用什么代码可以快速完成这个检查？

<details><summary>答案</summary>应先检查各特征的取值范围是否一致，可以用`df[特征列表].describe().loc[["min","max"]]`快速查看各特征的最小值和最大值。如果不同特征的取值范围相差悬殊（如几十倍以上），就必须先做标准化处理再聚类。</details>

**练习 3**：ARI（调整兰德系数）衡量的是什么？它和"聚类效果好不好"的直觉判断有什么关系？

<details><summary>答案</summary>ARI衡量聚类结果与真实分组标签之间的吻合程度，取值范围通常在0到1之间，1表示完全吻合。它把"聚类效果好不好"这种模糊的直觉判断转化成了一个具体可比较的数字，使得"标准化前后哪个更好"这类问题可以量化回答，而不是凭感觉猜测。</details>

**练习 4**：聚类分析完成后，为什么还要判断"结果是否有业务意义"？能不能直接拿聚类结果去用？

<details><summary>答案</summary>聚类算法只是数学上把数据分成了几组，不保证这几组对业务有实际意义。比如分出的群组可能恰好对应"高频高额/高频低额/低频高额/沉睡用户"这类有业务价值的分类，但也可能只是数学上凑出来的、无法对应任何实际运营动作的分组。训练师需要结合业务知识判断聚类结果能否转化为具体的业务策略，不能拿到结果就直接使用。</details>

**练习 5**：StandardScaler具体做了什么操作？

<details><summary>答案</summary>StandardScaler把每个特征转换为均值为0、标准差为1的分布（即标准化/Z-score标准化），公式为(x-均值)/标准差。转换后所有特征处于同一数值尺度，距离计算时不会被某个量纲大的特征主导。</details>

| 要点 | 一句话 |

| 核心教训 | 量纲不一致必须先标准化，否则聚类被大量纲特征主导（本例ARI从0.533升至0.905） |
