## 一、图像数据集的审核清单

课题1-1教的六维度方法不是只能用在表格数据上。换一种数据类型，六个维度还是那六个，只是**具体检查的动作**会变。图像数据有一个表格数据里不会遇到的新情况：**标注信息和图像本身是两份独立的文件**，这就让"完整性"这一个维度，变成了需要分**两个方向**检查的事。

```python
import pandas as pd
from pathlib import Path

labels = pd.read_csv("../数据集/transport_labels.csv")
images = set(p.name for p in Path("../数据集/transport_images").glob("*.jpg"))
labeled = set(labels["image_file"])

missing_img = labeled - images        # 方向一：标注指向不存在的图像
no_label    = images - labeled        # 方向二：图像存在但无任何标注

print("标注记录总数:", len(labels))
print("标注指向不存在图像数:", len(missing_img))
print("图像存在但无标注记录数:", len(no_label))

print("坐标非法(x2<x1):", (labels.x2 < labels.x1).sum())
print("坐标越界(y2>480):", (labels.y2 > 480).sum())
print("类别分布:", labels["label"].value_counts().to_dict())
```

**实测**：标注记录共106条，图像100张。标注指向不存在图像**4条**；图像存在但无标注记录**3张**；坐标非法(x2<x1)3条；坐标越界(y2>480)4条；类别分布bus占62%、tram仅4%，严重不均衡。

### 为什么"双向"都要查，少一个方向都不行

设想一下：如果有人标注的时候漏标了一张图，这张图会不会出现在标注表 `transport_labels.csv` 里？**不会**——它压根就没被标注过，所以标注表里根本不存在任何跟它有关的记录。这意味着：**只检查标注表内部的问题（比如坐标是否合法），永远不可能发现"图像存在但没人标注"这件事**，因为这个问题的全部线索都在图像文件夹那一侧，标注表里一个字都不会提。

同理，如果标注指向了一张已经被删除或改名的图像，这条记录会原样留在标注表里，但对应的图像已经不存在了——这个问题的线索又全在标注表这一侧。

> ⚠️ **最容易被忽视的检查项**：只检查标注文件内部的合法性（坐标是否越界），**忘记做标注文件与图像文件集合之间的交叉核查**。而交叉核查本身还要分两个方向做——两次集合差集运算，缺一个方向，那个方向的问题就是**彻底的零发现**，不是"发现得少"，是**一条都查不出来**。

**判别口诀**：只看一份文件本身能不能查出来这个问题？**能** → 内部检查就够了（如坐标合法性）。**不能，必须对照另一份文件** → 交叉核查（如标注↔图像对应关系）。

### 把六维度清单补完整：分辨率与重复图像

板书清单里除了交叉核查、坐标合法性、类别分布，还列了"分辨率是否一致""有无重复图像"两项。用代码验证一下：

```python
from PIL import Image
import hashlib

sizes = set()
hashes = {}
for f in Path("../数据集/transport_images").glob("*.jpg"):
    with Image.open(f) as im:
        sizes.add(im.size)
    h = hashlib.md5(f.read_bytes()).hexdigest()
    hashes.setdefault(h, []).append(f.name)

print("分辨率种类:", sizes)
print("重复图像组数:", sum(1 for v in hashes.values() if len(v) > 1))
```

**实测**：分辨率种类只有 `{(640, 480)}` 一种（一致，没问题）；重复图像组数为 `0`（没有重复）。

这两项检测结果都是"干净"的，但**不代表这两步白做了**。课题1-1最后反复强调过一件事：检测的意义不是"找茬证明数据有问题"，而是系统地把清单上的每一项都过一遍——有问题的揪出来，没问题的也要确认清楚、写进报告。少查一项，报告就是不完整的，哪怕那一项的结果是零。

## 二、结构化数据审核要点

除图像外，本课题还要把六维度方法应用到另外两种你以后最常接触的数据形态：**多人标注的文本数据**和**销售这类结构化业务数据**。

### 文本标注数据：同一条记录被多人标注，会冒出一个新问题

`service_annotations.csv` 记录了某电商客服对话的意图分类标注：300条对话，每条分别由3位标注员（A01/A02/A03）独立标注"咨询 / 投诉 / 闲聊"三类意图之一，共900行。

```python
import pandas as pd

d = pd.read_csv("../数据集/service_annotations.csv")
legal = {"咨询", "投诉", "闲聊"}

print("总行数:", len(d), "｜唯一对话数:", d["对话ID"].nunique())
print("意图标签缺失:", d["意图标签"].isna().sum())
print("标注依据缺失:", d["标注依据"].isna().sum())
print("非法取值(不在合法标签集内):",
      (d["意图标签"].notna() & ~d["意图标签"].isin(legal)).sum())

agree = d.groupby("对话ID")["意图标签"].apply(lambda s: s.nunique(dropna=False) == 1)
print("三人标签完全一致的对话数:", agree.sum(), "/", len(agree))
```

**实测**：意图标签缺失3条（完整性问题）；标注依据缺失12条（完整性问题）；非法取值（出现了"其他""咨询类"这两个不在"咨询/投诉/闲聊"合法标签集里的取值）6条（有效性问题）；**三人标签完全一致的对话只有166个，剩下134个（约44.7%）三人标的不完全一样**。

最后这一行和前面三行性质完全不同。前三行——缺失、非法取值——单独看一条记录就能判断出问题，这是**内部检测**就能发现的。但"三人标签不一致"不一样：单独看任何一条标注记录，标签本身都合法（"咨询""投诉""闲聊"哪个都不违规），问题只有把**同一个对话的三条标注放在一起对比**才能看出来。

### 为什么这属于"一致性"问题，而不是"有效性"问题

回忆课题1-1学的一致性：门店编码一会儿写"S001"一会儿写"s001"，同一个意思写法不统一。这里的逻辑是同一个——只是对象从"同一个字段怎么写"变成了"同一条标注任务被不同人处理，结果统不统一"。

> 🔑 **判别口诀**：只看一条记录本身是否合法 → 内部检测（完整性/有效性）；对照**同一个对象**被不同人处理的结果是否相同 → **一致性/交叉检测**。

### 这不是随机出错，是有规律的系统性差异

把其中一句高频内容单独拎出来看：

```python
sub = d[d["对话内容"] == "运费是多少"]
print("涉及对话数:", sub["对话ID"].nunique())
print(pd.crosstab(sub["标注员"], sub["意图标签"], dropna=False))
```

**实测**：同样一句"运费是多少"，对应55个独立对话。A01在55次里标了51次"咨询"；A02标了53次"咨询"；而**A03只标了33次"咨询"、却标了22次"投诉"**。

| | A01 | A02 | A03 |
|---|---|---|---|
| 标"咨询"次数（共55次） | 51 | 53 | 33 |
| 标"投诉"次数 | 1 | 1 | 22 |

同一句话，A01、A02几乎都判定为"咨询"，A03却有将近四成判成"投诉"。这不是随手标错几条的偶然波动，**是某个标注员在同一类内容上持续偏向同一个方向**。

> 📌 本课题先学会用"三人标签是否完全一致"这种最朴素的方式**发现**一致性问题，能说出它属于六维度里的"一致性"即可。下一阶段（三级课题2-2）会教你怎么用 Cohen's Kappa 这类指标**量化**不一致的严重程度，以及怎么诊断这到底是标注手册写得不够细，还是某个标注员本身存在系统性偏差——那是比"发现问题"更深一层的"诊断问题"。

### 销售数据：被1-1漏掉的那一项维度

课题1-1已经把 `cosmetics_sales.csv` 的完整性（销售额缺失120条/15%、会员等级缺失144条/18%）、一致性（门店编码S001/s001大小写混用）挖得很细。但六维度清单上还有一项1-1没专门检测过——**唯一性**：

```python
d = pd.read_csv("../数据集/cosmetics_sales.csv")
print("订单号重复数:", d["订单号"].duplicated().sum())
```

**实测**：订单号重复数 `0`。

结果是0，**不代表这项检测白做了**。没发现问题和没有查这个问题，是两回事：前者是"确认过，这里是干净的"，后者是"根本不知道这里干不干净"。质量检测报告要把检测清单**完整留痕**——结果合格也要写进去，不能因为没问题就跳过不记录。唯一性和时效性是最容易被漏查的两项，因为代码不会主动提醒你"你还没查这个维度"，必须自己对照清单一项项过。

## 随堂练习

**练习 1**：某图像数据集标注文件有500条记录，图像文件夹有490张图片。可能存在什么问题？该怎么核查？

<details><summary>答案</summary>可能存在标注指向不存在图像的情况（多出的10条可能对应已删除或丢失的图像文件），也可能存在图像重复使用多条标注的情况。应用集合运算核查标注文件中的image_file字段与实际图像文件名的差集，定位具体是哪些记录存在问题。</details>

**练习 2**：为什么只检查标注表内部的坐标合法性，无法发现"标注指向不存在图像"这类问题？

<details><summary>答案</summary>因为坐标合法性检查（如x2是否大于x1、坐标是否越界图像尺寸）只涉及标注表自身的字段数值，不涉及与图像文件的对应关系。"标注指向不存在图像"是标注表和图像文件集合之间的关系问题，必须用两者的集合运算（差集）才能发现，单看标注表内部数据是看不出来的。</details>

**练习 3**：类别分布中bus占62%、tram仅占4%，这种不均衡会对模型训练造成什么影响？

<details><summary>答案</summary>模型会倾向于学习数量占多数的类别（bus），对数量稀少的类别（tram）学习不充分，导致模型在实际应用中对tram类别的识别准确率明显偏低。处理方向包括对少数类过采样、或针对性补充采集更多tram类样本。</details>

**练习 4**：坐标字段中x2小于x1，这属于什么类型的问题？

<details><summary>答案</summary>有效性问题——坐标数据不符合逻辑定义域（矩形框的右边界应该大于左边界），属于明显的非法取值，需要退回标注环节核实修正，而不能直接使用这条记录。</details>

**练习 5**：图像数据集质量审核的完整检查清单应包含哪些项目？

<details><summary>答案</summary>应包含：标注与图像的交叉核查（标注指向不存在图像/图像无对应标注）、坐标合法性检查、类别分布均衡性检查、分辨率一致性检查、重复图像检查。五项检查覆盖了"跨文件关系"和"文件内部质量"两个层面，缺一不可。</details>
