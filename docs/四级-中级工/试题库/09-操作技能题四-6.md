## 一、场地设备要求

计算机一台，提供文本编辑软件，不得联网。

## 二、试题正文

某语音识别系统原部署于安静的室内客服场景，现需扩展部署到嘈杂的车载场景（用户在驾驶中使用语音助手）。

**第1题（15分）** 针对这一新场景，制定完整的部署方案，须覆盖六大部署要素。

**第2题（10分）** 部署后发现接口响应经常超时，请说明排查思路与顺序。

## 四、参考答案

### 第1题 部署方案

| 要素 | 车载场景针对性方案 |
|---|---|
| 硬件与算力 | 车载设备算力通常低于服务器，需评估模型是否需要轻量化或边缘推理方案 |
| 网络与时延 | 车辆移动中网络信号不稳定，需设计弱网/断网降级方案（如本地缓存常用指令） |
| 数据接口与格式 | 车载麦克风采集的音频格式/采样率可能与原客服场景不同，需适配 |
| 并发量 | 车载场景通常单设备单用户，并发量需求远低于客服中心，重点关注响应速度而非吞吐量 |
| 安全与权限 | 车载系统涉及驾驶安全，语音指令权限需严格限定（如禁止在驾驶中触发危险操作） |
| 回滚方案 | 部署失败时能快速切换回原有的按键交互方式，避免影响驾驶安全 |

### 第2题 排查思路

> 不应该上来就怀疑"模型识别能力不行"。正确排查顺序：
> 1. 先查**网络时延**——车载场景网络条件本身不如室内客服场景稳定；
> 2. 再查**并发量**是否超出设计容量——若车载场景实际接入设备数远超预期；
> 3. 再查**数据接口与格式**是否匹配——车载麦克风采样率/格式差异可能导致处理耗时异常；
> 4. 最后才排查模型本身的推理耗时是否因硬件算力不足而变慢。
>
> 这是本题核心评分逻辑：**先排查外部环境与接口因素，而非直接怀疑模型能力**——这和课题3-2"区分模型问题与产品/流程问题"的思路一脉相承。
